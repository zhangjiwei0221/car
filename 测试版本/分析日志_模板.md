# 分析日志 · 模板

> 每个日期目录放一份 `分析日志.md`，一个"组"一节。
> 目的：后来的人（包括三个月后的你）能回答 **为什么改 / 要测什么 / 上一轮什么结果**。

## <组名>（<状态：计划中 / 正在上线 / 已有数据>）

**上一轮出了什么**
- <哪个日期、哪个组、什么现象；当时的判断>

**本次想验证的假设**
> <一句话：改什么，期待什么变化>

**本次改动**
- <具体改了什么；改动幅度；没动什么>

**预期**
- <指标层面：失败率 / 关流失 / 重玩次数 / 别的>

**判定**
- <看到什么算假设成立；看到什么算不成立>

**如果失败，下一步假设**
- <把失败归结为什么；下一次准备怎么验证>

**已知风险 / 待补数据**
- <例如撞色、埋点、样本太小>

---

## 填写约定

1. **只写要什么与为什么**，不写实现细节（实现看 `01_项目文档/`）。
2. 数字等到手再补，不预填。
3. 一个组一节；组之间不混。
4. 旧结论被推翻时，用「本条结论已被 <日期> 的分析取代」标注，不改原文。
