# 04_派工工作区 · 总工（Gemini）↔ 施工（DeepSeek）协同规程

> **本目录用途**：由总工模型（**Gemini**）开具精确到文件、行号、命令和验收门槛的《派工单》，交由施工模型（**DeepSeek**，在 DeepSeek Harness 中运行）执行代码修改、跑脚本实测、填写交工报告；完结后由总工模型验收。

## 协作四条铁律
1. **唯一活单入口**：永远只读写 `04_派工工作区/当前任务单.md`。每次新派工前，将上一张已结单的 `当前任务单.md` 移入 `04_派工工作区/历史派工归档/YYYYMMDD_HHMM_<主题>.md`。
2. **真实时间戳（精确到时分）与模型署名**：
   - 派工与交工时，**必须执行 `date "+%Y-%m-%d %H:%M"` 获取本机真实时间填入单据**，严禁编造时间；
   - 明确标注**派工模型名称（`Gemini`）**与**接单执行模型名称（如 `DeepSeek-V3 / DeepSeek-R1 / deepseek-reasoner`）**。
3. **双联单不删改上半区**：施工模型接单后，只把顶部状态改为 `🟢 待总工验收` 并在下半区 `## 二、【接单施工交工区】` 填写实测结果、命令、改前改后对比与 `md5`，**严禁删改上半区 `## 一、【总工派工区】` 的要求与门槛**。
4. **严守 `AGENTS.md` 十一大红线**：严禁手改关卡 JSON 的 `spools / count / blocks`，严禁伪造数字，改 js 必跑 `node --check`。
