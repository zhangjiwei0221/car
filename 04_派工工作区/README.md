# 04_派工工作区 · 默认直做 vs 总工派单 ↔ 施工接单协同规程

> **核心原则**：由于用户会在 Claude Code 与 DeepSeek Harness 之间随时切换模型，**角色不与某一个模型硬绑定，而是 100% 按用户开口的指令自动切入「默认直做 / 总工派单与验货 / 施工接单」三档之一**。

---

## 一、三档自动切换口令表（开机必判）

| 用户怎么开口（触发信号） | 当前模型应进入什么角色 | 允许做什么 & 严禁做什么 |
|---|---|---|
| **① 未提“派单/出主意/任务单”**<br>（如：“把 L7 和 L8 对调”“查下这关为什么报错”“改下默认冰参数”） | **【默认直做档】**<br>（不分领导/工人） | • **直接动手干完**（改几行代码、`node --check`、拷文件、查数据、答疑）；<br>• **严禁端架子写派工单**把简单小事复杂化。 |
| **② “针对XX想主意 / 只出主意 / 派单 / 写任务单 / 验货”** | **【总工（领导）档】** | • **严禁跑重耗时造关/模拟脚本耗额度**！只读现有代码、报告与 `思维导图_V6/V7.md` 分析物理根因；<br>• **派单时**：先归档旧单 → 取 `date "+%Y-%m-%d %H:%M"` 真实时间 → 在 `04_派工工作区/当前任务单.md` 写代码级派工单；<br>• **验货时**：必查源码真实 diff、`node --check`、逐色容量守恒与 `md5`，绝不轻信下半区文字汇报。 |
| **③ “干活 / 接单 / 做当前任务单 / 04_派工工作区/当前任务单.md”** | **【施工（接单）档】** | • 直接读取 `04_派工工作区/当前任务单.md` 上半区执行代码修改与跑数；<br>• **严禁删改上半区、严禁自己再开新派工单、严禁擅自叠满过载障碍（如 `3管+3黑`）或留白难项**；<br>• 若用户在施工中途口头改了需求，必须在下半区交工表写明 **`用户 HH:MM 口头变更：...`**。 |

---

## 二、总工写单 & 施工交工的 5 条防乱铁律（从 #001~#005 实战提炼）

1. **唯一活单入口 & 旧单必归档**：
   - 永远只读写 `04_派工工作区/当前任务单.md`。
   - 每次总工开新单前，必须先把上一张已结单的 `当前任务单.md` 移入 `04_派工工作区/历史派工归档/YYYYMMDD_HHMM_派工单XXX_<主题>.md`。
2. **一单不超过 2 件事，颗粒度写到「代码级 + 命令级 + 禁区级」**：
   - 严禁写“请优化某函数”这种模糊意图；总工必须直接给出**目标文件路径、行号范围、可直接替换的 JS 代码块、完整 CLI 命令与参数**；
   - 必须写明**物理禁区**（例如：严禁在爬山后二次调用 `setupEndgameClimax`、严禁同时传 `--pipe-mode 3` 与 `--black-mode 3` 焊死棋盘、严禁拿 `humMid > 0.72` 的旧关冒充 C 档真样板）。
3. **真实时间戳（精确到时分）与模型署名**：
   - 派工与交工时，**必须执行 `date "+%Y-%m-%d %H:%M"` 获取本机真实时间填入单据**，严禁编造时间；
   - 如实标注派工模型与接单执行模型名称。
4. **双联单上半区神圣不可侵犯**：
   - 施工模型接单前先把待改代码备份到本单实验目录的 `_pre_change_backup/`；
   - 完结后只把顶部状态改为 `🟢 待总工验收`，并在下半区 `## 二、【接单施工交工区】` 填写实测结果、命令、改前改后对比与 8 位 `md5`，**严禁删改上半区 `## 一、【总工派工区】`**。
5. **严守 `AGENTS.md` 十一大红线**：
   - 严禁手改关卡 JSON 的 `spools / count / blocks`，严禁伪造数字，改 js 必跑 `node --check`，未获明确指令不动客户端 `bin/`（动前必备份并留 `md5.txt`）。
