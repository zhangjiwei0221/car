### 0. 物理诊断：为什么现在的 `BuildV7Stagger_v1.js` 还不够“聪明”？
在 `#007` 和 `#008` 中我们看清了现有 `BuildV7Stagger_v1.js` 的 **3 个死板痛点**：
1. **痛点 ①（拿图不体检，一刀切死参数）**：
   - 不管输入图是“单色大块千层饼（如 `11.txt` 136px 巨块）”还是“12~15 色碎片多主体图”，也不管用户想要 `A / B / C` 哪一档，全靠人工在命令行手写 `--pipe-mode --pipe-mouth --black-mode --q-count --rand-lo --rand-hi --hum-mid-max`；而且 `3 管道 -> 强制 0 冰`、`2 管道 -> 只留 row 2 两颗浅冰` 是写死的硬分支，极其死板。
2. **痛点 ②（选冰只看 `r >= 0.55*R` 的一刀切占比，没看颜色在图中腰的真实暴露深度，且 `shellSunk` 固定死 2 辆）**：
   - 现有 `easyShare` 只算 `r >= 0.55*BR` 的粗略占比，没区分**“底边第 0~3 行开门必消色”**与**“第 4~18 行中腰承接色”**；如果中后排深冰（`p=21/27/32`）误冻了底边开门急需色会卡死棘轮，误冻了顶层最后才露出的颜色又会让玩家毫无感知（绕路白给）。
3. **痛点 ③（跑完 6 个 style 发现偏松或偏紧时，不会自己“升/降挡”重试，只会挑个不达标的交差）**：
   - 比如 `#008` 的 `comp_02`（B 档跑出 `rand=.758, humMid=.850` 偏松）、`comp_04`（C 档跑出 `humMid=.825` 偏松）、`comp_05`（C 档跑出 `rand=.725` 偏松）——明明 `ratPass=true` 盘面余量很大，只要**自动升一档全局压力**（如：切 `dumbbell` 真哑铃管 + 沉底隔板兄弟车 `maxSink` 从 `2` 升到 `3~4` + 问号车 `qCount` 升到 `3~4` + `blackMode` 升到 `2~3`），就能把 `humMid` 压进目标带；反过来如果 6 个 style 全都 `ratPass=false`（太紧死锁），只要**自动降一档封锁**（减 1 个黑块、降低冰块参数 20%、`maxSink` 降为 1）就能救活！

### 3. 施工发现与遗留说明

1. **AutoGear 对 B 档偏松图极其有效**：`comp_02` 从 `.758/.742/.850` 两级升挡到 `.492/.533/.650`，**首次拿到 allPass**，证明“升挡加压”能把顺消图压进 B 档。

3. **+2 挡明显过冲**：`comp_05` gearP2 出现 `0/0/0`、`comp_04` gearP2 style2 rand `.9`；三黑+4沉底+4问号+三连链对 35×35 图过重。建议下一版把 +2 拆成细粒度（只加 `iceScale` / 只加 `maxSink`）。
4. **`--tier` 一键档位可用**：`--tier B/C` 自动带 7 门槛，`--tries/--iters` 叠加；未传 `--tier` 时旧 CLI 行为不变（`TP=null`）。
5. **AutoBand 条件已按实测修正**（见 §1 末尾），11.txt 触发、#008 六张全不触发；`--no-auto-band` / `--no-auto-gear` 可逐项关闭。
