### 1. 总工手把手教学：怎么用代码写出「好看、有逻辑、又能卡住三面墙」的背景生成器？

一个**既好看又能给 v7 三面墙提供纵向隔板**的背景，必须遵守 **4 条美术+物理设计法则**：
1. **法则 ①（成团不成渣：最小色块厚度 `>= 3px`）**：
   - 任何条纹、波浪、砖块、窗框的线条或色块，纵向厚度必须在 **`3 ~ 5 行`** 之间（横向宽度 `>= 4 列`）。**绝对禁止 `1×1` 或 `2×2` 棋盘格高频闪烁**！
   - 为什么？`3~5 行` 厚的横带/波浪在视觉上是清晰的色带/砖块，而在三面墙（`35×35`）里，`35 / 4 ≈ 8~10` 层纵向换色，刚好能把每一列切成 8~10 段串联锁，既不看花眼，又能彻底消灭一吸到底的千层饼！
2. **法则 ②（背景只用 `3 ~ 4` 种协调色，且必须与主体色拉开对比度）**：
   - 一张图的背景色控制在 **`3 ~ 4` 种颜色**（1 种主底色占背景的 40%~50%，2~3 种纹样/隔板色各占 15%~25%）。
   - **自动避撞色（极重要）**：先扫描本关选中的 2~3 个主体用到了哪些颜色（特别是**主体外圈轮廓色**），背景选色时**严禁使用与任何主体外轮廓色相同、或 RGB 距离 `< 85` 的颜色**！否则主体贴上去会和背景融为一团看不清轮廓。
3. **法则 ③（5 种最经典、好看且有逻辑的程序化背景母版，严禁写死单一图案）**：
   你要在脚本里实现以下 **5 套有视觉逻辑的参数化背景生成器**（支持任意正方形尺寸 `SIZE`，如 `35×35` 或 `38×38`）：
   - **母版 A `window_well`（井字画框窗格，最衬托多主体）**：
     - 灵感源自 `compose_well_v779.py` 与 `bg05_frame_jar`：以柔和浅色（如 `31` 米白或 `32` 浅黄，若主体外圈用了 `31/32` 则换其他浅底色）为主底；
     - 在画布外圈画 `2px` 宽的分段装饰边（每隔 10~12 格换色 A / 色 B）；
     - 在画布内部、**避开或环绕 2~3 个主体的分界线位置**（例如 `y = 11..13, 23..25` 两道 `3px` 宽横梁 + `x = 16..18` 一道 `3px` 宽竖梁），用色 A（横梁）和色 B（竖梁）穿插交织成「井字/十字画框」，把画布自然分隔成放主体的窗格，窗格四角还可点缀 `3×3` 的色 C 小角花。
   - **母版 B `wave_ribbons`（柔和正弦海浪/云带，横向串联锁最强）**：
     - 灵感源自 `bg06_sunset_waves` 与 `bg13_chevron_waves`：不用死板的水平直线，而是用柔和的**阶梯正弦波 / 折线波** `bandIdx = Math.floor((y + Math.round(2 * Math.sin(x * Math.PI / 8))) / 4)`；
     - 每条波浪带厚 `4px`，由 3~4 种协调色（如日落渐变、海洋渐变、马卡龙三色）按 `[c0, c1, c2, c1]` 循环交替铺满，每隔 2 条波浪带在波峰处镶嵌 `2×3` 的高光点缀色 `c3`。既有海浪/彩带的呼吸感，又保证每一列从底到顶必须跨过 8~9 道波浪隔板！
   - **母版 C `stagger_bricks`（大号错缝文化石/拼布墙，绝非碎棋盘）**：
     - 灵感源自 `bg09_brick_mosaic`：每块砖高 `4px`、宽 `8px`（`4×8` 大砖，面积 32px，绝不晃眼），上下相邻两排砖水平错位 `4px`（半块砖）；
     - 砖缝（每块砖底边 `1px` + 右边 `1px`）用统一的深/浅勾缝色 `c0`，砖面按 `(brickRow + brickCol) % 3` 用 `c1, c2, c3` 三种色彩交替填充。视觉上是整洁的卡通砖墙/拼布被面，物理上每一列每 4 行就有一道勾缝 + 换色砖面！
   - **母版 D `seigaiha_arches`（日式青海波/同心圆弧鱼鳞纹）**：
     - 灵感源自 `bg17_seigaiha_scales`：以半径 `R = 7` 的交错半圆拱门为单元（偶数排圆心每隔 14 列，奇数排圆心水平偏移 7 列、垂直间隔 5 行）；
     - 每个半圆从外到内分 3 层同心弧带：外弧厚 `2px` 用 `c1`、中弧厚 `2px` 用 `c2`、内芯用 `c3`，弧间底色用 `c0`。既有高级传统纹样美感，又有极强的斜向+纵向双咬合。
   - **母版 E `bunting_garland`（派对三角彩旗 + 宽幅底纹带）**：
     - 灵感源自 `bg19_party_bunting`：画布分成 3 段高 `11~12px` 的横幅区（分别以柔和色 `c0, c1` 交替为底，段间有 `2px` 装饰横条 `c2`）；
     - 每段顶部垂下宽 `6px`、高 `5px` 的倒三角彩旗（旗面用 `c2, c3` 交替），底部配 `3px` 高的几何花边。
4. **法则 ④（多主体黄金布局与独立轮廓保护）**：
   - 从 `txt图/图库/主体图纸库*`（共 **218 张 `18×18` 带 `0` 透明底的小主体**，如 `三角饭团-1.txt`、`冰淇淋-1.txt`、`小船-1.txt`、`火箭-1.txt`、`宝箱-1.txt`、`热气球-1.txt` 等）里挑 **2 个或 3 个主体**（先 `trim` 裁掉四周纯 `0` 空边，得到紧凑包围盒，通常只有 `13×14 ~ 16×16`）：
     - **3 主体品字形布局（推荐，适合 `35×35` 或 `36×36`）**：
       - **底左主体 S1** + **底右主体 S2**（落在下半区 `y ≈ 17..33`，左右分开，中间留 `2~4px` 背景隔断露出来！让三面墙开局底边同时啃 S1、S2 和中间/两侧的背景隔板）；
       - **顶中主体 S3**（落在上半区居中 `y ≈ 2..18, x ≈ 9..25`，正好压在 S1 和 S2 的头顶上方，形成**下二上一的“品”字形交错咬合**，终局最后剥离顶中主体 S3 + 顶部背景波浪！）。
     - **2 主体斜对角布局（适合 `35×35`）**：
       - **左下主主体 S1**（`y ≈ 16..33, x ≈ 2..19`）+ **右上副主体 S2**（`y ≈ 2..19, x ≈ 16..33`），左上角与右下角露出大片有层次的纹理背景，形成斜向对角推进。
   - **贴图规则**：只把主体中 **`v > 0`（非透明）的像素**盖到背景画布上，主体周围为 `0` 的透明格子 **100% 透出底下的图案背景**！这样主体不是生硬的方块贴纸，而是自然悬浮在背景纹样之上，且合成后全图 **`zeros === 0`（100% 满格正方形）**！

### 任务 1：新建 `03_工具/正式版/ComposeMultiSubject_v1.js`（多主体 + 程序化逻辑背景合成器）

1. **命令行参数契约**：
   ```bash
   node 03_工具/正式版/ComposeMultiSubject_v1.js \
     --size 35 \
     --subjects "三角饭团-1,冰淇淋-1,热气球-1" \
     --layout pin \
     --bg-style wave_ribbons \
     --out 实验关/派工实验_008_多主体背景合成/maps/comp_01.txt \

     [--seed 101] [--save-bg 实验关/派工实验_008_多主体背景合成/bgs/bg_wave_01.txt]
   ```
   - `--size`：画布正方形边长（默认 `35`，强制 `W === H`）。
   - `--subjects`：逗号分隔的 2~3 个主体名（自动在 `txt图/图库/主体图纸库*` 下查找 `<name>.txt`，必须是 `<=20×20` 且含 `0` 透明底的小主体；先 `trim` 掉外围全 `0` 行列）。
   - `--layout`：
     - `pin`（3 主体品字形：底左 S1、底右 S2、顶中 S3，相互之间保留 `>=2px` 背景缝隙不重叠，或最多只擦边不盖核心）；
     - `diag`（2 主体斜对角：左下 S1、右上 S2）；
     - `trio_diag`（3 主体阶梯斜列：左下 S1、中右 S2、左上 S3）。
   - `--bg-style`：内置实现上述 **5 套有逻辑好看的程序化背景母版**（`window_well` / `wave_ribbons` / `stagger_bricks` / `seigaiha_arches` / `bunting_garland`）；若传了 `--bg-file <path>`，则读取外部现成背景矩阵（若外部背景中的颜色与主体外轮廓撞色，自动将该背景色重映射为不撞色的安全色！）。
   - `--save-bg`（可选）：将单独生成的纯背景 TXT（`像素矩阵` 头 + `SIZE×SIZE` 数字矩阵）存盘，方便单独检视背景长相。
2. **硬性质量护栏（脚本内自动校验并打印摘要）**：
   - **护栏 ①（100% 满格正方形）**：输出矩阵必须 `H === SIZE && W === SIZE` 且 `zeros === 0`；
   - **护栏 ②（轮廓零撞色）**：提取所有主体非 `0` 像素的**外边界像素集合 `outlineColors`**（四邻域含 `0` 的主体像素颜色），背景所使用的 3~4 种颜色与 `outlineColors` 中任意颜色的 RGB 距离必须 **`>= 80`**（且颜色 ID 绝不相同），确保主体边缘 100% 清晰凸显；
   - **护栏 ③（色数与碎色控制）**：全图总颜色数控制在 **`10 ~ 16 色`**，每种颜色总像素数 **`>= 16px`**（无 `<16px` 孤立碎色，若主体自带极小点缀色 `<12px`，可在贴图前并入主体内 RGB 距离最近的同系色）；
   - **护栏 ④（背景美观度与三面墙分隔度自检）**：
     - 全图主体非 `0` 像素占比 **`38% ~ 58%`**（背景露出 `42% ~ 62%`）；
     - 全图每一列从底到顶平均换色次数 **`avgColChanges ∈ [7.5, 16.5]`**（既有充足纵向隔板，又绝不是 `>22` 的刺眼碎棋盘格！）；
     - 全图最大单色四连通块 **`maxComp <= 110px`**（消灭 `>120px` 一吸到底的巨型单色块）；
   - **护栏 ⑤（字符可视化预览输出）**：脚本生成每张图时，同步在同目录输出一份 `.preview.txt`（用 `0-9A-Y` 单字符网格打印：先打纯背景预览，再打叠上主体后的合成图预览 + 主体掩码图 `.` 为背景 `#` 为主体），确保肉眼一眼就能检查背景图案规整度与主体轮廓！

### 3. 施工发现与遗留说明

1. **哪套最顺**：`pin` 布局（底左+底右+顶中）在 35×35 下最稳，6 张里 4 张用它；背景母版里 **`stagger_bricks`（B3）与 chevron 外部背景（C6）**最容易进 B/C 档——每 4~5 行必换色、`maxComp` 小，v7 三面墙每列要跨 8~10 道隔板。
2. **哪套最软**：`wave_ribbons`（B2）与 `seigaiha_arches`（C4）——前者 4px 同色横带在策略 0 下一吸到底（rand .758），后者弧带太连续（hum .842 / humMid .825）；`bunting`（C5）居中但随机档 .725。
3. **后段波峰最高**：`comp_04` `2.00`（青海波）、`comp_01` `1.80`、`comp_02` `1.78`；但只有 `comp_06` 在 C 档内同时拿到 `1.35`，**“难”与“后段高潮”仍没在同一张图上同时最大化**。
4. **多主体没有自动增难**：主体自带的 10–15 个小车色把盘面变软，背景只负责“消灭千层饼”；难度仍需车场端的沉底/链/管/爬山去顶（与 #007 结论一致）。
5. **遗留**：① B2/C4/C5 可加 `--black-mode 3` 或换更碎母版重跑（本轮严格按任务单命令，未擅自加码）；② 2 主体 38% 覆盖下限与 maxComp 的矛盾已用 1.15× 放大绕过，若总工不接受缩放需放宽该 guard；③ 砖高 5px / 青海波 2 色为工程折中。
6. **证据目录**：`实验关/派工实验_008_多主体背景合成/README.md`（完整表、偏差说明、复现命令）。客户端 `bin/` 零改动。
