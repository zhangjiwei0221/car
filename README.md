## 这工程在解什么问题

```
车太碎 → 车多盘大、开局全是免费车 → 没有压力
车太大 → 车少盘小、每辆都能一口吃下 → 也没有压力

压力 = 中段（30~80% 进度）手里"攒着几张吃不完的票"持续得够久
```

一次生产：**切球 → 选盘 → 摆障碍 → 放车 → 求解 → 评估 → 择优/兜底**。

当前验收：

```
2 条硬门：可解 + 守恒
结构门：J≤20 / 可选中位≥2 / 被迫步≤20% / partial步≥20% / 吃满中位≤3 / freeLow≤30 / 最长免费连≤6
四玩家 + 六指标：只报告，不拦交付
```

> **历史**：本求解器最早用「六条门槛」判合格——
> 可解 / 稳健通关≥50% / 被埋=0 / 前期峰窗≤2 / 峰窗 3.2~4.8 / 稳打落后≤17。
> 出处：工作日志 §40（好关判据 v3）。这是最初形态，已不用于现行交付。

当前未决问题见 [`工程说明.md` §15.6](01_交接文档/工程说明.md)。

## 约定（改代码前先看）

1. **容量区间是用户输入**：`boxSizeMin/Max`、`capNormMin/Max` 不许被缩放、对半拆或按"目标车数"拆（踩过两次）
2. 交付要改版本号（`bin/index.html` 三处 + `css/style.css?v=`）
3. 改完先 `node --check`，用真关卡验证改前/改后数字
4. 关键改动写进 `02_工程/补丁/`，并追加一节到工作日志
