# 瞬时模式生成器实施计划（v525）

> 2026-10-26 / Kimi。基线：`84c2f92`（v524 回撤生成器接线，仅保留 `utils.eliminationOrder` 实验开关）。
> 本文件是 [`优质关卡生成_详细工作流程.md`](优质关卡生成_详细工作流程.md) 中 **P0~P3 的瞬时模式实施分支**，不是另一套验收标准。

## 1. 与总工作流程的关系

总工作流程回答“怎样从问题到最终可交付关卡”，分 P0~P6；本计划回答“瞬时模式这条技术主线具体怎样落地”。

| 总流程 | 本计划对应步骤 | 关系 |
|---|---|---|
| P0 容量合同 | 第1步规则契约、第3步容量计划 | P0仍是硬门；本计划先消除规则口径分裂，再保证每色容量合法 |
| P1 释放unknown | 第5步完整体验、第6步失败驱动 | 先建立同规则生成，再评价释放，不能用四边结果冒充瞬时结果 |
| P2 压力/容量组合 | 第2步instantPlayout、第3步容量计划 | 本计划把“每色方案联合”落到每辆车的动态回放 |
| P3 车序/盘面观感 | 第4步摆盘与车序 | 本计划让摆盘服从真实进场/槽位计划，再做首行和黑块比较 |
| P4 目标化障碍 | 第7步障碍 | 只有基础瞬时车序稳定后才允许进入 |
| P5 多图/UI/性能 | 第8步多图UI | 最终在固定校准集与留出集验证，不以外推代替证据 |
| P6 真人校准 | 第8步真人 | 机器指标通过后仍需盲评确认可学习和公平 |

**执行原则**：总流程是验收框架，本计划是当前主线的施工图；任何本计划结果仍必须通过总流程的硬合同、成功保护、多图和真人复核。

## 2. 已确认的执行顺序

1. **统一规则契约**：一个 `ruleMode` 派生 `bottomOnly` / `instantChain` / `elimOrder`，全链路同口径。
2. **接入 instantPlayout 到切车**：按真实最左空槽、曼哈顿最近、容量封顶生成每辆车的像素计划。
3. **容量计划**：在用户区间内对每色做可行拆分；临界容量使用“可达量/下一波/剩余量”的低成本候选，不逐像素盲试。
4. **摆盘与车序**：最终棋盘必须忠实表达计划中的进场顺序、车容量和颜色；回放不一致即淘汰。
5. **完整体验筛选**：同瞬时规则求中段3/4、债务起伏、显著释放、最终通关，不先看首通率。
6. **失败驱动修复**：远压力不足换基底，近压力不足局部调容量，释放unknown先查覆盖/排序，结构失败按具体门修。
7. **目标化障碍**：只为明确缺口添加最小功能单元，并做移除消融；禁止随机冰链和末段锁死。
8. **多图、UI、真人**：固定校准/留出集，真实UI落库，真人盲评后再冻结。

## 3. 逐步工作卡

### 第1步：规则契约（v525 已完成）

- `Generator.normalizeRuleConfig` 从 `ruleMode` 派生三态；兼容旧脚本的 `instantChain`/`bottomOnly` 字段。
- UI `getGenConfig` 同时发出 `ruleMode`；瞬时连锁时 `elimOrder='instant'`，其他模式为`ring`。
- 生成入口 `produceFixed` / `produce` / `produceGoal` / `produceDispatchCore` 统一归一化。
- 验证：三态单测；006默认四边旧/新最终关卡hash相同；瞬时模式候选配置为`instantChain + elimOrder:'instant'`。
- 边界：这一步只统一口径，**切车仍没有消费瞬时像素归属**；默认生产仍是四边。

### 第2步：instantPlayout 接入切车（v526 已完成首版）

- 把现有只读 `instantPlayout` 提炼成生成模块，默认使用**真实最左空槽**，而不是固定0号槽。
- 输出不是只有`color,count`，而是每车：
  `{id,color,cap,pixels,slot,start,enterOrder,finishOrder,debtSteps,releaseStep}`。
- 每车只吃一种颜色；每色像素总和必须等于目标图该色像素（含管道队列时另算）。
- 每车实际消耗像素必须为1..cap，不允许`unfinished`；若布局无法完成，报告失败原因，不伪造关卡。
- 接进`pickBoxSplit`的强制车单路径；`eliminationOrder('instant')`只作验证/分析，不能单独充当切车（v524证明是no-op）。
- 首轮验收：006/010/007全覆盖、无死锁、同色守恒、无车超过用户上限；每车像素Jaccard与此前原型一致或更好。
- 生产保护：默认四边hash不变；瞬时模式先只做实验开关，达到结构/UI门槛后才改默认。
- **v526结果**：新增`instant-playout.js`，真实最左空槽+FIFO+最近曼哈顿+每车像素轨迹；瞬时模式在切车前优先采用playout，四边/底部不进入该分支。
- 006/010/007计划均覆盖1225/1225、无死锁、无未完成、aboveMax=0；端到端均生成可解且结构通过关卡，耗时约0.53~0.79s。
- 默认四边006最终hash仍为`48680c72...`。遗留：低于下限车006=5、010=1、007=12，007最小2px，进入第3步容量计划。

### 第3步：容量计划（v527 首版完成）

- 先按颜色求可行车数集合：满足`Σcap=P`且每车在`[boxMin,boxMax]`；无可行解时明确`capacityInfeasible`。
- 每辆候选车按进场状态计算：当前可达量`A`、该色剩余量`T`、下一波解锁量`N`。
- 有限候选容量：`A`、`A+1`、`min(boxMax,A+N)`、`boxMax`、`T`（去重且夹回用户区间）。
- 每个候选都重跑完整playout，不看静态单点；记录容量变化导致的颜色、槽位、债务和释放变化。
- 小色可以通过解锁贡献承担关键债务，但不得用未声明的低于区间容量实现；用户若允许小容量档，需单独立参数合同。
- 首轮验收：原007最小2px、006/010低于下限问题消失，或明确判该图容量不可行；不得靠“余量并车”造巨车。
- **v527结果**：每色先求Σ=P的容量队列。可落在区间时均衡拆分；不可分时先减少belowMin车数，尾车过小再均衡拆分。007最小2px→16px、microCount=0；006/010/007仍全部覆盖、无死锁、aboveMax=0、结构出关。
- 区间数学不可分的车仍如实保留：006 belowMin=6、010=1、007=27；下一步用可达量/下一波/余量构造临界容量变体，比较压力与释放，不靠放宽上下界。

### 第4步：摆盘与车序（v528 已完成）

- 以playout的`enterOrder`作为摆车顺序，以真实槽位时间线作为压力目标，不再先按几何趋势重排。
- 检查首行同色run、首行颜色数、开局可选性；先报告再做观感比较，不直接牺牲压力。
- 最终生成关按瞬时规则回放，必须重现计划里的主要车序/容量/颜色；不一致则该候选淘汰。
- 保护：棋盘行列≥6、容量守恒、aboveMax=0、失败原因可诊断。
- **v528结果**：严格瞬时计划路径关闭需求重排/角色排程/交错/开局半满车/P7/陷阱等待改序后处理；按第0行可达BFS铺格。
- 006/010/007计划车单→棋盘格逐项匹配，参考计划路线分别37/27/46步完整通关，maxBuffer=1/1/2。求解器可另选合法路线，因此不要求全知路线逐车相同。
- 关键边界：路线能回放不等于有压力；下一步必须同时评价计划参考路线和求解最佳路线。

### 第5步：完整体验筛选（v529 已见正结果）

- 只用瞬时模式求解和评价：中段3/4、显著释放、释压动作可回放、最终通关、路线分布。
- `release unknown`保留为未知；先做P1状态覆盖/动作排序，再讨论预算。
- 真实压力曲线要同时有债务形成、暂存3/4平台和可执行释放，不能只看峰值。
- **v529结果**：纯supply计划路线中段3/4为0/0/0；`targetBuffer=4 + maxDebt24/40`后计划路线达到52.2%/75%/78.6%，maxBuffer均4，release found。
- 边界：同一棋盘的求解器最佳路线仍走低压路线，solver pass=0/3；计划路线通过不等于玩家实际容易走进压力路线。

### 第6步：失败驱动修复（债务参数已找到；有限分支路线约束下一项）

- 按压差/释放/结构/容量/摆盘分类路由。
- 一次只改一个因素；每次候选重新回放、求解、评价。
- 目标模式有总预算；连续快速无候选必须退避并记录真实原因。
- **v529~v530边界**：target4债务计划路线三图全过，但普通盘面存在低压绕路；单入口隔行走廊可让plan/solver三图全过，代价是黑块43.8~53.8%、盘面偏大，不能接受。
- 下一项不是继续单入口，而是保留1~3条有限高压力分支；以路线压力下限和黑块/盘面两个保护指标筛选。
- **v531结果**：2/3入口+入口债务车原型黑块11.1%~25%，但plan路线2/6通过、solver0/6；007在6×6上pipeCapacity全灭。分支拓扑可行，分支内部车序/分支选择未成立。
- **v532结果**：扫描2分支的4组入口位置（006/010/007共12组），plan 4/12、solver 0/12、solver低压路线12/12；006/007计划路线可到85.7%/81.5%，但release unknown，010计划路线76.5%但solver仍0。下一步不再扩大入口搜索，改分支内部债务序列。
- **v533结果**：2分支前缀债务prefix2~8扫描；007 prefix6/8求解器中段3/4达52%/72%，但release仍unknown；006 prefix6计划路线57.9%通过但solver10%。下一步锁定高压路线，专项搜索可执行释放动作。
- **v534结果**：007 prefix8高压父状态枚举117个完整路线候选，68个有显著释放、58个中段3/4≥50%、40个两者同时成立；最佳46步，中段3/4=80%、maxBuffer=4、显著释放1、独立回放通关，黑块17.9%、容量aboveMax=0/micro=0。证明“完整高压+释放+通关”可共存在一条路线。
- **v534边界**：只有007/seed1001；脚本未记录整轮墙钟和去重，尚未接生成器。下一项先做多图路线构造模块与成本收口，不进入障碍。

### 第7步：目标化障碍

- 仅当基础车序稳定后，针对“缺债务/缺释放/缺供给时序”添加一个最小功能单元。
- 冰值、锁链组、管道位置由债务窗口和需求时间线决定；每次做无障碍对照和移除消融。
- 不接受末段封关键色、随机冰链、只抬高首通死亡。

### 第8步：多图/真实UI/真人

- 预登记校准集和留出集；报告通过率、aboveMax、release unknown、P50/P90、轮数和超时。
- 真实UI验证模式选择、同规则日志、逐关落库、停止和预算；最终JSONL必须带`ruleMode/entryMode/elimOrder`证据。
- 真人盲评确认能理解暂存压力、能想到释放动作、不是背板；未通过前不把瞬时模式设为默认。
