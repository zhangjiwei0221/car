## 一、前辈的核心思路（三句话）

1. **合格 ≠ 难度。** 审核只回答"这关能不能用"，难度分单独算，两者互不决定。
2. **先造，再造不出来才救。** 基础阶段只做"建棋盘 + 首批障碍 + 六遍求解"，
   **不做任何换球/换位扰动**；只有候选没通过审核，才进入 `chokeSwap` / `chokeInflate` 分支。
3. **合格的判据是"卡点"，不是"平均压力"。** 卡点线 = `L − 1.8`（暂存 5 → 3.2），
   只要求 30~80% 区间里**至少有一个 5% 窗口**越线，且前期 0~30% 不出卡点。

> 换句话说：他们做的是**"找出合格的那一个候选"**，不是"把每一关都雕成理想曲线"。

## 二、他们的机器（可以直接对照我们的实现）

### 2.1 预算结构

```
K=6 个候选 × (1 基础 + B=3 卡点分支 + 9 二轮分支) ≈ 78 个生产状态
单关时间预算 5 分钟，到点停
```

### 2.2 六遍求解（判定"可解"的口径）

```
贪心×2（noise 0 / 0.6） → 三步前瞻树×2（noise 0 / 0.8） → 噪声贪心×2（noise 1.0 / 1.5）
任一遍通关即停
```

三类策略互补：贪心快、树能解贪心解不出的、噪声能救差一点的。

### 2.3 两类卡点手段（只对"未合格"的候选执行）

| 手段 | 做法 | 本质 |
| --- | --- | --- |
| `chokeSwap` 换球/搬盒 | ① 把前期锁链组的一个成员换成"**目标图里埋得最深**的颜色"；② 把"**网关色**"（消掉它能解锁最多其他像素的颜色）的盒子搬到离原位最远处或管道最深层 | 改变**位置**与**依赖时机** |
| `chokeInflate` 增容 | 把某色的暂存容量**集中灌进一个后期盒**，抬到容量上限的 1.5~2 倍；同色 donor 盒降到最小，总量守恒 | 改变**容量分布** |

按 60%/40% 分派；第二轮起 30% 概率走"增减障碍重生成"（±3 级、每级 5%）。

### 2.4 十二种卡点类型（结构期 / 变后期）

结构期（建盘时就铺）：`narrowPath` 窄路、`iceCluster` 冰簇、`chainCluster` 链簇、`questionCluster` 问号簇、
`chainIce` 冰叠链、`pipeChain` 管道口叠链、`narrowGapIce` / `narrowGapChain` 窄路口叠障碍。

变后期（候选已可解、未合格才用）：`bigBox` 超大盒、`rareColorKey` 稀有色占关键位、`swap` 换球、`inflate` 增容。

### 2.5 棋盘形态

`列 − 行 ∈ {1,2}`；尺寸按 `ov = 盒数 − (行列 − 黑块目标)` 选：
`ov ≥ 0` 能填满（多余进管道），`ov < 0` 会多出黑块。同档取 `ov` 更小者。

## 三、本轮实测补充（前辈文档里没有的）

### 3.1 目标图的开局暴露量，决定了免费车的下限

```
免费车数量 ≥ Σ_c ⌈E_c(0) / 平均容量⌉
```

实测这张 40×40 图：色 32 开局露 327px、色 1 露 152px，容量 50 → **至少 9 辆免费车**。
摆位、按层、三明治都改不了这个数——这是**图的属性**。

### 3.2 数字冰是"时间锁"，不是难度旋钮

`numice` 是**全局倒计时**（每取一个球减 1）。所以它的值应该等于"这辆车被锁到什么时候"，
而不是固定填 4 或 8。正确用法是按时差 `r − s` 推导。

### 3.3 铺盘的入口只认第 0 行

实机激活模型：**只有第 0 行初始激活**。铺盘的 BFS 若把四边都当入口（旧实现），
早熟色会被撒到左右边和底边——那些格子开局根本点不到。**修掉这一步覆盖率 44%→56%。**

### 3.4 方差极大，"选"比"造"可靠

同一套参数换一个归一化上限，覆盖率能从 69% 掉到 31%。
所以每关都应该跑**多档参数**（填充率 / 容量档 / 冰档）再由指标选优——这比精调单一参数有效。

### 3.5 哪些手段被证伪（别重复踩）

| 手段 | 结果 |
| --- | --- |
| 需求滞后 `fillLag` | 中位反而降（57→9%） |
| 闸门借车 `gateBorrow` | 扇出恒为 1，无效果 |
| 容量序列 `capSeqBoost` | 一好一坏，方差盖过信号 |
| 按块切车 `chunkCut` | 一好一坏 |
| 冰锁开局免费车 | 锁少无效、锁多死关 |
| 主动凑链 | 把 capTie 的对应关系打散，63%→32% |

## 四、给现在这套管线的制作流程（建议）

```
第 1 步  目标图体检
        · 开局暴露量 E_c(0) → 免费车下限
        · 若下限 > 6，先考虑换目标图（开局露出太集中，任何参数都压不出压力）

第 2 步  基础候选（不扰动）
        · 容量：按像素比例均分（25~64），上限别超 2×均值
        · 铺位：按层或按需求序，但**必须**复用同色限量 + 冰链避让
        · 障碍：冰按时差锁、链按色块配对

第 3 步  审核
        · 可解（六遍求解）
        · 卡点：30~80% 有窗口越 3.2；前期 0~30% 不出卡点
        · 覆盖率 band3Pct（本轮新增的"持续压力"指标）

第 4 步  不合格才补救（这是前辈的核心，我们现在缺这一环）
        · 补 1：把网关色的盒子搬到最远（≈ 三明治的定向版）
        · 补 2：同色容量集中到后期一个盒（≈ 增容）
        · 补完重解重审，合格即停

第 5 步  多档参数选优
        · 每关跑 6~8 次（填充率/容量档/冰档），按 band3Pct 选最好
```

## 五、一句话总结

> 前辈的路子是**"造一批 → 审 → 不合格的定向补 → 再选"**；
> 我们这几天一直在走"**构造理想曲线**"，反复失败的根本原因是
> **目标图本身的暴露结构决定了压力的上限**，不是构造手法不够巧。

**先把"不合格补救"这一环补上**（第 4 步），比继续调铺盘参数更有希望。
