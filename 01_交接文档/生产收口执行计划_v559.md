## 0. 一句话目标

把当前“评价框架已接通、局部样本可成功、但泛化未证明”的生成器，按证据逐阶段推进到：

**可解、守恒、容量不越界、棋盘优先行列 ≥7、车序和压力结构可控、释放可回放，并通过多图、独立 seed、真实 UI 和真人校准的关卡生产系统。**

不是把首通关卡压低，不是单纯增加搜索时间，也不是继续堆无法证明作用的指标或障碍。

## 1. 用户硬要求

1. 输入 TXT 像素图，批量生成客户端可直接使用的关卡 JSON。
2. 每色车辆容量之和必须等于该色像素数，包含管道 queue。
3. 用户输入的 `boxSizeMin/Max`、`capNormMin/Max` 不得被缩放、对半拆、按目标车数偷拆或静默改写。
4. 棋盘行、列均不得小于 6，最大 9×9。
5. 棋盘选择应优先 `min(rows, cols) >= 7`。
6. `6×6`、`6×7`、`7×6` 只作为经过数据验证后的兜底形态。
7. 7×8、8×7、7×9、9×7 是不同形态，必须覆盖并分别报告，不能只测一个方向后声称转置等价。
8. 目标体验不是“首通越低越好”：
   - 中段多数时间应承受暂存 3～4；
   - 应存在玩家能理解的显著释放；
   - 释放动作必须能接完整后缀并最终通关；
   - 不靠末段锁死唯一关键色、隐藏关键债务或纯背板制造难度。
9. 一个会话只走一条产线。纠偏、兜底、重产必须走 `runFlowOnce()`，不得另写 `produceFixed` 分支。
10. 所有关键改动必须有真实关卡前后数字、多个 seed、语法检查、版本、补丁、工作日志和可回退提交。


原则：

- 同一时间只推进一个里程碑。
- 一次只改变一个主要因素。
- 先基线、后实验、再决定是否进默认。
- 失败实验必须保留并回退，不把未找到写成无解。
- unknown 不写成 0，不写成死亡，不写成失败证明。
- 达标立即停，不为了用满预算继续搜索。

版本号可以因实际生产改动顺序调整；若只改只读实验工具，不单独提升生产 UI 版本。

## M5. v564 每色容量组合与局部车序

### 启动条件

只有 M3/M4 的单量或单对车实验仍不能形成稳定结果时，才启动本阶段。

### 目标

从“能修一个样本”升级为“每个基底有多个合法车辆角色方案”。

### 操作

1. 对每色建立合法容量候选：

   ```text
   sum(capacity) = pixels(color)
   ```

2. 每个方案标记角色：
   - 免费供给车；
   - 关键债务车；
   - 释放车；
   - 普通车；
   - 小容量关键车。
3. 小色不因面积小被排除。
4. 每色内部独立守恒；跨色联合只做方案选择，不转移像素。
5. 生成少量 Pareto 组合：
   - 压力覆盖；
   - 有效释放；
   - 选择宽度；
   - 车数/棋盘；
   - 首行观感；
   - 耗时。
6. 每个组合重新求解和完整评价，静态评分只用于剪枝。

### 通过条件

- 至少一个近失败基底完整转化。
- 已知成功不退化。
- 容量合同、可解和最终回放全部通过。
- 若仍无收益，保留为分析工具，不接默认生产。

## M6. v565 目标化障碍单因素实验

### 启动条件

- 基础关已能在容量、结构、压力和无障碍条件下接近目标。
- 不允许用障碍掩盖容量、车序或棋盘问题。

### 规则

每次障碍必须回答：

```text
在哪一步制造什么债务或选择？
预期何时释放？
移除这个单元后效果是否消失？
```

### 实验顺序

1. 数字冰。
2. 锁链。
3. 管道。
4. 黑块只用于必要的结构或形状，不用于随机补墙。

每种障碍：

- 同一基底无障碍 vs 一个最小功能单元；
- 容量和车序不变；
- 命中后做移除消融；
- 记录可解、压力曲线、释放、末段、路线分布、PlayerSim 死因和耗时。

### 通过条件

- 障碍单元有明确、可重复的作用。
- 移除后效果消失。
- 不靠末段锁死唯一关键色。
- 不引入容量越界、隐藏关键债务或体验回退。

否则回退，不进入默认。

## M8. 真人校准与最终冻结

### 目标

确认机器指标与实际体验方向一致。

### 方法

- A/B 隐去版本，随机顺序。
- 样本包含旧基底、生成器候选和明确反例。
- 记录：
  - 是否看懂暂存压力；
  - 在哪一步知道如何释放；
  - 是否靠背板；
  - 是否感到公平；
  - 是否愿意继续玩。
- 保存真人操作回放和 buffer 曲线，对照机器认定的释放点。

### 反馈映射

- “简单但首通低” → 查免费前期、背板、隐藏信息。
- “卡住但想不到释放” → 查选择可见性、解锁因果、供给时序。
- “首行丑/同色多” → 进入 P3 观感实验。
- 真人结论与代理冲突时，保留代理为待校准，不宣称公式胜过体验。

### 最终冻结条件

1. 硬合同全部通过。
2. 目标体验和独立回放通过。
3. 多图和独立 seed 达到事先确认的命中与耗时目标。
4. 真实 UI 批量、落库、停止、预算、版本一致。
5. 障碍可解释且消融有效。
6. 观感经用户确认。
7. 真人能识别并执行预期释放，未表现为纯背板或末段锁死。
