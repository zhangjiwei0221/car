# 参数与指标档案（2026-10-18）

> ⚠️ **本文写于 2026-10-18（v206 时代），数字已过期**：容量/棋盘/门槛/指标基线都以 [`工程说明.md`](工程说明.md) 为准。
> 仍有用的是"**每个参数是什么、在哪生效、删了怎么恢复**"这部分索引。
>

> 用途：右侧界面做过两轮精简（v185 删难度档/压力来源/生产档位/曲线实验，v186 删 C 档 15 组）。
> 参数**代码里都还在**（`getGenConfig` 读不到控件就走默认值），所以删掉的只是"界面入口"。
> 这份档案把"每个参数是什么、默认多少、在哪生效、删了怎么恢复"集中记下来；
> 以及"每个产出指标怎么算、现在基线是多少"——用来做深入分析，不用每次翻代码。
>
> 用户原话：「这一堆参数以后也许有用，但现在太碎；我需要知道所有的量化。」

## 一、生成参数（现在界面上）

### 1. 入口与盒

| 参数 | config key | 默认 | 作用 | 生效位置 |
| --- | --- | --- | --- | --- |
| 入口模式 | `bottomOnly` / `instantChain` | false / false | 四边入口 / 仅底部 / 瞬时连锁 | 求解、切盒、审核全链路 |
| 盒容量下限/上限 | `boxSizeMin` / `boxSizeMax` | **35 / 80** | 每辆车的像素容量区间 | `pickBoxSplit` → `baseFillBoxes` |
| 盒容量模式 | `boxSizeMode` | `random` | random / polar（两极化采样） | `makeCapPicker` |
| 切盒方式 | `boxCutMode` | `trend` | trend 趋势切 / anchor 锚点切 | `pickBoxSplitRaw` |
| 暂存格数 | `bufferLimit` | **5** | 实机固定 5，改它等于改规则 | 全程 |

### 2. 棋盘

| 参数 | config key | 默认 | 作用 |
| --- | --- | --- | --- |
| 棋盘模式 | UI `gen-board-mode` | 自适应 | 自适应=由车数反推；手动=按下面范围 |
| 行范围 | `boardRowsMin/Max` | 8 / 9 | 仅手动模式或作为偏好 |
| 列范围 | `boardColsMin/Max` | 11 / 16 | 同上 |

> 自适应模式下，范围只是"偏好"；装不下会自动换反推范围（v145）。**这就是小图套大方案会撞 `usableSpaceDeviation` / `structSurplus` 的根源。**

### 3. 障碍（比例 / 数量）

| 参数 | config key | 默认 | 作用 | 生效位置 |
| --- | --- | --- | --- | --- |
| 数字冰比例 | `icePercent`（+Min/Max） | **15%** | 冰数 = 空位格 × 比例 | `planObstacleSlotsFixed` ① |
| 黑块比例 | `blackPercent`（+Min/Max） | **10%** | 仅作"目标带"；真正墙数由 `solveSpaceQuota` 配额定 | 同上 ② |
| 锁链组数 | `chainCount`（+Min/Max） | **3 组** | 每组 2/3 连，必须正交相邻 | 同上 ③ |
| 问号比例 | `questionPercent`（+Min/Max） | **10%** | 强制偶数、不在第 0 行 | 同上 ② |
| 数字冰延后% | `numIceDelayPct` | **10** | 冰的数值 = 盒序位 + 总盒数×该比例 | `numIceValueFor` |
| 窄路开关 | `narrowPath` | true | 墙带 + 缺口 + 缺口冰/链 | 结构层 |
| 碎色闸门 | `fragmentMaxRate` | 0（关） | 碎色率超限整张跳过 | 前置闸门 |

### 4. 管道与可用空间

| 参数 | config key | 默认 | 作用 |
| --- | --- | --- | --- |
| 管道下限 | `minPipes` | **0** | 0 = 只在真有溢出盒时出现 |
| 管道深度 | `pipeMaxDepth` | **6** | 单管最多装几个盒 |
| 单管最少装 | `pipeMinFill` | **4** | 决定溢出最多摊给几条管道 |
| 兜底管道 条数/深度 | `pipeFallbackCount/Depth` | 2 / 3 | 落位不够时的第二级兜底 |
| 绝对下限 条数/深度 | `pipeFloorCount/Depth` | 2 / 2 | 低于此值→整体撤掉管道 |
| 可用空间目标 | `usableSpaceTarget` | **0（关）** | 开启后 B+P 联立求解（见 `solveSpaceQuota`） |
| 可用空间容差 | `usableSpaceTolPp` | 5 个百分点 | 偏离目标多少就淘汰候选 |

### 5. 卡点类型与批量

| 参数 | config key | 默认 | 作用 |
| --- | --- | --- | --- |
| 类型权重 | `chokeTypes`（12 个） | **全 0** | 勾中=权重 1，加权无放回抽 |
| 检查次数 | `chokeTypeRollsNormal` | **0** | 0 = 不启用类型化 |
| 命中概率 | `chokeTypeProb` | **0.5** | 每次检查的命中率 |
| 落位进度带 | `chokePosMin/Max` | **0.15 / 0.80** | 卡点类手段只在进度带内落位 |
| 候选数 | `candidateCount` | **6** | 每张图初生成几个候选 |
| 难度轮数 | `difficultyRounds` | **7** | 最终关卡的玩家路线多轮标定 |
| 单关预算 | `timeBudgetMs` | **300000**（5 分钟） | 到点兜底 |
| 简单关比例 | `easyRatioPercent` | **30** | 仅影响早停的 `requireHardPass` |
| 并发 | UI `gen-pool-size` | 6 | worker 数 |

## 三、产出指标（量化口径）

### 3.1 好关v3（v184 起每关自带）

| 判据 | 定义 | 阈值 | 在哪看 |
| --- | --- | --- | --- |
| 可解 | 全知求解走通 | 必须 | `goodV3.fails` |
| 稳健通关率 | 18 局（稳健/冒险/乱点各 6）里稳健的通关比例 | ≥50% | 日志「好关v3」、`generationEval.goodV3` |
| 被埋 | 稳健一局终局：某车量够但可达 0 的辆数 | =0 | 同上 |
| 前期峰窗 | 0~30% 进度内暂存峰值 | ≤2.0 | `audit.earlyMax` |
| 中后期峰窗 | 30~100% 内峰窗的 **18 局中位**（`lateMax.p50`） | 3.2~4.8 | `goodV3.midLateMax`（同时记审核值 `midLateAudit`） |
| 策略差 | 最好打法 − 最差打法的通关率 | ≤34 点 | `chokeV2PlayBatch.spreadPct` |

总分 100 = 压力 30 + 公平 30 + 选择 15 + 结构 15 + 节奏 10（只用于排序）。

### 3.2 审核（旧门，仍在用）

`audit.tier`（困难合格 / 简单合格 / 不合格）、`audit.pass`、`hasChoke`、`earlyOK`、`midOK`、`reasons[]`；
峰窗字段 `earlyMax / midLateMax / lateMax`，卡点线 `high = 3.2`。

### 3.3 卡点判据 v2（只读报告，未做硬门）

`bridges` 独木桥（≤1）· `r9` 预算判断点（≥12 达标）· `noGood` 无满解步数（≤3）·
`minPick` 最少可选项 · `hiBefore70Pct` 70% 前高压占比（≤10%）。

### 3.4 难度分 v5

`f1 玩家平均暂存/3.5 ×0.65 + f2 滞留占比/0.06 ×0.25 + f3 障碍/200 ×0.10 + 复活×8`；
分档：简单 0–30 / 普通 31–60 / 困难 61–80 / 极难 81–100；多轮标定取 `pickThreshold` 轴。

### 3.5 结构（拆图）

`veinLayers`：同色连通块数、最深依赖层、每层颜色数、每色最浅层；
`深层色` = 最浅层 ≥3 的颜色数；`解锁延迟` = 实际轮到 − 理论最短。
