## 0. 30 秒接管

### 我们要做什么

**根据像素图批量生成可解、守恒、观感合理、有真实选择和“积累—高压—释放”节奏的关卡。**

不是单纯压低首通率，也不是把求解器搜得很慢、首通 0%、末段锁死当成优质。

### 当前真正进度

- 评价入口、只读多路线/反事实、压力曲线、容量审计、债务生命周期、双时间线已经有工具。
- **这些主要是测量能力，不等于生成质量已经提高。**
- v494 全局车序排程实验失败：4/4 变体可解，0/4 优于 base，默认未采用。
- 默认生产为 `new_fixed`。v494 对默认生产的实际变化是补齐棋盘缩盘低于 6 的漏洞；timelineCompare 仅是旧产线关闭实验。
- 下一步不是继续堆模块，而是：**默认主产线多图基准 → 只读归因 → 针对最高频失败项做单变量实验。**

### 当前禁止事项

1. 不得把 v494 全局时间线排程设为默认或宣称成功。
2. 不得把“找到一条解”“首通低”“峰值高”“全部债务偿还”直接写成好关。
3. 不得把有界搜索未找到写成无解，不得把未知写成 0 或死亡。
4. 不得改写字段 `boxSizeMin/Max`、`capNormMin/Max` 来偷偷适配目标车数。
5. 不得让棋盘行列小于 6，不得破坏每色容量守恒。
6. 不得同时在多个因素上做 A/B，不得仅凭一个 seed 下结论。
7. 不得绕开 `runFlowOnce()` 另写纠偏/兜底产线，不得随意修改桌面客户端 bin。
8. 未经过真人校准，不得新增“好关压力阈值”。

## 1. 需求、边界与完成定义

### 1.1 [用户要求] 硬合同

- 真机与模拟器规则已经确认一致，不再把规则对齐列为阻塞。
- 每色车辆容量之和必须等于该色像素数，包含管道 queue。
- 棋盘行、列均不小于 6。
- 用户容量上下界不可被生成逻辑缩放、对半拆或按目标车数偷拆。
- 容量很重要；容量 ≤2 的车最多欠 2，不能作为持续债车。
- 首行大量同色不是绝对禁止，但影响观感，必须测量并可调。
- 障碍必须有明确作用，不能随机堆砌；不希望靠末段锁链挡住关键颜色形成难度。
- 好关的暂存压力应有起伏，并能持续形成高压，而非前期全免费或后期一次强堵。
- 一切关键改动可回退，有真实关卡前后数字、日志、补丁和 Git 提交。

### 1.2 [Kimi建议] 优质的四层验收

1. **硬门**：守恒、可解、独立回放、参数与棋盘合同。
2. **结构门**：排除长免费段、明显单线、畸形盘面等；现有 qGate 只是历史代理，不是最终真理。
3. **质量向量**：压力节奏、有效选择、恢复、路线丰富度、公平、观感分别报告。
4. **真人体验**：好玩、疲劳、惊喜、可学习、商业难度等由真人校准。

不把四层压成一个孤立“好玩总分”。候选选择应保留多目标与多样性。

### 1.3 非目标

- 不追求数学上证明所有关卡的全部最优解。
- 不追求所有路线压力完全一致。
- 不用求解器替代真人审美。
- 不在基础车序尚未合理时随机叠冰、链、管道。
- 不把“搜索很久”“唯一解”“首通 0%”本身当目标。

## 3. 数学模型与指标字典

### 3.1 状态转移

一关不是静态布局，而是确定性规则下的状态树：

\[
s=(E,U,A,B,O),\qquad s_{t+1}=T(s_t,a_t)
\]

- `E`：已消除像素；`U`：未取车辆；`A`：激活位置；`B`：暂存车辆与进度；`O`：障碍状态。
- 一个像素或一辆车序变化可能改变整棵后续状态树，所以必须动态模拟，不可只看静态盘面。
- 玩家模型与全知求解器的信息集不同；隐藏信息要单独处理。

### 3.2 可解与搜索语义

可解是存在动作序列到达胜利状态。找到并回放的路线是证书。

统一状态：

- `solved`：找到并回放成功；
- `dead`：可明确确认死亡；
- `not_found_within_budget`：预算内未找到；
- `budget_exhausted`：预算耗尽；
- `unknown/null`：证据不足。

### 3.3 容量合同与债务

颜色 `c` 的总像素为 `N_c`，用户容量区间 `[L,U]`，拆为 `n_c` 辆时：

\[
n_cL\le N_c\le n_cU,\qquad
\lceil N_c/U\rceil\le n_c\le\lfloor N_c/L\rfloor
\]

且每色容量和必须等于 `N_c`。不可精确兼容时保留余量证据，不伪造全在区间。

车辆容量 `k_j`、已消除 `x_j`、剩余 `d_j=k_j-x_j`。进场时 `d_j>0` 才形成债务。容量只决定债务上限，不直接决定难度。

### 3.4 需求、激活、取车、偿还

颜色累计显露供给：

\[
A_c(E)=Consumed_c(E)+Reachable_c(E)
\]

参考就绪时刻：

\[
\rho_j=\min\{t:A_{c_j}(t)\ge k_j\}
\]

同色车辆会竞争像素，所以 `ρ` 只是规划参考，最终以实际事件为准。

每辆车分别记录：

- `α_j = activateStep`：何时可用；
- `τ_j = pick/enterStep`：何时取车/形成债务；
- `δ_j = doneStep`：何时补完离场；
- `w_j = δ_j - τ_j`：等待窗口。

必须 `α_j≤τ_j`，但早激活不罚；债务看实际取车，不看激活。

### 3.5 压力曲线

- `b_t = |B_t|`：暂存车辆数，直接受槽位限制。
- `q_t = Σ d_j,t`：债务像素，与槽位压力不同。
- `g_t = |E_t|/|P|`：消除进度，用于跨关比较前中后期。

至少报告：峰值、高压占比、最长连续高压、释放幅度、完整压力周期、末段高压、路线间范围。

高压线 `h` 在真人校准前只是报告分桶，不得自动变成好关门。全部偿还、峰值高、周期长都不是独立质量结论。

### 3.6 有效选择与恢复

状态 `s` 的可点集合为 `M(s)`。对每个动作从同一父状态做反事实 `CF(s,a)`，分类为可通关、可恢复、明确死亡、未知。

- 可点不等于有效选择。
- 多个可通关动作若后续状态与策略等价，不应重复算丰富度。
- 唯一“已验证安全”不等于证明唯一活路，未知必须单列。
- 恢复要记录额外代价与恢复窗口，不只记是否最终通关。

### 3.7 路线、信息与观感

- 路线多样性按动作签名和关键状态分岔报告，同时记录搜索预算与覆盖。
- 公平性要比较玩家当时可见信息，不用全知结果指责玩家。
- 首行可记录颜色数、最大同色、最长相邻和颜色熵 `H=-Σp_c log p_c`；这是观感证据，阈值由用户校准。

### 3.8 指标使用分级

| 级别 | 用途 | 例子 |
|---|---|---|
| 硬门 | 不满足即拒绝 | 守恒、可回放解、行列≥6、用户容量边界 |
| 结构代理 | 当前筛选，可持续校准 | freeLow、freeRun、full/select 等 |
| 研究证据 | 报告和诊断，暂不硬门 | 压力周期、反事实、路线覆盖、债务集中 |
| 真人标签 | 校准目标 | 好玩、疲惫、公平、背板、观感 |

## 4. 所有实验的统一规范

### 4.1 实验前必须写清

1. **假设**：认为哪个因素会影响哪个真实结果。
2. **基线**：commit、版本、产线、源图、seed、完整配置、时间预算。
3. **唯一变量**：本轮只允许哪一个因素变化。
4. **样本**：3 seed 只作 smoke；开发至少 5 seed；最终用独立 seed/未见图复核。
5. **目标指标**：只选一个主要修复目标。
6. **保护指标**：可解、守恒、棋盘、容量以及不能明显退化的质量项。
7. **通过/拒绝条件**：在跑实验前写，不看完结果再改口。
8. **产物**：逐样本 JSONL、汇总、异常、耗时、结论和原始关卡 hash。

### 4.2 对照原则

- 同图、同 seed、同产线、同预算；只改实验因素。
- 同时改棋盘、容量和车序时，不能把结果归因于其中一个。
- 报告每个 seed，不只报平均；保留“有效→无效”等逐个退化。
- 时间预算不同不能直接把找解率当算法能力变化。
- 小样本只说“本批观察到”，不说普遍规律。
- 变体必须重新求解和独立回放；旧评价在 level 改动后作废。
- 失败变体保留数据，但不进入默认；compare 不允许强制替换更优 base。

### 4.3 实验记录模板

## P2．参数合同

**状态**：容量和棋盘部分完成；其他参数需逐项检查。

**操作**

- 记录 UI 请求 → resolved → sampled → final 实测。
- 检查重试、portfolio、后处理、裁盘、兜底是否覆盖参数。
- 对未生效参数报 `not_consumed/overridden/infeasible`，禁止继续质量 A/B。

**实验 E2：单参数合同**

- 假设：合法范围内改变参数应产生可观察且符合语义的变化。
- 样本：至少 3 seed 做链路 smoke。
- 操作：A=原值，B=只改一个参数；打印中间调用和最终盘面。
- 通过：参数被目标路径消费，且最终实测方向符合定义。
- 若 A/B 完全相同：判“未生效/被覆盖”，不是“该因素无难度作用”。

**保护**：容量边界、守恒、行列≥6、产线唯一。

## P3．求解与质量证据接入报告

**状态**：只读工具已有；生产接入未完成。

**操作**

**实验 E3：预算与召回**

- 假设：预算提升应提高路线召回，但成本需要可控。

**状态**：有 demandCurve、容量审计；联合规划未完成。

- 计算每色总量、首次露出、增量块、关键解锁关系。
- 在容量边界内枚举可行车辆数/容量组合。
- 检查车辆数与棋盘、管道容量是否相容。
- 区分免费供给、潜在债车和 micro 余量，不凭层号封 unlock/reserve。

**实验 E4：容量单变量**

- 假设：在同图同切法下，不同合法容量方案会改变债务窗口和免费段。
- 操作：固定 seed、棋盘目标、切法和障碍，仅选择不同**用户明确输入**的容量方案；生成逻辑不得越界。
- 样本：至少 5 seed；每方案记录可行性和实际车数。
- 目标：预先指定，例如减少过长免费段。
- 保护：可解、守恒、micro、债务集中、末段压力、耗时。
- 结论：报告 trade-off，不只选首通最低。

## P5．棋盘与车序联合优化

**实验 E5：局部单交换**

## P6．障碍目标化：数量、位置与参数联合决定

**状态**：设计已完成，生成实验未开始；必须在容量/车序基础稳定后做。本节是 **[Kimi建议]**，不是已验证配方。

### P6.1 核心原则：先有目标决策，再有障碍

禁止以“随机冰百分比 + 随机链组数 + 随机管道数，谁最难留谁”为主要生成方式。正确顺序：

```text
生成无功能障碍基础关
→ 找出主要结构问题
→ 定义希望出现的决策
→ 提出“类型 + 位置 + 参数 + 目标”候选
→ 重解、质量评估与消融
→ 只保留有明确边际作用者
```

问题与候选方向的初始对应：

| 基础关问题 | 目标决策 | 候选障碍 |
|---|---|---|
| 关键供给过早免费出现 | 是否先走其他路线、等待解锁 | 数字冰 |
| 逐辆免费消除，缺乏暂存规划 | 是否先清暂存再同时取车 | 锁链 |
| 同色供给过早集中 | 是否先消耗现有供给、等待后续批次 | 管道 |
| 棋盘取车顺序明显线性 | 先开哪条通路 | 黑块拓扑 |
| 信息判断没有成本 | 根据有限信息推断 | 问号，慎用 |

没有需要解决的问题时，允许障碍为 0；不要求每关都有冰链管道。

### P6.2 数量：必要结构 + 最小有效功能单元

障碍数量不先由质量百分比决定，而由下式决定：

```text
总障碍 = 必要结构障碍 + 经实验接受的功能障碍单元
```

- 一处需要延迟的供给：候选为 1 个数字冰；
- 一次同时进场规划：候选为 1 组锁链，而不是泛化的“链车百分比”；
- 一批需要延迟的供给：候选为 1 条功能管道；
- 必要结构黑块/管道与额外功能障碍必须分开统计。

用户数量/百分比配置可以是硬约束、搜索预算或视觉限制，但不能被解释为“越多越难”。采用**最小有效数量**：每加一组必须证明有边际作用，去掉后目标决策应减弱或消失。

停止添加的条件：目标已经形成；新障碍无明显边际收益；开始伤害可解性、释放、路线或观感；只能靠末段关键色强堵继续加压；达到用户预算；候选全部失败。

### P6.3 位置：棋盘激活图 × 目标需求图

位置由两张图联合推荐：

1. **棋盘激活图**：谁挡谁、取掉谁打开谁、唯一通路在哪里、哪些位置同窗口激活；
2. **目标需求图**：每色何时首次露出、何时新增可达、关键解锁色与后续供给窗口。

候选位置主要对应“激活与需求时机不匹配”“同时进场可形成规划”“通路可产生顺序选择”的位置。静态评分只用于排序候选，最终去留必须实际放置并重解。

统一排除或重点审查：末段唯一关键色、唯一狭长通道、组内长期无法激活、无法预知的断供、无替代路线、首行/整体明显视觉噪声。

### P6.4 数字冰：控制何时可用

**适合**：过早免费的关键供给、过早打开大片后续车辆的位置、过早开放导致顺序选择消失的通道、需要推迟到目标解锁窗口的供给。

**不适合**：末段唯一关键色、本来就长期等待的债车、多冰叠加后只剩固定顺序、纯延长时间的普通车。

**参数决定**：先测自然激活/可取时刻与目标需求窗口，再提出冰数值候选，以模拟得到的真实破碎/可取时刻验收。不能假设冰数字 N 必然等于 N 个有效决策延迟；锁链、路线和其他取车都会影响过程。

**E6a 实验**：A 为同一基础关，B 只加/改一个冰；容量、车序、其他障碍不动。目标为指定供给进入目标窗口并产生选择；拒绝纯等待、压力后移末段或实际作用与假设无关。

### P6.5 锁链：制造同时进场的暂存规划

**适合**：组内车辆能在相近窗口激活；玩家取链前有机会清暂存；周围有其他合法动作；组内车辆后续都有供给与偿还机会；能形成“先开路还是先清暂存”的选择。

**不适合**：末段唯一关键色、多链连续封同一通道、组内长期锁死、信息不足、同时进场必然溢出。

组大小 `g`、暂存上限 `L` 的静态必要条件为 `g≤L`，但还必须模拟动态条件：玩家在目标窗口能否通过合理操作腾出空间。静态合法不等于实际公平。

数量按希望形成的“同时进场决策窗口”反推，不能按链车百分比直接加难度。

**E6b 实验**：只加一组链，观察组内激活、进场时空槽、债务和恢复窗口；拒绝必然溢出、唯一活路、末段关键色强堵。消融后同时进场决策应明显减弱。

### P6.6 管道：必要守恒与功能延迟分开

**必要结构管道**：棋盘不能容纳全部车辆时用于守恒。设车辆总数 `N`，使用 `P` 条管道后的实际棋盘车上限为 `S(P)`：

\[
O(P)=\max(0,N-S(P))
\]

若每管容量范围 `[q_min,q_max]`，可行性检查：

\[
Pq_{\min}\le O(P)\le Pq_{\max}
\]

增加管道会占格并改变 `S(P)`，因此必须逐个搜索 `P` 并重算，不能只做一次除法。优先满足守恒、空间和观感的最少必要管道。

**额外功能管道**：只在需要延迟批次供给时增加。queue 应服务未来需求窗口，出口开放与供给匹配，不封唯一通路，不藏大量无处可放车辆，不制造不可预知末段断供。

**E6c 实验**：必要管道与功能管道分开对照。功能管道只改一条及 queue，观察释放时间、供给节奏与信息公平；拒绝只藏溢出、盲猜或末段断供。

### P6.7 黑块与问号

**黑块**只负责拓扑：把线性棋盘改成有先后选择的区域、形成开路结构、控制轮廓。若只是补空，应标为结构填充，不冒充决策障碍。拒绝唯一窄路和纯数量加压。

**问号**只研究可推理的有限信息。拒绝玩家可见信息相同却结果不同、无预警死亡。公平性证据不足前不进入默认生产。

**E6d/E6e**：黑块做通路消融，问号做信息等价状态与首次死亡检查；均不能只凭首通或峰值采用。

### P6.8 数量与位置的实际搜索算法

```text
base = 生成无功能障碍基础关()
evidence = 求解并分析(base)
problem = 找到一个主要结构问题(evidence)
candidates = 提出少量“类型+位置+参数+目标”候选

for obstacle in candidates:
    variant = 只放置(base, obstacle)
    if 不守恒 / 棋盘或容量合同失败 / 不可解: reject
    after = 重新求解并分析(variant)
    if 目标决策未出现: reject
    if 唯一活路 / 末段强堵 / 压力不释放 / 观感明显退化: reject
    if 去掉障碍后效果仍相同: reject  # 没有边际作用
    compare 后 accept 或 reject

每接受一组，基于新关卡重算时间线，再生成后续候选。
最后做逐组消融、多路线与独立回放复核。
```

不能一开始静态排完所有障碍；接受一组后激活与需求关系已经变化。组合搜索可以后续研究，但第一轮必须逐组可解释、可回退。

### P6.9 统一实验与验收

- A=同一基础关无该功能障碍，B=只加一组；其他条件不动。
- 先一个机制样本证明能测到作用，再对至少 5 个同类失败样本验证。
- 主要观察：目标决策、激活/供给窗口、压力积累与释放、债务集中、有效分支、恢复、末段和信息公平。
- **通过**：硬门不退化；预定目标改善；消融后效果减弱；多路线下不是仅对一条参考解有效；副作用可接受。
- **拒绝**：只降低首通、只让搜索更慢、只抬峰值；障碍可有可无；产生背板、唯一活路、废车或末段强堵。
- **产物**：障碍坐标/类型/参数/目标、前后时间线与路线、消融报告、质量 diff、compare 决策。

实施顺序按问题而不是固定全加：过早免费供给先研究冰；缺暂存规划先研究双车链；供给批次集中再研究功能管道；棋盘线性先改拓扑。至少一个可重复正结果前，不扩写随机组合配方。
