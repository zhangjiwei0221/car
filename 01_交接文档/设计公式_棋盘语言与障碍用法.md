# 设计公式：怎么讲清棋盘语言、怎么用好障碍

> 目标：把“摆障碍”从手感变成**可复述、可检查、可复用**的规则。
> 素材：006 v62（8链+4冰+2管+1问号+2黑）、00199 v9、216 v2 的实测经验。

---

## 一、棋盘语言：每个元素 = 一个“动词”

| 元素 | 语义 | 玩家读到的意思 | 对路径的影响 |
|---|---|---|---|
| **颜色** | KEY | “这辆车要这个色” | 决定**你能拿哪些车** |
| **容量** | DEBT | “这辆要 30 个，你手上只有 18” | 决定**拿了会不会欠** |
| **链（2–3 辆）** | AND | “这三辆要么一起满足，要么一起欠” | **放大承诺**（一次欠 2–3 倍） |
| **冰（param=N）** | WAIT | “第 N 个球之后才解冻” | **暂时删除**一批车 |
| **墙 / 黑块** | NOT | “这条路没了” | **永久删除**位置 |
| **管道** | AFTER | “先出 A，才轮到 B” | **串行化**两种色 |
| **问号** | UNKNOWN | “这条信息你不确定” | 只影响**玩家判断**，不影响全知解 |

**一句话概括**：
> 颜色与容量决定**可行集**；链放大**代价**；冰改写**时间**；墙改写**空间**；管道改写**顺序**；问号改写**信息**。

---

## 二、路径影响：可行集（Frontier）是唯一该盯的量

定义：**第 t 步的可行集 F(t) = 当前能点、且能装满的车**。

- `|F(t)| ≥ 3` → 宽松，玩家随便走（**没有卡点**）
- `|F(t)| = 2` → 有取舍
- `|F(t)| = 1` → **卡点**（被迫）
- `|F(t)| = 0` → 死锁

**所以“造压力”= 让 |F| 周期性塌缩到 1，再放开。**

| 障碍 | 对 F 的作用 |
|---|---|
| 冰 | 把若干车暂时移出 F（冰未解冻 → 不可点） |
| 墙 | 永久把位置移出棋盘 |
| 管道 | 把两色变串行 → F 里只剩前者 |
| 链 | 不改变 F，但把“点了能不能收”变成“2–3 辆一起收不收得掉” |
| 容量 | 直接决定某车在不在 F 里 |

**关键结论**：**链不给卡点，链给“代价”**；卡点是**冰、墙、管道**做出的（让 F 变小）。
006 的 at4=28，靠的就是“冰把关键色锁住 + 链把代价放大”的组合。

## 三、改道三件套：冰 / 墙 / 管道 怎么配合

你说的“冰块暂时让玩家偏离某条路”完全正确，而且它是**唯一可逆**的手段：

| 手段 | 时长 | 可逆 | 用途 |
|---|---|---|---|
| **冰** | 有限（N 球） | ✅ 解冻后恢复 | **临时改道**：逼玩家先去别处，再回来 |
| **墙** | 永久 | ❌ | **收窄**：删掉一条捷径，让“绕路”成为唯一解 |
| **管道** | 永久 | ❌ | **定序**：A 必须先于 B，造出“等待” |

**改道句模板（T3）**：

```
1) 冰封 A 色（param = t+6）      → F 里去掉 A 的车
2) 玩家被迫走 B（B 能装满）      → 走 3–5 步
3) A 解冻                        → F 重新包含 A，形成“呼吸”
```

**三个必须检查的点**：
- 冰封期间**必须还有 ≥1 条可走**（否则死锁）；
- 解冻时刻要**落在玩家快没路时**（早了没效果，晚了死锁）；
- 被封的 A 必须是**当前唯一能解的那条路**（否则玩家绕开就没感觉）。

**墙的用法**：只在“想永久删掉一条捷径”时用；006 里 2 个黑块就是干这个。
超过 2 个墙很容易把盘切碎 → 实测 7 个位置全部不可解。

**管道的用法**：把“两色并行”变“两色串行”。
006 的 2 条管道只当“释放门”，还没做出真正的串行——这是**未完成的部分**。

## 四、句型表（可直接照抄的五种句子）

| 句型 | 组成 | 作用 | 例子 |
|---|---|---|---|
| **T1 教学** | 2–3 色、无冰无墙 | 让玩家学会“点车=吃色” | 006 前 4 步 |
| **T2 债务** | 链 2–3 辆 + 目标色稀缺 | 制造“欠 2–3 倍” | 006 的 `5/40 + 5/40` |
| **T3 改道** | 冰 + 另一条可走的路 | 逼玩家绕路再回来 | 待做 |
| **T4 收口** | 墙 1–2 个 / 管道 | 删掉捷径、定序 | 006 的 2 黑块 |
| **T5 呼吸** | 主动留 2–3 步宽松 | 让玩家有“喘息” | 00199 的 11–27 段 |

**节奏公式（每关）**：
```
T1(4-6步) → T2(3-5步) → T5(2-3步) → T3(4-6步) → T2 → T4 → 收尾(2-3步)
每 5–7 步应出现一次 |F| 塌缩
```

## 五、可检查的数值规则（把“手感”变成判据）

| 指标 | 目标 | 现有工具 |
|---|---|---|
| 可行集塌缩次数 | 每 5–7 步 1 次 | `Validate006Level --audit` 的 windows |
| at4（满载边缘步数） | 20–30 / 50 步 | `MeasurePageOmni` |
| run4（最长连续） | 12–25 | 同上 |
| 前期卡点 | 允许（用户规则） | `--allow-early` |
| 冰数量 | ≈ 步数/12（50 步 → 3–5 块） | 手扫 / 待自动 |
| 墙数量 | ≤2 | 同上 |
| 链组 | ≥3 组（每组 2–3 辆） | `ChainPicker` |
| 管道 | 1–2 条（释放门或串行） | 手摆 |

**自检口诀**：
1. 每块冰都要回答“它封的是哪条唯一路？”——答不上就是惰性冰（006 里清掉过 3 块 `param=1` 的废冰）；
2. 每条链都要回答“它把哪两辆捆一起、代价翻几倍？”；
3. 每个墙都要回答“它删掉的是哪条捷径？”——删不出捷径就是白占位置。

### 三种障碍的“擅长”与预算

| 障碍 | 擅长 | 代价 | 实测 |
|---|---|---|---|
| 冰 | 后段（late4） | at4 可能小降 | 00099 late4 1→7 |
| 墙 | 前中段（at4） | 后段可能降 | 00041 at4 +5、00099 +14 |
| 管道 | 两色串行（隐藏+推迟） | 车数减少、峰值敏感 | 00041 at4 +6、00099 +19 |

**关键发现**：三者**共享同一个“难度预算”**（峰值余量）。
00041 上先加墙+冰（at4=31）之后再找管道 → 0 个候选（135 个候选一放就峰值 >4）。
→ 每关按预算选 1–2 种，不要全上。

每步输出：可点车数 / **能装满的车数（=F）** / 冰锁数 / 吃不满数。

### 四张成品关的实测

| 关卡 | 平均 F | F=0 步 | F=1 步 | 步数 | at4 | 形态 |
|---|---:|---:|---:|---:|---:|---|
| 00111 | 3.78 | 6 | 9 | 51 | 36 | 前 13 步几乎全 F≤2 |
| 00171 | 4.85 | 6 | 9 | 53 | 30 | 中段偶有放开 |
| 00071 | 3.10 | 7 | 5 | 52 | 28 | 均匀紧 |
| **0216 引导版** | **1.81** | 9 | **19** | 48 | 25 | 全程最紧，且是引导关 |

### 得到的判据

- **平均 F ≈ 2–3** 是好关的区间；
- **F=1 的步数占 35–45%** → 玩家一直在“唯一选择”上；
- **F=0 的步数 6–9** → 允许，但连续 2 步 F=0 就会变成死锁风险；
- 0216 平均 F=1.81，是四张里最“被迫”的，也正好是唯一严格过审的——两者一致。

### 这解释了之前所有失败

- 20 张批量里 at4 上不去的图，F(t) 基本常年 ≥5（玩家随便走）；
- 能出压力的图（00111/00171/00071），F(t) 有明显的塌缩段。

**所以“这张图能不能出压力”，可以提前用 F(t) 判断，而不必先跑构建。**
