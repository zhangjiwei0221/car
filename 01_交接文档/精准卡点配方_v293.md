# 精准制造卡点的配方（v293 现状 + 还缺什么）

> 这是本会话全部实测收敛出来的答案。**能算的部分写公式，不能算的部分写明是设计判断。**

---

## 一、卡点到底是什么（机制层）

暂存上限 `L = 5`。玩家每步取一辆车：

- 能装满 → 立刻消除，**不占槽位**
- 装不满 → 进暂存，**占一个槽位**

**卡点 = 同一时刻被迫持有 3 辆以上的未满车**（`L − 1.8 = 3.2` 是审核阈值）。

它成立需要两个条件**同时**满足：

```
① 前沿可点的车里，"此刻能装满的" ≤ 1~2 辆     ← 否则玩家总有得吃，不用背债
② 被背着的车在 2~4 步内会变得能装满            ← 否则是死格，玩家只能放弃，不是卡点
```

条件①②就是"精细"的全部含义。**大多数失败都是因为①不成立**（可吃的车太多）。

## 二、三个可计算的量（决定一切）

### 2.1 开局暴露量 `E_c(0)`

目标图一开局就露在外面的像素数。实测这张 40×40 图：色 32 是 **327**，色 1 是 **152**。

### 2.2 免费车下限

```
免费车 ≥ Σ_c ⌈ E_c(0) / 该色单车容量 ⌉
```

一辆车只要 `n ≤ E_c(0)`，它**从第 0 步就能装满**，放在哪都一样。

**这个数是目标的固有属性，摆位改不了，冰才能改。**

### 2.3 时差 `g = r − s`

- `r` = 该车能装满所需的目标进度（由颜色 + 容量决定）
- `s` = 该车所在格被点到的进度（由棋盘结构决定）
- `g ∈ [2,4]` 步 = 健康债务；`g < 0` = 免费车；`g > 5` = 死格

## 三、怎么切容量（有实测数据）

### 3.1 公式

```
平均容量 = 彩色像素总数 / 目标车数
目标车数 = 棋盘格数 × 0.86
每色容量 ≥ E_c(0) / capPerColor        （capPerColor = 2）
每色容量 ≤ min(84, 该色总像素)
全局下限 = 0.6 × 平均容量               （避免碎车）
```

### 3.2 实测边界

| 参数 | 可用范围 | 越界的后果 |
| --- | --- | --- |
| `capCeil` 上限 | **78~84** | 72 → 12/12 全灭（车多到装不下） |
| `capPerColor` | **2** | 1 → 开局断粮；3+ → 免费车太多 |
| 归一化下限 | 0.6×均值 | 更低会出 10px 的碎车 |

**40×40 图：中位覆盖 38%（bigcap），这是当前最好的配方。**

### 3.3 棋盘尺寸要跟图走（v293）

```
彩色像素 < 1300 → 5×6 / 5×7
否则            → 6×7 / 7×7 / 6×8
```

小图配大盘 = 每辆车太小 = 免费车太多 = 没压力。
实测：35×35 从 5×6 换到 6×7，覆盖率 13% → 5%。

## 四、怎么摆车（三条硬规则）

1. **入口只认第 0 行**（`simulator.js` 的激活模型）。BFS 若把四边都当入口，
   早熟色会被撒到左右/底边——那些格子开局根本点不到，等于白摆。
2. **第 0 行同色 ≤ 2 辆**，超了与深层"第 0 行没出现过的颜色"整组对调。
   否则第 0 行清一色，玩家一路点下去毫无阻力。
3. **按需求序铺**（`demand` 升序），但在免费车被压下去之前，**任何"把外层车埋深"的技巧都无效**——
   因为免费车埋在哪都是免费车。

## 五、让玩家"思考找别的路线"—— 这一条我们现在**没做到**

机制层能造出"必须背债"，但"玩家会思考去找另一条路"需要**棋盘上有另一条路**。

### 5.1 现在还缺什么

现在的棋盘是**实心矩形**：每个格子的唯一通路是从上面下来。
所谓"路线选择"只是"先清左边还是先清右边"，**没有真正的分叉**。

### 5.2 什么叫真正的分叉

```
┌─────────────────────────┐
│ 入口行                   │
├──────┬──────────┬───────┤
│ 支路A │  ★卡点★  │ 支路B │     ← 中间被锁，两边可走
│      │          │       │
└──────┴──────────┴───────┘
```

- **支路 A** 走过去能拿到颜色 X（卡点需要的色）
- **支路 B** 走过去能拿到颜色 Y
- 中间的卡点车挡住主干，玩家必须判断"先去哪边"

这才是"思考"。实现它需要**预留通道结构**（类似前辈的 `narrowPath` 窄路 + 缺口），
而我们现在的生成器**没有这个能力**（墙全压最后一行，等于不留通道）。

### 5.3 前辈是怎么做的

`narrowPath` 卡点类型：在棋盘中间建一道墙，留 1~2 个缺口。
缺口格上可以叠冰/叠锁链（`narrowGapIce` / `narrowGapChain`）。

**这就是"分叉"的工程实现**，我们没做。

## 六、完整配方（照做即可）

```
第 1 步  图体检
        · 算 E_c(0)，算免费车下限
        · 若下限 > 6：这张图做不出卡点，换图或接受低难度

第 2 步  定盘
        · 彩色像素 < 1300 → 5×6；否则 6×7

第 3 步  切容量
        · 每色 ≥ E_c(0)/2，全局上限 84，下限 0.6×均值
        · 归一到 [0.6, 1.6]×均值

第 4 步  铺位
        · 入口只认第 0 行；按需求序；第 0 行同色 ≤2

第 5 步  加冰（唯一的时间维手段）
        · 数字 = 时差 × 总车数（夹 2~12）
        · 只锁"需要等"的车，别锁开局免费车

第 6 步  （还没做）造分叉
        · 中间一道墙 + 2 个缺口
        · 缺口一侧放"卡点色"，另一侧放"解锁色"
        · 缺口叠冰/锁链

第 7 步  验收
        · 可解（六遍求解）
        · 30~80% 有窗口越 3.2，前期 0~30% 不出卡点
        · 覆盖率 band3Pct ≥ 45%
```

## 七、一句话总结

> **卡点是"前沿可吃的车 ≤2 辆"这个状态持续 2~4 步。**
> 它由两件事决定：**容量**（决定有多少免费车）和**入口结构**（决定玩家能不能绕开）。
> 我们这几个月只调了容量，**入口结构（分叉）从来没做过**——
> 而"玩家思考找别的路线"恰恰只能靠它。
