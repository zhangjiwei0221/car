# 需求：消除逻辑 —— 小车如何选择要消除的像素小人

## 一、规则

> **小车只选择与自己颜色相同的像素小人；先选最外层，同一层里从下往上、从左往右。**

---

## 二、算法步骤

### 参数

| 参数 | 类型 | 含义 | 可选 |
|---|---|---|---|
| `E` | 布尔二维数组 `[R][C]` | 已消矩阵。`true` = 该格的像素小人已被消除；**本函数会原地修改它** | 否 |
| `B` | 整数二维数组 `[R][C]` | 像素小人矩阵，存每个格子的颜色编号；`≤ 0` 表示该格没有像素小人 | 否 |
| `R`、`C` | 整数 | 图片的行数、列数 | 否 |
| `X` | 整数 | 小车的颜色 | 否 |
| `N` | 整数 | 小车的容量（本次最多消除几个像素小人） | 否 |
| **返回值** | 整数 | `count`：本次实际消除的数量，满足 `0 ≤ count ≤ N` | — |

### 步骤

```
1. 分层
   对当前所有未被消除的像素小人计算“层号”：
   - 位于图片最外一圈（上/下/左/右任一边），或上下左右四邻中至少有一个已被消除
     → 层号 = 0
   - 必须先消掉上一层才会露出来的 → 层号 = 上一层 + 1（逐层向内推算）
   注意：分层只按像素连通性计算，与颜色无关——别的颜色的像素小人同样算阻挡。
   层号在【每消除一个像素小人之后】都要重新计算一次（不是每辆车只算一次）。

2. 排序
   对「B[r][c] 等于小车颜色 X 且 E[r][c] 为 false」的像素小人计算排序键：
   key = 层号 × (R*C + 1) + (R - 1 - r) × C + c
   键越小越先被选中，等价于三条优先级：
   ① 层号小的先选（外层优先）
   ② 同层：行号大的先选（从下往上）
   ③ 同行：列号小的先选（从左往右）

3. 消除
   初始化计数 count = 0（表示“本次已消除的像素小人个数”）；
   循环执行：
   - 取当前 key 最小的像素小人，把该格的 E[r][c] 置为 true
   - count = count + 1
   - 一旦 count 达到容量 N，立即停止
   - 若已经没有可选的像素小人，也停止
   - 否则【重新计算层号】（回到步骤 1），再选下一个

4. 返回
   count（本次实际消除了几个，0 ≤ count ≤ N）
```

---

## 三、必须遵守的约定

1. **小车停在哪个暂存槽、离槽多远，都不影响选择顺序**；
2. 不做“就近”判断，只按 层号 → 行 → 列；
3. 别的颜色的像素小人同样算阻挡，直到它被消除；
4. 没有可选的像素小人（颜色不存在 / 全部被挡）→ 本次消 0 个，小车留在暂存区；
5. 可选像素小人不够容量 → 全部消除，小车**未完成**，留在暂存区。

---

## 四、暂存区里有同色小车时的争用顺序

当暂存区里有 **两辆或更多颜色相同的小车 A**，而颜色 A 的像素小人被暴露时，
先让哪一辆消，按下面顺序决定：

1. **剩余容量少的优先**（快装满的那辆先补满）；
2. 剩余容量相同 → **离“最近的同色像素小人”更近的那辆优先**；
3. 仍相同 → **槽位下标小的优先**（即更靠左的槽位）。

> 说明：常见情况下同色像素集中在某一侧，第 2 条就表现为“最靠左的那辆先”。

**三个可核对点**：

1. 第 1–4 个：先吃底行最左那格（第 1 个），再吃右下角那三个（第 2–4 个）；
2. 之后每往上一行，都重复同样的顺序：**先吃最左那格，再吃右边那三个**（5–8、9–12……）；
3. 容量 27 比容量 25 多消 2 个（顶行的第 26、27 个），其余次序完全相同。
