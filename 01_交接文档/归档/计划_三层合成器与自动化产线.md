## 一、图纸规格（三层）

| 层 | 内容 | 约束 | 颜色预算 |
|---|---|---|---|
| **L3 大边框** | 画布最外圈 | 可 2–4 段、**每段不同色** | 2–4 |
| **L2 背景** | 主体外的底 | 1–2 色（可 2px 棋盘） | 1–2 |
| **L1 主体描边** | 每个主体一圈 | **每个主体一个独有色**（只包它自己） | 4 |
| 主体内部 | 主体本体 | 每主体 1–2 色 | 4–5 |
| **合计** | | | **≤15** |

### 引导判据（用户定义）

> 玩家先消 L3 → 再消 L2 → **才碰到某个主体的 L1**。
> 只要 L1 没被碰，就不算开始掏那个主体。
> “先从哪个主体开始” = **哪个 L1 最先被消**。

### 深度阶梯（关键参数）

给每个主体一个 **L2 厚度 dᵢ**（主体 L1 外侧到画布边界的背景层数）：

```
d 小 → L1 早暴露 → 玩家先掏它
d 大 → L1 晚暴露 → 玩家后掏它
```

目标阶梯：目标主体 L1 首次被消 ≈ 第 6–8 步，其余三个 ≥ +10 步。

## 三、里程碑

### M1 三层合成器（参数化）
- 输入：4 个主体（素材 TXT）+ 每主体 `{描边色, 内部色, 深度 d}` + `{L3 段数/颜色}` + `{L2 颜色}`
- 输出：目标图 TXT + 预览 PNG + 颜色预算核对（≤15、最小色距 ≥80）
- 附带：**L1 阶梯测量器**（每主体描边色的首次被消步数）

### M2 流水线 runner
`node 03_工具/正式版/Pipeline_v723.js --target X.txt --rows 7 --cols 7 --guide <L1色> --guide-steps 6`
- 内部：SplitLevel → OverlapBuild（带约束）→ Validate --audit → 输出 JSON 报告
- 报告字段：capacity、at4、run4、peak、items、audit、L1 阶梯

### M3 参数扫描
- 深度组合 × 棋盘尺寸 × 种子 → 批量跑，按 (audit通过, at4, L1阶梯) 排序
- 输出候选清单，取 top-3 人工过目

### M4 接入与文档
- 产物进 `实验关/关卡XXX/vN/`
- 更新 `实验关/index.html`、`工作日志`、`Goal执行计划`

## 四、验收门槛（每关）

| 项 | 门槛 |
|---|---|
| 容量守恒 | `sum(count) == 像素数` |
| 可解性 | 关道具可通关（`useItems=false`） |
| 压力 | at4 ≥ 20、run4 ≥ 12、峰值 ≤ 4 |
| 审核 | `Validate006Level --audit` 通过 |
| 句子表 | 0 空窗；最长无压段 ≤ 4（教学段不计） |
| 引导 | 目标主体 L1 首次被消 ≤ 第 10 步；其余 ≥ +10 步 |
