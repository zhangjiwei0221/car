# E2 · 目标区域与车辆依赖执行计划

> 状态：**E2已完成**
>
> 当前结果：依赖图、摆车约束、容量边界、异色探针和双布局验证均已完成
>
> 下一阶段：`E3` 棋盘编译器MVP

## 1. 阶段目标

E2 不从随机棋盘猜故事，而是回答：

1. 每个取车动作实际消费哪些目标区域？
2. 哪些区域由前一手打开，下一手才能消费？
3. 哪些区域是跨车偿还？
4. 哪些车辆位置/颜色是硬约束，哪些只是容量余量？
5. 遵守这些约束时，能否生成第二个布局，而不是只有手工v8成立？

结论：六步剧情首先受“位置/颜色/时序”约束，而不是某个精确容量值。

证据：
`实验关/关卡6/E2_v1/same-color-double-swap-v1.json/md`、

### E2.5 关键格异色探针

共220个异色单交换：

- 24个保持六步主线；
- 196个破坏。

| 关键格 | 原色 | 可替换颜色 |
|---|---:|---|
| (0,2) entry | 30 | 无 |
| (0,1) hollow | 15 | 无 |
| (0,0) debt1 | 17 | 无 |
| (1,0) release1 | 31 | 无 |
| (0,3) debt2 | 34 | 无 |
| (1,3) release2 | 5 | 14、15、30、31 |

结论：

- 五个关键位置是硬颜色约束；
- 第二释放格是软约束，只需一种能补账的颜色；
- 决定故事的是关键格颜色与暴露顺序，不是同色容量排列。

证据：`实验关/关卡6/E2_v1/cell-color-swap-probe-v1.json/md`。

## 3. E2.6 已完成

做约束引导的非关键车辆重摆：

1. 固定六个关键位置的颜色；
2. 对非关键车辆做受限重摆；
3. 保持容量集合、目标图和棋盘合同；
4. 检查前六步和完整47步是否仍成立；
5. 如果失败，记录新增的哪个非关键约束；
6. 至少得到两个满足当前约束的布局。

“不同布局”在本阶段定义为：

- 所有关键格颜色保持一致；
- 容量多重集合与目标图不变；
- 非关键车辆至少有8个格子发生位置变化；
- 两个布局都必须独立通过前六步、完整47步和故事审计。

## 5. E2退出条件

1. 六步关键颜色/时序约束已机器可读；
2. 至少两个不同布局满足核心故事；
3. 两个布局都不存在关键区域提前消费；
4. 0复活PlayerSim走完核心债务/释放；
5. 全知无法跳过核心债务与揭示；
6. 所有约束输入/输出JSON可复跑；
7. 不修改生产代码；
8. 未通过前不进入E3棋盘编译器。

## 6. 当前不做什么

- 不进入E4语义障碍编译器；
- 不用换seed代替约束；
- 不把同色容量排列当成剧情约束；
- 不宣称单张v8成功等于E2完成。
