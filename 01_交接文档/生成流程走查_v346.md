# 生成流程走查（v346）

> 从点下「批量生产」到关卡落盘，**每个脚本做什么、传什么、返回什么**。
> 所有数字来自 v346 的真实运行（016 目标图，40×40，13 色）。
> 行号会随版本漂移，**按函数名找**。

---

## 0. 总览

```
app.js (主线程)
  │ getGenConfig()              读界面 → cfg
  │ batchProduce()              线程池：min(设定, 核数, 图数)
  │   └─ new Worker('js/gen-worker.js')
  ▼
gen-worker.js (后台线程)
  │ importScripts 7 个模块
  │ onmessage → AntSolver.Generator.produce(blocks, config)
  ▼
generator.js  produceDispatch()   ← 多轮 portfolio
  │ for i in 0..K-1:
  │   produce(blocks, cfg_i)      ← 单轮：候选 + 卡点树
  │     generateFromBlocks()      ← 基础候选
  │       pickBoxSplit()          切球
  │       buildBoard()            选盘 → 障碍 → 填车
  │       Solver.solve()          首解 6 遍
  │       evaluateGeneration()    覆盖率/峰窗/玩家/死因
  │     goodV3Of()                六门
  │     makeChokeVariant()        卡点树（不合格时）
  │   portfolioBetter()           择优
  ▼
app.js onmessage('result')
  │ finishBatch() 落盘 4 类产物
  ▼
输出文件/<批次>/ 合格关卡/ 不合格关卡/ 生产文档/ txt图/
```

## 1. 阶段 0：参数装配（`app.js` → `getGenConfig` / `genApplyFixed`）

**输入**：面板 1 的图、面板 2 的旋钮。
**输出**：一个 `config` 对象（约 40 个字段）。

关键字段：

| 字段 | 来源 | 016 实际值 |
|---|---|---|
| `boxSizeMin/Max` | 界面输入 40/60 | 40 / 60（v346 起只当上限） |
| `blackPercent` | 界面 | 13 |
| `icePercent` | 界面 | 18 |
| `chainCount` | 界面 | 4 |
| `boardRowsMin/Max` | 界面（v309 已删，用固定范围） | 4 / 7 |
| `boardColsMin/Max` | 同上 | 6 / 9 |
| `targetBand3Min` | 覆盖率滑杆 | 45 |
| `portfolioK` | 由「每图搜索时间」推导 | 3 分钟 → 4 |
| `timeBudgetMs` | 同上 | 45000（单轮） |
| `generatorFlow` | 写死 `'old'` | old |
| `targetCarCount` | 写死 0（v337 红线） | 0 |
| `cutMode` | v345 起默认 `layerCut2` | layerCut2 |

**这一步的两个坑（历史事故）**：
1. `FIXED_PRESETS` 会覆盖用户值 → 必须写回（v337）
2. `applyFillRatio` 会顺手写 `targetCarCount` → 必须清零（v337）

## 2. 阶段 1：任务分发（`app.js` → `batchProduce` + `gen-worker.js`）

**线程数**：`min(界面设定, navigator.hardwareConcurrency, 图数)`。

**Worker 协议**：

| 方向 | 消息 |
|---|---|
| 主→worker | `{cmd:'produce', index, blocks, config}` |
| worker→主 | `{type:'result', index, result}` |
| worker→主 | `{type:'progress', p}`（每跑完一个候选/变体） |
| worker→主 | `{type:'error', index, message}` |

**worker 加载的模块**（7 个）：
`utils.js`、`simulator.js`、`solver-strategy.js`、`solver.js`、`playersim.js`、`analysis.js`、`generator.js`

> 注意：worker **不加载** `color-libs.js`（读图用）和 `anchor-cut.js`（锚点切盒）。

**名额分配**（生产前一次性算好）：
- 简单关比例（`easyRatioPercent`，默认 30%）→ 决定 `requireHardPass`
- BOSS 名额（每 N 关一个）→ 决定卡点类型数

## 3. 阶段 2：`produceDispatch`（多轮 portfolio）

**入口**：`Generator.produce` 实际指向 `produceDispatch`。

**做什么**：同一张图跑 K 轮，每轮换一套结构组合，最后择优。

```
K = clamp(portfolioK, 1, 10)          // 3 分钟档 → 4
for i in 0..K-1:
    cfg_i = clone(config, {portfolioK: 1})
    cfg_i.cutMode 轮换（v345：奇数轮 layerCut2，用户手动指定则不轮换）
    cfg_i 还要轮换：
        棋盘尺寸（boardTryDims）
        结构组合（_MIX2：fillLag / capSeqBoost / chunkCut 的 8 种组合）
        填充率（applyFillRatio，0.62 / 0.70 / 0.86）
    out_i = produce(blocks, cfg_i)
    if portfolioBetter(out_i) 更好 → 保留
    若已全过 → 早停
return best
```

**择优顺序**（`portfolioBetter`）：
`可解 > 违规条数少 > 覆盖率高 > 目标分近 > 压力更持久`

## 4. 阶段 3：`produce`（单轮：基础候选 + 卡点树）

**做什么**：造基础候选 → 评估 → 不合格则展开卡点树（改车）→ 再评估。

**016 的实际规模**（来自 `perf` 埋点）：

| 指标 | 数值 |
|---|---|
| `baseCandidates`（基础候选） | 7 |
| `chokeVariants`（卡点变体） | 39 |
| `regenVariants`（整盘重铺） | 6 |
| `evalCalls`（评估次数） | 25 |
| `prefilterRejects`（粗筛淘汰） | 0 |

> 39 个卡点变体只精算了 25 次：粗筛（`greedyPrefilter`，40ms）先砍掉一部分。

## 5. 阶段 4：`generateFromBlocks`（核心：切球 → 选盘 → 障碍 → 填车）

**调用链**：

```
generateFromBlocks(blocks, config)
  │ ① boxes = pickBoxSplit(blocks, config)       切球
  │ ② board = buildBoard(boxes, config)          选盘 + 障碍 + 填车
  │     ├─ chooseBoardDimsFixed(n, config)       选盘
  │     ├─ placeDispersedBlackReal(...)          分散黑块
  │     ├─ 管道落位（靠底部，口朝可达方向）
  │     ├─ 填车（elimSeq 行优先 + W=6 交错）
  │     ├─ ensureBoardFull(...)                  裁行/补黑块
  │     └─ placeBoardObstacles(...)              冰 → 链 → 问号
  │ ③ applyIceSchedule / diversifyRow0 / limitRow0Free   第 0 行调参
  │ ④ StructuralDeadlockCheck                    结构卡死检查
  │ ⑤ greedyPrefilter                            粗筛（太松直接淘汰）
  │ ⑥ Solver.solve                               首解
  │ ⑦ evaluateGeneration                         评估
  │ ⑧ 未通过 → 减负重试（最多 maxRetries 次）
  └ return {level, valid, solveResult, generationEval, ...}
```

### 5.1 切球（`pickBoxSplit`）

**v346 的两条路**：

| 路 | 函数 | 规则 |
|---|---|---|
| 默认 | `pickBoxSplitRaw` → `baseFillBoxes` | 按颜色总量：≥上限按上限封箱，尾箱与前一箱平分；再 `normalizeCapacities` 只守上限 |
| 层切（默认） | `layerCutBoxes2` | 洋葱剥 4~6 层 → 小层并入同色最大层 → 每层每色 `n = ceil(px/上限)` → 每辆 `px/n` → 按「到期」排序设 `elimSeq` |

**016 的车单**（层切，40~60）：30 辆，容量 31~60，低于下限 5 辆。

### 5.2 选盘（`chooseBoardDimsFixed`）

- 候选：`boardRowsMin..Max` × `boardColsMin..Max`，且 `列−行 ∈ {1,2}`
- 优先：装得下（溢出 ≤0）→ 最贴合（格数−车数最小）
- 收紧：`格数 − 车数 > 2` 就缩列/缩行
- 016 结果：**5×7 = 35 格**

### 5.3 障碍（数量从哪来）

| 障碍 | 数量 | 落位 |
|---|---|---|
| 黑块 | `blackPercent` × 格数，或 `solveSpaceQuota` 配额反推 | 分散，避开第 0 行/墙行/管道 |
| 管道 | 溢出 `n − 可用格` 反推，每管 4~6 | 靠底部，口朝可达方向 |
| 数字冰 | `icePercent` × 车格数 | 全盘分散，值 = `numIceValueFor`（按进度位次） |
| 锁链 | `chainCount` 组 | 全盘或下半区，组内相邻、组间不相邻 |
| 问号 | `questionPercent` | 分散 |

**016 实际**：4 黑 + 6 冰 + 4 链 + 2 问号 + 1 管（藏 5 辆）。

### 5.4 填车

- `elimSeq` 升序、行优先单扫
- **W=6 局部交错**：每个格从队首 6 个里挑"左/上邻不同色"的
- 遇管道格：把当前车压进队列

## 6. 阶段 5：`Solver.solve`（首解）

| 遍 | 策略 | 参数 |
|---|---|---|
| 1 | 贪心 | `noise 0` |
| 2 | 贪心 | `noise 0.6` |
| 3 | 三步树 | `noise 0.6` |
| 4 | 三步树 | `noise 1.0` |
| 5 | 噪声 | `noise 1.0` |
| 6 | 噪声 | `noise 1.5` |

**任一遍通关即停**。产出：
- `pickOrder`：每步取的格子
- `stepBufferHistory`：每步结束的暂存长度
- `pressureSamples`：`{done, buf, reachable, locked, remaining}`

**016 实测**：28 步、buffer 峰值 4。

## 7. 阶段 6：`evaluateGeneration`（评估）

| 指标 | 算法 |
|---|---|
| `band3Pct` | 进度 30~80% 区间，`buf≥3` 的采样占比 |
| `band4Pct` | 同区间 `buf≥4` 的占比（尖峰） |
| `midLateMax` | 同区间峰值 |
| `steadyWonPct` | `chokeV2PlayBatch` 18 局稳健通关率 |
| `playerPassPct` | 10 局（5 手痒度 × 2 种子）玩家通关率 |
| `deathCauses` | 链/冰/管道/形状/断供 |

**016 实测**：band3=100（层切 82 是别的 seed）、峰窗 4、玩家 100%。

## 8. 阶段 7：`goodV3Of`（六门）

```
① 可解
② 峰窗 ∈ [pMin, pMax]（默认 3.2~4.8）
③ 稳健 ∈ [sMin, sMax]
④ 30-80% 覆盖 ≥ targetBand3Min
⑤ 尖峰 ≥ band4Min（默认关）
⑥ 玩家通关率 ≥ 25%
（可选）主死因占比 ≥ targetDeathCauseMin
```

全过 → `pass=true`；否则记 `fails`。

> **注意**：落盘分类读的是 `candTier`（可交付 + audit 有卡点），**不是** goodV3。这两套门在 v346 仍然并存（日志 251 节有记录）。

---

## 9. 阶段 8：卡点树（`makeChokeVariant`）

在已有候选上**只改车，不动障碍**：

| 分支 | 概率 | 做什么 |
|---|---|---|
| 换球 | ~60% | A 车的球色换成 B 色 |
| 增容 | ~40% | 某辆 +30 容量 |
| 重生成 | — | 改冰/黑/链比例，整盘重铺 |

每个变体重新 `Solver.solve` + 重新评估。

---

## 10. 阶段 9：择优 + 落盘

**`finalizeProduce`**：
- `candTier(cand)` → 0/1/2/3
- `tier < 2` → `fallback=true`（兜底）
- 写 `audit.pass`、`fallbackReason`、`playerWon`

**`app.js finishBatch`** 落盘：

```
输出文件/<批次>/
├─ 合格关卡/<图名>.json
├─ 不合格关卡/<图名>__超时兜底.json
├─ 生产文档/
│   ├─ 关卡数据/<图名>.json      ← debug（board/solve/audit/perf）
│   ├─ 逐关记录.jsonl
│   ├─ 分析报告.csv
│   ├─ 生产报告.md
│   └─ 批次配置.json
└─ txt图/
```

## 13. 数据流（按数据形态）

```
TXT 文本
 → parseTxt（app.js）→ blocks: number[][]（色号矩阵）
 → pickBoxSplit → boxes: [{color, count, elimSeq, due}]
 → buildBoard → board: {rows, cols, cells:[[{t,color,count,numice,chain}]]}
 → parseLevel（utils.js）→ parsed: {blocks, board, rows, cols, bufferLimit, totalBoxes}
 → Solver.solve → solveResult: {completed, pickOrder, stepBufferHistory, pressureSamples}
 → evaluateGeneration → generationEval: {persist, player, deathCauses, ...}
 → goodV3Of → goodV3: {pass, fails, persist: {band3Pct, band4Pct, ...}}
 → finalizeProduce → cand: {level, solveResult, audit, fallback, ...}
 → toGameFormat（utils.js）→ 客户端 JSON: {toprow, blocks, maprow, mapcol, spools}
```
