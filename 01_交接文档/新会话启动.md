## 1. 现在的造关流程（不是一键）

| 步 | 做什么 | 工具 | 谁做 |
|---|---|---|---|
| 0 | 定体验剧本（几拍、每拍欠多少） | — | 人 |
| 1 | 图体检：每色像素/连通区/最大区/初始曝露/顶部是否单色带 | `SubjectAudit_v720` | 脚本 |
| 2 | 切盒（trend 或 anchor），校验 `sum == 总像素` | `GenAnchorCut_v711` | 脚本 |
| 3 | 容量合同（[20,40] / [20,50] / [6,50]…） | — | **人拍板** |
| 4 | 首测：峰值 / at4 / 窗口 / 空窗 / 审核 | `MeasurePageOmni_v715`、`Validate006Level_v706`、`StoryReview006_v712`、`SentenceTable_v717` | 脚本 |
| 5 | 摆障碍：解锁表 → 句型（链/冰/管/黑） | 人判断 + `OverlapBuild_v719` 验证 | **人 + 脚本** |
| 6 | 复诊：句子表 0 空窗、审核、不靠道具 | `SentenceTable_v717`、`GapRepair_v718` | 脚本 |
| 7 | 交付：拷到 `实验关/关卡XXX/vN/` + md + 构建步骤 | — | 人 |
| 8 | 记录：工作日志一节 + Goal 一行 | — | 人 |

**自动化的是“算与验”，判断的是“选与舍”**：
选哪个主体、壳改哪色、容量怎么分级、句型怎么排 —— 这三件必须人（或 AI）做。

### 为什么不能一键

- 整片重排 → 峰值掉到 3（v50 教训）；
- 锚点切四个种子 → 最好 at4 只有 2，不如设计版 14；
- 只有“按解锁表配对 + memberswap”把 006 从 at4=21 推到 28。

一键批量只会产出大量需要逐个诊断的半成品。

## 3. 指标口径（页面口径 = runSolver(0,1,true,…,instantChain)）

| 指标 | 定义 | 目标 |
|---|---|---|
| `buffer` | 暂存区未收满条数 | 4=卡点；5=死亡边界 |
| `at4` | 全知路线里 buffer≥4 的步数 | 越大越好 |
| `run4` | 最长连续 buffer≥4 | 平台长度 |
| `空窗` | 两次 buffer≥4 之间 buffer<3 的连续步数 | **0** |
| `免费步` | 收满不欠债的步数 | 越少越好 |
| `解锁步` | 某色第几步够这辆车的容量 | 越晚越能当“锁芯” |

**收口三条件**：句子表 0 空窗、审核通过（或用户明确允许前期卡点）、**不用道具可解**。

## 4. 红线（违反过，别再犯）

1. **容量区间是输入**，脚本不得缩放/拆半；
2. **像素=容量精确守恒**（`sum(counts) == 目标像素`）；
3. **峰值 ≤4**（5 是死亡边界）；
4. **不靠道具**：no-item `runSolver` 必须通关；
5. **位置不控制曝露**：别指望整片重排改压力；
6. 改目标图 = 改合同 = 之前所有版本要重测。
