# 验收与排查清单

> 本次批准写入范围：`codex助理/毛线汽车/**`

## 1. 生产前检查

- 确认从项目根启动：

```bash
cd "/Users/wzy/Desktop/蚂蚁拿块游戏"
node "网页启动器/启动.js"
```

- 终端应打印：
  - 项目根路径。
  - `http://localhost:<port>/bin/index.html`。
  - 输出根为 `输出文件/`。
- 浏览器地址必须是 `http://localhost:<port>/bin/index.html`，不是 `file://.../bin/index.html`。
- 页面标题和功能区正常加载，生成器页能导入 TXT。
- 打开开发者工具时不应有核心 JS 404。
- 如使用方案文件，确认方案版本和入口模式：四边 / 底部 / 瞬时连锁。

## 2. 小批量冒烟建议

正式大批前先跑 2-3 张 TXT：

- 设置明确批次名，例如 `冒烟-v126-10-12`。
- 并发线程数先设 1 或 2，降低排查噪音。
- 单关预算可短一些做链路验证。
- 观察页面日志是否显示“逐关落库已启用”。
- 输出目录应生成：

```text
输出文件/冒烟-v126-10-12/
  生产文档/批次配置.json
  生产文档/生产状态.json
  生产文档/逐关记录.jsonl
  生产文档/分析报告.csv
  生产文档/生产报告.md
```

验收重点：

- `生产状态.json` 的已落库数递增。
- `逐关记录.jsonl` 一关一行。
- 合格关卡和 TXT 能在对应目录配对。
- `分析报告.csv` 有入口模式、合格档、难度分、卡点类型等列。
- 页面完成后显示输出目录，而不是要求下载 ZIP。

## 3. 大批生产中观察

- 页面进度条：已完成数应持续递增。
- 并发状态：应显示若干 Worker 在算。
- 终端日志：应出现 `[批次开始]`、`[落库]`、`[批次完成]`。
- 若某关超时，页面会记录“单关超时未返回”，服务写异常记录后继续。
- 若落库失败，页面应暂停并显示“重试落库”，不要关闭页面前先排查磁盘、权限、请求体大小或服务状态。

## 4. 生产后验收

检查目录：

- `合格关卡/` 中每个 JSON 是程序端干净结构。
- `txt图/` 中源图数量应与合格关卡配套。
- `不合格关卡/`、`不合格txt图/` 能解释被淘汰源图。
- `生产文档/生产报告.md` 的计数与目录数量大体一致。
- `生产文档/分析报告.csv` 能用表格软件打开，首列无乱码。
- `生产文档/关卡数据/` 存完整内部数据，可用于复盘。

建议抽查：

- 抽 1 个合格关卡导回模拟器，确认能加载。
- 对照 `逐关记录.jsonl` 的 `入口模式键` 和批次参数。
- 对照 `卡点位置`、`卡点计划`、`采样参数` 是否符合本批需求。
- 如果是底部/瞬时连锁玩法，确认程序端/排序端没有只拿干净 JSON 而丢入口模式。

## 5. 常见故障定位

| 现象 | 优先排查 |
| --- | --- |
| 页面提示未连接本地生产服务 | 是否通过 `node 网页启动器/启动.js` 打开；地址是否 http；服务终端是否仍在运行 |
| 页面卡死、停止不即时 | 是否 file:// 打开导致 Worker 不可用；是否主线程兜底模式 |
| 点下载 ZIP 没反应 | 这是兜底模式；先确认有没有更推荐的逐关落库输出；大 ZIP 下载需等待 |
| 生产完没有合格关 | 检查 `分析报告.csv` 的不合格原因、碎色闸门、入口模式、卡点阈值和参数过约束 |
| 输出目录跳号 | 同名批次目录已存在，服务会追加 `-2/-3` |
| 服务重启后页面无法继续旧批 | 需要走 `/api/production/resume` 恢复批次；当前 UI 闭环需另查 |
| 底部/瞬时连锁包玩法丢失 | 干净关卡本体不含入口模式，必须保留生产文档或外部分组 |
| 某关显示 WATCHDOG_TIMEOUT | 单关超过预算 + 120 秒仍未返回；看 `不合格txt图/` 和 JSONL 记录 |

## 6. 回滚/保全建议

- 正式大批前不要清理已有 `输出文件/`。
- 批次完成后整目录保留，不只拷贝 `合格关卡/`。
- 对交付包至少保留：
  - `合格关卡/`
  - `txt图/`
  - `生产文档/分析报告.csv`
  - `生产文档/逐关记录.jsonl`
  - `生产文档/生产报告.md`
  - `生产文档/关卡数据/`
- 如果要再跑同名批次，接受服务自动跳号，避免覆盖历史证据。
