# 风险清单与待确认

> 本次批准写入范围：`codex助理/毛线汽车/**`

## 1. 高优先级风险

### R1. 不要用 `file://` 正式生产

直接打开 `bin/index.html` 会失去 Web Worker 和逐关落库，只能走主线程 + ZIP 兜底。正式生产应使用：

```bash
node "网页启动器/启动.js"
```

### R2. 旧临时脚本有硬编码路径

`bin/js/_prodrun.js` 和 `_prodmerge.js` 写死了：

```text
/Users/red/Desktop/蚂蚁拿块游戏
```

这两个脚本只能作为历史参考。直接运行大概率写错路径或失败。

### R3. 文档版本不完全同步

`生成器逻辑体系.md` 顶部写 v99，但代码和更新记录已到 v126。交接时应按：

1. 当前代码；
2. `更新记录.md` v126；
3. 专项说明文档中对应章节；
4. 历史文档；

这个优先级阅读。

### R4. 入口模式不在干净关卡本体内

`fourSide`、`bottomOnly`、`fourSideInstantChain` 只记录在生产侧数据。后续如果只拿 `合格关卡/*.json`，会丢玩法标记，需要从批次记录或外部规则补上。

### R5. 随机种子未固定

批次配置记录中写的是 `Math.random（未固定种子）`。同一参数和同一源图不保证逐字节复现。需要可复现生产时，必须另立需求讨论随机源和 seed 注入。

### R6. `finalize_node.js` 会重写目标包

该脚本会清空并重写目标包内 `关卡/` 与 `txt图/` 的 JSON/TXT。只能对明确备份后的 20x20 包使用，不要拿正式大包直接试。

## 2. 中优先级风险

### R7. 服务内存态会随重启丢失

生产服务的 `batches` 存在内存中。服务重启后旧 `batchId/batchToken` 不可用，需要 `/api/production/resume` 从既有目录恢复。是否有完整前端按钮入口需继续核查。

### R8. 浏览器缓存问题虽有防护，但仍需留意

启动器会随机端口并给 HTML 注入 `?v=<SERVER_TOKEN>`，服务也发 no-store 头。若用户不是通过启动器进入，仍可能加载旧缓存资源。

### R9. 修图工具副本可能与主 bin 不同版

历史记录显示“修图工具 bin 副本对齐到 v105”。当前主 bin 是 v126。若修图工具还内置旧 `bin` 副本，不能默认与主生产口径一致。

### R10. 生产服务只写 `输出文件/`

这是安全边界，也是操作约束。不要期望通过 API 写到任意目录；批次名只能影响 `输出文件/<批次名>-MM-DD[-N]/`。

## 3. 待确认项

1. 当前团队正式上线包是否只接收 `合格关卡/`，还是同时需要 `生产文档/` 中的入口模式和排序字段。
2. 后续排序流程是否按 `isBossSlot` 把难关规格关卡放到逢 5 位。
3. 是否需要为主生产引入固定随机种子，以支持复现生产。
4. 是否要把 `生成器逻辑体系.md` 顶部版本从 v99 整理到 v126。
5. 是否需要为 `/api/production/resume` 补前端可视化入口或操作文档。
6. 修图工具内置生产/求解口径是否需要从 v105 同步到 v126。

## 4. 本次未验证

本交接包未实际启动浏览器生产，也未跑样例关。以下内容来自静态阅读：

- Web Worker 在当前机器浏览器中的实际可用性。
- 当前 Node 版本是否满足启动器运行。
- `/api/production/resume` 与现有 UI 是否已经闭环。
- 任一参数方案的实跑产能、合格率或难度分布。
