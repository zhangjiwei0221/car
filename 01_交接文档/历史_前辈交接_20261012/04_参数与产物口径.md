# 参数与产物口径

> 本次批准写入范围：`codex助理/毛线汽车/**`

## 1. 版本口径

- `bin/index.html` 当前引用 `css/js` 均为 `?v=126`。
- `bin/文档/版本记录/更新记录.md` 最高记录为 v126。
- `bin/文档/说明文档/生成器逻辑体系.md` 顶部仍写 v99，但正文已含 v120 等补充；接手时不要只看顶部版本号。
- 当前生产默认入口是 `AntSolver.Generator.produce()`，默认走 `produceFixed()`。

v126 核心含义：

- 候选筛选阶段仍用单轮难度，保证速度。
- 只在最终选中关卡出口进行多轮玩家路线难度标定。
- `difficultyRounds` 默认 7。
- 死亡边界救援成功后必须重解析最终 `level`，避免用旧 `parsed/result` 做难度标定。

## 2. 参数来源

网页生产参数主要来自 `app.js getGenConfig()`：

- 基础玩法：`bottomOnly` / `instantChain`
- 盒容量：`boxSizeMin`、`boxSizeMax`、`boxSizeMode`
- 暂存：`bufferLimit`
- 棋盘范围：`boardRowsMin/Max`、`boardColsMin/Max`
- 障碍：`icePercent`、`blackPercent`、`chainCount`、`questionPercent`
- 区间化参数：`icePercentMin/Max`、`blackPercentMin/Max`、`chainCountMin/Max` 等
- 管道：`minPipes`、`pipeMaxDepth`、`pipeMinFill`、`pipeFallback*`、`pipeFloor*`
- 卡点类型：`chokeTypes`、`chokeTypeRollsNormal/Boss`、`chokeTypeProb`
- 前置闸门：`fragmentMaxRate`
- 批量生产控制：`candidateCount`、`timeBudgetMs`、`easyRatioPercent`、`difficultyRounds`

参数方案文件位于 `方案文件夹/`。当前可见方案包括：

- `方案_v119四方向.json`
- `方案_v120四方向消除方案.json`
- `方案_v120四方向低管道去微棋盘.json`
- `方案_v110底部消除.json`
- `方案_v100参数底部消除参数.json`
- `方案_v95四方向消除统一默认参数.json`
- 以及更早的 v91/v95/v104/55x55 方案

## 3. 入口模式

入口模式只写入生产侧记录，不写入干净关卡本体：

| key | 中文 | 含义 |
| --- | --- | --- |
| `fourSide` | 四边入口 | 默认玩法 |
| `bottomOnly` | 仅底部入口 | 目标图上/左/右封闭，只能从底边向内消除；棋盘取盒不变 |
| `fourSideInstantChain` | 四方向瞬时连锁 | 每次取盒后一次性快照当前可达同色全集，按起点距离消除 |

因此程序端或排序端如果需要区分玩法，必须依赖批次记录、CSV、`关卡数据` 或外部批次分组，而不是单个干净关卡 JSON。

## 4. 审核口径

当前审核要点来自 `生产审核评分体系.md` 和 `analysis.js`：

- 暂存上限记为 `L`。
- 卡点线：`L - 1.8`。
- v119 后卡点判定区：`[30%, 100%]`。
- 窗口宽：5%。
- 前期区间：`[0%, 30%]`，前期不能过压。
- 中期阶段已移除，旧字段保留主要是兼容 CSV。
- 分档：
  - `合格`：有卡点且前期安全等条件满足。
  - `简单关·趋势过平`：可用但趋势过平，服务端仍按合格类统计为简单关。
  - `不合格`：不满足可用/审核条件。

注意：合格门和难度分是两条线。v118 后难度评分 f1 cap 与卡点线已经解耦，不应因改审核阈值顺手改难度评分。

## 5. 难度口径

当前难度主要基于玩家版表现：

- 玩家平均暂存
- 玩家滞留/无量纲占比
- 障碍项
- 复活影响
- v126 最终关卡多轮标定

生产记录会保留：

- `difficulty`
- `grade`
- `difficultyCalibration`
- `difficultySingle`
- `generationEval`
- `solve`
- `audit`

## 6. 正式逐关落库产物

正式服务输出：

| 路径 | 内容 |
| --- | --- |
| `合格关卡/` | 程序端干净 JSON，供上线/程序端使用 |
| `txt图/` | 合格源 TXT |
| `不合格关卡/` | 有关卡结构但未合格的 JSON，文件名带失败分类 |
| `不合格txt图/` | 不合格、跳过或异常的源 TXT |
| `生产文档/批次配置.json` | 输入清单、生成参数、页面版本、种子策略 |
| `生产文档/生产状态.json` | 当前批次统计与已完成输入索引 |
| `生产文档/逐关记录.jsonl` | 一关一行完整生产摘要 |
| `生产文档/分析报告.csv` | Excel/筛选用量化表 |
| `生产文档/生产报告.md` | 人读报告 |
| `生产文档/关卡数据/<名>.json` | 完整内部 board/solve/audit/debugData |

## 7. ZIP 兜底产物

服务不可用时，浏览器内存模式输出 ZIP：

- `关卡/`
- `txt图/`
- `求解数据/`
- `关卡数据/关卡数据.json`
- `关卡数据/分析报告.csv`
- `关卡数据/生产报告.md`
- `索引.csv`

这条路径不是推荐正式生产方式，原因是整批数据在浏览器内存中汇总，崩溃会丢已生产结果。
