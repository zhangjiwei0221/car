# 生成流水线（v206）

**拆图 → 合球 → 铺球 → 选棋盘 → 铺障碍 → 二次验证 → 复检 → 合成 → 检查/审核/评分 → 出炉**

每个环节写三块：**流程是什么 · 我们做了什么 · 应该做成什么样**。

---

## ① 拆图　✅ 有

- **流程**：把目标图拆成结构——同色连通块、依赖层、每色埋在第几层、每层多少像素。
- **我们做了什么**：
  - 消除轮次 `eliminationOrder`：每色最早第几轮被吃掉（1~2 早出、≥3 深埋）；
  - 层表报告：每层色块/像素/颜色数、每色最浅层、色块位置表；
  - 选图扫描（按深层色分级）、开局体检（开局暴露哪些色）。
  - 生产里目前只用“早出/深埋”这一档判定。
- **应该做成什么样**：
  - 输出**每色每层的像素预算**（第几层多少像素、能切几辆、每辆多大）；
  - 输出依赖关系（哪个色开哪个色的壳），供合球直接消费；
  - 成为切法的唯一依据，而不只是观察报告。

## ② 合球　❌ 缺

- **流程**：决定每色切几辆、每辆容量多大、覆盖哪几层。这一步决定“债的形状”。
- **我们做了什么**：
  - 仍是“像素数 ÷ 平均容量”平均切，车与层无关；
  - 唯一设计动作：给一辆深埋色车增容 ×1.5~2（同色扣减守恒）。
- **应该做成什么样**：
  ```
  现在：某色 1225 px ÷ 平均容量 30 → 41 辆，大小均匀
  应为：第 1 层 40 px、第 3 层 260 px
        → 浅层 1 辆 40（开壳车）
        → 深层 7 辆 37（被包车，注定欠债）
  ```
  - 浅层切开壳车（容量≈该层可达）、深层切被包车（容量>当下可达）；
  - 每色总量守恒；车单输出「颜色 / 容量 / 起始层」；
  - 能回答：这关设计了几笔债、各多大、什么时候还。

## ③ 铺球　🟡 有效

- **流程**：把车放到棋盘上——谁在可点位置、谁被压在里面、出场顺序如何，形成阻挡关系。
- **我们做了什么**：
  - 车按消除趋势排序、逐行左→右填盘；
  - 设计器：取开局“可点集合”，把可点且早出的车与不可点且深埋的车对调，直到可点早车 ≤ 目标档；
  - 11 个变体（早车档 4/3/2/1/0 + 增容 1.5/2）各跑一关，按 goodV3 择优。
  - 成绩：40×40 3/10 → **10/10**；35×35 1/10 → **4/10**。
- **应该做成什么样**：
  - 以“可点集合 × 深度”为约束排布：可点环上只放深埋车，浅色车放内圈；
  - 给出一条**目标压力曲线**，按曲线排车；
  - 直接算出该放哪辆，而不是靠穷举变体。

## ④ 选棋盘　🟡 可用

- **流程**：定行列、黑块与管道配额，保证车放得下、暴露面与设计匹配。
- **我们做了什么**：
  - 行列范围界面可填，硬范围生效（超出直接报错，不再偷偷换尺寸）；
  - 形态约束（列 − 行 ∈ {1,2}）、可用空间/黑块/管道配额联立。
  - 实测：只改棋盘范围、不开设计扫描，全过率不变。
- **应该做成什么样**：
  - 盘子大小由“车数 × 暴露面”反推：周长 ÷ 车数 ≤ 阈值（如 0.45）；
  - 范围只是护栏，真正决定尺寸的是这条比例约束。

## ⑤ 铺障碍　❌ 缺

- **流程**：用冰、锁链、问号、管道、墙控制节奏。
- **我们做了什么**：
  - 按比例撒，位置随机；
  - 三次定向尝试全部失败（挂债车 / 挂解药车 / 拆解药车）；
  - 已验证：障碍不是压力主因，量也不是剂量（冰 0→20% 峰窗乱跳）。
- **应该做成什么样**：
  - 障碍挂在设计好的债上：冰压开壳车、管道藏供给、墙封关键路径；
  - 位置由车单与层表决定，不是随机；
  - 做不到就降级为“节奏装饰”，不指望它造压力。

## ⑥ 二次验证　🟡 只验结构

- **流程**：铺完障碍再验一遍——死锁、可解、被埋。
- **我们做了什么**：结构卡死检查 + 求解筛选；被埋数并入 goodV3。
- **应该做成什么样**：还要验**设计意图**（该欠的债有没有欠、硬垫是否落在设计区间），不通过就回③重排。

## ⑦ 复检　✅

- **流程**：求解 + 审核，看压力曲线。
- **我们做了什么**：六遍全知求解 + 三步前瞻；卡点线 3.2、curveOK；18 局玩家线取中位峰窗。
- **应该做成什么样**：加“设计对账”（实际曲线 vs 目标曲线），差值反馈回③。

## ⑧ 合成　✅

- **流程**：内部棋盘 → 程序端关卡 + txt + 调试数据。
- **我们做了什么**：干净 JSON + txt + 求解数据 + 关卡数据（含 board/solve/audit）。
- **应该做成什么样**：关卡里带设计元数据（车单、债点、目标曲线），便于复盘与二次编辑。

## ⑨ 检查 / 审核 / 评分　✅

- **流程**：判断能不能用、有多难。
- **我们做了什么**：goodV3 六条（可解、稳健≥50%、被埋=0、前期≤2、峰窗 3.2~4.8、稳打落后≤17）；难度分 v3 只展示；口径已修（spread → steadyGap）。
- **应该做成什么样**：阈值用真人标签校准；按难度分做档位。

## ⑩ 出炉　✅

- **流程**：落库、打包、给程序端用。
- **我们做了什么**：合格/不合格分目录、生产文档、ZIP 兜底。
- **应该做成什么样**：自动挑选 + 自动分档命名 + 一键导入实机。

---

## 一句话总结

| 状态 | 环节 |
| --- | --- |
| ✅ 有 | 拆图、复检、合成、检查/评分、出炉 |
| 🟡 能用 | 铺球（设计器）、选棋盘（范围）、二次验证（只验结构） |
| ❌ 缺 | **合球**（切法模板）、**铺障碍**（随机撒） |

两个断点补上之前，压力只能靠“铺球”这一个手段凑。
