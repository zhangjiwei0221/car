# 运行入口与操作手册

> 本次批准写入范围：`codex助理/毛线汽车/**`

## 1. 推荐启动方式

在项目根目录执行：

```bash
cd "/Users/wzy/Desktop/蚂蚁拿块游戏"
node "网页启动器/启动.js"
```

指定端口：

```bash
node "网页启动器/启动.js" 8123
```

启动器会做这些事：

- 检查 `网页启动器/生产服务.js` 与 `bin/index.html` 是否存在。
- 选择空闲端口，默认从 8000-8060 范围内随机起点扫描。
- 使用当前 Node 拉起本地生产服务。
- 打开 `http://localhost:<port>/bin/index.html`。
- 服务端静态托管项目根目录，并给本地 JS/CSS 注入本次启动令牌，绕开浏览器旧缓存。

不要直接双击 `bin/index.html` 做正式生产。`file://` 模式下 Web Worker 和本地逐关落库都不可用，只能退回主线程和 ZIP 兜底。

## 2. 网页生产步骤

1. 打开页面后切到“生成器”视图。
2. 导入 TXT 图，可以多选。
3. 选择或导入参数方案，也可以直接调 UI 控件。
4. 设置批次名、并发线程数、单关预算、简单关比例、难关间隔等生产控制项。
5. 点击批量生产。
6. 页面先探测 `/api/production/ping`：
   - 成功：进入逐关落库正式模式。
   - 失败：进入内存 + ZIP 兜底模式。
7. 生产中：
   - Worker 返回结果。
   - 主线程组装记录。
   - 如果逐关落库开启，必须服务确认 `persisted:true` 后才派发下一关。
8. 完成后：
   - 正式模式：页面显示 `输出文件/<批次>/`，无需下载 ZIP。
   - 兜底模式：点击“下载关卡包 ZIP”保存。

## 3. 停止与失败处理

网页层：

- 后台线程模式：点击停止会 terminate 当前 Worker，并对已经落库的关卡收尾。
- 主线程模式：只能在当前关结束后停止，页面会短暂无响应。
- 单关看门狗：超过 `timeBudgetMs + 120s` 仍无返回时，记录为超时异常并重启该槽位继续。

落库层：

- `/api/production/result` 和 `/api/production/error` 都按 `batchId + inputIndex` 幂等。
- 写盘失败时网页暂停派发，并显示“重试落库”；不会继续空转生产。
- 服务重启后，内存中的 `batchId/batchToken` 会丢失；服务端提供 `/api/production/resume`，可从已有 `输出文件/<批次>/生产文档/逐关记录.jsonl` 重建批次状态，但当前页面是否暴露完整续跑操作需另查 UI。

## 4. 本地服务 API

| API | 作用 |
| --- | --- |
| `GET/POST /api/production/ping` | 探测服务，返回 `service: ant-production` |
| `GET /api/production/status?batchId=...` | 查批次状态 |
| `POST /api/production/start` | 创建批次目录，写 `批次配置.json` 和 CSV 表头 |
| `POST /api/production/result` | 落库一关成功结果 |
| `POST /api/production/error` | 落库跳过/异常记录 |
| `POST /api/production/stop` | 标记批次停止 |
| `POST /api/production/finish` | 标记批次完成 |
| `POST /api/production/resume` | 恢复已有批次目录的内存态 |

安全边界：

- 只监听 `127.0.0.1`。
- 只允许写入项目根 `输出文件/`。
- 文件/目录名会清洗，路径会 realpath 前缀校验。
- 单请求体上限 64MB。
- 不执行客户端传入命令。

## 5. Node 离线脚本

### 5.1 `bin/generate_node.js`

用途：20x20 小图批量生产，偏合法性稳定，不追求卡点难度。

默认：

```bash
node "bin/generate_node.js"
```

等价输入/输出：

```text
输入：txt图/20x20图纸_9关
输出：output/20x20关卡包_9关
```

也可指定：

```bash
node "bin/generate_node.js" "<源TXT目录>" "<输出目录>"
```

### 5.2 `bin/finalize_node.js`

用途：补齐已有 20x20 关卡包到目标总数，并做更严格的合法性复核。

默认：

```bash
node "bin/finalize_node.js"
```

等价参数：

```text
包目录：output/20x20关卡包_20关
目标数：20
```

也可指定：

```bash
node "bin/finalize_node.js" "<关卡包目录>" 20
```

注意：`finalize_node.js` 会清空并重写目标包内 `关卡/` 与 `txt图/` 的 JSON/TXT 文件。这是脚本设计行为，不能对正式生产包随意运行。
