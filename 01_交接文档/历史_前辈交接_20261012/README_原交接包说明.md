## 交接结论

当前主生产链路不是单个脚本，而是由三层组成：

1. `网页启动器/启动.js` + `网页启动器/生产服务.js`：推荐正式入口，负责用 `http://` 打开生产器并逐关落库到 `输出文件/`。
2. `bin/index.html` + `bin/js/app.js` + `bin/js/gen-worker.js`：浏览器生产 UI、批量调度、Web Worker 并发、停止/落库/回退 ZIP。
3. `bin/js/generator.js` + `solver/simulator/playersim/analysis/utils`：真正的生成、求解、玩家模拟、审核和难度评分核心。

当前页面资源版本号为 `v126`；`bin/文档/版本记录/更新记录.md` 最高记录为 v126。另有旧文档 `生成器逻辑体系.md` 顶部仍写 v99，需要按“历史文档”看待，以代码和 v126 更新记录为准。

## 已核对事实

- 项目根规则要求 Codex 默认只读，常规可写区是 `codex助理/**`；本次新增文档符合该范围。
- `bin/index.html` 引用主资源均带 `?v=126`。
- 主网页生产链路优先走本地生产服务逐关落库；服务不可用时才回退为内存汇总 + 手动下载 ZIP。
- 本地生产服务只监听 `127.0.0.1`，唯一允许写入根是 `输出文件/`。
- 生成核心出口是 `AntSolver.Generator.produce()`；当前通过 `produceDispatch()` 默认分发到 `produceFixed()`，旧流程仍保留为 `produceLegacy()`。
- Node 脚本 `bin/generate_node.js`、`bin/finalize_node.js` 是小图/补包 headless 工具，不等同于当前推荐的网页逐关落库主流程。
- `bin/js/_prodrun.js`、`bin/js/_prodmerge.js` 含 `/Users/red/Desktop/蚂蚁拿块游戏` 旧硬编码路径，应作为历史临时脚本，不建议直接交付使用。
- 已按用户追加要求贴入完整主 `bin` 快照：`完整主bin快照_20261012/bin/`。
