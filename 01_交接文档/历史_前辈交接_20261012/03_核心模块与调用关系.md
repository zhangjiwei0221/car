# 核心模块与调用关系

> 本次批准写入范围：`codex助理/毛线汽车/**`

## 1. 当前主流程模块

| 模块 | 角色 | 接手要点 |
| --- | --- | --- |
| `网页启动器/启动.js` | 跨平台启动器 | 推荐入口。负责选端口、拉服务、开浏览器。macOS 优先 Chrome，降低 localhost 缓存问题。 |
| `网页启动器/生产服务.js` | 本地逐关落库服务 | 正式生产数据落盘点。只写 `输出文件/`，每关写盘确认后网页才继续派发。 |
| `bin/index.html` | 主页面 | 当前资源版本 `?v=126`。包含模拟器与生成器两大视图。 |
| `bin/js/app.js` | 前端总控 | 导入、参数读取、批量调度、worker 池、落库、ZIP 兜底、导入包解析、分析报告导出。 |
| `bin/js/gen-worker.js` | 批量生产 Worker | 只做模块加载和 `AntSolver.Generator.produce()` 调用，消息协议很窄。 |
| `bin/js/generator.js` | 生成核心 | 当前 `produce()` 默认分发到 `produceFixed()`；旧流程仍保留。 |
| `bin/js/analysis.js` | 审核和难度 | `chokepointAudit()`、`difficulty()`、多轮重标定等口径来源。 |
| `bin/js/solver.js` | 全知求解器入口 | 调度贪心和树搜索策略，输出 `pickOrder`、压力样本等。 |
| `bin/js/solver-strategy.js` | 求解策略 | 三步前瞻、暂存释放、启发式评分等。 |
| `bin/js/simulator.js` | 规则模拟 | 四边、底部、瞬时连锁等消除规则，盒执行与暂存状态。 |
| `bin/js/playersim.js` | 玩家版模拟 | 用于玩家通关、玩家暂存、难度评分和重标定。 |
| `bin/js/utils.js` | 数据转换/工具 | TXT 解析、关卡格式转换、颜色工具、消除顺序等基础能力。 |
| `bin/js/zip.js` | 浏览器 ZIP | 仅兜底模式/单关导出等浏览器打包使用。 |

## 2. 生成核心出口

`generator.js` 底部导出关键点：

- `produce: produceDispatch`
- `produceLegacy: produce`
- `FLOW: DEFAULT_FLOW`
- `produceFixed`
- `generateFromBlocksFixed`
- `structuralDeadlockCheck`
- `blocksFromTXT`
- `checkBottomEntryFeasibility`

当前默认：

```text
DEFAULT_FLOW = 'new_fixed'
AntSolver.Generator.produce(blocks, config)
  -> produceDispatch()
  -> produceFixed(blocks, config, opts)
```

回退旧流程的三种方式：

```text
AntSolver.Generator.FLOW = 'old'
produce(blocks, Object.assign({}, cfg, { generatorFlow: 'old' }))
AntSolver.Generator.produceLegacy(blocks, config)
```

## 3. 前端批量调度关系

```text
index.html
  -> app.js init()
     -> 绑定 btn-gen-start
     -> batchProduce()
        -> getGenConfig()
        -> genPersistProbe()
        -> genApi('/api/production/start')
        -> genSpawnPool()
           -> gen-worker.js
              -> importScripts(...)
              -> AntSolver.Generator.produce()
        -> genOnResult()
           -> genBuildRec()
           -> genPersistPayload()
           -> genPersistOne('/api/production/result')
        -> finishBatch()
           -> 正式模式：/api/production/finish
           -> 兜底模式：AntSolver.Zip.create(files)
```

并发口径：

- UI 可设置线程数。
- 线程数不会超过 `navigator.hardwareConcurrency`。
- 每个 Worker 一次只处理一关。
- 单关预算是每关自己的墙上时间，不因并发缩短。
- Worker 失效时会把在飞关卡退回待处理队列，由其他槽重跑。

## 4. 生产服务落库关系

```text
app.js genPersistPayload()
  -> record.gameLevel        程序端干净关卡
  -> record.debugData        完整内部数据
  -> record.audit/difficulty 生产判断信息
  -> record.txt              源图

生产服务 persistResult()
  -> classify()
  -> 写 JSON/TXT/debugData
  -> 追加 逐关记录.jsonl
  -> 追加 分析报告.csv
  -> 重写 生产状态.json
  -> 重写 生产报告.md
```

合格必须同时满足：

- `rec.valid === true`
- 全知通关
- 玩家通关
- 合格档属于 `合格` / `简单关·趋势过平` / 旧字样兼容
- 不是 `fallback`

## 5. 历史与辅助脚本

| 脚本 | 判断 |
| --- | --- |
| `bin/generate_node.js` | 可用的 headless 辅助脚本，但参数针对 20x20 小图，与主网页生产不同。 |
| `bin/finalize_node.js` | 可用的 headless 补包/复核脚本，会重写目标包内容，需谨慎。 |
| `bin/js/_mkmanifest.js` | 历史辅助，需另查具体场景。 |
| `bin/js/_prodrun.js` | 历史临时生产脚本，含旧绝对路径 `/Users/red/...`。 |
| `bin/js/_prodmerge.js` | 历史临时合并脚本，含旧绝对路径 `/Users/red/...`。 |

接手建议：正式生产先走网页启动器，不要把 `_prodrun/_prodmerge` 当成可直接复用的主工具。
