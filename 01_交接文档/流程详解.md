# 关卡生成流程详解（v338 现状）

> 面向"想看懂这个工具怎么运转"的说明。括号里是代码里的函数名，方便对照。
> 一关的真实账本（40×40 / 容量 30~70 / 3 分钟档）：
> **造盘 93 个 → 精算 53 个 → 求解 80 次 → 39 秒**，其中 75% 的时间花在求解。

---

## 0. 触发与并行

```
界面「批量生产」 → 线程池（每线程一个 Worker）
                → 每张图派一个任务 → 生成一关 → 落盘 → 领下一张
```

- 线程数 = min(界面设定, CPU 核数, 图数)
- 每关有看门狗：`每图搜索时间 + 4 分钟`没返回就判卡死跳过

---

## 1. 参数装配（`genApplyFixed`，在 app.js）

这一步把"你填的几个数"变成"这一关的完整配置"。顺序很重要：

```
① 读界面     球容量区间 30~70 / 覆盖率门槛 / 每图搜索时间 / 主死因
② 套预设     FIXED_PRESETS（小图 24~36、大图 40~60）
③ 覆盖回来   第 ② 步会把用户填的值盖掉 → 这里再写回用户值
④ 定棋盘范围  按像素数：<1300px → 4~6 行 × 6~8 列；≥1300 → 4~7 行 × 6~9 列
⑤ 搜索计划    搜索时间 → 轮数 × 单轮预算（3 分钟 = 4 轮 × 45 秒），候选上限 14
⑥ 定死开关    generatorFlow='old'（旧流程）、targetCarCount=0（不按目标车数拆车）
              capNormMin/Max = 用户容量区间（归一化也用这个）
```

> **坑 1**：预设合并写成了 `Object.assign({}, cfg, preset, {...})`，`preset` 在后面会盖掉用户值，
> 所以第 ③ 步的"写回"是必须的，历史上漏过一次。

---

## 2. 多轮产线（`produceDispatch`）

一张图不是造一次，是**造 K 轮**，每轮换一套"结构组合"，最后挑最好的一关：

| 轮次 | 结构组合 | 含义 |
|---|---|---|
| 1 | 0/0/0 | 基线 |
| 2 | 2/2/0 | 摆放滞后 2 + 容量序列 2 |
| 3 | 0/2/2 | 容量序列 + 按块切 |
| … | … | 8 种组合轮换 |

每轮流程：

```
produce(blocks, _cfg)   ← 单轮：造若干候选、评估、择优（见第 3~5 节）
   ↓ 结果
portfolioTuple() 打分 → portfolioBetter() 比较 → 保留最好
   ↓
meetsEarlyStopQuality() → 达标就提前结束整张图
```

比较顺序（`portfolioBetter`）：

```
可解 > 违规条数少 > 覆盖率高 > 目标分近 > 压力更持久
```

> **坑 2**：`applyFillRatio()` 会顺手写 `cfg.targetCarCount = 格数 × 填满率 ≈ 46`。
> 旧流程的棋盘是按盒数反推的，不该再按"目标车数"拆车 —— 否则 60 的车会被对半拆成 30。
> v337 起：调用完立刻清零。

## 3. 造一关：切球 → 选盘 → 障碍 → 放车

### 3.1 分盒 / 切球（`pickBoxSplit` → `baseFillBoxes`）

**目标：把每种颜色的像素，切成若干"车"，每辆车容量落在 [下限, 上限] 之间。**

```
对每个颜色（单独处理，不能跨色合并）：
  T = 该色总像素
  T ≥ 上限  → 一辆辆按【上限】封箱：60, 60, 60 …
  T < 上限  → 整车一辆（容量 = T）
  收尾余数 < 下限 → 和最后一辆平分（493 = 7×60 + 13 → 73 平分 → 37 / 36）

切完再归一化（normalizeCapacities）：
  超过上限的 → 对半拆
  低于下限的 → 并入同色其它车
```

典型结果（30~60，色 493）：`60,60,60,60,60,60,60,37,36`

> **坑 3**：这条链上有两个开关能把车悄悄拆碎：
> `targetCarCount`（按目标车数拆，会拆出 30）和 `capNormMax`（归一化上限设小了也会拆）。
> 现在两者都跟用户输入对齐（v337）。

### 3.2 选盘（`chooseBoardDimsFixed`）

**目标：挑一个行列，装得下所有车、形状不太长条、可用率够高。**

候选条件：

```
① 在范围里（4~7 行 × 6~9 列）
② 形态：列 − 行 ∈ {1,2}（不许正方形、不许 5×9 这种长条）
③ 配额：车数 ≈ 格数 × 86%（usableSpaceTarget）
④ 装得下优先：溢出 ≤0 的尺寸优先
⑤ 同样装得下 → 挑【最贴合】的（v338 前是随机，会挑到 48 格装 33 辆车）
⑥ 选完再收紧：格数 − 车数 > 2 就缩（v338）
```

### 3.3 摆障碍（`buildBoard`）

按比例撒，配几何约束：

| 障碍 | 比例来源 | 约束 |
|---|---|---|
| 黑块（墙） | `blackPercent`（5%） | 不连成一条、优先压底部 |
| 数字冰 | `icePercent` + 按时差后处理 | 分散（最小间距 2）、第 0 行最多 1 块 |
| 锁链 | `chainCount`（2 组） | 组间不相邻、可激活 |
| 管道 | 由"车 − 格"的溢出量反推 | 每条深度 ≤6、口子朝可达方向 |

### 3.4 放车（填格子）

```
按"切球顺序"填格：先切的盒 → 先铺（行优先）
```

**关键事实：只有第 0 行开局可点。** 所以第 0 行 = 开局的全部菜单。
第 0 行全是"点了就能吃满"的车 → 开局零压力 → 覆盖率上不去。

### 3.5 事后修正

| 修正 | 做什么 |
|---|---|
| `applyIceSchedule` | 数字冰的值 = "这色需要它的时刻 − 现在能取的时刻"，不是随机数 |
| `diversifyRow0` | 第 0 行同色最多 2 辆 |
| `limitRow0Free` | 第 0 行最多留 2 辆"免费车"，其余换深层色 + 加冰 |
| `ensureBoardFull` | 有空洞 → 裁行 → 裁不动就补黑块（≤2 块） |

### 3.6 首解（`Solver.solve`）

**6 遍求解，任一遍通关即停**：贪心×2 → 三步树×2 → 噪声×2。

产出一条取盒序列 + 每一步的暂存占用（`pressureSamples`）。

解不开 → 进入重试循环（最多 5 次），每次**减负**：

```
黑块 ×0.85、冰 ×0.9、锁链 ×0.85、窄路提前撤
```

## 4. 评估（`evaluateGeneration`）

把"难度"量成四个数：

| 指标 | 怎么算 | 用途 |
|---|---|---|
| **覆盖率** `band3Pct` | 进度 30~80% 区间里，暂存 ≥3 的采样占比 | 主门槛 |
| **峰窗** `midLateMax` | 同一区间的暂存峰值 | 门槛 3.2~4.8 |
| **尖峰** `band4Pct` | 同区间里暂存 ≥4 的占比 | 可选门槛（默认关） |
| **玩家通关率** `playerPassPct` | 5 种手痒度 × 2 种子 = 10 局，不给复活 | 门槛 ≥25% |

顺带算**死因分布**（链/冰/管道/形状/断供），供"希望主死因"使用。

---

## 5. 六条门槛（`goodV3Of`）

```
① 可解
② 峰窗 ∈ 3.2~4.8
③ 稳健在区间
④ 覆盖率 ≥ 滑杆
⑤ 尖峰≥4 ≥ 5%      （默认关）
⑥ 玩家通关率 ≥ 25%
```

全过 = 合格；任意一条不过 = 记一条违规，继续换候选。

---

## 6. 不合格怎么办：卡点树（`makeChokeVariant`）

在**已有候选**上只改车，不动障碍：

```
分支（3）× 轮次（2）：
  ├─ 换球（约 60%）：把 A 车的球色换成 B 色 → 制造"这色怎么又来了"
  ├─ 增容（约 40%）：某辆车 +30 容量 → 制造"大车吃不下"
  └─ 重生成：改障碍比例（冰/黑/链）整盘重铺
每个变体都重新求解 + 重新评估
```

---

## 7. 兜底

```
不合格但超时 → 取"最接近"的那一关（先比违规条数，再比覆盖率）
峰窗出带     → bandFixOnce：冰 ±15% 再整轮产一次
连可解都没有 → 全灭兜底：宽松盘（填满 0.80、允许 2 条管道、只要求可解）
```

## 附：时间都花在哪

```
造 1 个盘            ≈ 3 毫秒
精算 1 个候选        ≈ 4.3 秒（21 次求解）
  ├─ 求解 6 遍       ≈ 3.5 秒
  ├─ 玩家 10 局      ≈ 0.9 秒
  └─ 其它            ≈ 0.1 秒
一关（3 分钟档）     ≈ 39 秒 ~ 180 秒（合格早停）
```

**造关几乎不花时间，贵的是"证明这关好不好"。**
