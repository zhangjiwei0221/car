# 生产方案 v300（按「求解器_原工程」的思想整理）

> 目的：把三个会话、几十个实验开关收成**一份可执行、可验证、可回退**的做法。
> 依据：`~/Downloads/求解器_原工程`（前辈的 v126 体系）+ 2026-10-19~20 的实测。

---

## 一、指导思想（照搬前辈）

```
造一批  →  审  →  不合格的定向补救  →  选优
```

四条原则，一条都不能少：

1. **合格 ≠ 难度**：审核只回答"能不能用"（可解 + 有卡点），难度分单独算。
2. **基础阶段不扰动**：建盘阶段只按参数摆放，**不做换球/换位**。
3. **不合格才补救**：候选没过审核，才动"换球（搬盒）/ 增容"。
4. **兜底三档**：合格 > 简单关（趋势过平）> 兜底（可解但无卡点）。

我们的附加项只有一个：**数字冰**（前辈没有），用法见第五节。

## 三、当前生效的参数（v300）

### 3.1 容量（决定"有多少免费车"）

```
capTie          : true      每色容量 ≥ 开局暴露量 / 2
capPerColor     : 2         开局每色最多装满 2 辆
capCeil         : 84        上限（72 会全灭，78~84 等价）
capNormalize    : true      同色内拆分/合并到 [0.6, 1.6]×均值
目标车数        : 格数 × 0.86
```

### 3.2 棋盘（决定"每辆车多大"）

```
彩色像素 < 1300 → 5×6 / 5×7 / 6×7 / 6×8
否则            → 6×7 / 7×7 / 6×8 / 7×8
形态约束        : 列 − 行 ∈ {1,2}
```

### 3.3 铺位（决定"每辆车什么时候被点到"）

```
入口            : 只认第 0 行（fillSeedsTopOnly = true）
顺序            : 按 demand 升序（早熟色靠前）
第 0 行同色     : ≤ 2 辆，超出与深层对调（diversifyRow0 兜底）
墙              : 全部压最后一行（wallBottomFirst）
```

### 3.4 障碍（决定"玩家能不能走捷径"）

```
数字冰          : 4 块，按"时差"取值（见第五节）
锁链            : 按色块大小配对（chainByDemand=4），自然配对，不硬凑
问号            : 6%
黑块            : 0（配额产生的墙除外）
```

## 五、数字冰：我们唯一的原创

前辈的冰是装饰（固定值、固定位置）。我们把它变成**时间锁**：

```
numice = 这辆车在接下来几个球之内不可用（全局倒计时，每取 1 个球减 1）
```

**正确的取值方式**：数字 = 时差 `r − s`（颜色够用时刻 − 被点到时刻）× 总车数，
夹在 2~12。这样它刚好在"颜色够了"的时候化开。

**错的用法**（都实测过）：
- 固定填 8 → 开局太短、中段太长，两头都不对；
- 锁开局免费车 → 锁 6 辆就 2/3 的 seed 死关（开局无车可吃）。

## 九、照搬原工程参数的实测结果（2026-10-20 补测）

用原工程 v120 的**制作参数**（容量 40~60、盘 7~9×8~10、黑块 5%、链 2、问号 8%、窄路开）在**本引擎**上跑：

| 方案 | 覆盖中位 | 最高 | 审核峰窗 | 容量范围 |
| --- | ---: | ---: | ---: | --- |
| 原工程 v120 参数 | 22% | 42% | 3 ~ 4.5 | 22~60 |
| **原参数 + 我们的数字冰** | **35%** | 48% | 3.5 ~ 4.5 | 22~60 |
| 现生产 bigcap（容量耦合） | **43%** | 86% | — | 10~86 |

### 结论

1. **数字冰是有效的**：同一套原参数，加冰 22% → 35%。
2. **原参数不用 capTie 也能出压力**（22~35%），且容量范围干净（22~60，没有 10 和 86）。
3. **但原参数的盘型（7×8~8×10）在本引擎里只能跑到 3~8%**——
   因为原工程有一套**"按实际盒数选盘型"**的算法（`chooseBoardDimsFixed`，见生成器逻辑体系 §2），
   我们没有移植。**只抄参数、不抄选盘算法，会差一截。**

### 所以要真正"照搬原工程思想"，缺的是这一块

```
原工程：先切盒（容量 40~60）→ 数出盒数 → 按 ov = 盒数 − (行列 − 黑块目标) 选盘型
我们：  先定盘（格数×0.86）→ 再按像素/车数反推容量 → 切盒
```

顺序是反的。**下一步应该是移植 `chooseBoardDimsFixed`**，而不是继续调参数。
