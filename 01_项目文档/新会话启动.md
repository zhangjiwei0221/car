## 4. 红线（摘自 `AGENTS.md`，全文以它为准）

1. 容量是用户输入：`sum(count) == 像素总数`（含管道队列），不许缩放/拆半；
2. 口径统一：一律 `--mode a --ref corner`；
3. 验证必须用真关卡 + 数字；
4. 不许用推理代替实测（已因此错过 ≥5 次）；
5. 改 js 先 `node --check`；
6. 客户端 bin 不许动；
7. 一次只动一件事，先 `git commit`；
8. 文档只收敛不新增；
9. 并行中间文件带 pid/uuid；
10. **改完必须更新 `工程说明` 与 `进度与下一步`**；
11. 需求文档只写“要什么”。

## 5. 已知的坑（别再试）

| 手段 | 结论 |
|---|---|
| 打碎目标图（1px/2px 打乱） | ❌ 画面不可辨认，用户否决 |
| 末段冰 / 末段大车 / 末段双开 | ❌ 不产生债务，峰值不变 |
| 墙 / 删车并容量 | ❌ 越删越糟 |
| 几何分带（按距离切条） | ❌ 玩家选颜色不选位置 |
| 延后闸门解锁 | ❌ 死锁（前一主体耗尽后无车可取） |
| 按碎片度挑官方图 | ❌ 与 at4 无相关 |
| 只换棋盘边界圈 | ❌ 可换对数不足 |
| 全图打碎目标图 | ❌ 画面不可辨认（用户否决） |
| 管道 | ⚠️ 会留下空格且不可补黑块；用前确认收益 ≥3 步 |
| 冰加在"单车辆颜色"上 | ❌ 直接不可通关（该色没有第二辆车能收） |

**已确认有效**：颜色按主体独占（目标感）、数字冰闸门（顺序）、`LayerByEdge` 分层（前松后紧）、`--buf-threshold`、死亡判定「结算后 ≥上限且无车装满才死」。
