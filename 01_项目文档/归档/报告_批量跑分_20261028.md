# 批量跑分报告（2026-10-28，20 张官方图）

## 结论先说

> **成功率 0/20 = 0%**（判定标准：at4≥20 且 run4≥12 且 峰值≤4 且 审核通过 且 容量守恒）

- **容量守恒：20/20 全过**（`SplitLevel_v722` 可靠）；
- **峰值：20/20 都是 4**（不触顶）；
- **卡住的是审核与 at4**：16 张“审核不过”、4 张“at4 不足”。

所以“稳不稳定”的答案是：**当前这条流水线还不能稳定产出合格关**。

## 根因

`OverlapBuild_v719` 的目标函数是 **最长低压段 + 低压步总数**，
它**不知道审核要求“前 30% 不许有峰窗≥3.2”**，所以把债造在最容易的位置——开头。

## 正在验证的修法

给构建器加 `--no-early K`（前 K 步不许 buffer≥4），对上面 12 张重跑，
看能否把“审核不过”转成“通过”。（后台运行中）

## 筛图器（ImageFilter_v725）：用“2 轮快速探测”预判

### 为什么不用静态特征

flat 关（无障碍）= 天然没压力，20 张图的 `flatAt4` 全是 0 → **静态特征无法预判**。

### 改用“快速探测”

先跑 **2 轮构建**（约 1 分钟），看能到多少 at4；`at4 ≥ 10` 才继续跑满 4–5 轮。

### 验证（6 张已知结果的图）

| 图 | 2 轮探测 at4 | 跑满后 at4 | 真实结果 | 探测判断 |
|---|---:|---:|---|---|
| 00071 | 25 | 28 | PASS | 保留 ✅ |
| 00111 | 33 | 36 | PASS | 保留 ✅ |
| 00171 | 25 | 30 | PASS | 保留 ✅ |
| 00041 | 0 | 2 | FAIL | 丢弃 ✅ |
| 00181 | 1 | 4 | FAIL | 丢弃 ✅ |
| 00091 | 0 | 9 | FAIL | 丢弃 ✅ |

**6/6 全对**（阈值 at4≥10）：3 个 PASS 全保留，3 个 FAIL 全挡住。

### 命令

```bash
node 03_工具/正式版/ImageFilter_v725.js --dir 关卡 --n 20 --probe 2 --min-at4 10 --json 输出/筛图特征_probe.json
```

20 张全量验证正在跑。

### 筛图器全量验证（20 张，对照第一轮真实结果）

阈值 `at4 ≥ 10`：

| 指标 | 结果 |
|---|---|
| 保留 | 7/20（省掉 13 张 = **65% 的构建时间**） |
| 保留者中真 PASS | **3 / 3（全中）** |
| 被误丢的真 PASS | **0** |
| 精度 / 召回 | 43% / **100%** |

保留下来的 7 张：00071(25)*、00111(33)*、00171(25)* + 00001(16)、00021(17)、00151(16)、00161(10)
（打 * 的是真 PASS；其余 4 张是“擦线”图：at4 18–21、run4 7–11）

**阈值换成 `at4 ≥ 20` 时：保留 3 张、3 张全 PASS，精度 100%、召回 100%。**

### 结论

筛图器可用：
- **保守用法**：`--min-at4 20` → 只跑有把握的图，零浪费；
- **宽松用法**：`--min-at4 10` → 保留擦线图，交给构建器再爬。

已接入 `BatchScore_v723 --probe-min <N>`：先 1 分钟探测，不达标直接跳过。
