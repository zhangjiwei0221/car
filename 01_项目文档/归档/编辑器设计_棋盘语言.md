# 编辑器设计：把棋盘当语言来写

> 用户提问（2026-10-28）：“不能通过利用障碍和车子的阻挡关系控制他们的棋盘语言，
> 从而引导玩家的行为吗？帮我发散性地思考这种游戏编辑器怎么做。”
>
> 这份文档是发散稿：先给模型，再给“词法/句法/篇章”，最后给编辑器该长什么样。

## 1. 模型：关卡 = 时间展开的可达图

把棋盘想成一张**随时间变化的图**：

- 节点：每辆车（颜色 + 容量 + 位置）、每个目标区域；
- 边：`可达`（这辆车现在能不能点）、`消费`（点了会吃掉哪些区域）、`揭示`（吃掉后打开哪些区域）；
- 时间：玩家的第 t 次取车。

玩家在 t 时刻能做什么，只取决于：**当前可点集合** × **每色当前可用像素**。
- 可点集合由**几何**决定（黑块/管道/冰/位置）；
- 每色可用像素由**已揭示区域**决定（车序 + 目标图 vein）。

**障碍 = 编辑这张图的三类操作**：

| 操作 | 手段 | 改的是 |
|---|---|---|
| 静态删点/删边 | 黑块、管道占格 | 可点集合（永久） |
| 动态删点 | 数字冰（param=全局球数） | 可点集合（时间窗） |
| 加依赖边 | 管道队列（出口空才吐） | 动作的先后关系 |
| 合并节点 | 锁链 | 动作粒度（一次取 2–3 辆） |
| 改需求 | 容量重分配 | 每辆车要多少像素（债的大小） |
| 隐藏信息 | 问号 | 玩家的信念，不影响可解性 |

所以“引导玩家”= 让**预期动作序列**在这张图上成为“最省力路径”，其他路径要么更贵、要么被删掉。

## 2. 词法：每种障碍是一种“语法标记”

| 障碍 | 语义 | 玩家感受 |
|---|---|---|
| 锁链 | **和（AND）**：这几辆必须一起拿 | “我点了它，怎么还欠着？” |
| 管道 | **之后（AFTER）**：出口空了才给 | “得先把那个位置清出来” |
| 数字冰 | **等（WAIT）**：N 球之后才解冻 | “这辆现在不能碰” |
| 黑块 | **无（NOT）**：这条路不存在 | “过不去” |
| 问号 | **？（UNKNOWN）**：颜色未知 | “要不要赌一把” |
| 容量差 | **欠（DEBT）**：先拿一部分，剩下的欠着 | “先拿着，等颜色齐了再还” |
| 位置 | **远近（DISTANCE）**：在走廊的哪一段 | “够不着/够得着” |

一句话：**链=和、管=之后、冰=等、黑=无、问号=问、容量=欠、位置=远近。**

## 3. 句法：五个“句型”= 五个节拍

| 句型 | 写法 | 例子 |
|---|---|---|
| 教学句 | 一辆能吃完的车 + 它打开的区域 | 开局 2–3 步免费 |
| 债务句 | 链(便宜车, 晚解锁车) | 006 的 `(5,5)+(6,5)` |
| 释放句 | 晚解锁车的颜色区终于开到 | 还款那几步 |
| 变奏句 | 换一种颜色重复债务句 | 第二段平台 |
| 收尾句 | 冰/管把最后一辆扣到末段 | 尾段 }

**关键规则：债务句和释放句必须“交叠”——上一句还没还完，下一句就要开始**，否则就是 v58 的 11 步空窗。

## 4. 篇章：怎么让句子交叠（可算）

1. 用“解锁表”给每辆车标 `unlock(car)`＝该颜色第几步够它的容量；
2. 债务句选 `unlock` 晚的车做“锁芯”，配一辆 `unlock` 早的车做“被扣的便宜车”；
3. 下一句的**入场步**要 ≤ 上一句的**释放步**（交叠），否则加一句“过渡句”（小债）；
4. 过渡句的写法：链(两辆 unlock 差 5–8 的车)，或管道(把某辆晚解锁车放队列，出口在上一句末尾)。

## 5. 编辑器该长什么样（四层）

### 5.1 剧本层（用户直接编辑）
- 拖 5 个节拍块，每块填：**预期可点色、预期欠多少、预期何时还、允许几条恢复路线**；
- 每块显示“当前是否成立”（绿/黄/红），红的地方点一下给修复建议。

### 5.2 依赖层（自动）
- 目标图 → 区域图 → 车序 → 消费/揭示边（已有 E2 工具）；
- 每辆车自动得到角色：`教学/债务/释放/诱饵/收尾`。

### 5.3 棋盘层（半自动）
- 用户画走廊（哪些格子连通）；
- 系统按“句型”自动落链/管/冰/黑，并给出“为什么放这里”的一句话理由；
- 每个障碍可点开看：**它挡的是谁、解锁的是谁、移除后哪句塌**。

### 5.4 验证层（一键）
- 全知参考解：步数、每步 buffer、每笔债的进入/释放；
- 对抗解：免费优先、避债优先、寻债优先、行/列优先——**每句是否都撞墙**；
- 可行性：每个链组是否真能释放（解锁表）；
- 输出一张“句子表”：每句的开始/结束/压力/是否交叠。

## 6. 可尝试的七个“新句型”（发散）

1. **门（gate）**：管道出口放在另一条走廊尽头 → 两种颜色被迫串行；
2. **岔路（fork）**：两条走廊，一条冰门晚开 → 玩家选“先难后易”还是“先易后难”；
3. **回声（echo）**：同一颜色前后各来一次（锚点切盒天然有）→ 第一次免费、第二次欠债；
4. **诱饵（bait）**：一辆大免费车，吃了它就把后面的关键区吃掉 → 贪心玩家吃亏；
5. **沙漏（hourglass）**：冰的 param 精确设在“玩家刚好还完上一笔债”的那一步 → 无缝续压；
6. **多层锁（stack）**：同一条走廊同时用 链+管+冰，制造三段递进；
7. **双钥匙（two-key）**：两辆不同色的晚解锁车绑在一起，必须同时满足两种颜色才能放 → 长承诺。

## 7. 我们现在缺的那一步

我们有“测量”（git 里那堆 Audit/Measure），有“事后分析”（故事线复盘），
但**没有“从意图编译到棋盘”的那一步**：

> 输入：句子表（每句的预期步数、债、释放）
> 输出：车的位置、链组、管道、冰参数

这一步是编辑器的核心，也是“脚本不灵活”的根源——
它不是搜索，而是**约束求解**：在“容量守恒 + 每色可拆 + 走廊连通”的约束下，
解出一组摆法，使每句的“入场步/释放步”落在给定窗口里。

## 8. 下一步建议（按性价比）

1. **先做“句子表 → 验证”**（半天）：把当前关卡的曲线自动切句，标出每句是否交叠；
2. **再做“交叠修复器”**（1–2 天）：对每个空窗，按解锁表建议“加哪一句”；
3. **最后做“从句子反解棋盘”**（重）：约束求解器。

前两步就能把“空窗”问题变成“可诊断、可修”的问题，不需要重写生成器。
