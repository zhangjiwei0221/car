# 产线 v1.5 计划：按可达性建造（2026-11-10）

> **状态：已停止（2026-11-11 用户决定）。** 本文保留为实验记录，不再继续 CarSplitPlan/PlacementPlan/批量；v1 仍是现役，v3 是“更清楚造关”的实验层。

> **定位**：v1.5 不是新的入口模式产线，也不是 v3/v4 的替代；它是 **v1 的建造层升级**。
> 输出仍是标准关卡 JSON，交给 v3 验收，也可以给 v4 的 bottom-only 模式使用。
> **一句话**：v1 先造再验；v1.5 先算 reach，再决定切车、摆位、障碍。

---

## 0. 为什么不是“继续修 v1”

v3 反复证明了三件事：

1. **容量 > 还款前可达 = 死**；这不是调冰能救的。
2. **链组是整组判定**：任一成员容量 > 入场步可达，整组必死。L3 的 `28:98/19:54/30:54` 在第 2 步 19 可达 0、28 可达 76，后面怎么修都只能在“能玩但平”和“保压力但不可通”之间二选一。
3. **局部修只改症状**：L5/L10 点击结算变好，但 PlayerSim p2 反而退步；G8_57 can✓ 但 C0=1，单旋钮修不掉。

所以 v1.5 要改的不是参数，是**建造顺序**：

> 先把“这个颜色什么时候可达、这辆车最晚什么时候必须还”算出来，再决定车多大、放哪、和谁成链。

## 1. v1.5 的建造流程

```
0. 输入：目标图 + 入口模式（fourSide / bottomOnly）
1. Reach 时间线：每个颜色在第 1..N 步的可达量
2. 债分配：每色拆几辆、每辆多大；容量 ≤ 该车最晚还款前的 reach
3. 摆位：按“希望暴露的步”排 row0 / 浅格 / 深格
4. 障碍：链组只选“入场步可达够”的成员；管道补晚段；冰做时间门
5. 开局：open≥5、C0=0、F0<3
6. 中段：链/管道/晚段大车，mid 45–80
7. 验收：v3 硬门 + PlayerSim；不过回到 2/3/4，不先加冰
```

### 1.1 Reach 时间线

- 用现有 `ReachabilityCurve_v1` / `ReachPlan_v1` / `CapacityReachCheck_v1` 的语义；
- 对每个颜色输出 `reach[color][step]`；
- 因为路线会变，先算**保守下界**和**乐观上界**两条；建造用下界，验收用实际路线；
- 关键量：`latestSafeFill[color]` = 该颜色最晚在哪一步之前必须把车填满。

### 1.2 债分配

- 每色总像素固定（红线）；
- 大车容量 ≤ `reach[color][latestSafeFill]`；
- 小车用于开局/恢复，不能是 3–5px 碎车；
- 多车色用“大+小”，不要平均切；
- 链组成员额外约束：`count ≤ reach[color][chainEntryStep]`。

### 1.3 摆位

- row0：放便宜/能吃完的车，保证 open≥5；
- 浅格：放中段债，保证 mid 有压力；
- 深格：放 late debt / 缓解；
- 内格不放普通车（会堵求解器），只放管道/黑块；
- 链组必须正交相邻，且成员在入场步可达。

### 1.4 障碍

- 链：先选“入场步可达够”的颜色，再决定组；不能先定组再修容量；
- 管道：晚段供给/顺序杠杆，队列算容量守恒；
- 冰：时间门，参数按目标窗口推，不搬图；
- 黑块：不制造不可达内格。

### 1.5 开局 / 中段

- 开局：`open≥5`、`C0=0`、`F0<3`；
- 中段：`mid 45–80`，用链/管道/晚段大车，不靠加冰硬推；
- 目标不是 D 低，是“有压力但可恢复”。

### 3.1 SeedGate（先于 ArlCheck）

不通过就不进全量检查：

- 逐色容量守恒；
- 无空格 / 管道队列合法；
- 每辆车容量 ≤ 最晚还款前 reach；
- 每个链组成员容量 ≤ 入场步 reach；
- 开局估算 open≥5；
- 没有“0 可达颜色”进入早期链组。

## 11. v1.5 与 v1 的关系（取代条件）

**v1.5 不整体取代 v1。** 它只取代 v1 的**初始建造层**：切车、摆位、链组/管道落位。目标图契约、容量守恒、输出 JSON、v3/v4 验收都沿用。

### 当前阶段

- v1 仍是默认候选生成器；
- v1.5 只完成链组窗口（M2c），切车/摆位仍是 v1 产物；
- 候选 1 过 v1.5 硬门，但视觉结构不干净（底行碎车、30:35 堆积），**不能作为“v1.5 取代 v1”的证据**。

### 什么时候可以让 v1.5 成为默认

必须同时满足：

1. **两张不同图**（G8_40 + G8_57/G8_43）都能出候选；
2. 每张至少 3 个候选，过 v1.5 硬门（can/peak/open/C0/F0/点击/PlayerSim p2/layout）；
3. 视觉结构干净：无尾料碎车堆、无同色连≥6、30 色大块不再 10 辆挤在一起；
4. 与 v1 同图对比：v1.5 在 mid/选择空间/PlayerSim 至少一项更好，且不牺牲 can。

满足后：v1.5 成为新图的默认建造层；v1 保留用于旧图和 fallback。
