## 1. 阶段目标

E4不从“冰12个、链6组”开始，而是从剧情节拍推导障碍：

```text
StoryBeat
→ 缺失的故事能力
→ 选择一种语义机制
→ 绑定车辆/区域/时序
→ 完整验证
→ 移除消融
```

没有明确故事能力的关卡允许0障碍。

## 2. 障碍角色

| 角色 | 机制候选 | 目标 |
|---|---|---|
| delay | 数字冰、管道 | 让动作在当前节拍前不可用 |
| bind | 2/3连锁链 | 形成共同承诺与共同释放 |
| reveal | 管道、空间包裹 | 分阶段揭示关键区域 |
| shape | 黑块、棋位 | 阻挡旁路或塑造方向 |
| obscure | 问号 | 在前后有线索时增加推理 |

## 3. 每个障碍必须记录

```text
beatId
role
mechanism
targetCars
targetZones
expectedPlayerEffect
removalPrediction
actualRemovalResult
```

## 4. E4里程碑

### E4.1 语义障碍 Schema

建立独立JSON格式，能表达：

- 节拍绑定；
- 机制和参数；
- 目标车辆/格子；
- 预期玩家行为；
- 移除后应发生的变化。

退出：

- 不把数量配额写入Schema；
- 每个障碍必须有角色和移除预测；
- Schema可被编译器读取。

结果：完成。

### E4.2 delayedGate · 数字冰

首个实例：

```text
beatId: second_group_gate
role: delay
mechanism: numice
```

目标：

- 第一组完成前锁住第二组；
- 第一次短释放后开放第二债务；
- 第二次短释放后开放支持车辆；
- 移除冰后可见选择明显变宽。

退出：

- 全知/PlayerSim核心故事不变；
- 债务/释放、R59/R65和终局不变；
- 移除消融证明顺序可读性受影响；
- 记录自动路线是否改变。

结果：完成。可见选项5/5→1/2，路线和终局不变。

### E4.3 groupDebt · 锁链

寻找或构造一个2/3连锁组：

- 至少一辆可立即收满；
- 至少一辆留下债务；
- 整组共同滞留；
- 后续区域或车辆释放整组；
- 移除链后该共同承诺消失。

结果：完成。(0,1)15/24 + (0,0)17/26形成2连组；
15完成、17欠10，31/30下一手释放；无链六步变有链五步。

### E4.4 reveal · 管道

仅当剧情需要“暂存供给、之后揭示”时生成：

- 管道queue与目标像素守恒；
- 关键区域不得在计划前暴露；
- 移除管道后节拍提前或消失。

结果：本轮否决，没有独立故事职责。

### E4.5 shape · 黑块

- 当前两个结构黑块先纳入语义Schema；
- 移除后必须改变旁路或释放口可读性；
- 不补洞、不造墙。

结果：通过。移除两黑块后仍可通关，但全知与玩家计划路线均改变。

### E4.6 obscure · 问号

- 仅在有前后线索时试验；
- 隐藏答案不能是唯一可恢复手段；
- 若只增加背板成本，则否决。

结果：否决，没有可推断线索。

### E4.7 综合消融

对每个机制分别移除：

- 路线是否仍成立；
- 玩家可见选择是否改变；
- 故事节拍是否错位；
- 是否只是装饰；
- 是否可与其他障碍互相替代。

结果：完成。冰+链+黑块组合通过，管道/问号0。

## 5. E4退出条件

1. 每个实际障碍都有beat/role/effect/ablation；
2. 删除关键障碍会改变对应故事或可见选择；

4. 机制组合通过容量、可解、区域和0复活PlayerSim；

6. 无法证明必要的障碍被删除；
7. E4结果仍是实验产物，不自动接入生产。
