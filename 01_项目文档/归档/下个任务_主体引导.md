# 下个任务：目标图“主体引导”（从内部掏）

> 交接说明：这是 2026-10-28 讨论后确定的下一个课题。
> 新会话请先读本文件，再读 `关卡流程_当前.md` 与 `主体与引导_设计.md`。

## 1. 背景（用户原话要点）

- 目标图由**图案主体 + 过渡色**构成；
- 某个非背景色 A 全图都有一点，背景褪去后小车吸收很分散 →
  **玩家整体上在赌能不能收满**；
- 玩家不会去数像素，但**从一个主体开始会有专注感**，而不是看全图；
- 所以要**控制每个主体的包围色（壳色）**，才能做到“从目标图某个地方开始消”。

## 2. 目标

让关卡呈现“**先开某个主体的壳 → 掏空这个主体 → 再下一个**”的节奏，
而不是“全图散着吸、赌能不能满”。

## 3. 已经做过的分析与结论（可直接复用）

### 3.1 “赌”的量化

对每色：像素总量 / 连通区数 / 最大连通区。
- `容量 ≤ 最大连通区` → 确定（能在一处吃完）；
- `容量 > 最大连通区` → 赌，跨区数 = `ceil(容量 / 最大区)`。

## 5. 待做（建议顺序）

### 第 1 步：壳唯一化（先做一个主体）
1. 选 **006 的电视：内 28 / 壳 33**（33 只出现在它周围，重复最少）；
2. 在目标图像素矩阵里把这块的壳换成**全局唯一色**（选一个当前没用或极少用的色号）；
3. 用 `GenAnchorCut_v711.js` 重切，确认 `sum == 1225`；
4. 首测：`MeasurePageOmni_v715` / `Validate006Level_v706 --audit` / `SentenceTable_v717`。

### 第 2 步：验收“开壳”指标
新增（或手算）两个指标：
- **开壳步**：该主体壳色第一次被消掉的步数（目标：≤5 步）；
- **掏空步**：该主体内部第一次被吃到 ≤50% 的步数（目标：开壳后 ≤4 步）。

### 第 3 步：分级容量（A/B/C）
- A 确定性：主体色车容量 ≤ 最大区；
- B 预算：过渡色车容量压到 ≤ 最大区（能压多少压多少）；
- C 允许赌：剩余过渡色车放非关键路径。
约束：同色容量总和不变（守恒）、[20,40]（006 合同）。

### 第 4 步：把“主体节奏”写进句子表
- 每个债务句对应“开一个壳”，每个释放句对应“掏空一个主体”；
- 用 `SentenceTable_v717` 检查交叠，`OverlapBuild_v719` 修空窗。

## 6. 验收标准（缺一不可）

1. 选定的主体：开壳步 ≤5、掏空步 ≤开壳+4；
2. 壳色唯一（`SubjectAudit` 报 ✅）；
3. 压力不倒退：at4 ≥ 当前版本、空窗 ≤1、峰值 ≤4；
4. 不用道具可解（no-item `runSolver` 通关）、CLI 可解；
5. 容量守恒。

## 7. 已知硬约束（别重复踩）

- **006 不可能“全确定”**：白 304px / 最大区 23 → 需 ≥14 辆白车，棋盘 49 格放不下；
- **末段长平台不可能**：像素=容量精确守恒，最后一辆必然填满（见 `关卡流程_当前.md` §7）；
- **位置不控制曝露**：整片重排会让峰值掉到 3（v50 教训）；
- 改目标图 = 改容量合同 = 之前所有版本要重测。
