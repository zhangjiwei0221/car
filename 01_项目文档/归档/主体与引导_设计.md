# 主体与引导：从“吸得散”到“从内部掏”

> 用户观察（2026-10-28）：
> 目标图由“图案主体 + 过渡色”构成。某个非背景色 A 全图都有一点，
> 背景褪去后小车吸收会很分散，玩家整体上在赌能不能收满。
> 想从一两个主体入手（“从内部掏”），涉及两件事：
> ① 主体由什么颜色/轮廓构成；② 包围主体的背景或框是什么颜色，
> 会不会和别的主体重复、导致不能按想要的路线走。

## 1. 把“赌”变成数字

对每个颜色算三个量：像素总量、连通区数、**最大连通区**。

一辆车要收满，若 `容量 ≤ 最大连通区` → 它总能在一处吃完（**确定**）；
若 `容量 > 最大连通区` → 必须跨区收集（**赌**），跨区数 = `ceil(容量 / 最大区)`。

## 2. “从内部掏”的设计含义

主体 = **区数少、最大区占比高**的颜色。它像一个“池子”：
- 包围它的颜色是“壳”，壳没开，池子进不去；
- 壳一开，池子是一整块，玩家能算清“还差多少”。

所以引导 = **先定主体与壳，再谈车**：

1. 选 1–2 个主体（如 006 的 28/4、00199 的 32/31）；
2. 主体的**壳色必须唯一**（不和别的主体共用），否则开口会串味；
3. 主体色的车容量 ≤ 最大区 → 确定性；
4. 过渡色（31/30/5）当“预算”，容量压到 ≤ 最大区，让玩家少赌。

### 006 的壳色重复问题（实测）

主体候选里，**15 同时是“15”和“22”的包围色**（`15←15/22`）。
这意味着：开 15 的口子，会同时影响两个主体 → 路线会串。

## 3. 体检应该加的三项

`SubjectAudit_v720.js` 已实现：

1. **分散度表**：每色 像素/区数/最大区/最大占比 → 主体 vs 过渡；
2. **包围色唯一性**：主体候选的壳色有没有重复；
3. **车辆跨区检查**（配 `--level`）：每辆车需要几个区，列出“赌”的车。

## 4. 对容量合同的约束（重要）

“不赌”要求：`该色所有车的容量 ≤ 最大区`。

006 白（31）304px、最大区 23 → 至少要 `ceil(304/23)=14` 辆车才不赌；
现在棋盘 49 格（45 车）放不下 → **006 不可能做到“全确定”**。

所以只能分级：

| 级别 | 颜色 | 处理 |
|---|---|---|
| A 确定性 | 主体（28/4/21/13/15） | 容量 ≤ 最大区，作为骨架/债 |
| B 预算 | 过渡色（31/30/5） | 容量压到 ≤ 最大区，能压多少压多少 |
| C 允许赌 | 剩余过渡色车 | 放在非关键路径，明确告诉玩家“这辆要看运气” |
