## A. 当前实际链路（2026-10-30 更新）

### A.1 七步

```
① 选图       ← 我：看 GuideScan 排名 + 三条判据（见 A.2）
② 切车       ← SplitLevel_v722（容量守恒：sum(count) == 像素数）
③ 加基础障碍  ← OverlapBuild_v719（链/换位/容量互换/冰）
④ 按缺口配障碍 ← ObstaclePlan_v745（冰/墙/管道，自动选优，默认不允许空格）
⑤ 验收       ← Validate006Level_v706 + DamageCurve_v739
⑥ 判定       ← 我：at4 / run4 / late4 / 峰值 / 审核 / 阶梯
⑦ 落盘       ← 关卡文件 + 试玩页 + 日志一节
```

### A.2 选图三条判据（缺一不可）

1. **四象限齐全**：四个象限都有“独占色”（只在该象限出现的颜色），否则无法量引导；
2. **首手落左下**：corner 规则下，第一手消除的像素**只落在左下象限**
   （扫法：`GuideScan_corner` 之后逐张跑首手；216 张里 49 张满足）；
3. **阶梯跨度 ≥ 30**：第二个主体比第一个晚 ≥ 8 步。

> 参考：`输出/首手落左下_49张.json`（49 张候选）、`输出/引导候选_corner全.json`（按跨度排序）。

### A.3 指标缺口 → 用哪个障碍（决策树）

| 症状 | 先试 | 命令 |
|---|---|---|
| **at4 < 20**（前中段松） | **墙**（≤2 块），不行再**管道** | `WallSearch_v742` / `PipePair_v744` |
| **late4 < 4**（后段空） | **冰**（≤3 块，只加在链组成员上） | `LateIceSearch_v743 --chain-only` |
| 两者都缺 | **先空间类**（墙/管道），**再时间类**（冰） | `ObstaclePlan_v745 --all-pairs` |
| 峰值 = 5 | 减一个障碍 / 换图 | — |
| 不可解 | 换图（别硬调） | — |
| 阶梯跨度掉 > 5 | 否决这组障碍 | — |

**为什么“先墙后冰”**：实测 00041 先墙后冰 at4=31，先冰后墙只有 21（墙改变车数后，冰才锁得准）。

### A.4 验收清单（全过才算成品）

```
□ 容量守恒：sum(count) + 管道队列 == 像素数
□ 无道具可解、峰值 ≤ 4
□ at4 ≥ 20、run4 ≥ 12
□ 审核：允许早期卡点，但 30%–100% 必须有一个卡点窗口
□ 引导：阶梯跨度 ≥ 25，第二主体 ≥ 第一 + 8
□ 棋盘上没有空格（有的话用 --no-empty 重建）
□ 归因：拿掉这个障碍后 at4 或 late4 掉 ≥ 3（否则判为“表演”，不计入设计）
```

### A.5 常见坑（都踩过）

| 坑 | 现象 | 对策 |
|---|---|---|
| 把空格涂黑 | at4 27→3（黑块不算“空”，管道不能吐球） | 构造阶段就 `--no-empty` |
| 障碍全上 | 0 个候选（峰值余量耗尽） | 每关 1–2 种，共享难度预算 |
| 用旧口径量 | 峰值被误判成 5 | `Validate --ref corner --mode a` |
| 单块冰硬加 | 不可解 147 / 无收益 159 | 冰必须上在**链组成员**上 |
| 冰加在空格图上 | 视觉混乱 | 拒绝空格 |

## 0. 定体验剧本（你 + 我）

先写清楚这关要玩家经历什么：

- 允许的恢复路线（玩家走错后还有没有救）。

产物：一张句子表（§1 的验收标准）。

## 1. 选图与体检（脚本）

工具：`TargetStoryAtlas`（区域/曝露）、自写体检脚本

看四件事：

1. **每色像素量**（有没有 <20 的碎色，决定容量合同）；
2. **最大连通区**（决定哪些车能一次吃完）；
3. **初始曝露**（开局有几种色可点）；
4. **顶部是不是单色带**（决定开局免不免费——00199 就是 13/28 双色带）。

## 2. 切盒（脚本）

工具：`GenAnchorCut_v711.js --cut trend|anchor`

- `trend`：趋势切，覆盖容易不全（要核 `sum == 总像素`）；
- `anchor`：锚点切，守恒好，但车容量会超上限（要放宽合同）。

验收：`sum(count) == 目标像素`，且每色可拆。

## 3. 容量合同（你拍板）

- 006：`[20,40]`；
- 00199：`[20,50]`（大色块多）；
- 00152/00022：`[6,50]`（有 6–18px 小色）。

红线：合同是输入，任何脚本不得自行缩放。

## 5. 建模与摆障碍（我 + 脚本）

### 5.1 解锁表（关键）

对每辆车算「解锁步」＝该色第几步才够它的容量。
- 解锁晚的 = 天然“锁芯”；
- 全程度不足的 = 永远还不掉的债（不能拿来当锁芯，会锁死）。

工具：`unlockTable`（在 `OverlapBuild_v719.js` / 临时脚本里）。

### 5.2 摆法（按句型）

| 句型 | 手段 |
|---|---|
| 教学句 | 开局 2–3 辆能吃完的车（别放冰） |
| 债务句 | 链(便宜车, 晚解锁车) |
| 释放句 | 让晚解锁车的颜色到位（不动） |
| 过渡句 | 链两辆 unlock 差 5–8 的车 |
| 收尾句 | 冰把最后一辆拖到最后（param=目标球数） |

### 5.3 自动构建（脚本）

`OverlapBuild_v719.js`：以“空窗最小 → at4 最大 → run4 最大”爬山，
移动类型：

- `memberswap`：链组成员与异色车交换「颜色+容量」→ 改释放节奏（最有效）；
- `posswap`：两辆非链车换位置 → 改出场顺序；
- `capmove/capswap`：同色容量转移/互换 → 改每辆要多少；
- `chain`：相邻两辆成链；
- `ice`：加数字冰（param=全局球数）。

## 6. 复诊与收口（脚本）

- `SentenceTable_v717.js`：句子表是否 0 空窗；
- `MeasurePageOmni_v715.js`：at4 / run4 / 道具；
- `Validate006Level_v706.js --audit`：产品审核；
- `GapRepair_v718.js`：若还有空窗，列出候选与结论（修得动/修不动）。

## 6.5 三件工具 = 三阶段计划（当前进度）

之前定过一个三步计划，这里对齐一下现状：

| 阶段 | 计划内容 | 现状 | 工具 |
|---|---|---|---|
| **第1步** | 句子表验证器：自动切句、标出哪句没交叠 | ✅ **完成** | `SentenceTable_v717.js` |
| **第2步** | 交叠修复器：按解锁表建议“补哪一句、放哪两辆” | ✅ **完成，但结论是“局部修补无效”** | `GapRepair_v718.js` |
| **第3步** | 从句子反解棋盘（约束求解） | ⚠️ **只做了收敛版** | `OverlapBuild_v719.js` |
| （未做） | 完整反解：给定句子窗口 → 解出车的位置 + 障碍 | ❌ 没做 | — |

### 三点说明

1. **第2步的“完成”是工具完成，不是问题解决**：
   它证明了 006 的 12 步空窗**没有任何单链/单冰能补上**，因此才有了第3步。
2. **第3步是“收敛版”**：
   只允许动 **车序 / 同色容量 / 链 / 冰**，棋盘与目标图不动；
   移动类型：`memberswap / posswap / capmove / capswap / chain / ice`；
   目标：空窗最小 → at4 最大 → run4 最大（可选尾段权重）。
3. **完整反解还没做**：
   那需要“给定 5 句的入场/释放窗口，解出位置与障碍”，属于约束求解，
   组合爆炸大、且需要把“走廊连通”“每色可拆”编码成约束——目前没有投入。

## 附：指标定义

| 指标 | 定义 | 怎么看 |
|---|---|---|
| `buffer` | 暂存区里“还没收满”的条目数 | 4 = 卡点；5 = 死亡边界 |
| `at4` | 全知路线里 buffer≥4 的采样步数 | 越大越有压力（006 v62=28/47） |
| `run4` | 最长的连续 buffer≥4 | 平台长度（006 v62=16） |
| `空窗` | 两次 buffer≥4 之间 buffer<3 的连续步数 | 0 = 压力不断档 |
| `免费步` | 收满、不欠债的取车步数 | 越少越“每一步都要想” |
| `免费前缀` | 全零债动作能走的最长前缀（beam） | 开局自由度 |
| `解锁步` | 某色第几步才够这辆车的容量 | 越晚越能当“锁芯” |
