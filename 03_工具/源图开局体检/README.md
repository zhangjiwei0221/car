# 源图「体检」—— 这张图能不能出"有选择"的关？能不能出"有压力"的关？

## 一句话

把目标图 `.txt` 丢进来，**一秒**出两个数：

1. **开局露出几种颜色** —— ≥5 色 = 开局就有分支；≤2 色 = 前段只能按唯一路线走，**跟你怎么调参数无关**（2026-10-15 逐条实测过，见 `01_交接文档/工作日志_20261012.md` 第十七节）。
2. **深层色储备**（2026-10-18 加）—— "≥3 层才露脸"的颜色有几个、占多少像素。**它决定切球层能不能做出长期债**：0 个 = 压力只能靠障碍；≥3 个 = 可以靠"车比货早到"做压力。

> 两个数一起看：开局色决定**有没有得选**，深层色决定**有没有得压**。
>
> ⚠ **深层色不能一票否决**：用户认可的"小鹿"（蚂蚁关卡_1791972704634）是 **0 个深层色**——
> 它的长债来自**容量**（车装不满、等后续像素），不来自层深。本判据只覆盖"层深型"长债；
> 0 个深层色只说明"切球层做不出层深型长债"，**不等于关卡不好**。

## 用法

```bash
# 单个文件
node 开局体检.js ../../04_素材与转换/截图转换/Level4_目标图_27x32.txt

# 一次体检一批（会多给一张汇总表）
node 开局体检.js 04_素材与转换/**/*.txt
```

Mac 上也可以**双击 `开局体检.command`**，或者把文件**直接拖到它上面**。

支持两种输入：目标图 `.txt`（空格/逗号分隔的色号矩阵）、以及带 `blocks` 的关卡 `.json`。

## 为什么看这一项

玩家每一步的可选项 = **【棋盘顶行的车】**（第 0 行恒可取）∩ **【目标图上当前暴露的颜色】**。

一辆车只有在"自己颜色的暴露像素 ≥ 这辆车的容量"时才吃得满；而"暴露" = **贴图边** 或 **邻接外部背景** —— 也就是**从画的外圈往里剥**。

所以：**整张剪影被一个颜色勾边包住**的图（比如那张蚂蚁关卡：24 号色包了一整圈，140 像素），剥掉外圈之前，里面所有颜色一个像素都不露面 → 开局能吃满的选项恒为 1~2，无论怎么调障碍比例、棋盘大小、可用空间容差、车容量，都改不动。

## 改图时怎么提这个数

* **在轮廓上开口**：让内层颜色在外圈"探出头"（哪怕几个像素，那一整块同色块就算暴露）。
* **把外框拆成几段不同颜色**：一条勾边线分成几种色，开局就有几种可吃。
* **让色块贴到图边**：贴图边的彩色像素天然算暴露（BUS 那几张 16×13 的图就是这么拿到 8 色的）。
* 顺带留意**每色暴露像素不要比车容量还小**：否则连唯一暴露的那一色都吃不饱（车容量下限在生成器里叫"盒容量"，10~40 就是 10~40 个像素）。

> 注意：本工具只看"图"。它不检查碎色率——那个用 `03_工具/像素画工具` 的报告，或生成器开工前的那道碎色闸门。
>
> 想验证"深色储备 → 峰窗"在**生产链路里**是不是也成立，用 `03_工具/拆图报告/真跑一关.js`：
> `node 真跑一关.js --cut-only <图.txt>`（只看切球层）或 `--fit-small`（小图适配、带障碍）。
