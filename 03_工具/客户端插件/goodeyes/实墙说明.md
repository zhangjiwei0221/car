# 「警示线实体化」说明（给开发讲）

## 一句话

把棋盘的上、左、右三边从"出口"改成"墙"，只保留底边作为唯一出口。

---

## 一、这个游戏原本怎么判断"小人能不能被选"

棋盘是一个像素矩阵，每个格子是一个小人（`TargetBlockElement`）。一个格子能不能被选中，取决于它**是否被挡住**，而"被挡住"的判定是：

> 从这一格出发，沿上/下/左/右四方向走，如果能走到**棋盘外面**，就算"能出去" → 不算被挡住 → 可以被选。

对应两个函数（`TargetBoard` 类）：

| 函数 | 作用 |
|---|---|
| `_canBlockReachExit(r, c, exitMap)` | 单点判断：四邻域里只要有一格越界（或 `exitMap` 为真），就认为能出去 |
| `_buildExitPathMap(passable)` | 预计算：把四条边上的格子标记为出口，再 BFS 扩散出"哪些格子能通到出口" |

四邻域是 `kDirections = {(0,1),(0,-1),(1,0),(-1,0)}`，所以四个方向的"越界"在代码里是四个独立判断：

```
nr < 0          → 越界（底边，因为内部 row 0 = 底部）
nr >= rows      → 越界（顶边）
nc < 0          → 越界（左边）
nc >= cols      → 越界（右边）
```

`_buildExitPathMap` 里的播种逻辑等价于：

```
if (row == 0 || col == 0 || col == cols-1 || row == rows-1) → 这个格子是出口
```

---

## 二、改成了什么

| 位置 | 改前 | 改后 |
|---|---|---|
| 底边 `nr < 0` | 出口 | **出口（保留）** |
| 顶边 `nr >= rows` | 出口 | 墙 |
| 左边 `nc < 0` | 出口 | 墙 |
| 右边 `nc >= cols` | 出口 | 墙 |
| 出口播种 `col == 0` | 是出口 | 不是 |
| 出口播种 `col == cols-1` | 是出口 | 不是 |
| 出口播种 `row == rows-1` | 是出口 | 不是 |
| 出口播种 `row == 0` | 是出口 | **是出口（保留）** |

效果：贴着上/左/右三边的像素小人，必须先等它"里面"的邻居被消掉、露出通往底边的通路，才会变成可选。

---

## 三、具体改在哪（6 个字节）

都在 `Contents/MacOS/ParkPassenger` 这个二进制里（基址 + 偏移）：

### 1) `_canBlockReachExit` @ 0x10030CBE0

| 地址 | 原字节 | 新字节 | 含义 |
|---|---|---|---|
| `0x10030CCA6` | `01` | `00` | `nr >= rows` 时返回的常量 true → false |
| `0x10030CCAA` | `01` | `00` | `nc < 0` 分支的默认值 true → false |
| `0x10030CCB8` | `01` | `00` | `nc >= cols` 分支的默认值 true → false |

> 底边的 `0x10030CC95`（`movb $1,-0x1`）不动。

### 2) `_buildExitPathMap` @ 0x10030C670

栈上变量：**`-0x8c` 是行号 `row`，`-0x90` 是列号 `col`**（这点很关键，第一次就是这里搞反的）。

| 地址 | 原字节 | 新字节 | 含义 |
|---|---|---|---|
| `0x10030C782` | `00` | `00` | `row == 0`（底边）：**保留**，不改 |
| `0x10030C793` | `00` | `ff` | `col == 0`（左边）：比较值改成 -1，永不成立 |
| `0x10030C7A7` | `01` | `00` | `subl $1, %edx` 改成 `subl $0`，使 `col == cols` 永不成立（右边） |
| `0x10030C7BF` | `01` | `00` | `subl $1, %ecx` 改成 `subl $0`，使 `row == rows` 永不成立（顶边） |

## 四、为什么不改游戏文件

这个规则**不是配置项**，是编译进二进制的。所以采用**运行时补丁**：

- 写一个 dylib（`libwall.dylib`）；
- 启动游戏时用 `DYLD_INSERT_LIBRARIES` 注入；
- dylib 构造时用 `mach_vm_protect(..., VM_PROT_COPY)` 拿到代码页写权限，改上面 6 个字节，再 `sys_icache_invalidate` 刷指令缓存；
- 游戏文件一个字节都不动 → **不带插件启动就是原样**，回退零成本。

启动方式：

```bash
# 正常启动（原版）
open ParkPassenger.app

# 带墙启动
cd "$APP/Contents/Resources"
DYLD_INSERT_LIBRARIES="/path/to/libwall.dylib" "$APP/Contents/MacOS/ParkPassenger"
```

现成脚本：`03_工具/客户端插件/goodeyes/启动_插件.command`（同时带墙 + 警示条）。

## 五、怎么验证

1. 日志 `/tmp/pp_wall.log` 应有 6 条 `patch ...`，地址形如 `0x102d15ca6`（= 基址 + 偏移）；
2. 游戏里进一关：上/左/右边缘的像素小人**不再一上来就能选**；底部的照常；
3. 反向验证：不带 `libwall.dylib` 启动，行为恢复原样。

## 六、踩过的两个坑（讲的时候可以提）

1. **变量搞反**：`_buildExitPathMap` 的循环里 `-0x8c` 是行、`-0x90` 是列。第一次把"行==0"当成左边关掉了，结果**底边被封、左边留口**，出现"明明有缺口却出不来"的现象。修正后正常。
2. **内部坐标是反的**：JSON 里的 `blocks` 是自顶向下，解析时做了 `rows-1-i` 翻转，所以**内部 `row 0` 才是底边**，`nr < 0` 才是"从底部出去"。

---

## 七、局限

- 墙在**棋格边界**（`rows`/`cols`）。如果图案没有铺满格子，图案和边界之间空出来的格子仍然可以走 —— 视觉上会看到"缺口"在图片边缘、但墙在外面。
- 如果要求"墙贴着图案边缘"，需要先算出图案的像素包围盒（非空格子的 min/max 行列），再把包围盒外的格子视为墙 —— 这是另一个改动，目前没做。
