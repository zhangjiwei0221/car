# 07 · 文档维护与版本发布规则

> 与 `.kiro/steering/codex-review-workflow.md`、两个 hook 一致。目的：让文档与代码/版本/产物长期对齐。

## 一、大项完成自动检查并同步

完成下列任一大项时，必须检查并同步**真正受影响**的当前正文、历版逻辑、总索引与版本记录：

- 求解器（选盒/贪心/前瞻/锁链/暂存/复活）；
- 生成器（建棋盘/铺盒/卡点分支/换球/障碍/管道）；
- 审核（合格标准/难度/兜底/候选选择/合格门）；
- 批量生产（Worker/停止/看门狗/导入导出/报告/演示）；
- 正式参数/字段/文件格式/版本发布流程。

按范围检查：`bin/文档/版本记录/更新记录.md`、`bin/文档/版本记录/生产器重构日志.md`、`bin/文档/说明文档/生成器逻辑体系.md`、`bin/文档/说明文档/生产器重构需求.md`、`bin/文档/说明文档/生产审核评分体系.md`、`bin/文档/说明文档/求解器算法逻辑.md`，以及本目录 `00`–`06`。**只更新真正受影响的**；未变动的不得伪造更新，应说明「已检查、无需更新」。

## 二、正式回执按需生成

- 只有用户明确表达（写入/提交回执、生成交接回执、准备给 Codex 审查等）时才生成正式回执。
- 完成大项、完成版本、修改代码、更新文档、Stop Hook 触发**都不**自动等同于生成回执。
- 文档同步与正式回执是两件独立事项，互不替代。

## 三、小任务（含「中途任务」）仍需同步

小任务若改变系统逻辑、公式、数据结构或工作流，仍需按第一节同步受影响文档；「中途任务」完成后在 `bin/文档/版本记录/生产器重构日志.md` 或当前大版本指定记录里加一条可追溯小项，大版本完成时汇入正式版本记录。

## 四、事实/待实现/实验/建议/历史必须分栏

- 文档中「当前正文」只写**当前正式在用**逻辑；
- 已批准待实现、实验规则、建议、历史逻辑分开标注；
- 结论标证据强度 E1/E2/E3/E4；不得用 E1 宣称功能已落实，也不得用 E2 宣称浏览器交互已验收。

## 五、每项历史逻辑的记录要求

记录：变更前后行为、变更原因、停用原因、恢复入口（对应备份/版本/代码位置）。历史逻辑**保留**，不被当前正文覆盖删除。

## 六、版本发布前一致性检查清单

发布新版本 vN 前逐项确认一致：

1. `bin/index.html` 全部 `?v=` 已 bump 到 vN（当前 11 处：1 CSS + 10 JS）；
2. `bin/文档/版本记录/更新记录.md` 顶部新增 vN 条目并移动「（当前）」标记；
3. `bin/文档/版本记录/生产器重构日志.md` 追加对应 P 阶段并注明「vN 发布」；
4. `备份/vN发布_bin_js/` 已建（含 bin/js + style.css + index.html.bak）；
5. 受影响的系统说明文档已按第一节同步；
6. 本目录 `00`/`01`/`03` 的「当前版本」已更新到 vN；
7. 验证结论如实记录（E3 静态 / E4 实机分开写，缺 E4 不写成已验收）。

## 六b、产物与需求的命名归档规范（2026-07-27 起）

- **输出文件命名**：`输出文件/` 下新产物统一 `<名称>_<月-日>`（只含月/日，如 `小像素关卡包_08-03`）；同日多批加序号后缀。详见 `输出文件/命名与归档规范.md`。
- **产物归档**：已完结产物就地归入 `输出文件/历史输出_<月-日>/`，只移动、不改内容、不再改名。
- **新需求**：一律写入 `codex助理/codex需求文档/`，用需求包格式 `需求包_<主题>_<YYYY-MM-DD>_<版本>/`（至少 00_任务总览 + 01_需求与验收）。
- **历史需求/审查归档**：归入 `codex助理/历史需求与审查_<月-日>/`，仅作追溯，不构成当前需求与授权。
- 归档或改名后，必须同步本目录 `04`/`05` 索引中的路径引用。

## 七、边界

- 文档同步**不授权**修改业务代码；系统说明/版本记录只能作为「当前已批准业务任务」的同步内容写入。
- `codex助理` 内交接 MD 属工作流文档例外，但不得被用来绕过业务代码写入审批。
- 不移动/删除/重命名备份与产物；不凭目录名断定产物正式性。
