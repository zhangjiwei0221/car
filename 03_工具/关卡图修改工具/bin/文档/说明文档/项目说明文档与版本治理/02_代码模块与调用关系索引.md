## 三、生产闭环调用链（每节点标文件·主函数，E2）

```
TXT 输入
  → 解析目标图        generator.blocksFromTXT / utils.parseLevel
  → 建棋盘            generator.generateFromBlocks → buildBoard（尺寸随机/黑墙窄路/守恒反推管道/顺序填球）
  → 首批障碍          buildBoard 内（问号+冰全填，锁链 50%）
  → 合法性门          generator.structuralDeadlockCheck（结构可达+无共用出口，不求解）
  → 快速/完整求解     solver.solve（六遍：greedy×2→tree×2→noise×2；基础首解可 greedyOnly）
                        └ 单步选盒 solver-strategy.pickBestMove（greedy/tree）
                        └ 机制     simulator.listMoves / applyPick / floodFillEliminate
  → 玩家模拟          playersim.run（含复活）
  → 审核与难度        analysis.chokepointAudit（合格档） + generator.computeDifficulty→analysis.difficulty（难度分）
  → 卡点分支与兜底    generator.produce（未合格→makeChokeVariant：chokeChainColorSwap/chokeSwap/chokeInflate + applyPressureAdjust；B×N 轮；candTier/candBetter 三档兜底）
  → 卡点类型抽取(v103) generator.produceFixed 每关调一次 pickChokeTypes(config, isBossSlot)
                        → 加权无放回抽 N 种【互不重合】类型（BOSS/普通分别配额），经 config._chokePlan
                          透传给 buildStructureCandidateFixed → planObstacleSlotsFixed（冰簇/问号簇/链簇/
                          chainIce/pipeChain）与卡点变体层（bigBox/swap/inflate）
                        └ 结构失败 → generateFromBlocksFixed 按风险序逐个摘掉聚集类型重试（chokeFallback）
                        └ 变体分支透传父候选 chokePlan/chokeStat；失败返回也带 chokePlan（避免归因盲区）
  → 生产前置闸门(v102) generator.produceFixed 在【生成候选之前】依次判定，超限即返回 level:null、不消耗时间预算：
                        ① [仅底部入口] checkBottomEntryFeasibility → bottomEntryInfeasible
                        ② [碎色]      checkFragmentGate → computeFragmentation（同色4连通+0-1BFS隔断
                           +eliminationOrder轮次做长期隔断过滤）→ fragmentGateBlocked
                        闸门不参与审核档次、不进难度分；fragmentMaxRate=0 时整段跳过
  → 批量结果          app.batchProduce → app.genSpawnPool（N 个 gen-worker 槽位，默认 6）
                        → 每槽 genSlotDispatch 领一关 → gen-worker 跑 produce → app.genOnResult
                        └ level 为 null（前置闸门拦截/候选全灭）→ genBuildRec 返回 gateBlocked 记录
                          → genOnResult 走【跳过】分支（非异常）→ 落库 status:'GATE_SKIPPED'
                          → 生产服务.classify 归 skipped（不计入异常数与不合格数）
  → 逐关落库(v94正式)  app.genPersistPayload → app.genPersistOne → POST /api/production/result
                        → 生产服务.persistResult（分类 classify + atomicWrite/appendLine）→ persisted=true
                        → app.genSlotSettle 释放该槽并领下一关（v101 起【按关独立】，不再全局串行；
                          写盘失败则该槽停住 + genRetryPersist 重试全部待重试关）
  → 批次续跑(v101)     POST /api/production/resume → 生产服务.resumeBatch（按 逐关记录.jsonl 重建
                        doneIndexes 与计数、签发新 batchToken）；服务重启/换 batchId 后可继续写同一批次目录
  → 批次收尾          app.finishBatch → POST /api/production/finish|stop（展示输出目录与计数，**不打整批 ZIP**）
  → 兜底模式(未连服务)  app.finishBatch → zip.create → app.genDownloadPending（手动下载，仅 file:// 等场景）
```

## 五、说明

- 求解器「策略 / 流程 / 机制」三层解耦：改策略只动 `solver-strategy.js`，`pickBestMove` 契约不变即可（E2）。
- 全知求解器与玩家模拟器共用 `simulator.js` 机制，差异只在信息量与决策口径（E2）。
- `levels.js` 当前仅 4 行，为历史示例入口的空桩，实际关卡来自导入/生成（E2）。
