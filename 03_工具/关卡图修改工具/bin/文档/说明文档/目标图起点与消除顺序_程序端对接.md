# 目标图起点与消除顺序 · 程序端对接说明

> 用途：交付给程序端，用于对齐「蚂蚁从哪里开始吃目标图像素」的口径。
> 依据：当前正式代码 v94，`bin/js/simulator.js` / `bin/js/utils.js` / `bin/js/solver.js`。
> 性质：逻辑说明文档，本文件不改任何代码。

---

## 0. 一句话结论

**起点不是固定的「目标区底部中间」，而是每个球一个起点，由它入场时占到的暂存槽位决定。**

程序端当前实现（所有块都用底部中间当起点算距离）与本项目求解器、玩家模拟、网页演示的口径**不一致**。这会导致同一关卡在两端算出不同的消除顺序，进而出现「求解器判可解、程序端打不通」或「暂存峰值不一致」。

---

## 1. 先分清两套坐标系

| 网格 | 数据 | 尺寸（典型） | 作用 |
|---|---|---|---|
| 棋盘 / 元素区 | `cells[r][c]` | 8~9 行 × 9~10 列 | 蚂蚁盒所在处，决定「能取哪个盒」 |
| 目标图 / 目标区 | `blocks[r][c]` + `eliminated[r][c]` | 55 × 55 | 像素消除处，决定「消掉哪些像素」 |

起点只作用在**目标图**上，棋盘取盒规则与本文无关。

坐标约定（重要）：数组 `r=0` 是**顶行**，`r=rows-1` 是**底行**。游戏语义上蚂蚁从底部进入，所以起点行恒等于 `rows-1`。

---

## 2. 起点由暂存槽位决定

### 2.1 槽位分配：最左空槽

球入场时，取暂存区当前**最左边的空槽**：

```js
function leftmostFreeSlot(s) {
  var used = {};
  for (var i = 0; i < s.buffer.length; i++)
    if (s.buffer[i].slot != null) used[s.buffer[i].slot] = 1;
  for (var k = 0; k < s.bufferLimit; k++)
    if (!used[k]) return k;
  return s.buffer.length;   // 全占 = 溢出
}
```

- 槽位编号 `0 .. bufferLimit-1`，`bufferLimit` 默认 **5**。
- 球离场后槽位立即释放，下一个球又会拿到靠左的槽。
- **只有滞留球（消不完、占着槽）才会把后续球的起点往右推。**

### 2.2 槽位 → 目标图起点坐标

```js
function slotStartCoord(slot, rows, cols, bufferLimit) {
  if (slot == null) return null;
  var col = Math.floor((slot / Math.max(1, bufferLimit)) * cols);
  if (col > cols - 1) col = cols - 1;
  if (col < 0) col = 0;
  return { r: rows - 1, c: col };
}
```

即：

```text
起点行 = rows - 1            （恒为底行）
起点列 = floor(slot / bufferLimit * cols)
```

`bufferLimit=5`、`rows=cols=55` 时的完整对照表：

| 槽位 slot | 起点列 c | 起点坐标 {r, c} | 位置 |
|---|---|---|---|
| 0 | 0 | {54, 0} | 左下角 |
| 1 | 11 | {54, 11} | 底部偏左 |
| 2 | 22 | {54, 22} | 底部中偏左 |
| 3 | 33 | {54, 33} | 底部中偏右 |
| 4 | 44 | {54, 44} | 底部偏右 |

注意：**没有任何一个槽位映射到底部正中（c=27）**。程序端现用的「底部中间」不等于其中任何一档，连最接近的槽 2 也差 5 列。

### 2.3 起点入场即固定

球一旦入场，`start` 写入该球的暂存条目并**终身不变**，后续每一轮消除都用它自己的起点：

```js
s.buffer.push({
  color, progress, need,
  slot,          // 占用的槽位
  start,         // ← slotStartCoord 的结果，之后不再变
  enterStep, key, link
});
```

哪怕左边的槽腾空了，已在场的球也**不会**改用新起点。

## 3. 单个球的消除顺序

函数：`floodFillEliminate(eliminated, blocks, rows, cols, colorId, maxCount, trace, start, bottomOnly)`

一次调用最多消 `maxCount` 个 `colorId` 像素（`maxCount` = 该球剩余订单量）。

### 3.1 排序键（生效版本）

```js
var AREA = rows * cols;
var SOURCE_SPAN = AREA * (AREA + 1);

function tieOf(r, c, source) {
  if (source === 0 || source === 3) return c;        // 底/顶：左 → 右
  if (source === 1) return rows - 1 - r;             // 左：下 → 上
  return rows - 1 - r;                               // 右：下 → 上
}

function keyOf(r, c, source, depth) {
  var base = source * SOURCE_SPAN + depth * AREA + tieOf(r, c, source);
  if (start) return (Math.abs(r - start.r) + Math.abs(c - start.c)) * (4 * SOURCE_SPAN) + base;
  return base;
}
```

键值小者先消。优先级从高到低：

1. **离起点的曼哈顿距离**（权重 `4 * SOURCE_SPAN`，压倒其余一切）——传了 `start` 才有；
2. **入口源 source**：底(0) → 左(1) → 右(2) → 顶(3)；
3. **依赖波深度 depth**：从入口进入需经过几层；
4. **同波内次序 tieOf**：底/顶按左→右，左/右按下→上。

### 3.2 动态依赖波（depth 的含义）

不是「一次性算好静态距离」，而是消一格就刷新：

- 初始扫描：贴外边的同色像素 `depth=0`；邻接**当前已消空洞**的同色像素，从空洞继承真实路径深度 `depth+1`。
- 每消掉一格，它四邻的同色像素**继承该格的 source**，`depth+1` 入堆。
- 同一像素若被更高优先入口 / 更短路径再次揭示，允许更新键值（旧堆节点弹出时丢弃）。

跨球连续性的关键：上一个球挖出的空洞会带着真实入口深度保留下来，所以第二个同色球不会把所有残余像素重新当成 `depth=0`。

### 3.3 可达性

```text
默认：四边皆为外部开口
bottomOnly：仅底边(r=rows-1)开口，上/左/右视作墙 → 目标图只能自底向上溶解
```

初始 `eliminated` 由 `AntSolver.outsideReachSeed(blocks, rows, cols, bottomOnly)` 生成：从边缘的空格（`blocks[r][c] <= 0`）BFS 铺开。**封闭空腔不算可达**，不会从内部凭空开始消。

## 4. 多球并存时，球与球之间的顺序

`autoReleaseBuffer` 每轮循环：

```js
if (s.useSlotStart && s.buffer.length > 1) {
  var distCache = {};
  for (每个暂存球 bi)
    distCache[i] = (bi.need - bi.progress) > 0
      ? peekNearestDist(s, bi.color, bi.start)   // 只探测，不消除
      : Infinity;
  order.sort(function (a, b) { return (distCache[a] - distCache[b]) || (a - b); });
}
```

`peekNearestDist` = 「离**我自己的起点**最近的、可达的同色像素的曼哈顿距离」：

```js
function peekNearestDist(s, color, start) {
  var best = Infinity;
  for (r, c 全扫) {
    if (s.eliminated[r][c] || s.blocks[r][c] !== color) continue;
    if (!reachableCell(s.eliminated, s.rows, s.cols, r, c)) continue;
    var d = start ? (Math.abs(r - start.r) + Math.abs(c - start.c))
                  : ((s.rows - 1 - r) * s.cols + c);
    if (d < best) best = d;
  }
  return best;
}
```

规则：**每轮先让「离自己起点最近」的球消**，平手按暂存顺序（索引小者先）。单球时跳过排序（省开销，行为等价）。

循环直到某一轮没有任何球取得进展（`changed === false`）才停。

## 5. 离场、锁链与溢出

- **普通球**：`progress >= need` 立即离场，槽位释放，`completedBoxes++`。
- **锁链组（2 或 3 连）**：同组共享 `link`；整组进暂存，**组内全部消完才一起离场**。已消完的成员仍占槽等伙伴——这是把后续球起点推向右侧的主要来源。
- **溢出判死**：`buffer.length > bufferLimit` → `overflow = true`。锁链整组入场时在 `autoReleaseBuffer` **之前**判定，以捕获瞬时峰值；瞬时溢出不可救（道具也不行）。

## 6. 与程序端现行实现的差异及后果

| 项 | 本项目口径 | 程序端现状 | 后果 |
|---|---|---|---|
| 起点数量 | 每球一个，随槽位变 | 全局一个 | 消除顺序整体偏移 |
| 起点位置 | 底行、列 = `floor(slot/5*55)` → 0/11/22/33/44 | 底部正中（c≈27） | 无一档吻合；靠左关卡差异最大 |
| 滞留影响 | 滞留球占槽 → 后续球起点右移 | 无影响 | 卡点/锁链关差异被放大 |
| 起点是否可变 | 入场即固定 | 恒定 | 单球关差异较小，多球关差异明显 |
| 球间顺序 | 按各自起点的最近可达距离动态排 | 无此概念或按固定序 | 暂存峰值与通关性可能反转 |

因为「距离优先」的权重压倒依赖波，起点错位会直接改写整条消除序列，不是细微误差。

## 7. 实现伪代码（可直接对照移植）

```text
入场(box):
    slot  = leftmostFreeSlot()            # 0..bufferLimit-1，全占则溢出
    start = { r: rows-1, c: floor(slot / bufferLimit * cols) }
    entry = { color, need: box.count, progress: 0, slot, start, link }
    progress += floodFillEliminate(color, need, start)
    if progress < need: buffer.push(entry)   # 否则直接离场
    if buffer.length > bufferLimit: overflow = true
    autoRelease()

autoRelease():
    repeat:
        changed = false
        if buffer.length > 1:
            按 peekNearestDist(color, 各自 start) 升序排，平手按索引
        for each 未完成球:
            got = floodFillEliminate(color, need - progress, 该球 start)
            if got > 0: progress += got; changed = true
        移除已完成球（锁链需整组完成）
    until not changed

floodFillEliminate(color, maxCount, start):
    用已消空洞重建每个可达空格的 (source, depth)
    初始候选 = 所有可达的未消同色像素，继承 (source, depth)
    小顶堆按 keyOf(r,c,source,depth) 取出：
        距起点曼哈顿距离 > source(底0/左1/右2/顶3) > depth > tieOf
    每消一格：四邻同色像素继承 source、depth+1 入堆
    消满 maxCount 或无候选则停
```

## 8. 建议的对齐自检

程序端改完后，用同一关卡 JSON 逐项比对（本项目侧可用求解器输出的 `pickOrder` 与 `eliminated` 矩阵）：

1. 单球关：只有 1 个盒时，起点必须是 `{rows-1, 0}`（槽 0），不是底部中间。
2. 五球滞留关：让 5 个球同时滞留，逐球核对起点列 = 0 / 11 / 22 / 33 / 44。
3. 释放复用：让槽 1 的球先离场，下一个入场球必须重新拿到槽 1（列 11），不是槽 5。
4. 锁链关：整组占槽期间，后续球起点应右移；组内成员即使已消完也不得提前释放槽位。
5. 逐像素比对消除序列（trace），而不是只比「是否通关」——通关一致不代表顺序一致。

## 10. 两处源码瑕疵（不影响本文口径，供程序端读码时避免误读）

1. `floodFillEliminate` 内有**两个同名 `keyOf` 声明**：前一个是「静态最近边」版本 `keyOf(r, c)`，后一个是「入口源 + 依赖波」版本 `keyOf(r, c, source, depth)`。因函数提升，**后者覆盖前者，前者是死代码**。移植时只按第 3.1 节（后者）实现。同一函数内的 `reachable(r, c)` 同样没有调用点，实际可达性由 `edgeSource` + 空洞 BFS 承担。
2. `simulator.js` 中 `createState` 对 `useSlotStart` 的注释写「默认关(求解器/生成)」，但实际调用方 `solver.js`、`playersim.js`、`app.js`、`utils.js` 全部传或默认为 `true`。**注释过时，实现才是准的**：求解器走的就是本文的槽位起点口径。

以上两点仅为读码提醒，项目侧尚未修改（改动需另行批准）。
