# 蚂蚁拿块关卡图修改工具 · 使用说明

> 本页面精简后不再展开详细解释，所有操作说明统一收在这份文档里。

## 1. 工具用途

美术需要知道"玩家玩到某个进度区间时，目标图上被消掉的是哪一块"，好在那个位置改色、改图案，
改完后还要能重新构造出一个真正可玩、可解的新关卡。本工具做三件事：

- 按真实通关路线定位任意进度区间对应的目标图区域；
- 提供美术编辑（34 色完整色库、当前图颜色分组、全局替换、靠色检查、框选局部编辑），
  并能把改好的图重新构造成合法关卡；
- 对比修改前后的暂存压力、难度、可解性，多关改完后一次性批量导出全部结果。

## 2. 推荐操作流程

1. 导入关卡（目标图 + 关卡本体，求解数据可选）；
2. 求解（有求解数据直接回放，没有就现场求解）；
3. 填写进度区间并定位，查看该区间对应的目标图区域；
4. 需要交叉核实时跑多路线复核，查看稳定/高频/浮动区域；
5. 需要改图时开启美术编辑：点选改色，或框选出一块区域再在区域内改；
   改前可以先看"当前图用到的颜色"分组和靠色检查结果；
6. 想让重构按上线关卡的参数走时，先导入一份生成器标准参数文件；
7. 核对"关键参数确认"区里这次会生效的参数，然后点"重新生成关卡"把新目标图构造成合法关卡；
8. 查看暂存压力图和指标对比表，切换"查看原关卡/查看重构后"分别回放核对；
9. 对当前区间做修改前后的区域对比，看进度区域专用对比图；
10. 这一关满意了就"添加为待导出库"，然后直接切到下一关继续改；
11. 全部改完后从待导出库一次性批量导出（也可以只导出当前这一关的完整对比包）。

上面是**改关卡**的主流程。另外还有一条独立路线：**只想从图里抠出主体部分、攒成素材**，
不重构、不求解、也不进待导出库 ——

> 导入 TXT → 开启美术编辑 → 选区工具圈出主体 → 剔除选区内/外 → 存入**图纸库** → 批量导出 txt

见第 13 节。两条路线用的是同一个选区，可以混着走（比如先剔掉杂物再重构），但图纸库和待导出库
是两个互不影响的库。

抠好部件之后还有第三条路线：**把多个部件拼成一张多主体的新图** ——

> 顶栏点「🧩 拼接图纸」→ 设定新画布规格 → 把部件放上画布 → 拖到合适位置 →
> 检查输出 → 最终效果图 → 导出 TXT 或存回图纸库

见第 14 节。拼接工作台是独立的，不会动你正在改的关卡。

## 3. TXT、关卡、求解数据的导入方式

支持两种导入入口：**选择文件**（一次多选若干文件）和**选择文件夹**（递归读取整个目录，适合批量导入）。

工具按文件名（去掉扩展名）自动把同一关的文件配对到一起，识别三类文件：

- `xxx.txt`：目标图，即像素颜色矩阵；
- `xxx.json`：正式关卡本体，用于还原棋盘结构、障碍、管道等；
- `xxx.solve.json`：求解数据，**可选**，有则可直接回放不必重新求解。

`.txt`、`.json` 以外的文件自动忽略。批量导入只做配对和索引，不会自动求解、也不会自动跑多路线，需要你手动点击对应按钮。

**配对只看文件名，不看目录名。** 所以 `txt图/` 还是 `TXT图/`、大小写不同都没关系，
只要同一关的三个文件去掉扩展名后同名就能配上。

### 强烈建议带上求解数据（2026-08-05 起生成器已默认导出）

没有 `xxx.solve.json` 时工具只能**现场求解**，而现场求解是按**时间预算**（180 秒）跑九遍求解梯队的，
不同机器、不同 CPU 负载可能停在不同一遍，于是取盒顺序 `pickOrder` 会不一样、**原理上无法复现**。
（梯队用的种子本身是写死的，所以这个漂移不是"随机种子"造成的。）

带上求解数据就没有这个问题：工具直接读现成 `pickOrder`，逐步轨迹再由工具按真机口径毫秒级重放。

网页生成器从 2026-08-05 起，批量导出与单关导出都会产出 `求解数据/<关卡名>.solve.json`，
与 `关卡/`、`txt图/` 同名构成三件套，整包直接选文件夹导入即可。
这些文件里**只有 `pickOrder` 是权威**，不含 `replay`/`defaultInterval`（工具反正自己重放）。

**汇总文件会被跳过而不是报错**：导出包里的 `关卡数据/关卡数据.json` 是整批聚合数据、不是单关文件。
以前它会被算进"读不出来的文件"，看着像导入出错；现在导入统计里显示为"跳过汇总文件 N"，属正常。

## 4. 进度区间定位方法

进度口径统一为：**已完成盒数 ÷ 总盒数**。

在"进度区间"卡片填写上下限百分比（或使用几个常用快捷按钮），点击"定位区域"。

因为盒子是一个一个完成的，进度是离散的，不一定存在正好等于你输入数字的那个时刻。工具会把你填的上下限
自动吸附到**最近的实际可达进度**，并同时显示你要求的区间和实际采用的区间，方便你确认两者是否有明显偏差。

## 5. 单路线与多路线区别

- **单路线**（求解路线 + 进度区间定位）：只取一条通关路线，用来看"这条路线下，该进度区间对应的目标图区域"。
- **多路线复核**：由你主动点击启动，最多取 3 条互不相同的可通关路线，用来交叉核实"不同的通关走法，是否都会在
  差不多的位置消除差不多的像素"。多路线复核不会自动执行，也不会替代单路线的定位结果。

## 6. 稳定、高频、浮动区域含义

多路线复核后，会把每一步的目标图区域按出现频率分成三类，并可分别开关显示：

- **稳定区域**：在全部路线中都出现的区域，说明无论怎么玩，这块区域大概率都会在这个进度附近被消除；
- **高频区域**：在大多数（但不是全部）路线中出现的区域；
- **浮动区域**：只在少数路线中出现的区域，说明这块区域的消除时机对走法比较敏感。

三个开关互相独立，可以同时勾选任意组合，切换开关只是重新绘制画面，不会重新跑多路线求解。

## 7. 美术修改方法

开启"美术编辑"后可以改目标图的颜色，支持撤销、一键还原为原图。改色只影响这里显示的目标图，
**不会自动重新构造关卡结构**——棋盘尺寸、障碍、管道、盒子容量都不会跟着联动重算。改完图案后，如果需要一个
真正可玩的新关卡，需要用"重构关卡"功能。

### 7.0 只做美术时把界面收干净（2026-09-15 新增）

页面顶栏有两个开关，专门解决"美术编辑和主体提取隔太远、中间夹着一堆用不上的功能"：

- **纯美术编辑模式**：勾上后收起 7 块与生产/求解有关的卡片（求解路线、进度区间、多路线复核、
  自动演示、暂存压力图、重构关卡、待导出库）以及棋盘/暂存对比区。
  这样「8. 美术编辑」和「12. 主体提取」就**直接相邻**，抠图时不用来回滚页面。
  只是**收起显示**，数据、选区、图纸库全都还在，取消勾选立刻恢复。开着时这个开关本身是高亮的，
  不会让你以为功能丢了。
- **折叠全部 / 展开全部**：把所有功能卡片折成只剩标题。也可以**单独点任意卡片的标题**折叠它。

两者是**独立**的：切换纯美术模式**不会**动你手动折叠的卡片；反过来折叠也不影响模式。
两个状态都会记住，下次打开页面还是这个样子。清掉浏览器数据只会重置界面布局，不会影响图纸或关卡
（界面偏好存在单独的位置，和两个库分开）。

> **"还原为原图"需要点两次**（2026-08-20 起）。这个按钮会丢弃本关全部像素修改、撤销记录也一起清空，
> 手误点一下就白改了，所以加了二次确认：第一次点击**不会还原**，按钮会变成红色的"确认还原？"，
> 再点一次才真的执行。变红后的极短时间内（0.4 秒）故意不接受点击，防止双击穿透；
> 4 秒内不点第二次就自动取消，按 Esc 或点页面别处也能取消。日志区会同步写明发生了什么。

### 7.1 完整色库：已有颜色被一个外框圈在一起

色库列出正式毛线色库的全部 34 个颜色，每个都带中文名，全部可选。色号与中文名直接取自项目正式色表，
工具内不另存一份，不会出现工具和游戏端色号对不上的情况。

**这张目标图已经用到的颜色，会集中排在一个共同的外框里面**；当前没用到的颜色排在这个外框外面。
框内框外合起来就是完整的 34 色，**不是两套色库**，也没有另外一块"当前目标图颜色"面板。

```text
┌──── 当前目标图已有颜色（12 种） ────┐
│  ■ ■ ■ ■ ■ ■ ■ ■ ■ ■ ■ ■           │
│  每个色块下方标出像素数与占比        │
└─────────────────────────────────────┘
完整色库中当前未使用的颜色（22 种，同样可以直接选用）
  ■ ■ ■ ■ ■ ■ ■ ■ …
```

每个色块下面都写着**中文颜色名和色号**；框内的色块还多一行像素数与占比。凡是显示颜色数量的地方，
都会同时写出颜色名，不会只给一个色号让你去猜。

- 点任何色块（框内框外都一样）= 选为当前绘制颜色。
- 框内每个色块下面有一个**整图替换**按钮 = 把整张图里这个颜色全部换成另一色：
  点它，再点你要换成的色块即可。

**误触了怎么取消**：点下替换按钮后，页面上会出现一条醒目的状态条，写明正在替换哪个颜色、等你点目标色。
想取消有五种办法，随便哪种都行，而且**都不会改动任何像素、不需要按撤销**：

1. 点状态条上的"取消替换"按钮；
2. 按 Esc；
3. 再点一次那个"整图替换"按钮（此时按钮文字已变成"取消替换"）；
4. 点页面空白处；
5. 点目标图（这时只会取消替换，不会落笔改色）。

### 7.2 分组会自动跟着目标图变

做完下面任一操作后，框内框外会立即重新识别，不需要手动刷新：整图替换、框选区域替换、拖动绘制改色、
用了一个原来没用过的颜色、把某个颜色全部换掉让它消失、切换关卡、从待导出库重新调取关卡。

规则很简单：**目标图里还有的颜色进框内，已经没有的移到框外。**

### 7.3 靠色检查

有五组颜色两两之间在实机上偏接近，容易让玩家看不清区别，工具会检查这五组：

| 靠色对 | 说明 |
| --- | --- |
| 2 / 3 | 浅红 · 粉红 |
| 17 / 18 | 灰蓝 · 蓝色 |
| 20 / 22 | 绿色 · 青蓝 |
| 28 / 29 | 橙色 · 深棕2 |
| 31 / 32 | 浅灰 · 灰色 |

同一组的两个颜色**同时出现**在图上就算命中，会被标出来提示你考虑换掉其中一个。检查分两处显示：
一处针对整张图，一处针对当前框选的选区。这五组是固定的，工具不会自己按颜色相近程度再追加别的组合。

### 7.3b 碎色率检查（2026-08-25 新增）

这一项告诉你**这张图还要修到什么程度**才不会在生产阶段被卡掉。

**什么算「碎色」**：图上那些自己不够大、旁边同色也凑不够的小片。
一个盒子要装 35~80 个像素，如果同色像素散成互不相连的小块，盒子就得跨很多小片才吃得饱，
订单会在暂存区待很久，后期容易卡住。判定口径：

| 项 | 口径 |
| --- | --- |
| 色块 | 同色**四方向**连通（和游戏消除方向一致） |
| 孤立块 | ≤ 1 像素 |
| 小色块 | 2 ~ **7** 像素（**2026-08-25 放宽**：原为 2~10） |
| 正常块 | **≥ 8** 像素 |
| 并簇 | 两个同色块之间夹的异色**不超过 3 像素、且种类不超过 1 种**时算「靠得够近」，并成一簇 |
| 救回 | 一簇的总像素 **≥ 8** 就整簇算正常（小块靠拢也能凑成一块） |
| 长期隔断 | 夹在中间的颜色如果**不会先于本色被消除**，则不并簇（等不到它让路） |
| 碎色率 | 最终仍是碎色的像素数 ÷ 全图彩色像素数 |

> **2026-08-25 口径放宽的影响**：小色块从「≤10 像素」放宽到「小于 8 像素」后，
> 同一张图的碎色率会**低约 4.3 个百分点**（344 关实测中位 18.92% → 14.53%）。
> 也就是说同一张图现在更容易达标，但**这不代表图变好了**，只是判定标准放宽了。
> 因此下面的阈值与等级刻度都是按新口径重新算过的，不要拿 8-24 之前的数字对照。

**面板给你四件事**：

1. **碎色率与等级**，以及是否达标。五级刻度（2026-08-25 按新口径重算）：

   | 等级 | 碎色率 | 差关率 | 严重差关率 | 好关率 |
   | --- | --- | ---: | ---: | ---: |
   | 很整 | ≤ 10.54% | 23.5% | 1.5% | 33.8% |
   | 偏整 | ≤ 13.42% | 23.5% | 8.8% | 32.4% |
   | 中等 | ≤ 15.57% | 25.0% | 11.8% | 27.9% |
   | 偏碎 | ≤ 17.97% | 39.7% | 10.3% | 20.6% |
   | 很碎 | 更高 | 45.8% | 13.9% | 20.8% |

   （全样本基础率：差关 31.7%、好关 27.0%。差关率在「中等 → 偏碎」之间跳得最明显。）
2. **该改到什么程度**：超标时给出「至少要把 N 个碎色像素并入邻近同色块」。
   这是**下界**——实际把一个孤立像素接到旁边同色块上，常会连带救回同簇的其它小块，
   所以真要动的像素通常比这个数少。改完点「重新计算」看最新值；
3. **分色明细**：按碎色率降序排，排在最前面的颜色最碎，先修它最划算；
4. **高亮碎色像素**：勾上后被判为碎色的像素会在图上打红色蒙层 + 白边，直接看出该修哪里。

   > **2026-08-25 修好了一处误标**。此前高亮会把**视觉上连续**的图形也标红，典型是
   > 「一条连续的边缘带」和「只隔 1 个像素的两条同色条带」——它们在正式判定里会被
   > 并簇救回、本来不算碎色，但高亮那一层没做并簇，所以多标了。实测 6 张图误标 608 块，
   > 其中隔 1 像素的占 92%、条带形状占 427 块。
   > 现在高亮与上面的碎色率**用同一套判定**：标红的就是正式算作碎色的像素，
   > 分色明细的数字也能和「碎色率」那一栏对得上。
   > 真正孤立的单像素、以及间隔较远（超过 3 像素）的小块，仍然会正常标红——并簇的判据一个字没放宽。

**阈值怎么选**（随时可改，下拉里的值都是实测值，不是拍的）：

| 阈值 | 来源 |
| --- | --- |
| **18%**（当前采用，默认） | 用户 2026-08-25 定的上限。生产端的碎色闸门用的是同一个值 |
| 11.47% | **新口径下好关率最高那一档（四等分 Q1）的上界**（好关率 32.6%、严重差关率 3.5%）。想要"原来那种筛选强度"就选它 |
| 10.54% | 新口径五等分最整档上界（好关率 33.8%、严重差关率仅 1.5%），最严 |
| 18.79% / 20.47% | 旧口径（小色块≤10）时期的 Q2 上界与差关率断点，保留为备选 |
| 自定义 | 直接填百分比，任意值 |

> ⚠ **18% 在新口径下比较宽松**，这一点要知道。344 关实测：18% 会放过 **79.1%** 的图
> （旧口径下同一个 18% 只放过 43%），而放过的这批里好关率 28.7%，
> 和全样本基础率 27.0% 几乎没差别——也就是说**这道闸门基本没在挑图**。
> 它换来的是产能：200 新图过闸率 13% → **58.5%**，347 修复批 28.8% → **59.9%**。
> 如果你要的是把图修到"确实更整"，把阈值调到 11.47% 更有依据。

**阈值是可调参数，改完立刻生效**：碎色率本身与阈值无关，所以换阈值**不用重新计算**，
达标判定和「至少要救回多少像素」会立即跟着变。你选的值会**记住到下次打开工具**，
不用每次重选（存的只是一个数字，不占待导出库的空间）。

**这个数字和生产端是同一个数**：工具的碎色计算（`js/fragment.js`）是生产端
`bin/js/generator.js` 的同源副本，已用 60 张真实图逐字段校验完全一致（最大差 0.00）。
**默认阈值两边也是同一个 18%**。所以在工具里按默认阈值达标的图，生产时不会因碎色被卡掉。

> 如果你把工具里的阈值调宽（比如 20.47%），那就只是**工具这边**放宽了；
> 生产端仍按它自己的 18% 判。想让生产端也放宽，要去生产器页面改「碎色上限%」。

**面板里那几个百分比要怎么理解**：等级下面写的「差关率 / 严重差关率 / 好关率」来自
2026-08-24 对上线 345 关的**现象观察**（按碎色率五等分后各档的线上表现）。
这是**相关性**，不是「碎色导致差关」的因果结论——差关成因是多维的，碎色只是其中一个能量出来的现象。
拿它当修图的参考刻度可以，别当成唯一判据。

**为什么不实时刷新**：全图算一次约 0.1~0.3 秒（要算消除轮次），
拖着笔刷逐格重算会明显卡手。所以改动后面板会标「数值已过期」，点「重新计算」再刷。

### 7.4 拖动绘制与框选局部编辑

编辑工具有**五种**（2026-09-02 起从两种扩到五种），用单选切换，下一行是"只在选区内绘制"开关和"取消选区"按钮：

- **拖动绘制**（默认）：按住左键在图上拖，经过的像素连续改成当前颜色，松开结束。
  只点一下就只改那一格，所以以前"点一格改一格"的用法没有丢。
  原来那个单独的"点选改色"工具已经取消，改色统一走这一个。
- **矩形框选**：拖拽出一个矩形选区。就是原来的"框选编辑"，行为没变。
- **套索**：按住左键沿着你要的边缘画一圈，松开自动闭合成选区。用来贴着不规则轮廓取件。
- **同色块**：在图上点一下，与该点**同色且四连通**的一片会整块被选中。适合外圈是整圈同色背景的图。
- **按色选**：在图上点一下，**全图**所有这个颜色的像素一次全选，不要求相连。

后四种都是"选区工具"，产出的都是**同一种选区**（内部按逐格掩码记录，不是只记一个矩形），
所以它们可以**混着用、叠起来**。怎么叠由**"叠加方式"**这一行的四个选项决定（2026-09-15 起）：

| 叠加方式 | 意思 | 快捷键 |
| --- | --- | --- |
| **替换**（默认） | 丢掉旧选区，只要这次选的 | — |
| **加选** | 并到当前选区上 | 按住 **Shift** |
| **减选** | 从当前选区里挖掉 | 按住 **Alt** |
| **交集** | 只留下两者**重叠**的部分 | 无（见下） |

按住 Shift 或 Alt 会**临时覆盖**这一行的选择，松手就恢复，所以习惯用修饰键的话不用先改设置。
**交集没有配快捷键**：mac 上 Ctrl+点击会被系统当成右键菜单、Cmd 又和浏览器快捷键打架，
按住拖拽都不合适，所以交集只走这个单选。

**交集是本轮新增的重点**，它解决的是"描边色既在边缘也在主体上"这个问题，详见 §13.7 去毛边。
一句话：先圈范围，再把叠加方式设成交集，然后按色选 —— 得到的就是"**这个范围里**的这个颜色"，
主体其它地方的同色一格不动。

> 交集需要**先有一个选区**才能相交。如果还没有选区就选了交集去点按色选，工具会明确告诉你
> "交集需要先有一个范围"并且**不改动选区**，不会悄悄退化成"全图该色"（那正是会毁掉主体的操作）。

典型用法就是叠：先用"同色块"一击选掉外圈背景，再按住 Shift 用套索补上它没连到的零碎，
最后按住 Alt 把误选进去的主体边缘减出来。

选区在画布上是**淡青色覆盖 + 青色描边**（青色是专门给选区留的，和碎色检查的红、进度区间的白分开，
三种同时开也不会混）。处于选区工具时画布本身会描一圈边，提示你现在点下去是"选"而不是"画"。

**"只在选区内绘制"在所有工具下都生效**：勾上并且已有选区时，落笔一律限制在选区**实际形状**内，
**选区以外的像素不受影响**。注意这里按的是逐格形状，不是外接矩形——用套索圈一个 L 形，
L 形凹进去的那块**不算**在选区内，落笔不会改到它。选区内也可以做只针对选区的颜色替换，
改法和整图替换一样，只是范围限定在选区里。不需要选区时点"取消选区"清掉（会把选区整个清干净，
不会残留一个看不见但仍然生效的范围）。

选区还是"主体提取"的输入——**先在这里选好，再去第 13 节剔除**。

### 7.5 面板可以拖成悬浮框，也能拉大拉小

目标图右侧那块空位现在放两块面板，上下排列（目标图放到最大也不会挡住它们）：

- **编辑改动统计**：已改动像素 / 总量守恒 / 逐色变化；
- **5. 显示与导出**：像素尺寸、描边与淡化开关、格线、标出区间前已消除范围、导出 PNG / 导出区间定位 JSON。

这两块和整个"美术编辑"面板，右上角都有一个**悬浮**按钮：

1. 点"悬浮"→ 面板脱离原位变成浮层；
2. 按住**标题栏**拖动 → 移到屏幕上任意位置；
3. 按住**右边缘 / 下边缘 / 右下角**拖动 → 放大或缩小（右边缘只改宽，下边缘只改高，右下角同时改）；
4. 点"收回原位"→ 放回目标图右侧。

位置和尺寸都会记住，收回再悬浮时回到同一状态。拖动被限制在窗口范围内，不会拖出屏幕找不回来。

报告里的逐色变化和改动坐标都带中文颜色名。

## 8. 重新生成关卡（只有一种方式）

重构关卡只有一个按钮：**"重新生成关卡"**。以前的三种策略选项（①保障碍布局换色重配、②完全重新生成、
③保结构重切盒）已在 2026-07-31 精简为只保留②，①③已删除，页面上不再有策略单选。

删掉①③的原因：它们要求完全保留原棋盘骨架，而 55×55 这批关卡的骨架容量普遍只有 45~55 格，
新目标图像素稍多、或原棋盘没有管道时就装不下，实测 9 次尝试全部失败，实际用不了。
现在这一种方式允许重新排布棋盘尺寸、管道和障碍，覆盖面最广；代价是新关卡在视觉骨架上可能和原关卡不一样。

失败时会原样告诉你原因，不会假装成功，也不会悄悄换一种算法再试。

### 8.1 点之前先看"关键参数确认"

按钮上方有一块"关键参数确认"，用中文列出这一次**真正会生效**的参数：

参数来源（导入的方案文件名，或"工具默认参数"）、底部消除开关、盒容量区间、暂存上限、
黑块/冰块/问号占比、锁链组数、棋盘行列范围、窄路缺口范围。

方案文件里同一个参数可能存了两份值：一份是**正式参数本体**，另一份是**当时页面上的输入框状态**。
两者不一致时，这里会专门标一行"字段冲突"，逐条写清"方案里的历史输入值是多少、正式生效值取的是哪个"。
**正式生效值一律取参数本体**，页面历史输入状态只是留档，不参与生成。

另外，暂存上限是玩法固定口径（5）。方案文件里就算写了别的值也不采用，这时会标一行"被工具强制覆盖"告诉你。

### 8.2 导入生成器标准参数

默认用工具自己的默认参数。想让重构和某批上线关卡口径一致，就导入那批关卡用的参数文件，
支持三种真实格式：生产批次配置（`批次配置.json`）、生成器网页端导出的方案文件、纯参数对象。

导入后界面显示：识别到了哪些参数、**哪些字段没被识别**。没识别的字段会如实列出来，不会悄悄丢掉。
重构按导入的参数执行，不会用默认值把你的参数盖掉；重构结束后界面还会显示"实际生效参数"供你核对。
导出包里的 `生效的生成器参数.json` 记录了原始识别参数、未识别字段、字段冲突、实际生效参数四份数据。

### 8.3 重构后的棋盘和障碍参数核对

结果面板先给出重构后棋盘的实况：**行×列与总格数、盒/黑块/管道/空格各多少**。

以前挑棋盘尺寸是随机的，盒子少而棋盘大时会补出远超目标比例的黑块（例如目标 10% 补到 20% 以上）。
现在生成器改为按盒数挑尺寸：优先选"盒子加上一点管道余量刚好装得下"的棋盘，并要求形态是"列比行多 1 或 2"。
确实找不到合法形态时会退回原来的随机做法，并在结果里标出来告诉你这次形态没卡住，不会假装合规。

棋盘实况下面是**障碍参数核对**表，四项逐条列出**目标值、实际值、偏差、是否在容差内**：

| 参数 | 分母（与正式生成器一致） |
| --- | --- |
| 黑块 | 棋盘总格数 |
| 冰块 | 棋盘上的盒格数 |
| 问号 | 棋盘上的盒格数 |
| 锁链 | 按组数算，不是比例 |

**容差是你 2026-07-31 批准的**：百分比类参数允许偏离目标 ±5 个百分点；锁链按组数算，允许 ±1 组
（3 组的 5% 只有 0.15 组，按百分点没意义）。这个容差和它的来源会一起显示在页面和导出报告里，
不会像以前那样悄悄用"目标 +5"判合格却不告诉你容差是多少。

两个容易误读的地方，工具会主动说明：

- **窄路缺口的锁链和冰块不占配额**。开启窄路后，每个缺口会额外加一组锁链（组号从 90 起）和一个冰块，
  这是窄路机制自带的，不算在你设定的锁链组数和冰块比例里。所以核对表里的锁链只数普通锁链，
  窄路那部分单独报数，不参与容差判定。
- **冰块有时会显示"本次不做判定"**。要把这两类冰块分开，需要生成结果带上冰块的来源明细，
  而有一类生成路径产出的关卡不带这份明细。这时工具**不猜**：把两类冰合起来的数值照实显示，
  但标明本次不做判定，既不算通过也不算超标。看到这个标记时，冰块偏差偏高是正常的，不代表参数失效。

### 8.4 玩家验证：正式一次 + 5 个随机种子多轮

重构成功后，玩家验证结果分两部分显示：

- **正式单次**：直接取生成器内部自己那次玩家模拟的结果，口径与线上生产完全一致；
- **多轮随机种子**：另外用 5 个固定种子（7 / 101 / 2029 / 33333 / 65537）各跑一次，
  逐轮列出种子、是否通关、暂存峰值、复活次数/上限、完成盒数/总盒数，并汇总通关率和平均值。

多轮结果是给你判断"这一关是不是稳定可打通"用的：5 轮都通关比只有 1 轮通关可靠得多。

**如果玩家模拟根本没跑起来**（比如解析后的关卡盒数为 0、或每轮取球次数都是 0），
工具会明确报"玩家验证接口异常"并说明原因，**不会把它写成"0% 通关率"**。
看到这个提示时，玩家相关数值本次一律不可用，不要拿它判断难度。

### 8.5 关于旧数据：请注意这几项已作废

2026-07-30 版说明里那张"①0/9、③0/9、②8/9"的成功率表格，以及"玩家相关数值目前不可信"的警告，
都随本次整改作废。原因和处理方式如下：

- **那批 0% 是测量错误，不是关卡质量问题**。当时工具把没解析过的关卡对象交给了玩家模拟，
  模拟根本没跑起来（盒数为 0、一次球都没取），所以对任何关卡都返回"未通关"。
- **"玩家打不通是黑块太多造成的"这个说法不对**。当时打不通是模拟没运行。
  黑块偏多是另一个独立问题（挑棋盘尺寸不看盒子数量，多出来的空格全补成黑块），
  它确实会影响难度，但和当时的 0% 没有因果关系。这个问题已在本次修掉。
- **"那道玩家门槛成功拦下了真人打不通的关卡"这个说法也不对**。它对任何输入都判未通关，
  属于无差别拦截，没有鉴别力。
- **2026-07-31 之前导出的包和报告不会被删除，但里面的玩家相关数值一律无效**：
  "玩家是否通关 / 玩家暂存峰值 / 玩家复活次数 / 多轮玩家通关率"这几项请不要采信。
  其余内容（目标图、关卡本体、求解路线、像素守恒等）不受影响。
  需要有效的玩家数据，请重新导入那一关，用现在的"重新生成关卡"重跑一次再导出。

## 9. 暂存压力图查看方法

### 9.1 全知和玩家是两套轨迹，用按钮切换

卡片上方有两个按钮：**查看全知轨迹** / **查看玩家轨迹**。当前是哪一套，按钮会高亮，图上方也会写明。
两套数据各自来自真实求解过程，互不代替，不会拿一套补另一套。

- **全知轨迹**：来自正式全知求解的消除顺序。横轴是完成进度 0%–100%。
- **玩家轨迹**：来自正式玩家模拟真实操作过程中每一拍的暂存占用。横轴是操作步数（图上标真实步号，不是百分比）。
  玩家正常使用复活机制，复活次数会一并显示。

切到玩家轨迹后会多出两个控件：

- **玩家随机种子下拉**：5 轮各一个种子，每项标出该轮是否通关和峰值，选哪轮就看哪轮的曲线。
- **看重构后关卡 / 看原关卡**：勾选看重构后的（需要先重构成功），取消勾选看原关卡的。
  第一次看原关卡时会现跑一次多轮玩家模拟，要等几秒。

图上方固定写出：当前查看类型、玩家随机种子、坐标轴含义、暂存上限、暂存峰值与均值、本轮是否通关与复活次数。

两种"没有数据"的情况分得很清楚，都不会画成一条贴底的 0 压力曲线：

- **无有效玩家轨迹**：这一轮玩家一次球都没取到、或没记录到暂存变化。会写明是哪种原因。
- **玩家验证接口异常**：模拟根本没跑起来。这时玩家相关数值一律不可用，请把现象反馈出来。

### 9.2 修改前后对比是另一个维度

"叠加修改前后对比"只作用于**全知轨迹**，叠的是同一关修改前和重构后的两条全知曲线。
它和"全知 / 玩家"不是一回事：前者比的是关卡改动，后者比的是求解方式。图例里会分别写清楚，不会只写"修改前 / 重构后"。

纵轴是暂存区当时占用的数量，虚线标出暂存上限，
图上会标出暂存峰值、均值，以及你当前选定的进度区间和主要卡点位置。

重构成功后，勾选"叠加修改前后对比"可以在同一张图上叠加显示原关卡和重构后关卡两条曲线（按各自的进度百分比对齐，
盒数不同也能对比），同时会显示一张前后指标对比表（是否可解、求解步数、暂存峰值/均值、前中后期压力、卡点位置、
难度分档、玩家是否通关、玩家暂存峰值、玩家复活次数、多轮玩家通关率）。

关于**前中后期压力和卡点位置**这几项：它们来自正式审核用的压力样本，不是从点击顺序反推出来的。
如果当前这一关拿不到正式压力样本（比如导入的求解数据里没带），这几格会显示"正式压力审核暂无数据"，
**不会用估算值填上去**——宁可空着，也不给你一个看起来像真的、实际是猜的数字。

## 10. 修改前后对比方法

重构成功后，"重构关卡"卡片会出现"查看原关卡 / 查看重构后"切换：切换后画面、棋盘区、暂存区、自动演示都会
对应显示原关卡或重构后关卡的真实回放，互不影响，可以分别播放核对。

切换到任意一侧后，进度区间会按你当前设置的百分比重新定位（不是直接复制另一侧的定位结果），这样两侧的区间
含义才是一致的。点击"对比当前区间"可以看到修改前后该区间对应的目标图区域：共同区域、只在修改前出现的区域、
只在修改后出现的区域。

点完之后下方会出现一张**进度区域专用对比图**，这是单独画的一张图（不是上方主画布的截图）：
用极淡的灰画出目标图轮廓作定位参考，然后把三类区域各用一种颜色实心标出来——共同区域、只在修改前消除、
只在修改后消除，图内自带图例和各类的像素数，单独把这张图拿出来看也能读懂。导出时导出的就是这张图。

如果没点过"对比当前区间"，导出包里不会有这张图，而是放一份说明告诉你怎么补做，不会拿别的图充数。

## 11. 导出文件说明

- **导出当前视图 PNG / 导出区间定位 JSON**：随时可用，导出当前画面截图或当前区间定位的详细数据。
- **导出修改后 TXT / 导出对比报告**（美术编辑内）：导出改色后的目标图，或一份记录改动像素和颜色变化的报告。
- **导出完整对比包（ZIP）**（需先重构成功）：一次性打包当前这一关的全部内容。目录按"给游戏用"和
  "给工具用"分开，避免拿错文件：

```text
正式游戏端关卡文件/  原关卡_官方格式.json、新关卡_官方格式.json、说明.txt
目标图/              原图.txt、新图.txt
工具内部数据/        原关卡_内部结构.json、新关卡_内部结构.json、
                     原求解数据.solve.json、新求解数据.solve.json、玩家结果对比.json
生效的生成器参数.json
对比/                暂存压力图.png、进度区域专用对比图.png、对比分析报告.md
```

`正式游戏端关卡文件/` 里的 JSON 是官方格式，可以直接交给游戏端；`工具内部数据/` 里的是带完整棋盘的内部结构，
字段与本工具的导入格式一致，可以直接重新导入核验。两者不要混用，目录里也放了一份说明提醒这一点。

`对比分析报告.md` 直接写全了全部指标，不需要再回页面上看：是否可解、求解步数、暂存峰值与均值、
前中后期压力、卡点位置、难度分档、玩家是否通关、玩家暂存峰值、玩家复活次数、多轮玩家通关率，
以及像素守恒、生成器守恒校验、结构死锁检查、盒数、区间连通区域数、三类区域各自的像素数。
报告里的数字和页面上那张指标对比表来自同一份计算，不会出现两处结论不一致的情况。

## 12. 待导出库与批量导出

改多关时不用一关一关分别下载。一关重构成功、核对满意后点"添加为待导出库"，
就可以直接切到下一关继续改，最后一次性全部导出。

**加入的前提**：必须重构成功并通过验证才能加入。没通过验证的关卡不会以"通过"状态进库。

**同一关再次加入**：会更新原来那一条，不会产生两条重复记录。所以某一关改完加进去、后来又想重新改，
重新重构成功后再点一次"添加为待导出库"即可，库里始终是最新那一版。

**每条记录保存的内容**：原关卡标识与来源文件名、原目标图与改后目标图、原关卡与重构后关卡、
生成器参数与实际生效参数、原求解结果与重构后求解结果、进度区间、暂存压力与玩家结果（正式单次 + 多轮）的前后对比、
重构后棋盘与黑块实况、进度区域对比数据、验证状态、**目标图修改时间与重构时间**、条目最后更新时间。

从库里"打开"一条记录时，会把库里保存的修改后目标图恢复到画面上，你可以接着改。
**调取和继续修图都不会自动重构、也不会自动导出**：需要新的重构结果就再点一次"重新生成关卡"，
需要新的导出包就再点一次导出。旧的导出包不会被删除或覆盖——导出文件名带导出时间戳，多次导出互不影响。

**刷新页面不会丢**：库存在浏览器本地，关掉页面、刷新、重新打开工具都还在，直到你主动清除。
需要继续改某一关时在库里点"打开"；如果那一关当前不在导入列表里，会提示你先重新导入该关的文件。

**能放多少关 / 满了怎么办**（2026-08-25 修）

浏览器给每个站点的本地存储配额约 **5 MB**，这是浏览器定的、不是工具设的。
库面板上现在直接显示**占用水位**：已用多少 MB、占配额百分之几、单关约多大、按当前体积还能放约多少关，
超过 60% 标「偏高」、超过 85% 标「接近上限」。

## 13. 主体提取与图纸库（2026-09-02 新增）

这一节对应页面上的 **`12. 主体提取`** 卡片。做的事情是：把一张关卡目标图里**你要的那部分**留下、
其余抹成空白，存成一张"图纸"，攒成一个图纸库，将来把**多张图纸拼到同一张图上**，
让原本一关只有一个主体的关卡变成多主体。

### 13.1 整个流程

1. 导入 TXT 或关卡，进"美术编辑"（第 7 节）；
2. 用五种工具里的选区工具把主体圈出来（第 7.4 节，可以 Shift 加、Alt 减，慢慢修）；
3. 按需点一个剔除按钮：
   - **只保留选区内**：选区外全部抹空 → 用来**提取主体**；
   - **挖空选区内**：选区内抹空、外面保留 → 用来**删掉杂物**；
4. 不满意点"上一步"退回，或"还原全图"回到刚导入的样子；
5. 起个名字点"存入图纸库"；
6. 攒够了点"导出全部图纸（ZIP）"拿到 txt。

第 3 步可以**反复做**：先挖掉左上角一坨杂物，再挖右下角，再只保留中间——每次都记一步，
"上一步"可以逐步退回。

### 13.2 被剔掉的地方写 0，尺寸不变

这两条是刻意定的口径，直接决定后面能不能拼：

- **被剔掉的位置写入 `0`**，不是删掉、不是留空行。所以图纸仍然是一份格式完全正常的 TXT，
  能被本工具、也能被其他读这个格式的地方正常读回；
- **画布尺寸保持原样**。20×20 的图提出来还是 20×20，主体在原来的位置上，**不会被裁到外接矩形、
  也不会被挪到左上角**。

为什么坚持不裁：因为拼接靠的就是"两张图纸的坐标系是同一套"。都保持 20×20，
把两张叠起来就只是**逐格取非 0**，不需要任何平移换算。一裁一挪，拼的时候就得反过来算偏移，
多一层容易错的换算。

画布上值为 `0` 的格子画成**斜纹**（"显示空位斜纹"开关，默认开）。用斜纹而不是某个纯色，
是因为颜色 id 里本来就有深色，纯色填充会和"真的有一个深色像素"分不清。

### 13.3 四种选法分别什么时候用（有实测数据，别当成都一样好用）

拿 `20x20图纸_44关/` 这 44 张真实素材实测过，结论直接写在这里，也写在页面面板上：

| 选法 | 适合的图 | 实测 |
| --- | --- | --- |
| 同色块 | 外圈是**整圈同色**背景 | 如 `2.txt`：色 14 共 153 格且**连成一整块**，点一下外圈就没了 |
| 套索 | 背景色被打断成噪点、或根本没有背景 | 如 `108.txt`：色 25 有 168 格却被切成 **10 块**，从 (0,0) 点下去只连到 **5 格**，同色块基本没用 |
| 矩形框选 | 主体大致方正，或先粗切一刀再修 | 最稳，任何图都能用 |
| 按色选 | 想干掉散布全图的某一个颜色 | 不要求相连，一次全中 |

**44 张的整体情况**：用"选四角同色块"一击就能剔掉 **25% 以上**像素的只有 **20 张**；
剔不到 5% 的有 5 张（`130` 3%、`128` 2%、`125` 1%、`5` 1%、`790` 1%）。

所以口径是：**手动选区（矩形 + 套索）是主力，自动选法只是加速器**。
比例太低时按钮会直接告诉你"这张图自动选法帮不上，请手动框"，而不是让你以为点了就好了。

### 13.4 关于"只留最大连通块"

页面上有这个按钮，但**对这批素材没用**，这里说清原因，免得你以为它坏了：

这 44 张**每一张都是 400 格全部非 0**（没有一格是空的），整张图的非 0 像素**四连通只有 1 块**——
就是整张图。"最大连通块"选出来的就是全图，剔除之后什么也没少。

它有用的场合是：**你已经剔过几刀**、图上出现了空白，主体和残留杂物断开了，
这时候按一下能把剩下的零碎一次清掉。所以它的定位是**收尾**，不是入手第一步。
只有 1 块时按钮会明确提示"对这张图没用"，不会假装做了事。

旁边还有 **"选中零碎小块"**（2026-09-15 新增），和它是一对：

| | 判断依据 | 适合 |
| --- | --- | --- |
| 只留最大连通块 | 只认第 1 块 | 图上确定只有一个部件 |
| **选中零碎小块** | **尺寸阈值**（不超过 N 格） | 想留下次大的有用部件，只清真正的碎渣 |

实测你那张熊猫图剔掉背景后有 24 块：主体 2206 格，其余 23 块合计只有 103 格、单块最大 37 格，
所以阈值填 40 就能一次清净而不碰主体。阈值填得太大会把主体也圈进来，
这时按钮会**明确警告**并告诉你该调到多少以下，不会让你一剔就把图清空。

### 13.5 图纸库

- **和"待导出库"是两个库，互不影响**。图纸存在浏览器本地一个**独立的位置**
  （`antArtTool_pieceLibrary_v1`，关卡库是 `antArtTool_exportLibrary_v1`），
  所以清空图纸库不会动到你攒的关卡，反之也一样；
- 每条记录：名字、尺寸、非 0 像素数、用到的颜色、**主体外接矩形**、来源文件名、做过哪几步剔除、时间。
  列表里带缩略图；
- **同名会自动加序号**，不会悄悄覆盖你之前存的；
- **全空的图不给存**（会明确报错）。全抹空了才存进去，后面拼接时就是一张什么都没有的图纸，
  不如当场告诉你；
- 点一条可以**读回画布**继续改。尺寸和当前画布不一致时会**拒绝并说明**，不会强行拉伸或截断；
- 导出：
  - **导出全部图纸（ZIP）** = `图纸/*.txt` + `清单.csv` + `说明.md`；
  - **导出图纸库（JSON）** = 一个文件带走全部，可以在另一台机器上导入回来。
    导入时会按类型过滤，混进来的非图纸内容不会被收进图纸库。

可以直接逐格取非 0 合并，不需要坐标换算。这一条用两张 20×20 各提一半（左右正好互补）验证过。

### 13.7 去毛边：只清边缘的描边色，主体轮廓一格不动

这是 2026-09-15 针对你提的蜗牛图和熊猫图新增的做法。

**先说清问题在哪。** 你那两张图的边缘主要是黑色（深灰，色 33）在起作用，但**同一个颜色也构成主体的轮廓**。
实测：

- 熊猫图深灰共 **573 格**，其中左右边缘带里只有 **68 格**，主体腹地有 **505 格**；
- 而且深灰在图上是**碎的**：熊猫 573 格切成 **94 块**、最大块仅 89 格；蜗牛 267 格切成 **73 块**、最大块仅 24 格。

于是原来的两个工具都不好用：

- **同色块**点一下只能选到 9%~16%，一次够不着整条边缘；
- **按色选**会选中全图 573 格，一剔除，主体轮廓的 505 格**全没了**（实测三张图分别被抹掉 24.8% / 22.9% / 26.1% 的像素）。

**做法（四步）：**

1. 用**套索**圈住要清理的边缘一带（熊猫就圈左右两侧和脚下那条，蜗牛圈底部那条）；
2. 把**叠加方式**改成**交集**；
3. 用**按色选**点一下那个描边色 —— 或者更省事：在下方"选区内颜色"列表里找到该色，点它右边的 **"只选"** 按钮；
4. 到「12. 主体提取」点**"挖空选区内"**。

第 3 步得到的就是"**圈里的那个颜色**"，实测熊猫是 68 格。第 4 步剔除后：边缘带里的深灰清空，
**主体腹地那 505 格深灰一格没少**，其它颜色也一格没动。

**"只选"按钮**（在"选区内颜色"每一项的右边）是这套流程最省力的入口 ——
那个面板本来就列出了选区里有哪些颜色、各多少格，点一下就等于"圈定范围 ∩ 这个颜色"，
不用切工具也不用先改叠加方式。按住 Shift/Alt 点它则是加选/减选，
对象同样是"**选区内的**该色"而不是全图该色。

同一条边缘可以反复做：换个范围再来一次，或者换个颜色再来一次。每次剔除都记一步，"上一步"能退回。

> **为什么不做成一键"自动去毛边"？** 试算过按形态学"剥掉最外一层"的做法：
> 会削掉蜗牛 10.6%、熊猫 14.7%、财神爷 22.1% 的像素，**主体轮廓会跟着被削**。
> 那不是去毛边，是啃主体。所以这里保持半自动 —— 范围由你圈，工具只保证"只动圈里的那个颜色"。

> **为什么熊猫的栅栏不能用"只留最大连通块"清掉？** 实测那些栅栏、花盆、脚下的部分
> **与熊是连通的**，全都在那个 2206 格的最大块里。最大连通块只能清掉右上/左上散落的小花（23 块 103 格）。
> 栅栏必须靠上面这套圈范围的办法。

## 14. 图纸拼接工作台（2026-09-18 拼接 2.2）

这是主体提取那条链的终点：把抠出来的部件摆到一张新画布上，做成**多主体**的目标图。
点顶栏的 **🧩 拼接图纸** 进入，它是独立工作台，**不会动你正在改的关卡**；
点「退出拼接」回到常规界面，画布和图层都留着。

### 14.1 整个流程

1. **① 新建画布**：填行、列，点「新建画布」。这就是新 txt 图的规格，不限于 55×55；
2. **② 部件来源**：「导入 TXT 图」（可多选）或「从图纸库全部添加」。进入拼接时如果图纸库里有东西会自动带进来；
3. 在部件列表里点 **「放上画布」** → 它成为一个**图层**。工具会自动找一个不与已有部件重叠的空位；
4. **拖拽**挪位置。选中后用**方向键**逐格微调（按住 Shift 一次 5 格）；
5. 先按需要生成**包围 / 背景 / 分隔**规则层，再用 **⑥ 检查输出**；
6. **导出拼接图 TXT** 或 **存入图纸库**。

②「部件来源」、③「画布上的图层」、以及出图区里的「最终效果与稀少颜色」都可以点右上角
**悬浮**，脱离右栏后拖到任意位置；拖右边缘、下边缘或右下角可以拉大拉小。

### 14.2 图层控制与摆放期可以叠

这是刻意分开的两件事：

- **编辑期**：部件可以随便叠在一起，工具只把重叠的格子用硬边红框标出来，不阻止你做任何操作。
  先大致摆好再慢慢调，这跟美术平时的习惯一致；
- **出图时**：重叠也不阻止导出。最终从底层空白开始，按图层列表真实层序从下往上合成；
  同一格有多个非 0 像素时，**只输出最顶层的像素 id**。检查面板只提示覆盖了多少格、涉及哪些图层。

主体**伸出画布**或部件**完全在画布外**现在只提示，不阻止导出。导出 TXT 时只写当前画布内的最终像素；
如果你是从 60×60 改成 50×50，旧背景或旧主体超出去的部分会自动裁切。真正会被拦的只有：
最终图为空；或勾选「要求背景填满」时仍有背景空洞。

图层列表支持按职责区分 **主体 / 包围 / 分隔 / 背景 / 手绘**。点击同一格内连续重叠的可选图层，
会在命中的图层之间轮换；在移动工具下从空白处拖动，可以框选多个图层。框选时按住 Shift/Cmd
会把结果加入当前选择，减少“点不到下面那层”的情况。

### 14.3 图层能做什么

每个图层在列表里都有一排小按钮：

| 按钮 | 作用 |
| --- | --- |
| 改名 | 修改图层显示名称，便于区分多个主体 |
| 复制 | 复制图层并自动偏移 1 格，复制后自动选中新图层 |
| 换色 | 把这个图层的全部非 0 像素换成当前画笔色，包围子层也能直接这样改色 |
| 置顶 / 置底 | 移到全部图层的最上层 / 最下层，最终导出会尊重这个层序 |
| ↑ ↓ | 调层序。越上层越后画，重叠时盖住下面的 |
| 居中 | 把这个部件在画布上居中 |
| 固定 | 锁住位置防误拖（固定后拖不动也画不了，会明确提示） |
| 隐藏 | 暂时不显示，**也不参与覆盖提示与导出** |
| 移除 | 从画布拿掉（部件列表里还留着，可以重新放） |

**多选合并**：在画布上 **Shift 点击**、或在图层列表里 Shift 点名字，选中 2 个以上后点
「合并选中图层为新主体」。合并后它们变成一个整体，**不能再单独拖开**。
如果被合并的图层之间原本有重叠，被盖住的像素会**真的丢掉**（不是暂时挡住），工具会明确警告。

拖拽是**无损**的：位置只记一个偏移，部件本身的像素一格不动，所以拖来拖去、拖回原处都不会有损耗。

### 14.4 规则生成：包围、背景与分隔

拼接 2.2 把“主体摆放”和“画面规则”拆成不同图层，避免把背景、包围线误当成主体覆盖错误：

- **生成主体包围**：必须先选中主体。选中一个主体就只为它生成包围；Shift/Cmd 多选多个主体，就给每个主体分别生成一个包围**子图层**。
  子图层默认在父主体下方，拖动父主体时会一起移动；子图层本身也可以单独选中、微调、隐藏、删除或换色；
- **生成背景**：整张画布生成有规律的颜色底层，支持斜纹、棋盘、点缀、条纹和纯色，不再是单一颜色硬填；
- **生成主体分隔**：根据主体外接范围的接近区域生成分隔层，限制作用距离和线宽，且不覆盖主体；
- **生成背景+包围+分隔**：按当前参数依次生成三类规则层；
- 同类规则再次生成时会替换旧规则层，不会改动主体原图；
- 背景层默认固定且不参与画布点选，避免拖动主体时误抓背景。

背景默认插到最底层，分隔默认插在背景上方，包围默认插在父主体下方；但最终导出只认图层列表的真实层序。
如果手动把某个层置顶，它就会成为对应格子的最终输出来源。

包围色、背景主色、背景辅色、分隔色的输入框都可以直接手填色号，也可以点输入框旁边的色块展开 34 色列表。
列表里会显示色块、中文色名和色号，不用再靠数字猜颜色。

### 14.5 在图层上画（涂色 / 直线 / 边框 / 填充）

**新建画布后直接就能画**，不用先手动建图层。规则是：

| 当前状态 | 画到哪里 |
| --- | --- |
| 画布上还没有图层，或一个都没选中 | **自动新建一张覆盖整张画布的「绘制层」**并选中它，这一笔就画在它上面。接着画都落在同一层 |
| 已经选中某个部件 | 画在**那个部件**上（画到部件范围外的部分会被忽略，并告诉你） |
| 选中的部件被**固定** | 不画，提示你先「解固」或另起一层。锁了就是锁了，不会偷偷帮你新建 |
| 选中了**多个**图层 | 不画，提示先单选一个（说不清该画到哪个上面） |

自动建出来的叫「**绘制层**」，手动点「新建空白图层」建的叫「空白图层」，方便你在列表里分辨。
想另起一层就点「新建空白图层」。

> 画布还没建的时候点画布会提示你先去①新建画布，不会毫无反应。

| 工具 | 用法 |
| --- | --- |
| 移动图层 | 默认。拖部件挪位置 |
| 手动涂色 | 按住拖，经过的像素改成当前颜色。快速拖动也不会有断点 |
| 直线 | 拖出起点到终点，**松手才落笔**；拖动中有半透明预览 |
| 填充 | 点一下，把与该点相连的同色（或空白）区域整片换色 |
| 边框 | 拖一个范围松手即生成；或点「铺满整张画布」 |

**线宽**填在下面，单位就是**格**。勾「当橡皮擦」则把经过的地方涂成空（值 0）。
画笔颜色在「当前画笔颜色」里点选，和「8. 美术编辑」用的是同一个颜色。

**一笔算一步**：拖一条长线只需撤销一次，不用点几十下。撤销/重做的完整口径见 14.10。

### 14.6 六种边框形态与局部替换

边框形态有六种：**田字格 / 口字型 / 斜线型 / Z型 / L型 / N型**，都可以选颜色和线宽。

生成后，下面会列出它的**各个部件**，可以单独给某一部件换色。以田字格为例，它的部件是
外框 / 中间十字 / **左上口 / 右上口 / 左下口 / 右下口** —— 所以「把左上那一口单独换个颜色」
点一下就行，其余一格不动。Z型是上横/斜段/下横，L型是竖段/下横，N型是左竖/斜段/右竖。

**自制边框**：在空白图层上画好之后，点「把选中图层导出为模块 TXT」存成一个模块图纸，
再用②的「导入 TXT 图」加回部件列表 —— 从此它就是一个可以反复使用的自制边框。

关于线宽：同一个线宽在所有形态里都是**实际粗细**，且**不会超出你拖的那个范围**。
（贴边的线向内侧加宽，中间的十字两侧均匀加宽。）

### 14.7 出图口径

- 导出的 txt 就是标准格式（首行「像素矩阵」，空位是 `0`），能再导入本工具，也能交给生产侧；
- 「存入图纸库」会把拼接结果作为一条新图纸存进去，**它自己也能当部件再拿来拼**。
  条目里记了是哪几个部件、各自摆在什么偏移，可以追溯这张图是怎么拼出来的；
- 尺寸就是你新建画布时定的规格。
- 默认勾选「要求背景填满后才能出图」。未生成背景，或拍平结果仍有 0 格空洞时，检查会提示具体空洞数，
  导出和存图纸库都会被拦；取消勾选后可以只按主体合法性出图，但这属于明确放宽校验。
- 重叠不再拦截导出；检查面板只做覆盖提示，导出结果永远按最顶层像素 id 生成。
- 画布外裁切不再拦截导出；检查面板只提示超出格数，TXT 只输出当前画布内的像素。
- 隐藏层、辅助层和 `exportable=false` 图层不会进入最终 TXT。
- 点「最终效果图」可以查看无高光、无描边、无选中框的真实输出预览；下面的颜色分布列表和导出 TXT 使用同一份拍平结果。

> **生产侧还没适配**：多主体关卡在生产/求解那边是否需要额外处理，本轮没有涉及也没有验证过。
> 目前拼接只保证「产出一张格式正确的多主体目标图」。

### 14.8 最终效果、稀少颜色检查与悬浮面板

「最终效果图」只显示真实输出，不画覆盖红框、选中框、边界线，也不会显示稀少颜色高亮。
它下面的颜色分布就是导出 TXT 的颜色分布。

「稀少颜色检查」用同一份最终图统计：

1. 先填阈值，例如「少于 8 格」；
2. 点「检查稀少颜色」；
3. 列表会显示命中的颜色、数量、占比和位置示例；
4. 点「高亮」会在拼接主画布上标出这个颜色的最终输出位置；
5. 点「换成当前色」会把这些最终可见像素替换成当前画笔色。重叠处只改最终可见的顶层像素；固定图层会跳过并提示。

这个功能适合找“只有几格的漏色/碎色/误点色”。它不改导出口径，只是帮你定位和批量替换。

### 14.9 推荐的拼接检查顺序

1. 先开稍大的画布，把主体摆出明显间距；
2. 用图层列表的改名、复制、置顶、置底和固定整理结构；
3. 生成包围、分隔和背景，再点「检查输出」看覆盖、裁切和背景空洞；
4. 若有覆盖提示，按「最终效果图」判断最顶层是否正确；若有裁切提示，确认超出部分是否就是你愿意裁掉的内容；
5. 用「稀少颜色检查」找漏色/碎色，必要时高亮定位并换色；
6. 先导出一份 TXT 做回读验证，再存入图纸库供后续继续拼接。

### 14.10 撤销与重做（2026-10-16 新增）

拼接里**每一步都能退回**：放上小图、生成背景/包围/分隔、拖动摆位、合并、删图层、
改画布规格、清空画布、导入部件，以及画的那一笔。

| 操作 | 怎么做 |
| --- | --- |
| 撤销 | 点 **↶ 撤销**（工作台顶栏与「⑤ 在画布上画」里各有一个），或按 **Ctrl/⌘+Z** |
| 重做 | 点 **↷ 重做**，或按 **Ctrl/⌘+Shift+Z**（也支持 Ctrl+Y） |

几条用法上的说明：

- **一步 = 一次操作**。拖一条长线、连按方向键微调十下、点一次「生成背景+包围+分隔」，
  都只算一步 —— 撤销一下全退回，不会让你点十几次。方向键连按只在相邻 1.5 秒内合并成一步；
  中间做了别的事就分开记；
- **撤销和重做都只看拼接工作台**。常规界面（目标图那边）有自己的编辑撤销，两边互不影响，
  所以 Ctrl+Z 只在拼接工作台里接管；
- **重做会因新操作失效**：撤销之后如果又做了别的操作，就走上了新的分支，重做按钮会变灰
  （和常见编辑器一致）；
- **按钮上会写还能撤几步**：顶栏的按钮显示「↶ 撤销 (3)」＝还能撤 3 步；
- **焦点在输入框里时不抢**：光标在「拼接图名」等输入框里按 Ctrl+Z 仍是浏览器自己的文本撤销；
- 撤销到最开始（连画布都是刚建的）时，会把画布一并退回「还没有画布」的状态，再点就提示没有可撤销的了；
- 撤销步数有上限：栈最长 **60 步**；画笔类（涂色/直线/边框/填充…）压栈后按 **40 步**封顶
  —— 它一次可能动几十上百格像素，留太深会白占内存。

> 实测口径：这一版用无头浏览器把「放上→撤销→重做」「画一笔→撤销只退这一笔」
> 「拖动→撤销回原位」「合并/删除/清空/改规格→撤销」「一键生成→一步撤销」
> 「撤到底再重做到底」「图层列表里的复制/改名/层序/居中/固定/隐藏」等 14 组场景、
> 99 项断言逐条跑过，并把撤销后的画面存进图纸库逐格比对，
> 结果与界面显示一致。

## 15. 常见失败原因和处理方式

- **求解未通关**：说明这条求解路线没能走完，不会出区间结果，请检查关卡本体是否正确、或换一种求解方式重试。
- **重新生成失败，提示"无合格候选"**：生成器在给定的时间预算内没找到满足合格门的关卡。
  可以把改动幅度收小一点、或换一份参数（例如放宽盒容量区间、降低障碍占比）再试。
- **结果里标了"本次棋盘形态未卡住"**：说明按盒数找不到"列比行多 1 或 2"的合法棋盘形态，
  这次退回了随机挑尺寸。关卡仍然可用，但棋盘形态没卡住，需要你自己判断是否接受。
- **提示"玩家验证接口异常"**：这不是 0% 通关率，是玩家模拟没跑起来（盒数为 0 或每轮都没取球）。
  这种情况下玩家相关数值全部不可用，请把这个现象反馈出来，不要按它判断难度。
- **障碍参数核对里某项标了"超出容差"**：先看是哪一项。黑块超出通常是棋盘比盒子需要的大，
  可以调小盒容量区间让盒子数量增加，或调整棋盘行列范围；冰块/问号/锁链超出说明这一版障碍分布偏离了参数，
  重新点一次"重新生成关卡"换一个候选通常就回到容差内。
- **冰块那一项写着"本次不做判定"**：这不是失败。见 8.3 最后一段——本次结果没带上冰块的来源明细，
  没法把按比例设定的冰块和窄路缺口自带的冰块分开，所以工具不做判定，而不是硬给一个结论。
- **导出完整对比包按钮无法点击**：需要先把"重构关卡"跑成功一次，成功后才会出现导出入口。
- **导入后提示缺关卡/缺求解/缺TXT**：说明该关的三件套文件没有配齐，按文件名核对是否有拼写或后缀不一致的问题。
- **拼接出图提示背景未填满**：先点「生成背景」，或关闭「要求背景填满后才能出图」；若要交给生产侧，建议保留默认闸门。
- **拼接提示有覆盖**：这不是错误。导出不会被阻止，重叠格只输出最顶层的像素 id；点「最终效果图」看真实输出。
- **拼接提示有画布外裁切**：这也不是错误。导出不会被阻止，TXT 只输出当前画布内的像素；如果不是故意裁掉，就把对应图层拖回画布内。
- **生成分隔提示没有像素**：主体数量不足、主体距离太远，或「距离」参数太小；可增大分隔距离，或先把主体摆得更接近。
- **点击总是选到上面的图层**：在同一格连续点击会轮换命中的可选图层；也可以使用移动工具从空白处拖框选。

## 16. 已知限制

- 重构后的关卡结构可能与原关卡不同（棋盘尺寸、管道、障碍都会重排），这是"完全重新生成"的固有取舍，不是缺陷。
  想要"棋盘看起来和原图一样"的做法（原①③）已因骨架容量装不下而删除；
- **玩家相关数值的口径**：正式单次来自生成器内部，多轮来自 5 个固定种子。两者种子不同，
  数字可能不完全一致，这是正常的——判断稳定性请以多轮通关率为准；
- **重新生成的合格门由正式生成器决定**，工具不在外面另加一道门槛。也就是说，多轮通关率低的关卡
  仍可能被生成器判为合格；多轮结果是给你人工判断用的参考，不是自动拦截条件。是否把多轮通关率
  提升为正式合格门，涉及线上生产口径，需要另行确认后再改；
- 重构本身仍是一关一关手动触发（点"重新生成关卡"），工具不会自动批量跑重构；
  批量的是**导出**环节——多关改完加入待导出库后可以一次性打包（见第 12 节）；
- **求解器与生成器现在放在工具目录自己的 `bin/` 里**（2026-08-03 起随工具打包，这样整个文件夹能直接拷到别处用）。
  这是正式代码的一份拷贝，正式来源仍是项目里的 `bin/`。**注意：两者不会自动同步**——
  正式代码更新后如果没有重新拷一次，本工具还是用旧代码跑，而且不会报错。
  需要重拷时按 `bin/来源说明.md` 里的命令操作；
- **目标图始终水平居中**：缩放、恢复默认比例、切换关卡、切换进度区间、进出编辑模式、播放或停止动画、
  从待导出库调取关卡之后都保持居中，不再贴左。图比查看区域宽时仍然可以横向滚动，左右两边都能滚到，
  居中不会让任何内容访问不到，也不会改变点选改色的坐标；
- **拼接已可用，但生产侧仍未适配**（2026-09-15）：拼接工作台能产出格式正确的多主体目标图
  （第 14 节），但**多主体关卡在生产/求解那边是否需要额外处理，仍未涉及、未验证**；
- **拼接没有自动排布**：没有横排/竖排/网格这类一键布局。摆位是美术判断，
  目前是拖拽 + 方向键微调，放部件时会自动找一个不重叠的空位；
- **合并图层不可逆**：多个图层合并成新主体后不能再单独拖开；若它们原本有重叠，
  被盖住的像素会真的丢掉（操作时会明确警告）；
- **绘制工具目前只在拼接工作台里**：直线、六种边框、填充这些是 2026-09-15 为拼接加的，
  「8. 美术编辑」那边仍是原有的拖动绘制与颜色替换，没有接这几样；
- **"只留最大连通块"对全图密铺的图无效**：`20x20图纸_44关` 这批每张都是 400 格全非 0、
  四连通只有 1 块，按了等于没按（按钮会如实提示）。它的用处是在你已经剔出空白之后清残留；
- **自动选法覆盖面有限**：44 张里"选四角同色块"一击能剔 ≥25% 的只有 20 张，5 张剔不到 5%。
  主体提取的主力是手动矩形 + 套索；
- **去毛边是半自动的，没有"一键去毛边"**（2026-09-15）：范围要你自己圈。
  试算过自动"剥掉最外一层"的做法，会削掉蜗牛 10.6%、熊猫 14.7%、财神爷 22.1% 的像素，
  主体轮廓会跟着被削，所以没做成那样。见 §13.7；

  仍然连成 1 块，按连通块的手段无从下手，只能靠套索 + 交集。按钮会如实拒绝并提示，不会假装做了事；

  必须圈范围。这不是工具的缺陷，是这批美术图本身的形态；
