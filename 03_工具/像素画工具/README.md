# 图片 → 像素画目标图（工具）

## 一句话

任何图片（照片/插画/游戏截图/AI 出图）丢进来 → 出**像素画 TXT**（目标图）+ 预览图 + 碎色率报告；
也支持把**已有的 TXT 目标图**缩放成新尺寸。转完直接丢进求解器「导入TXT图」就能生产。

## 用法

```bash
# 图片 → 像素画
node 图片转像素画.js <图片> <列数> <行数> [选项]

# 已有 TXT → 新尺寸（放大/缩小都行；放大是硬边放大，不会糊）
node 图片转像素画.js <目标图.txt> <列数> <行数> [选项]
```

| 选项 | 默认 | 说明 |
| --- | --- | --- |
| `--colors N` | 12 | 最多用几种颜色（超出就按用量保留前 N 色，其余吸附到最近的保留色） |
| `--despeckle N` | 8 | 去碎色：4-连通块小于 N 格的并进邻色（0 = 不处理）。图越花哨越要调大（12~20） |
| `--sample mode\|avg` | **mode** | 取色方式。`mode`＝**主色聚类投票**（2026-10-14 起默认）：格内像素各自的色先按"相近色"聚成一簇，再取最大那簇的代表色 —— 同一条线的抗锯齿像素会合成**一个**颜色；`avg`＝旧的"整格平均色再吸附"口径（对照用） |
| `--protect N` | 0（关） | 细线保护阈值：格内占比 ≥N 的「对比色」（与主色亮度差≥0.25）在**连续两格以上**时保留。`0.3`=中，`0.2`=强。**有线稿/描边的图用它**；带阴影/渐变/照片类的图建议保持 0，否则会撒黑点 |
| `--inner N` | **0.75**（v153 起） | 取色窗口：每格只取**中间这一片**投票（0.75 = 格心 75%）。整格（`1`）会把四边的抗锯齿与立体倒角也算进去 → 深色倒角多投票、描边变粗、黑块变多。AI 放大图/带阴影的图用默认 75%；细碎花纹多可试 0.6 |
| `--bg auto\|none` | auto | auto = 把贴边的背景色整片挖成空位 0；none = 保留。**auto 不看内容**，只认"四边出现最多的那个色" —— 美术自带整圈边框时会被整片挖掉（v153 起转完会报「挖掉了 N 格」，数字大就是挖错了，改 `--bg none`） |
| `--outdir` / `--name` | . / 输入名 | 输出目录 / 文件名前缀 |
| `--bin` | 交接包快照的 bin/js | 取色表 + 碎色闸门判定用 |
| `--lib auto\|older\|official` | **auto** | **色库**（v154 新增）：`older`＝工程惯用的真实毛线 34 色（1-34，0=空位）；`official`＝游戏真实官方 22 色（色号 **0-21**，空位 **-1**）。选 `official` 时**取色表就换成那 22 个真色**，产出的每个色号游戏里都有，可直接上实机；`auto`＝输入是 TXT 就自动认（有 `-1` → 官方；有 >21 的编号 → 老），图片输入按 `older` |

例：

```bash
node 图片转像素画.js ~/Desktop/我的画.png 53 53 --colors 8 --despeckle 12 --name 蘑菇
node 图片转像素画.js Level4_目标图_27x32.txt 53 53 --colors 6 --name 花_放大
# 线稿/描边类（要保住细线）：
node 图片转像素画.js ~/Desktop/线稿.png 53 53 --protect 0.3 --colors 10 --name 线稿
# 直接产出官方色库格式（色号 0-21、空位 -1，能上实机）：
node 图片转像素画.js ~/Desktop/我的画.png 53 53 --lib official --name 蘑菇_官方
```

## 2026-10-15 v154：网页版「像素图精准模式」

**解决什么**：同一片颜色因为高光、阴影、压缩噪点或轻微渐变，被逐格判断成几个不同色号。

网页版新增：

| 选项 | 作用 |
| --- | --- |
| **像素图精准模式** | 默认开启。先取每格中心的中位色，再把全图相近的格心归并，同一簇强制使用同一个色号 |
| **同色归并** | 低/中/高/超强四档。低最保守；带光影的拼豆图可从中开始试 |
| **格心 50%** | 精准模式默认只看格心，避开立体珠子/格子的边缘和倒角 |
| **拼接图提醒** | 如果源图宽高比例和填的行列数差很多，结果区会提示“先裁出单独一张图” |

推荐入口：**勾选「像素图精准模式」+「同色归并：低」+「格心 50%」+ 取消「把贴边的背景色挖成空位 0」**。
如果浅粉、浅灰这类本来就接近的颜色被合并，把「同色归并」调低；如果同一颜色还拆成几段，调到中或高。

> 注意：精准模式不能把左右拼接图变成单张图。像“左边原图 + 右边预览”的对比图，仍要先裁出其中一半。

## 2026-10-15 v154（续）：色库 —— 老色库 34 色 ↔ 官方 22 色

**为什么要加**：拿到官方 JSON 提取的 300 关后，发现游戏真机用的是**另一套 22 色**（色号 0-21、空位 -1），
和工程惯用的 34 色（1-34、空位 0）**没有一个同 Hex 的色**、编号空间还冲突（老的 `0`=空位、新的 `0`=黄色）。
在这之前，工具只能按 34 色取色，要交回实机就得再让求解器做一次近似转换（最远色差 129.4）。

**加了什么**

| 入口 | 选项 | 作用 |
| --- | --- | --- |
| 命令行 | `--lib auto\|older\|official` | 见上表 |
| 网页版 | 「**色库**」下拉（取色板上方） | 老色库 34 色 / 官方 22 色；切换时**取色板会同步重建**，并把当前图按新色表重算一遍 |

**顺带修掉一个真 bug**：TXT 读入原来用 `/^\s*\d/` 过滤数据行，**以 `-1` 开头的行会被整行丢掉** ——
官方 300 关里 **180 关**有这种行、共丢 **5276 行**，矩阵缺行错位（每行都以 `-1` 开头的图会**一行都不剩**）。
已改成 `/^\s*-?\d/`。

**实测**

- 老色库默认路径（`--lib older` 或 `auto`）与改动前**逐字节一致**（9 关对照：凡旧过滤器不丢行的 3 关，
  TXT 与预览 PNG 完全相同；其余 6 关的差异**正好都等于**旧过滤器要丢的行数 → 差异全部来自 bug 修复）。
- 官方 300 关用 `--lib official` 全量跑通：**0 关出错**，产出的编号**只落在 {-1} ∪ [0,21]**，22 色全部用到。
- 工具产出的官方 TXT 能被自己 auto 认出（"出现 -1"），也能被求解器识别为 official、转成老色库
  （越界 0 个），且**新→老→新 往返逐像素无损**。
- 网页版切换色库的验证脚本：`js_web_check.js`（jsdom；找不到会跳过）。

**注意两点**

1. 选 `official` 时，官方里没有的颜色（如 34 色的深灰 `#010101`、中灰 `#BBB6B7`）会落到最近的官方色，
   **画面观感会变** —— 这是"只许用真机色"的必然取舍，不是 bug。
2. `--bin` 指向**没有 `color-libs.js` 的旧工程副本**时（例如 `03_工具/关卡图修改工具/bin/js`），
   老色库照常可用；选 `official` 会给出清晰提示让你换 `--bin`，不会抛一堆栈。

## 2026-10-15 v153：保真度读数 + 取色窗口 + 「挖背景」的代价提醒

**起因（用户实测）**：一张方方正正、本来就对齐到 34×34 格的 AI 像素画，转出来"识别不好，边框的粉色甚至没了"。

**根因（已复现）**：`把贴边的背景色挖成空位 0` 这一项**不看内容**，只认"四边出现最多的那个色"。
那幅画的**整圈粉色边框**正好是四边最多的色 → 被当成背景**整片挖掉**。实测：

```
那张 34×34 的图（1536×1536）：
  挖背景 开 → 挖掉 116 格（10.0%，5 号浅粉），粉色只剩 38 格，保真度 75.6%
  挖背景 关 → 空位 0，粉色 154 格回来，保真度 85.7%   ← 差 10.1 个百分点，就是整圈边框
```

**这一版加了三个东西**

| 加的东西 | 干什么 | 在哪 |
| --- | --- | --- |
| **保真度** | 转换后报「保真度 xx%（不一致 N 格）」。参考口径 = 每格**格心 3×3 像素的中位色** —— 格心那点正是"这格看上去是什么色"，避开了上高光/下阴影/四边抗锯齿。**这是"识别得好不好"的可比较数** | 网页结果区 / 命令行 |
| **「挖背景」代价提醒** | 挖了就在结果区报警：`⚠ 本图挖掉了 116 格（10.0%，颜色 5 浅粉）— 如果这是美术自己的边框/底色，请取消勾选再转一次` | 网页结果区 / 命令行 |
| **取色窗口**（网页下拉 / 命令行 `--inner`） | 每格只取**中间那一片**投票（默认 75%，可选整格 / 60%）。AI 放大图、带阴影描边的图，格子四边有一圈抗锯齿+立体倒角，整格投进去会让**深色倒角多投票**（描边变粗、黑块变多） | 网页「取色窗口」/ `--inner 0.75` |

**推荐设置（AI 生成的像素画 / 本来就对齐到网格的图）**

```
网页版： 取消勾选「把贴边的背景色挖成空位 0」 + 取色窗口「格内 75%」 + 去碎色 0 + 最多用色 0(不限)
命令行： --bg none --inner 0.75 --despeckle 0 --colors 34
```

**这张图的实测对照**（同一张 1536×1536 → 34×34）

| 设置 | 保真度 | 空位 | 粉色 |
| --- | --- | --- | --- |
| 网页版原来的做法（整格 + 挖背景） | 75.6% | 116 | 38 |
| 网页版 + 取色窗口 75% | 76.4% | 116 | 38 |
| **+ 不挖背景（推荐）** | **85.7%** | **0** | **154** |
| 命令行**默认**（`--bg auto --despeckle 8`） | 60.8% | 146 | — |
| 命令行按推荐设置 | 85.6% | 0 | — |

> 命令行默认的「去碎色 8」对这类美术很伤（把小于 8 格的小色块并进邻色）→ 命令行转这种图请显式给 `--despeckle 0`。
> 剩下那 14% 不一致，主要来自源图本身的**渐变/高光/阴影**（一格里的颜色不是纯色，本来就没有唯一"正确"答案）+ 色表粒度。

## 2026-10-14 改了取色口径（为什么）

**现象（用户实测）**：一条**单色**的直线，转出来变成"一节一节不同颜色"的线。

**根因**：旧口径是"整格求平均色 → 吸附到色表"。抗锯齿的直线落在格子里时，边缘像素会把平均值拉向背景，
而且**同一条线的像素会分别吸附到好几个相近的暗色**（例如深棕 20% + 深蓝 20%），每格混到的比例又不同 →
同一条线被切成好几段不同色。

**现在**：默认改成**主色聚类投票** —— 先把格内像素各自吸附到色表，再把"颜色相近"的项**聚成一簇**（簇心取色表色，
不是像素均值，否则相近色并不到一起），取最大那簇的代表色；这样整条线只剩一个颜色。
需要保住细线/描边时，把**细线保护**打开（网页版下拉，命令行 `--protect 0.3`）。

实测（同一张 40×30 的"单色抗锯齿直线"）：平均口径那一行是"中灰/浅灰"这类混色，聚类+细线保护后**整行 32 格全是同一个色**；
同一张甜甜圈截图（40×40）：用到的颜色数 22 → **14**（默认口径），画面明显干净。
网页版（`图片转像素画.html`）与命令行版已对齐成同一套口径。

产出三样：`<名字>_<列>x<行>.txt`（首行"像素矩阵"，空格分隔，0=空位）、`..._预览.png`（带格线的预览）、
屏幕上的**每色格数**与**碎色率**（用的就是生成器那把尺子，上限 22%，直接告诉你过不过闸）。

## 该拿什么图来转（关键）

**适合转的**：扁平色块画、像素画、图标/emoji 风格插画、拼豆/十字绣图纸、剪纸风、乐高/积木风；
换句话说 —— **色少、色块大、轮廓清楚**的图。

**不适合的**：照片、写实插画、有明显渐变/高光/阴影的 3D 渲染图、细密纹理（草地/毛发/噪点）。
这些转出来会到处是小碎块，**碎色闸门（≤22%）过不了**，生成器会直接判"这张图不适合做关卡"跳过。
（真要转，就先把 `--colors` 压到 6~8、`--despeckle` 提到 15~20，牺牲细节换过闸。）

拿到 AI 出图的话，提示词往这几个方向写：`flat vector illustration / sticker / pixel art / 4-color palette / thick outline / no gradient / plain background`。

## 尺寸怎么定（两条硬约束）

1. **碎色率 ≤ 22%**（工具会报）。
2. **棋盘格数 ≈ 车数 + 障碍格**，且 **空格数 ≤ 车数**。图太小（几百像素）→ 车太少 → 大棋盘直接"候选全灭"。
   经验值：**目标图 1500~2500 个非空像素**（约 35×45 ~ 53×53）比较好发挥；想做出"压力"更别低于 ~1200。

## 为了"有压力 + 靠推理"该画成什么样

- **别让一种颜色整圈包外壳**（那是"剥洋葱"，玩家没得选 = 没压力）。
  让 **3~4 种颜色在轮廓上交替出现**，开局就都露头 → 玩家必须选顺序。
- 每种颜色的**露头量**最好**小于一辆车的载客量**（车容量是生成器参数，见 `盒容量下限/上限`）
  —— 这样"取车填不满 → 进暂存等位"才会发生，暂存被压到 3~4 就是卡点。
- 留 1 个**只有少量像素的稀有色**（比如 20~60 像素）当"钥匙色"，它会被切成 1 辆车，什么时候取它就成了推理点。

## 转完在哪微调（不用手绘）

- `02_工程/完整主bin快照_20261012/bin/参考/目标图TXT编辑器_可手动框选版/index.html`：拖拽填充、框选替换颜色、孤立像素扫描。
- 生产器里的「✏️ 手动摆盒」→「改目标图」画笔：点/拖改单格、橡皮擦空、吸管取色、Ctrl/⌘+Z 撤回，
  改完直接「每色人数核对」当场告诉你差多少。

# 单文件网页版（推荐日常用）

`图片转像素画.html` —— **双击就能打开**，不用命令行、不装任何东西、图片不上传。

1. 点左边的框选一张图（或把图拖进去）
2. 定**列×行**（尺寸正好等于原图像素时点「用原图像素」）
3. 按需调：最多用几色 / 去碎色 / 背景挖空 / 哪些颜色允许用（点色块可关掉）
4. 点「转换」→ 右边出**预览**（左原图、右结果，带格线）+ **每色格数** + **碎色率**；
   下面文本框就是 TXT（可直接复制），也能「下载 TXT / 下载预览 PNG」

取色用的是 **redmean 加权距离**（比裸 RGB 欧氏更接近人眼），所以有渐变、抗锯齿、轻微压缩噪点的图也能吸到正确的色号。
网页版里的碎色率是**近似口径**（同色 4-连通块 < 8 格算碎）；要**正式口径**（跟生成器完全一致的那把尺子）用命令行的 `图片转像素画.js`。
