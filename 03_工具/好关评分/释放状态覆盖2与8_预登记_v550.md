# release 状态覆盖 2 vs 8 · v550 预登记

> P1.1 单因素实验。只验证“当前只试前2个高压状态是否漏掉释放”，不修改生成器、关卡、动作排序、容量、棋盘或障碍。

## 1. 假设

v548 在六个 prefix=12 样本中发现：

- 每个样本沿参考路线有22～29个合格高压状态；
- 当前 release 评价只尝试前2个；
- 已试6个备选全部是预算耗尽 unknown，`solvedNoRelease=0`。

因此假设：把状态覆盖从2提高到8，可能在已有关卡和已有路线中找到当前漏掉的释压动作。

## 2. 固定样本

- 图：007。
- 棋盘/seed：7×9/1001、7×9/1002、7×9/32677、9×7/1001、9×7/1002、9×7/32677。
- 生成配置与 v547 prefix=12 完全一致：瞬时连锁、shortDebt、52车、`[20,40]`、targetBuffer4、maxDebt40、2分支、prefix debts12、无障碍、无P7、无trapPost。
- 六个重生成关卡必须分别匹配 v547 hash；任一不一致则该样本不能参与结论。

## 3. 唯一变量

- A：`maxDecisionStates=2`，取 `produceGoal` 已生成的 `_experienceFull.releaseDecision`。
- B：同一关卡、同一 `solveResult`、同一参考路线，只把`maxDecisionStates`改为8。

以下全部固定：

- 状态顺序：沿参考路线从前到后；
- `maxAlternativesPerState=3`；
- `altTimeMs=350`；
- `altMaxNodes=1200`；
- `releaseWindow=4`；
- `minReleaseAmplitude=1`；
- 不增加总替代动作数、不改变动作排序、不额外做路线搜索。

## 4. 指标

每个样本记录：

- hash复现；
- A/B release status、found、decisionsTried、alternativesTried、highPressureStates；
- unknownAlternatives、solvedNoRelease、elapsedMs；
- evidence中的referenceStep、progress、beforeBuffer、minBufferWithinWindow、releaseAmplitude、finalReplayValid；
- A→B状态迁移与额外墙钟。

## 5. 通过 / 否决

### 通过

至少1/6样本满足：

1. A不是found；
2. B为found；
3. B evidence存在且`finalReplayValid=true`；
4. 所有A已found样本在B中仍found。

通过只说明“状态覆盖能救回评价”，不等于关卡整体通过；结构门、完整目标、黑块和真人体验仍需单独验收。

### 否决

- B仍全部unknown：说明只增加状态数不够，下一步按P1.2只改备选动作排序；
- B出现found但最终回放无效：不能算通过，转P1.2/P1.3；
- 任一hash不一致：停止该样本归因，不能拿新关卡替代v547结论。

## 6. 禁止事项

- 不修改生成器、`goalStructPass`、ExperienceGoal源码或生产默认；
- 不同时改容量、车序、棋盘、障碍；
- 不把B的found写成“完整目标通过”；
- 不把未知写成无释放；
- 不增加每动作350ms/1200节点预算。

## 7. 产物与回滚

- 上一版：`0d8f46b`（v549 UI修复）。
- 脚本：`释放状态覆盖2与8_v550.js`。
- 结果：`释放状态覆盖2与8_v550.json`。
- 本实验不产生生产补丁；通过后才讨论是否把状态覆盖接入评价。
