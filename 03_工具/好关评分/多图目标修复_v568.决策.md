# 多图目标 worker 修复决策 · v568

## 问题

v567 多图真实UI：

- 006+010各一个普通worker；
- 两者均使用base食谱与supply；
- 从第1轮起持续`instantPlayout 70/70`淘汰；
- 2关0合格。

单图A/B/C则正常，尤其B分支能够产出目标关。

## 完整配置差异

实际抓取的配置对比：

| 字段 | 单图branch | 多图slot |
|---|---|---|
| goalBases | 1 | 3 |
| portfolioK | 1 | 3/4 |
| p7BaseCount | 1 | 3 |
| requireHardPass | false | true |
| 配方 | A/B/C | base |
| 策略 | A/C supply，B shortDebt | supply |

## 实验

1. 仅把多图策略改成shortDebt：仍noCandidate。
2. 再把配方改成B（exposeCut/1管道/4冰）：仍noCandidate。
3. 再把`goalBases/portfolioK/p7BaseCount`从3/3/3降为1/1/1：
   - 006与010均在第1轮产出候选；
   - 不再是instantPlayout全灭。

## 真实UI结果

最终v568方案：

- 多图每个目标worker使用B配方 + shortDebt；
- goalBases=1、portfolioK=1、p7BaseCount=1；
- 006/1001首轮有关卡并在本轮目标通过；
- 006 PlayerSim最终6/6稳健、6/6冒险、6/6乱点，但qPass因“太容易/没岔路”未过；
- 010/1002在观察的多轮中均有结构有效关卡，但没有目标通过；
- 停止测试时006已经完成，010仍在其预算轮次内，所以本轮不能声称多图质量完成。

## 决策

- v568保留“多图从0候选修复到持续可出关”的修复；
- 不宣称多图目标泛化完成；
- 后续独立seed/留出图必须继续验证010类和更多图；
- targetBuffer继续禁用；
- 单图A/B/C策略保持不变。
