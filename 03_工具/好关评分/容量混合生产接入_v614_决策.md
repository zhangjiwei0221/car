# v614 实验决策：混合容量填盘接入生产

## 要解决的问题

v613 生产关仍出现 `6×7 / 32 车 / 10 黑块（23.8%）`。用户指出此前确定的方案是
“用更多小容量车替代补位黑块”，而不是继续接受合规但明显的黑块占位。

v576 已证明容量可以精确拆成 40 锚点与 6~18 小车，并填满 7×7；但该能力只在实验脚本里，
网页生产没有传入 `capacityMix`。v613 的路线障碍规划器只改冰/链，不改变车数与容量，
因此不可能解决该问题。

## 实验假设

1. 先按容量上限计算最少车数，再从 7×7~9×9 合法棋盘中选择最小可容纳盘面；
2. 固定 `目标车数 = 棋盘格数`，并让每色做精确混合拆分；
3. 试验容量区间使用用户指定的 `6~40`，不允许越界；
4. 黑块固定为 0，不用 `blackPercent` 调整补位；
5. 默认关闭；只有勾选“混合容量填盘实验”时才改变生成配置。

## 改动

- `bin/index.html` 增加默认关闭的“混合容量填盘实验”开关，以及容量上下限输入；
- `app.js` 在开关开启时自动选择 7×7~9×9 的最小可容纳棋盘，并注入
  `capacityMix`、精确目标车数、固定棋盘和 0 黑块合同；
- `generator.js` 随最终结果输出 `capacityMixPlan`，记录计划车数、实际车数、
  容量上下限、40 锚点和小车数量；
- 体检报告和生产记录新增“混合容量填盘”证据；
- 版本升至 v614；
- 新增 `容量混合生产接入_v614.js` 及 4 seed 结果与关卡。

## 验证

### 离线 00199 / 4 seed

- 4/4 有效；
- 4/4 为 `7×7 / 49 车 / 0 黑块`；
- 4/4 容量合同通过；
- 每关实际容量为 `7~40`，有 6 辆落在 `6~18` 小车段；
- seed1001 的 qGate 与 ExperienceGoal 均通过：
  freeLow30%、免费连6、吃满中位3、压力步61%、峰值4、
  中段3/4为84%、显著释放2；
- seed1002/32677/88001 有效且 0 黑，但 qGate 与目标体验未过；
  此轮目标通过数为 1/4，说明“能消黑块”已成立，稳定性尚未成立。

### 真实 v614 页面

- 页面勾选实验后选盘日志为：`源像素1600，容量6~40 → 至少40辆车；选盘7×7（49车/0黑块）`；
- 生产完成 1/1，最终为 `7×7 / 49 车 / 0 黑块`；
- 页面最佳分支为 branch B 第8轮：
  freeLow14%、免费连3、压力步60%、中段3/4为85.7%、显著释放2；
- 体检报告结构门通过，质量仍未过；
- 目标体验显示未通过；最终页面峰窗为3，不能冒充已完成的难关；
- 浏览器控制台 error/warning 为0。

## 决策

1. v614 保留为默认关闭的实验版本；
2. v575 仍是稳定生产基线；
3. “小容量车替代黑块”现已从离线脚本接入网页生产，并在真实页面验证到 0 黑块；
4. 当前主要遗留从“黑块太多”转为“部分 seed 的债务不足”；
5. 下一轮优先在 0 黑块基底上复用 v606/v612 的小车锁链与冰收尾，而不是重新调黑块比例；
6. 多图、多 seed 和 PlayerSim 稳定通过前，不把该实验设为默认。
