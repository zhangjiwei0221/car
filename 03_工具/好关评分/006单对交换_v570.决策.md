# 006 单对交换 · v570 决策

## 结论

**否决。**

预登记的唯一交换：

```text
(1,4) color33/count20
↔
(3,0) color17/count38
```

虽然保持了逐色容量守恒，并让未完成的局部曲线达到 50%，但候选关卡沿原计划路线在 step24 死亡，PlayerSim 也只到 48%。因此不能把局部 50% 当成通过。

## 复现

- 基线 hash：`f91d8cf7...`，匹配；
- 候选 hash：`a5c1b9141c9f69edab04c437f285093d69a8243b8fd90a6ea2cdce29e14e94c3`；
- 两个交换点均为普通盒；
- 交换前后逐色容量和完全一致；
- 容量总量、逐色守恒、aboveMax、棋盘合同仍通过；
- 候选结构门仍通过。

## 失败证据

### 原计划路线死亡

- 候选路线前 22 步与基线相同；
- step23 拾取提前到来的 color17/count38 后：
  - buffer 从 3 升到 4；
  - 只消除 31px，留下 7px 债务；
  - 基线 step27 同样车辆可消除 35px、只留 3px。
- step24 原计划再拾取 `(1,3) color28/count35`：
  - 该车此时完全无法消除；
  - buffer 从 4 升到 5；
  - 没有后续可消除进度，形成死局；
  - 路线在 24 步终止。

### 局部曲线不能作为通过证据

由于路线在中途死亡，`ExperienceGoal` 只得到 16 个中段采样点，局部显示：

- 中段 3/4 = 50.0%；
- maxBuffer = 5；
- 显著释放 1；
- `reference_replay_failed`。

这是不完整路线上的截断指标，不能用于验收。

### PlayerSim

- 未通关，进度 48%；
- 20 次拾取后停止；
- bufferPeak = 4；
- 平均 buffer = 1.45；
- 结束时仍有 4 辆车滞留；
- 最后一次拒绝原因是 `highPressure`。

### qPass 诊断

`Generator.evaluateLevel` 的另一条 Solver 路线也不能救回质量：

- qPass = false；
- 学会后 100%；
- 前瞻 100%；
- T=8%；
- R=13pp；
- 最长免费连 7。

该诊断只作补充，不替代原计划路线；即使它通过也不能覆盖路线死亡。

## 根因修正

原假设“把 color17 提前到 step23 仍只会留下 3px 债务”不成立。

同一辆车在 step23 的当时只可完成 31px，而不是 step27 的 35px。提前四步后：

- 多留 4px 债务；
- 占住一个额外槽位；
- 又阻断后续 color28 的消除；
- 从目标中的“第三辆短债车”变成 step24 的满槽死局。

## 决定

1. 否决该交换；
2. 不追加第二对交换；
3. 不扩大局部交换候选数；
4. 不增加障碍或搜索时间掩盖失败；
5. 下一轮另立一个单因素供给计划策略实验。
