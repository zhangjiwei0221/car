# release 备选动作排序 · v551 预登记

> P1.2 单因素实验。固定 v550 的八个高压状态和全部搜索预算，只改变每状态前三个备选动作的排序。

## 1. 背景与假设

v550 结果：

- 六样本在状态上限8下，2/6 found、4/6 unknown；
- 两个 found 样本 hash 相同，实际只救回一个独立基底；
- 命中仅把 buffer 3→2，仍`significant_release_missing`；
- 四个 unknown 中，9×7/1002与9×7/32677结构已经通过，是最高优先级。

当前排序是：参考动作第一，其余按`Simulator.listMoves`的棋盘顺序取前三个。假设其中部分真正能完成车辆或立即降压的动作因为棋盘顺序靠后而没有进入前三个。

## 2. 固定样本

- 图：007。
- 棋盘/seed：7×9/1001、7×9/1002、7×9/32677、9×7/1001、9×7/1002、9×7/32677。
- 配置与v547 prefix=12完全一致；六关必须匹配v547 hash。
- 参考路线：`produceGoal`返回的同一`solveResult.pickOrder`。

## 3. 唯一变量：备选排序

### A：v550基线

- `maxDecisionStates=8`；
- 参考动作第一；
- 其余按棋盘顺序；
- 每状态前3个；
- 每动作350ms、1200节点；
- 基线状态直接采用v550结果，并要求与v550逐样本状态一致。

### B：即时降压排序

- `maxDecisionStates=8`；
- 参考动作仍第一；
- 非参考动作按以下字典序排序：
  1. 执行后buffer下降量降序；
  2. `canConsume=true`优先；
  3. 本次即时消除像素数降序；
  4. 原棋盘顺序作为最终tiebreak；
- 每状态仍只取前3个；
- 每动作仍为350ms、1200节点；
- releaseWindow4、minReleaseAmplitude1不变。

## 4. 指标

- 六关hash复现；
- B release status、found、decisionsTried、alternativesTried；
- unknownAlternatives、solvedNoRelease、searchLimited、elapsedMs；
- found evidence的referenceStep、progress、beforeBuffer、minBufferWithinWindow、releaseAmplitude、finalReplayValid；
- B找到的动作在排序中的名次、bufferDrop、canConsume、immediateEliminated；
- 结构门、freeRunMax、fullMedian2；
- 完整体验曲线`significantReleaseCount`与`curvePass`，用于区分“评价找到释放”和“目标显著释放成立”。

## 5. 通过 / 否决

### 评价层通过

至少一个v550为unknown的样本在B中变found，且：

- evidence存在；
- `finalReplayValid=true`；
- v550已found样本在B中不丢found。

### 目标相关通过

在评价层通过基础上，至少一个新增found样本的完整体验曲线满足`significantReleaseCount>=1`/`curvePass=true`。

### 否决

- B相对v550没有新增found：动作排序不是当前主因，下一步进入P1.3，分离状态/预算与关卡供给；
- B有新增found但所有新增样本仍`significantReleaseCount=0`：不进入生产，继续只读分析释放幅度或供给；
- 任一hash复现失败：该样本不进入结论。

## 6. 禁止事项

- 不增加状态数、每状态备选数、350ms或1200节点；
- 不修改ExperienceGoal源码、生成器、`goalStructPass`或生产默认；
- 不改变参考动作第一的顺序；
- 不同时改容量、车序、棋盘、障碍；
- 不把found写成完整目标通过。
