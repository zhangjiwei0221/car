# v597 决策：冻结开局免费供给不能逼出前期卡点

日期：2026-10-27

## 实验范围

基底：v594 `3_0__3_3`。

从第1手的6个免费满解格中同时冻结2～4格：

- 颜色28：`(0,0)(0,1)(0,3)(0,6)`；
- 颜色13：`(0,4)(0,5)`；
- 数字冰统一为`numice=4`；
- 2格15个、3格20个、4格15个，共50个变体。

除数字冰外，不改变颜色、容量、车数、棋盘、黑块或其它障碍。

## 总体结果

| 指标 | 结果 |
|---|---:|
| 变体 | 50 |
| 可解、守恒、容量合同通过 | 50/50 |
| 实际前期限压 >0 | **0** |
| 实际前期限压 ≥20% | 0 |
| qGate通过 | 0 |
| 卡点参考门通过 | 0 |
| `maxBuffer≥3` | 7 |
| 实际中后期峰窗 ≥3.5 | 0 |

## 最好组合

`(0,4)+(0,6)`，两个数字冰，颜色分别为13和28：

- qGate：freeLow 67%、免费连13、吃满中位3；
- `maxBuffer=3`；
- 中段3/4=12.5%；
- 全知线实际峰窗3、显著释放1；
- PlayerSim实际峰窗4，但显著释放0；
- 取最差 r9=8、无满解6、独木桥0；
- 前期限压仍为0%。

另外3个组合让PlayerSim出现一次显著释放，但这些组合的`maxBuffer`只有2，实际前期限压仍为0，不能算通过。

## 解释

冻结开局6个免费供给中的2～4个后，求解器和PlayerSim都会重新排路线：

- 有的改从颜色26、30、31、32继续取得满解；
- 有的把压力推迟到中后期；
- 初期始终能找到足够的免费满解，暂存不会自然升到3。

因此问题不是“第1行几个免费口没封住”，而是：

1. 基底的颜色依赖允许路线不断找到替代供给；
2. 当前容量分配让很多颜色在早期就能吃满；
3. 单靠障碍封口会诱发绕行，不能形成前期债务。

## 决策

1. 停止在`3_0__3_3`上继续叠加早冰。
2. 不扩大到5～6个冰，避免用障碍数量掩盖基础车序问题。
3. 下一实验必须改“颜色依赖与早期车序”，而不是继续封供给口。
4. 数字冰保留给已经有早期真实债务的基底，用来放大和稳定卡点，而不是从零制造卡点。
5. v575仍保持冻结，本实验未修改默认生成器。
