# 9×7 显著释放与动作搜索归因 · v553 预登记

> P1.3 只读归因。解释为什么 9×7 三例完整曲线有`significantReleaseCount=1`，但 v550/v551 的 8状态×3备选动作搜索仍为unknown。

## 1. 样本

- 9×7/1001、9×7/1002、9×7/32677。
- 生成配置与 v547 prefix=12完全一致；三关必须匹配v547 hash。
- 固定`maxDecisionStates=8`、每状态3备选、350ms/1200节点、当前动作顺序。

## 2. 归因问题

对每个曲线显著释放事件（`pressure.releaseEvents.amplitude>=2`）：

1. 事件发生在第几个参考动作；
2. 事件前压力是否在20%～85%区间；
3. 事件父状态是第几个合格高压状态；
4. 当前“前8状态”是否覆盖该父状态；
5. 若直接执行参考动作并可回放完整后缀，是否能产生同样的显著降压。

第5项只使用已知参考路线后缀，不搜索新路线、不增加预算。

## 3. 预算审计

对当前前8个高压状态的前3个动作，重复与v550相同的24次有界搜索，并逐动作分类：

- direct release；
- search release；
- 路线完成但释放幅度不足；
- budget unknown；
- 无路线且预算未耗尽；
- 路线存在但最终回放失败。

本审计不提高350ms/1200节点，也不改变状态排序。

## 4. 判定路由

- **覆盖不足**：显著释放父状态不在当前前8个高压状态，但参考动作+完整后缀可回放产生显著释放；
- **动作排序/搜索不足**：释放父状态在前8，参考动作也合法且后缀可回放，但当前评价没有命中；
- **门槛区间错位**：显著释放事件发生在20%～85%之外，当前releaseDecision不会尝试；
- **供给不足**：曲线事件无法在参考路线上重放为合法降压；
- **预算不足证据**：24个动作仍有大量budget unknown，但同时必须报告覆盖/供给事实，不能只归因预算。

## 5. 输出

每关输出：

- 所有显著释放事件及父状态序号；
- 当前前8状态覆盖情况；
- oracle后缀回放证据；
- 24次动作搜索的逐项结果与分类计数；
- release curve原因、结构门、freeRun/fullMedian。

## 6. 禁止事项

- 不增加状态数、备选数、350ms、1200节点；
- 不修改ExperienceGoal源码、动作排序、生成器、容量、车序、棋盘或障碍；
- 不把oracle参考后缀回放写成新搜索发现；
- 不把unknown写成无释放。
