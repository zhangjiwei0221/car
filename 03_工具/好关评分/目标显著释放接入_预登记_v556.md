# 目标体验显著释放评价接入 · v556 预登记

> 生产接线实验。把已分别验证的“中段分层8状态”和“最小释放幅度2”作为同一目标体验评价包接入；时间模式和其他玩法不变。

## 1. 为什么是配置包

- v554验证分层采样能选中真实释放父状态；
- v555验证`minReleaseAmplitude=2`能跳过低幅度释放并命中显著释放；
- 生产当前默认仍是顺序状态、`maxDecisionStates=2`、幅度1，单独改幅度2无法复现实验结果。

因此v556只对`instantChain + experienceGoal=true + acceptMode=target`注入：

```text
maxDecisionStates=8
stateSampleMode='midStratified'
minReleaseAmplitude=2
```

其他调用路径保持默认sequential/2/1。

## 2. 固定样本

- 9×7/1001、1002、32677；生成配置与v547 prefix=12一致。
- 1002、32677结构已通过；1001结构仍有免费连7>6。
- 记录与v547 hash是否一致，但目标模式若因更准确评价而选中不同候选，必须解释，不能静默忽略。

## 4. 通过条件

1. 三个目标样本的最终config均为8/midStratified/2；
2. 1002与32677在目标评价中找到amplitude≥2、最终回放有效的释放；
3. 1001不得被硬判通过；
4. 时间模式hash保持基线；
5. `node --check generator/app/playersim/experience-goal`通过。

- 任一路径仍使用幅度1/顺序2；
- 1002或32677显著释放丢失；
- 1001被错误判通过；
- 时间模式hash变化；
- 需要增加状态数/预算才能通过。
