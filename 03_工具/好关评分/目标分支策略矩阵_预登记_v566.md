> 日期：2026-10-26
>
> 类型：只读实验，确定是否能通过分支多样性覆盖不同供给计划。

## 背景

完整UI配置下：

- supply：4/4有效、4/4结构、1/4目标；通过010/1002；
- shortDebt：4/4有效、4/4结构、1/4目标；通过006/1001；
- targetBuffer：2/4有效、0/4目标；006与1.45容量臂冲突。

因此测试“保留supply，同时让另一目标分支使用shortDebt”，而不是全局替换。

## 固定案例

- 006 / seed1001：supply未过、shortDebt在base recipe下已过；
- 010 / seed1002：supply在base recipe下已过、shortDebt未过。

## Recipes

A（baseline）：

```text
cutMode=layerCut2
maxPipes=2
chainByDemand=4
iceForceSteps=0
```

B（现有的暴露序/少管道分支）：

```text
cutMode=exposeCut
maxPipes=1
chainByDemand=4
iceForceSteps=4
```

## 策略

- supply；
- shortDebt。

不测试targetBuffer，因为完整UI配置下006已复现无候选。

## 固定参数

- 完整 UI 配置：`capScalePlan=[1.45,1.15]`、candidateCount14、p7BaseCount1；
- boardRows4~6、boardCols6~8，如实复现当前页面 base config；
- semanticObstacles、usableSpaceTarget0.86；
- 目标模式20秒、最多2轮/40秒；
- candidateCount14、goalBases1、portfolioK1；
- 局部交换修复保持开启；
- 除 recipe 与 policy 外不改其它参数。

## 通过条件

- 每个案例至少一个分支目标通过；
- 006/1001与010/1002可被同一个两分支组合覆盖；
- 所有分支有效、结构通过、容量守恒、aboveMax=0；
- 仅分支配方不同，不提升总分支数。

## 否决条件

- 两分支组合仍无法同时覆盖两案例；
- shortDebt只在006有效但破坏010 existing supply；
- 分支配方改变导致容量/结构失败。
