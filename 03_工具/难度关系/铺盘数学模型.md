# 铺盘的数学模型（从空棋盘推导）

> 目标：把「怎么摆车」写成可计算的量，而不是靠试。
> 现状数据来自 40×40 图、6×7 盘（42 格）、1500 个彩色像素。

---

## 1. 定义

### 1.1 目标区（只由图片决定，无法改）

对每种颜色 `c`，定义**暴露函数**

```
E_c(p) = 进度 p 时，颜色 c 已经露出（可被消掉）的像素数
```

它是非减函数，`p ∈ [0,1]`，`E_c(1) = P_c`（该色总像素）。
这就是代码里的 `demandCurve`。

**实测开局值**（p=0）：

| 颜色 | `E_c(0)` |
| --- | ---: |
| 32 | **327** |
| 1 | **152** |
| 31 | ~130 |
| 24 | ~90 |
| 其余 | 0~20 |

### 1.2 车

第 `j` 辆车有颜色 `c_j` 和容量 `n_j`，约束：

```
Σ_{j: c_j = c} n_j = P_c          （守恒）
```

### 1.3 释放时刻

一辆车能被装满的最早进度：

```
r_j = min{ p : E_{c_j}(p) ≥ n_j }
```

- `r_j = 0` → **免费车**：从第一步起就能装满
- `r_j > 0` → 要等到某个进度

### 1.4 激活时刻

棋盘上第 `i` 个格子（按暴露距离 BFS 序）大约在第几步被点到：

```
s_i = i / N            （N = 格子数，近似值）
```

严格说这不是单一时刻——玩家可以在前沿里任选。见 §4。

### 1.5 时差（本轮的核心量）

```
g_j = r_j − s(i_j)                   （车 j 放在格子 i_j 上）
```

| `g` | 含义 | 对压力的作用 |
| --- | --- | --- |
| `g < 0` | 点了就满 | **无**（随点随消） |
| `0 ≤ g < 1` | 差一步 | 轻微 |
| `2 ≤ g ≤ 4` | 等两三步 | **正是债务** |
| `g > 5` | 等太久 | 玩家放弃 → 死格 |

## 2. 为什么现在"随点随消"

实测 38 辆车的 `g` 分布：

| `g < 0` | `0~1` | `1~2` | `2~4` | `4+` |
| ---: | ---: | ---: | ---: | ---: |
| **26~28** | 2 | 1~2 | 2 | 5~8 |

**70% 的车 `g < 0`。**

原因是纯粹的算术：色 32 开局就露出 327 px，而一辆车只要 40 px。
`r = 0` 对色 32 的**前 8 辆车**都成立 —— 它们放在哪个格子都是免费车。

> **结论：只要 `n_j ≤ E_c(0)`，这辆车就必然是免费车，摆位无法改变。**

要让 `g > 0`，只有两条路：

1. **增大 `n_j`**（少车大车，方案 A）：`n ≈ 60`，色 32 只剩 5 辆免费车
2. **推迟该色的"可用"**（数字冰）：把它锁到 `E_c` 追上 `n_j` 的那一步

## 3. 压力的数学形式

设第 `t` 步点击的车集合为 `K_t`（每步 1 辆），已装满的为 `F_t`。
**暂存（债务）数**：

```
B(t) = |{ j ∈ K_t  :  r_j > 当前进度 }|
```

约束 `B(t) ≤ 5`（暂存上限）。

用户要的形态：`B(t) ≥ 3` 在进度 30%~80% 的**大部分时间**成立。

**可行性的硬约束**：玩家每步必须能点到车，且必须有车能吃（否则死锁）：

```
∀t: 前沿可点数 ≥ 1
∃t: 前沿中 r_j ≤ p(t) 的车数 ≥ 1      ← 否则一步也走不了
```

把两条合起来，就是**排队平衡**：

> 每步"到货"（新变成可吃的车）至少 1 辆、至多 2 辆；
> 而每步"消耗" 1 辆。差额就是债务的增长速度。

债务要从 0 涨到 3，需要连续 3 步"到货 0 辆"；
要维持在 3，需要长期"到货 ≈ 0.5 辆/步"。

---

## 4. `s_i` 是近似值（必须承认的误差）

真实的前沿有 6~7 格可点，玩家可以任选。所以 `s_i` 不是固定值，而是
**该格第一次进入可点集合的步数**，它取决于玩家怎么清。

这就是为什么"按 `i/N` 排好"经常失效：同一辆车在不同打法下 `g` 会差 2~3 步。

**规避办法**：不要依赖单一 `s_i`，而是让**整个前沿**都满足
"1~2 辆能吃 + 3~4 辆不能吃"。这需要按**层**（row）而不是按格子序号来排。

## 5. 可执行的算法：阶梯铺盘

### 5.1 输入
- 车的列表（颜色 + 容量），已按 `r_j` 升序
- 格子的激活序（按 `(dist, row, col)`）

### 5.2 状态
```
debt   = 当前被迫背债的车数（目标 3）
freeCnt= 当前前沿里能吃的车数（目标 1~2）
```

### 5.3 规则（逐格放置）

```
for 每个格子 i（按激活序）:
    if debt < 3:
        选一辆 r 略大于 s_i 的车（g ∈ [2,4]）   ← 制造债务
        debt += 1
    else if freeCnt < 1:
        选一辆 r ≤ s_i 的车（免费车）           ← 保证能走
        freeCnt += 1
    else:
        选一辆 g ∈ [1,2] 的车                   ← 轻微债务，维持平衡
```

### 5.4 稀缺性问题

当 `r = 0` 的车占 70% 时，`g ∈ [2,4]` 的车只有 2 辆 —— **算法没有材料**。
所以这个算法必须配合 §2 的两条前提之一：

- 车做大（`n ≈ 60`）→ `r > 0` 的车变多
- 或接受"免费车占多数"，只在开局用少量冰把它们的 `r` 推后

### 5.5 验收

布置完后，用真实求解器跑一遍，检查：
- `g` 分布：`2~4` 的辆数应 ≥ 8（现在只有 2）
- 覆盖率 `band3Pct` ≥ 45%
- 开局可点 ∩ 可装满 ≤ 2

## 6. 结论（给实现者的三条）

1. **不要把"摆位"当独立问题**：`g = r − s` 里 `r` 由容量决定，
   容量不定，摆位就是空转。这是 v268~v282 反复失败的根因。

2. **免费车的数量是硬指标**：`count(r_j = 0)`。它是"随点随消"的直接度量，
   现在 15~28（取决于容量方案），目标是 ≤ 8。

3. **冰是唯一的"时间维"手段**：它不改 `r`，但能改"可用时刻"，
   所以它应该只用来处理**开局那几辆免费车**，而不是中段。

## 7. 补充：棋盘是偏序，不是一条线（用户 2026-10-20 的疑问）

> 「我从中间取一辆车，他就解锁下一行的一辆；我取一行的那辆，又会解锁三辆车。
>  如果从不同的位置开局，解锁的车的结果也会不同。」——完全正确。

### 7.1 精确可计算的三件事

设 `Q` = 已清空的格子集合，前沿 `F(Q)` = 与 `Q` 正交相邻且未被点过的格子。
玩家每步从 `F(Q)` 里任选一格 —— **这是一个偏序（partial order），不是全序**。

能精确算的：

| 量 | 算法 | 用途 |
| --- | --- | --- |
| `s_min(i)` 最早可点步数 | 从第 0 行做 BFS 的距离 | 下界：这辆车最晚能多早被点 |
| `s_max(i)` 最晚可点步数 | 若玩家最后才走这条支路 | 上界 |
| 解锁扇出 `fan(i)` | 拿掉 i 后新增的可点格数 | 找"必经点" |
| 前沿宽度 `|F|` | 状态相关，6~7 格 | 玩家的自由度的度量 |

**不能精确算的**：玩家实际的点击顺序 —— 它是自由的。
所以任何摆位方案，效果都是一个**分布**，不是定值。这就是为什么同样参数跑三次，
覆盖率能从 25% 跳到 75%。

### 7.2 该用的抽象：按「层」，不按「格序」

既然顺序不唯一，就不要用线性的 `s_i = i/N`。改用**层号** `L(i)`（行号）：

```
玩家在第 L 层作业时，整体进度 ≈ L / R        （R = 行数）
```

这个估计**对顺序不敏感**：玩家无论从左到右还是从中间开花，
当前作业的层号都只有 1~2 层的波动（前沿永远贴着已清区）。

于是铺盘规则变成：

> **第 L 层的车，释放时刻 r 应落在 `(L + lag) / R` 附近**，`lag ≈ 2`。

这样每一层都是"要等两层"的债务，而层内怎么点都不影响大局。

### 7.3 为什么这能解决"从中间开局"的问题

从中间开局时，前沿会同时包含第 L 层和第 L+1 层的格子，
两层车的 `r` 相差 `1/R ≈ 0.17`（约 6 步）。

- 若玩家先清上层：拿到的车 `r ≈ (L+2)/R`，等 2 层 → 债务
- 若玩家先挖下层：拿到的车 `r ≈ (L+3)/R`，等 2~3 层 → 债务更长

**两种打法都会产生债务**，不会出现"换个开局就白给"。

### 7.4 前提条件（还是要先满足）

按层铺盘要求 `r` 在车集合里有足够的分辨率：

- 需要 `r` 的不同取值 ≥ R + lag ≈ 8 档
- 现在（小容量）只有 3~4 档，因为 70% 的车 `r = 0`

→ **仍然要先解决"免费车占多数"**（方案 A 把车做大，或冰把开局几辆锁住），
  否则按层规则只能把少数几辆 `r > 0` 的车挤在少数几层，一半的层没有材料。

### 7.5 落地顺序（建议）

```
第 1 步：把免费车压到 ≤ 8 辆     （容量 / 冰）
第 2 步：按层铺盘，lag = 2       （本节的规则）
第 3 步：用求解器验收 —— 看 g 分布是否出现 8 辆以上落在 [2,4]
```
