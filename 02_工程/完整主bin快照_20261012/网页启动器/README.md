# 网页启动器

生产器页面**必须用 `http://` 打开**。目录里的东西都是为这一件事服务的。

## 先说为什么不能直接双击 `bin/index.html`

双击 HTML 是 `file://` 协议，会同时失去两样东西：

| 失去的能力 | 后果 |
| --- | --- |
| 后台线程（Web Worker）被浏览器禁用 | 批量生产退回主线程 → 界面卡死、「停止」按钮不即时生效 |
| 没有本地落库服务 | 只能整批跑完再点 ZIP 下载；浏览器一崩，**已生产的关卡全丢** |

用 `http://` 打开才有「每关生产完立刻写盘、写盘确认后才生产下一关」。

## 三种启动方式

### ① 命令行（最可靠，跨平台，推荐）

```bash
cd "<项目根目录>"
node "网页启动器/启动.js"
```

指定端口：`node "网页启动器/启动.js" 8123`

这条路**不需要执行权限、不触发 macOS 隔离属性、macOS/Windows/Linux 通用**。
换电脑后如果双击不好使，直接用这个。

### ② macOS 双击

双击 `启动生产器(http).command`。它会先自愈（补执行权限、清隔离属性），再委托给 `启动.js`。

### ③ Windows 双击

双击 `启动生产器.bat`。同样是找到 node 后委托给 `启动.js`。

> 三种方式的**启动逻辑是同一份**（都走 `启动.js`：选端口 → 起服务 → 开浏览器），
> 不存在「双击和命令行行为不一致」的问题。

## 拉不起来时先自检

```bash
node "网页启动器/自检.js"
```

只做检查、不改任何文件，逐项列出 Node 版本、关键文件、端口占用、
以及 macOS 的执行权限与隔离属性，最后直接告诉你下一步敲什么。

## 换电脑后拉不起网页的四类成因

| 成因 | 现象 | 处理 |
| --- | --- | --- |
| **执行权限丢失**（zip/网络传输常丢 `+x`） | 双击 `.command` 无反应，或被当文本打开 | `.command` 现已自愈；或直接用方式① |
| **macOS 隔离属性** `com.apple.quarantine` | 双击报「来自身份不明的开发者，无法打开」 | `.command` 现已自愈；或 `xattr -cr "网页启动器"` |
| **没装 Node.js** | 提示找不到 node | 装 https://nodejs.org/ ，或 `brew install node` |
| **目标机器是 Windows** | `.command` 根本不执行 | 用方式③ 或方式① |

前两类是跨机器最常见的，而**旧版启动器对这两类完全不能自愈**——这也是本次修复的主因。

## 文件说明

| 文件 | 作用 |
| --- | --- |
| `启动.js` | **跨平台启动器核心**。选空闲端口（默认 8000-8060 扫）、用 `process.execPath` 拉起服务（复用当前 node，绕开 PATH 问题）、按平台调 `open`/`start`/`xdg-open` 开浏览器，并显式打印 URL 备手动复制 |
| `自检.js` | 环境自检，只读不改 |
| `启动生产器(http).command` | macOS 双击入口（自愈后委托 `启动.js`） |
| `启动生产器.bat` | Windows 双击入口（委托 `启动.js`） |
| `生产服务.js` | 本地生产服务：静态托管页面 + `/api/production/*` 逐关落库接口。只监听 `127.0.0.1`，**只允许写 `输出文件/`** |

## 安全边界

- 服务只监听 `127.0.0.1`，不对外网开放；
- 唯一可写目录是 `输出文件/`，路径经清洗与越界校验；
- 每次启动生成一个随机 `serverToken`，页面与服务靠它对应。

## 关闭

启动窗口里按 `Control + C`，或直接关掉那个终端窗口。
