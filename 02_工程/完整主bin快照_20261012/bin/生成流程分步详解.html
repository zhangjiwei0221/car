一句话

把一张彩色拼图拆成小推车，停进停车场，让玩家一辆辆拉走；工厂做很多遍，挑一版“能过、又有点难”的。

七个动作

  1. 拆图：把图案按颜色装车；
  2. 找停车场：选一个装得下的棋盘；
  3. 设路障：摆冰、锁链、传送带；
  4. 试玩：四个不同水平的试玩员；
  5. 体检：qPass 看各项指标；
  6. 修理：A1~A4 按毛病修；
  7. 交付：合格的叫“合格”，不合格也给你看，标“偏松”。
你玩到的一关，就是这七步里“试玩 + 体检”之后的结果。

四个试玩员

🐣 首通新手，10 次过几次
🙂 学会后死几次后，能不能过
🧠 前瞻能往前想两步的人
👁 全知开天眼的电脑，必须能过

体检为什么不是“越高越好”

指标奶奶版
首通新手过太多 → 太简单；过太少 → 太难；要 20~50%
学会后死几次就会 → 100% 说明“一学就会”，后面没压力；要 55~85%
T真正需要做选择的步数；太低 = 一条路走到黑
R高手和普通人差多少；太低 = 大家都走同一条路
free手里空着、随便拿的免费步；太多 = 没压力
J死在“看不见”的管道上的比例；太高 = 不公平
你说的“没压力”，翻译成体检就是：首通太高、学会后 100%、free 太高、T 太低。

切车：目标图 → 车单

把像素剪影切成一辆辆“车”，容量由像素分布决定。

扫描线 · 按暴露顺序切
31 30 34 31 35

输入 / 输出

  • 输入：目标图 TXT（像素颜色 + 剪影）
  • 输出：车单 {color, count, due}，总和必须等于像素总数

两种切法

切法特点
exposeCut按目标图暴露顺序；前沿平均 2~4 时用
layerCut2按层切；前沿过大时用

硬约束

  • 容量区间是用户输入，不缩放、不对半拆；
  • 所有车 count 之和 = 目标图像素数（守恒）；
  • 切不出车 → 直接跳过这张图。

管道为什么不是垃圾桶

  • 溢出才进管道；每管最多 4 辆；
  • 管道同时是“未知信息”，死亡会算 J；
  • J > 20% → A1 修；不是继续塞。

管道死亡为什么可怕

玩家看不到队列里的颜色/数量，第一次死亡无法归因。J 高时优先修公平性，不是加难度。

当前：maxPipes=2 · pipeMaxDepth 硬夹 4 · 单管≤4。

06

诊断主因：先判，再修

每轮只修一个主因，不随机换关。

J > 20管道/问号死亡
A1 公平
T < 10 / R < 15没岔路
A2 岔路
freePct > 50开局白给
A3 收紧
learned < 55太黑
A4 减负

诊断顺序

  1. 公平性 J；
  2. 岔路 T/R；
  3. 开局 free；
  4. 太黑 learned/look。

顺序不能反：J 不公平时，先修 T 只会更黑；free 太松时，先修 T 会被免费步稀释。

诊断是“当前主因”，不是“所有问题一起修”。

A1–A4：每步具体改什么

不是“修一下”，每一步都有明确的格子级动作。

A1 管道公平J>20
  • 合并同色上盘
  • 换位暴露
  • 移管道/降隐藏
A2 压力点岔路T<10 / R<15
  • 35~70% + free≤1 + full≥2
  • 加链/冰
  • 锁安全替代
A3 收紧开局freePct>50
  • 早熟车加冰/链
  • 换深
  • 换切法
A4 太黑减负learned<55
  • 拆一组链
  • 拆一块冰
  • 加安全替代

pipe.queue.splice(qi,1)

A2 具体改动

A3 具体改动

早熟车 numice=1/2
或 与相邻盒成链
或 与 40~65% 债务车交换
A2/A3 都有 T/R/free 守卫：修坏就回滚。

主因 ↓≥5T/R 不崩free 不涨
接受回滚
不改善 → 试下一个算子；全失败 → 基底 dead

守卫

指标限制
T / R掉 >5 拒绝
freePct涨 >5 拒绝
freeRunMax涨 >2 拒绝
J涨 >5 拒绝

最多 3~5 轮；每轮只修一个主因，修不动就换基底，不在一关上死磕。

这是“局部搜索”，不是随机重开。
