# StackSort 关卡求解器 — 项目总结

> 一个纯前端（无框架）的 StackSort 关卡求解器 + 可玩网页。
> 目标：用"玩家最优策略"求解关卡、估计理论最少步数、为关卡设计提供数据。
> 状态：**9 种障碍全部实现，100/100 关全通关，平均最优步数 40.38，全量约 12s。**

---

## 一、游戏机制（核心规则）

- **棋盘**：K 列 × H 行（3×3 ~ 8×8），每格一张色卡；列底（最下行）为出口。
- **暂存区**：只有 1 张手牌。
- **移动**：点击未完成列 → 手牌放入该列顶部 → 整列下移 → 列底卡被挤出成为新手牌 → 步数 -1。
- **完成列**：一列全为同色即完成并锁定（万能牌不参与判定，但列里有万能牌就不算完成）。
- **万能牌(Rainbow)**：1 张/关，最终必须进暂存区；卡在中间且暂存是该列同色时系统自动扶正到底部。
- **胜负**：所有列完成=通关；步数耗尽或炸弹爆炸=失败。
- **合法关卡**：每色数量是行高 H 的整数倍、各色占列数之和=K、万能牌恰好 1 张。

## 二、求解器三层架构

```
第3层  决策分发框架 solveTagged   ← 打标签 → 跑所有决策模式取最优 → 记忆胜出模式
          │
第2层  决策模式（5 种） gated / always / dual / dualLk / gatedX   ← 锁列策略 × 双色块 × 中转扩展
          │
第1层  手牌驱动路由 chooseRoutingMove   ← 每步"手上这张牌该放哪" + 有效步评估 + 中转
```

### 核心原则（设计者确认，贯穿全程）

1. **不靠打分调权重**（已多次验证：加 score 权重会此消彼长、互相污染、whack-a-mole）。
   障碍必须走 **分发 + 刚性策略**。
2. **决策分发是核心**：识别关卡类型 → 打标签 → 跑所有决策模式取最优 → 记住该标签胜出模式 → 同类复用。
   "求解很快，大不了所有决策暴力跑几遍取最优。"
3. **有效步评估**：选放哪列不能只看"该色最多"，要算有效步：
   - 顶部同色连续段（即时有效，最高权重）
   - 挤出底牌是否有用色（2-for-1）
   - 被埋同色（需清杂，打折）
4. **分状态锁列(commit)**：无障碍→无脑锁预期列；有高难度障碍→全场不锁列（容错优先）。

## 三、决策树（完整逻辑）

```
solveTagged(关卡)
│
├─ 1. obstacleTag(state)  打标签 = 障碍组合 + 尺寸桶
│      例：plain@5x5 / Ice@5x5 / Covered+Ice@7x7 / Bomb@4x4
│
├─ 2. 取记忆 decisionMemory[tag]（上次胜出模式）排到最前
│
├─ 3. 对每个决策模式跑 runsPerMode 遍：
│     ┌─────────────────────────────────────────────┐
│     │ 决策模式注册表 DECISION_MODES                  │
│     │  • gated  : 障碍期不锁列（省步、容错，治 L16） │
│     │  • always : 一律锁列（个别关更短，治 L89）     │
│     │  • dual   : 双色块优先 + 不锁列                │
│     │  • dualLk : 双色块优先 + 锁列                  │
│     │  • gatedX : 不锁列 + 中转列临时扩展(空转破局)   │
│     └─────────────────────────────────────────────┘
│        每遍：首遍确定性 → 之后随机平局分流 → 后段放宽 eps 纳入次优步逃生
│
└─ 4. 取所有模式中能通关且最短的 → 记忆该 tag 的胜出模式 → 返回

────────────────────────────────────────────────────────

单遍求解 solveOnce → 每步调用 chooseRoutingMove(手牌驱动路由)：
│
├─ 炸弹爆炸？ → 终止（此路径失败）
│
├─ 看手牌色 X，分析颜色 analyzeColors（区分"有用色"vs"事实杂色"）
│    · 有用色 = 可达副本数 ≥ 行高（能凑满一列）
│    · 被锁住列(冰块/石墙/保护列/Key-Lock)里的色 = 不可达，暂作杂色
│
├─ 若 X 是【有用色】：
│    ① 已锁定为 X 的预期列可点 → 用之（多列并列随机挑）
│    ② 否则在未锁定列里按【有效步评估】选 X 的归属列
│         · 顶部同色连续段 ×20  · 总数 ×6  · 被埋同色 −3  · 挤出有用底牌 +8
│         · 双色块模式：含该底层双色块的列额外加成（灌底层触发转换）
│         · 捆绑：回避仍被绳捆住的列（可选）
│       → gated 模式且有隐藏障碍则不锁列；always 模式或无障碍则锁列
│    ③ X 有用但无归属（预期列被冻结）→ 走中转
│
└─ 若 X 是【万能牌 / 事实杂色】→ 走中转 chooseTransit：
     · 顶部已有同色的列（建立连续性）最优先 +12
     · 越杂乱越适合当中转 +3/色种    · 未锁定列 +5    · 底牌有用 +8
     · 多限定列时万能牌优先丢限定列（化解互锁死循环）+15
     · 【中转列临时扩展，gatedX 模式】杂色空转≥行高步时触发：
       底牌有用 +25、埋的有用色 ×4、允许打扰已起头的列 → 征用新列把有用色顶出来破局
```

## 四、9 种障碍的实现与策略

| 障碍 | 关卡 | 机制（大白话） | 求解策略 |
|------|------|----------------|----------|
| **问号 Surprise** | L8+ | 卡到列底/暂存区才揭示真色 | 低难度，全知版直接读真色，当无障碍 |
| **冰块 Ice** | L16+ | 冻结整列(隐藏)，全场完成 N 列后解冻(数字递减) | 高难度，盯有用色完成去解冻；gated 不锁列 |
| **捆绑 Linked** | L25+ | 横向锁两列，点一列带动整个连通分量旋转 | 低难度，二选一主攻一列；绳到底行即断 |
| **限定色 FixedColor** | L35+ | 列只收指定色/万能牌 | 当作"目标色已知"的普通列；多限定列时万能牌丢进去容错 |
| **石墙 Rock** | L45+ | 锁列(隐藏)，左右任一相邻列完成即解锁 | 相邻列=最高优先，完成它解锁 |
| **双色块 Dual** | L55+ | 块含底层(待完成)+顶层(杂色)，底层完成则转换成顶层乱序列 | 高权重，优先灌底层色触发转换；底层完成=有效完成事件 |
| **锁定列 Key+Lock** | L65+ | Lock 锁列(显色)，Key 卡转到列底则解锁最左被锁列 | 高难度，正常点击钥匙列把钥匙压到底；gated 不锁列 |
| **保护列 Covered** | L80+ | 盖住列(隐藏)，必须先完成一列指定色才解锁 | 高难度，完成有用色顺势解锁；哨兵色(16_4)按"完成任意1列"解锁 |
| **炸弹 Bomb** | L100 | 附在某色块，每步倒计时-1，归零前需完成该色订单否则失败 | 纯时间压力，按色追踪；爆炸即判该路径失败 |

> **关键修复（设计者发现）**：双色块底层完成（转换）也算一次"有效完成事件"，
> 会解冻冰块 / 解锁石墙 / 解锁保护列 / 拆炸弹（用 `completionEvents`/`everCompleted`/`completedColors` 追踪），
> 胜利判定仍只用真正锁定完成的列。

## 五、全量求解结果（100 关，每模式跑 40 遍取最优）

**汇总：合法可支持关 100，通关 100，失败 0，平均最优步数 40.38，全部在步数上限内。**

### 按障碍分类的代表结果（步数 / 上限 · 胜出模式）

**无障碍 plain（24 关）**：L1 4/30、L4 9/50、L13 24/35、L24 44/50、L31 57/70、L42 61/70、L98 58/70 …（多数 gated）

**问号 Surprise**：L8 16/60、L9 20/50、L14 38/50、L40 50/55、L74 49/55（gated 为主）

**冰块 Ice**：L16 19/35、L17 24/45、L20 29/45(always)、L23 34/55、L32 56/75(dualLk)、L94 78/90(always)

**捆绑 Link**：L25 7/35、L26 15/30、L29 31/45(dual)、L33 45/55(dual)、L93 58/75

**限定色 Fixed**：L35 22/40、L36 38/45(always)、L38 43/50、L83 43/50

**石墙 Rock**：L45 13/30、L46 29/40(always)、L51 47/60、L57 35/50(dual)、L61 26/35(always)

**双色块 Dual**：L55 28/60、L56 54/75(dual)、L59 77/80、L79 98/100(always, Dual+Ice)

**锁定列 Key+Lock**：L65 21/35(dual)、L66 31/45、L67 46/60、L72 66/85、L73 68/70(dualLk)、L77 66/85、L78 53/70

**保护列 Covered**：L80 14/30、L81 40/50、L82 41/65、L84 81/95(always)、L86 53/60、L88 51/80、L90 56/65、L92 45/75、L97 39/60

**炸弹 Bomb**：L100 11/30（炸弹倒计时20，剩余11时拆除）

**混合障碍（典型）**：
- L49 Fixed+Ice+Rock 43/45(always)
- L75 Ice+Link+Surprise 58/80(always)
- L77 KeyLock+Rock 66/85(dualLk)
- L88 Covered+Fixed+Surprise 51/80(always)
- L89 Fixed+Rock 62/65(dualLk，需 eps 逃生)
- L99 Dual+Link+Surprise 75/75(always)

### 各障碍标签的胜出决策模式分布

- **gated**（障碍期不锁列）：绝大多数无障碍关、问号、多数冰块/限定/保护列
- **always**（一律锁列）：部分石墙、大尺寸冰块、Covered@8x8、多数难混合关
- **dual / dualLk**（双色块优先）：所有双色块关、部分捆绑关、Covered+Ice

> 同一标签不同关可能胜出模式不同 → 框架对每关都跑全部模式取最优，再记忆"最常胜出"的供同类优先。

## 七、可扩展性

- **新障碍**：引擎加该障碍状态 + `isLocked/isBlocked` 判定 + 完成事件钩子；
  求解器在 `obstacleTag` 加标签、`hasHiddenObstacle`/`analyzeColors` 接入（若锁颜色供给）。
- **新共用决策**：在 `DECISION_MODES` 注册表追加一个模式即可，框架不动。
- **A/B 评估**：换策略前后各跑 `node bench.js 40`，对比"平均最优步数"与"各标签胜出模式"。

## 八、已知遗留 / 待优化

- 多障碍**硬优先级排序**（双色块>钥匙>保护列>石墙>冰块>限定色）尚未显式编码——当前靠"跑全部模式取最优"间接覆盖，可作为后续刚性策略加强。
- 有效步的"顺手连同色"可继续细化（区分"连同色是否增加该列挤压目标色进度"=1+1 还是普通 1）。
- L49 / L89 等少数高压混合关仍需 eps 逃生才压进步数上限（能力 100%，但非首遍确定解出）。
- 双色块"转换后顶层规划"为浅层（未做深度规划），个别关如 L79 步数贴近上限。

## 九、玩家版求解器（模拟真实玩家 + 问号难度标定）

> 全知版读得到问号真色 → 抓不住"问号对人类的认知难度"。玩家版在**不完全信息**下模拟熟练玩家，
> 产出"一次过率/平均步数"，用来反推问号(及后续捆绑等软障碍)的难度权重。详见 `求解器策略推理.md` 玩家版章节。

### 模型
玩家版 = 复用全知版全部策略，唯一区别：决策时**未揭示问号(Surprise)色被屏蔽**。
给 `Solver.solveOnce` 注入 `observe=maskSurprise`（每步生成玩家可见视图，问号色置空；move 仍在真实棋盘执行）
+ 策略开关。全知版默认不传这些 → 零影响。

### 四条玩家策略（设计者定，写入决策树，全量跑取最优）
1. **纯问号关 = 无障碍 → 贪心锁列**（`relaxUseful`：放宽有用色判据，任意可见色都可占列）。
2. **问号+硬障碍 → 障碍优先 + 无可用块时降级挤压问号**（`squeezeUnknown`）。
3. **顺手连色防杂色循环**（`antiJunkLoop`：连色列已全杂色则不再连色，避免空转）。
4. **伪万能中转块**（`pseudoWild`：中转耗尽时把杂色停进"纯连色已锁列"，靠引擎自动扶正免费清除，省 1 步）。

问号是"软障碍"永不改变策略；硬障碍才是目标。实测最优策略普遍是 `greedyA`（贪心+always锁列+③④）。

### 成绩
- 玩家版 **100/100 全通关**，平均最优步数与全知版持平(~40)，非问号关零偏差。
- 问号难度标定（`calibrate-surprise.js`，玩家版 A/B）：紧余量下一次过率随问号密度近似线性下降 ≈ 0.5×密度，
  步数膨胀极小 → 问号难度本质是"紧余量下成功率波动"。推导内部权重 `问号 obsRaw = round(密度×30)`（待接线）。
