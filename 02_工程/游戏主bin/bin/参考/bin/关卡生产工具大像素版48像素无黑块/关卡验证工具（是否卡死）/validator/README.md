# 关卡元素活路验证工具说明

## 工具定位

`validator` 是独立于毛线关卡生成工具的新静态网页工具目录。

工具只读取生成工具保存的关卡 JSON 文件，只验证元素区 `spools` 中元素的可活动性，不验证目标区 `blocks` 的颜色消除逻辑。

后续实现形态与生成工具一致：直接打开 `validator/index.html` 使用，不依赖构建流程和本地服务。

## 输入数据

输入文件为毛线关卡生成工具保存的关卡 JSON。

验证工具主要使用字段：

- `maprow`
- `mapcol`
- `spools`

`toprow` 和 `blocks` 本工具不参与验证。

如果 `spools` 缺失、不是二维数组、或单元格不是对象，应输出文件格式错误并停止验证。

元素区数据必须是矩形二维数组，每一行长度必须一致。如果不是矩形数组，输出 `invalid_data` 并停止验证。

`maprow`、`mapcol` 必须与 `spools` 实际尺寸一致。如果不一致，输出 `invalid_data` 并停止验证。

## 坐标约定

内部坐标使用数组坐标：

- `row` 从 0 开始
- `col` 从 0 开始

结果展示时建议同时输出表格坐标，便于人工定位：

- 表格行 = `row + 1`
- 表格列 = `col + 1`

示例：

```text
数组坐标 row=4, col=2；表格坐标 第5行 第3列
```

## 元素分类

分类优先级固定为：

```text
死元素 > 空格 > 链条 > 普通元素
```

### 死元素

死元素不可移动、不可消失，也不可作为活路。

当前死元素包括：

- 边界墙壁
- 黑块：`id === -1`
- 管道：`type` 包含 `11`、`12`、`13`、`14`

边界墙壁说明：

- 左边界、右边界、下边界视为死路
- 第一行本身是活路来源，不需要通过上边界寻路
- 越出元素区范围的位置视为不可通行

### 空格

只有 `id === 0` 且 `type === 0` 时，才是完全空格。

空格算活路，可以作为寻路路径。

空格不是需要验证的元素，因此即使某个空格没有活路，也不作为失败元素输出。

`id === 0` 但 `type` 是管道时，按管道死元素处理。

`id === 0` 但 `type` 是链条、冰块、钥匙、锁、问号等非管道特殊元素时，输出 `invalid_data`。

### 普通活动元素

除死元素、空格、链条以外的元素，都按普通活动元素处理。

以下特殊类型在本验证工具中不额外阻塞寻路，均按普通活动元素处理：

- 冰块 `4`
- 问号 `6`
- 钥匙 `21-25`
- 锁 `31-35`

如果一个元素的 `type` 同时包含链条 `5` 和其他特殊类型，则按链条元素处理。

### 链条元素

链条 `type` 包含 `5`，并且 `id > 0`。

链条是唯一需要特殊规则处理的元素。

## 基础活路规则

验证核心是从元素区向第一行寻找活路。

规则：

1. 第一行中非死元素的位置默认有活路，因为第一行向上视为出口。
2. 空格可以作为活路路径。
3. 普通活动元素只要能通过上下左右任意方向连接到已有活路，就算活元素。
4. 已经判定为活元素的位置可以继续为其他元素提供活路。
5. 死元素不能作为活路，也不能被验证为活动元素。
6. 所有非死、非空元素都验证完毕并且都能找到活路，关卡才通过。

寻路只使用上下左右四个方向，不使用斜向。

第一行特殊规则：

- 第一行的空格直接算活路。
- 第一行的普通元素直接算活元素，并且可以继续作为活路扩散。
- 第一行的链条元素只能先算该链条端点有活路。
- 第一行的链条端点不能单独作为路径节点继续扩散；必须等链条对两端都满足活路条件后，整对链条才加入活路集合。

推荐实现方式是固定点迭代：

1. 先从第一行的空格和普通元素出发，扩散普通活动元素和空格。
2. 再检查链条对是否满足链条活路规则。
3. 新增活链条后继续扩散普通活动元素和空格。
4. 重复执行，直到没有新的活路出现。

## 链条配对规则

读取数据后先扫描全部链条元素。

有效链条对必须满足：

- 两个链条元素上下或左右相邻
- 不能斜向相邻
- 每个链条元素只能有一个相邻链条伙伴
- 两个链条元素互相配对

如果链条元素找不到伙伴，或一个链条元素同时邻接多个链条元素，应判定为链条配对异常，并输出失败坐标。

斜向相邻不算链条伙伴。只有斜向链条邻接时，应按找不到合法伙伴处理。

链条配对方向：

- 水平链条：两个链条元素在同一行，左右相邻
- 垂直链条：两个链条元素在同一列，上下相邻

## 链条活路规则

链条对不能按普通元素直接扩散，需要整体判断。

单独判断链条中某一个元素时，成对的另一个链条元素所在方向算死路，不能作为该元素的活路来源。

单个链条元素的活路判断：

- 除配对方向以外，在其他三个方向中能连接到已有活路，则该链条元素单端有活路
- 如果该链条元素位于第一行，第一行默认活路也可以使该单端有活路
- 配对方向上的另一个链条元素不能用于单端寻路

链条对整体判断：

- 两个链条元素都单端有活路时，这一对链条才算有活路
- 只有链条对整体有活路后，这两个链条元素才可以加入活路集合
- 加入活路集合后的链条元素，可以继续为其他普通元素、空格或链条对提供活路

示例：

```text
水平链条 A-B

A 判断活路时，不能通过 B 方向寻找活路
B 判断活路时，不能通过 A 方向寻找活路
A 和 B 都能从其他方向找到活路时，A-B 这一对才算活
```

```text
垂直链条 A
         B

A 判断活路时，不能通过 B 方向寻找活路
B 判断活路时，不能通过 A 方向寻找活路
A 和 B 都能从其他方向找到活路时，A-B 这一对才算活
```

## 结果判定

验证通过条件：

- JSON 文件格式可读取
- `spools` 数据可解析
- 所有链条元素配对合法
- 所有非死、非空元素都能找到活路

验证失败时，输出失败元素坐标。

失败类型建议包括：

- `blocked`：普通元素或链条元素无法找到活路
- `invalid_link_pair`：链条配对异常
- `invalid_data`：关卡 JSON 或 `spools` 数据格式错误

输出信息需要尽量详细。链条配对异常应输出所有异常链条坐标，不只输出第一个异常。

输出示例：

```text
验证失败：3 个元素不可活动

1. blocked
   数组坐标 row=4, col=2；表格坐标 第5行 第3列；id=12；type=0

2. invalid_link_pair
   数组坐标 row=5, col=3；表格坐标 第6行 第4列；id=8；type=[5]

3. blocked
   数组坐标 row=5, col=4；表格坐标 第6行 第5列；id=9；type=[5]
```

验证通过时输出：

```text
验证通过：全部元素均可活动
```

## 页面结构

工具页面保持简单，包含：

- 加载关卡按钮
- 验证元素按钮
- 文件名称标签，用于显示当前已加载文件状态
- 结果文本框，用于输出验证通过、验证失败、失败坐标和错误信息

不需要复杂布局，也不需要目标区展示。

## 逻辑检查结论

当前规则可以形成稳定的图遍历验证模型，没有必须依赖目标区消除逻辑的部分。

需要在实现中避免的逻辑问题：

- 不要把空格当作失败元素；空格只提供活路。
- 不要把第一行链条端点直接当作整对链条已激活。
- 不要让链条的一端通过配对方向直接判定为有活路。
- 不要在链条只有一端有活路时把整对链条加入活路集合。
- 不要让黑块、管道或越界位置参与寻路。
- 不要把冰块、锁、钥匙、问号当作死元素；本工具只关心元素能否向第一行找到活路。
- 链条配对异常应单独输出，否则后续活路判断会不稳定。
