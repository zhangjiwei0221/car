# 关卡生产器 · 优化规划与待办

> 核心原则：**用"高手求解路线"的暂存区压力数据衡量难度**；所有障碍的数量与分布都导向这条压力曲线。
> 难度评分体系（权重 0.05/0.4/0.2/0.35、四档 简单0-25/普通25-50/困难50-70/极难70-100）已固化，见《难度评分体系.md》。

## 已完成
- [x] 难度评分体系权重/档位更新并全包对齐。
- [x] **难度阈值改为区间** `[min,max]`（含端点），默认 30-100；网页 + run.js + server.js + 环境变量 `DIFFICULTY_MIN/MAX`。
- [x] **多轮失败兜底**：10 轮仍不合格时，输出"最接近合格"的关卡到 `不合格关卡/`，并在汇总报告标注「不合格 + 原因」（对照 4 套标准 + 卡死）。
- [x] **关卡内嵌分析报告**：合格关卡 JSON 写入 `_analysis`（难度/档位/曲线/卡点/暂存等，合格那一刻固化、无求解器随机性）。
- [x] **功能2 计划A · 分组排序独立工具**：网页 `/sort.html` 导入一批合格关卡 → 读内嵌 `_analysis` → 按「组大小/Boss阈值/起始关号/命名模板」一键分组排序+重命名 → 输出到产出包根目录 `排序结果_日期/`（含 排序清单.csv）。端点 `/api/sort-batch`，逻辑在 `sort_levels.js → sortAndWriteFromLevels`。
- [x] **全部参数接入网页 UI 并同步生效**：生产页可调 **难度区间 / 最大轮次 / 每轮候选 / 冰块占比 / 问号占比 / 锁链密度 / 后区起始行 / 加压增量 / 障碍区域预设**。区域预设升级为**棋盘画布拖拽框选**：选障碍+本次占比%，在棋盘上拉矩形（相对坐标、显示网格、每笔不同色边框、可叠加），作用范围可选「全部关卡」或「勾选 input_txt 里的关卡」。网页 → `/api/start` → `server.js` 转环境变量传给生成器；生成器障碍系数与区域（相对矩形 `rect` 或命名区域）均读环境变量（缺省即原值）。
- [x] **功能3 可视化框选 UI**：已完成（上一条）。生成器 `cellInSpec` 支持相对矩形 `{x0,y0,x1,y1}`（格子中心判定），命名五分区向后兼容。

## 进行中 / 本期目标

### 功能2 · 分组排序（计划A：独立按钮工具）—— ✅ 已完成
- 已实现：网页 `/sort.html`「📚 导入合格关卡 → 批量分组排序」，可调 组大小 / Boss阈值 / 起始关号 / 命名模板，一键重排+重命名，输出到 `排序结果_日期/`。
- 难度来源：读关卡内嵌 `_analysis`（无求解器随机性）。缺 `_analysis` 的关会被标注提醒。

### 功能3 · 障碍生成区域/分栏（导向压力曲线）—— ✅ 已完成（配置驱动）
现状规则：① 数量锁定 ② 几套默认随机位置 ③ 为拟合难度曲线的渐进加压（用高手求解路线撮合）。
已实现：
1. 仍可**预设锁定**各类障碍数量（数量公式不变）。
2. **五分区分栏**：左上/左下/右上/右下/中；每类障碍(冰块/问号/锁链)可写 `{region,count}`，区域配额优先、剩余全盘补齐。
3. **作用域**：`global` 全局 + `perTxt[文件名]` 覆盖；无预设的类型走默认随机。
4. 障碍放置后仍交回求解器反推难度；未命中 `[min,max]` 时保持渐进加压多轮重试。
- 配置：产出包根目录 `障碍区域预设.json`（示例见 `障碍区域预设.示例.json`，说明见《障碍区域预设说明.md》）；run.js/server.js 已通过 `OBSTACLE_PRESET_FILE` 传入。
- 代码：`run_batch_txt_node.js` 的 `resolveObstaclePreset / inRegion / placeSingleTypeWithRegions / placeChainsWithRegions`。
