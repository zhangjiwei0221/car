# 参数配置说明

> 修改本文档对应的代码位置已标注，改参数后直接跑 `node run.js` 即可生效。

## 一、生成参数（关卡生产工具）

**代码位置**：`关卡生产工具大像素版48像素无黑块/tool/scripts/run_batch_txt_node.js`

| 参数 | 当前值 | 含义 | 环境变量 |
|---|---|---|---|
| SINGLE_COLOR_EXTRACT_PERCENT | 5 | 单色提取百分比 | SINGLE_COLOR_EXTRACT_PERCENT |
| SPOOL_BASE_PIXEL_COUNT | 48 | 基础像素（每组球的像素量） | SPOOL_BASE_PIXEL_COUNT |
| FIRST_ROW_RANGE_MULTIPLIER | 1 | 第一行范围倍数 | FIRST_ROW_RANGE_MULTIPLIER |
| NEXT_ROW_RANGE_MULTIPLIER | 1.1 | 后续行范围倍数 | NEXT_ROW_RANGE_MULTIPLIER |
| MAX_PIPE_DEPTH | 6 | 管道最大深度 | 代码常量 |
| MAX_ATTEMPTS | 100 | 单次生成内部尝试上限 | MAX_ATTEMPTS |
| 棋盘最大尺寸 | 10行×9列（列≥行） | calculateBoardSize(totalGroups, 9, 10) | 代码常量 |

## 二、障碍物数量公式

**代码位置**：`run_batch_txt_node.js` → `generateOne()` 函数内

| 障碍物 | 基础公式 | 示例(90格) |
|---|---|---|
| 冰块 | `Math.floor(boardCells × 0.15)` | 13个 |
| 问号 | `Math.floor(boardCells × 0.25)` | 22个 |
| 锁链 | `1 + Math.floor(regularCells / 20)` 对 | 约4对 |
| 管道 | `Math.ceil((totalGroups - rows×cols) / 5)` 个 | 取决于目标图 |
| 黑块 | 0（noblack模式） | 0 |

**修改方法**：网页生产页直接调（冰块占比/问号占比/锁链密度/后区起始行/加压增量/障碍区域预设）；命令行可用环境变量 `ICE_RATIO/QUESTION_RATIO/CHAIN_DIVISOR/BACK_ROW/ICE_BONUS_RATIO`（缺省即上表默认值）。

## 三、渐进加压策略

**代码位置**：`run_batch_txt_node.js` → `generateOne()` + `_placeIceBiased()` + `_coverChainsWithIce()`
**触发方式**：`run.js` 根据循环轮次设置 `DIFFICULTY_LEVEL` 环境变量

| 轮次 | DIFFICULTY_LEVEL | 冰块策略 | 锁链策略 | 数量加成 |
|---|---|---|---|---|
| 第1轮 | 1 | 全棋盘随机散开 | 随机相邻配对 | 无 |
| 第2轮 | 2 | 50%偏向后区(row≥40%)，50%全随机 | 随机 | 无 |
| 第3轮 | 3 | 同第2轮偏向后区 | 锁链格覆盖冰块(20%双覆盖/80%单覆盖) | 无 |
| 第4-10轮 | 4 | 同第3轮 | 同第3轮 | +10%冰块 +1对锁链 |

### 可调参数

| 参数 | 当前值 | 含义 | 修改位置 |
|---|---|---|---|
| 后区阈值 | row ≥ rows×**0.4** | 定义"中后期区域"的行号比例 | `_placeIceBiased()` 的 `threshold` 参数 |
| 后区冰块占比 | **50%** | 偏向后区放置的冰块比例 | `_placeIceBiased()` 的 `backCount = count × 0.5` |
| 锁链双覆盖概率 | **20%** | 锁链对两格都覆盖冰块的概率 | `_coverChainsWithIce()` 的 `Math.random() < 0.2` |
| 冰块加量比例 | 基础×**10%** | 第4轮起额外增加的冰块 | `iceBonus = Math.ceil(baseIce × 0.10)` |
| 锁链加量 | **+1对** | 第4轮起额外增加的锁链对数 | `chainBonus = 1` |

## 四、合格判定参数

**代码位置**：`run.js` 常量区 + `大像素毛线关卡求解器/js/validator.js`

| 参数 | 当前值 | 含义 | 修改位置 |
|---|---|---|---|
| DIFFICULTY_MIN / DIFFICULTY_MAX | **30 / 100** | 难度强度需落在 [min,max] 区间（含端点）；窄区间精准命中 | `run.js` 顶部常量 / 环境变量 / 网页输入框 |
| 卡点暂存阈值 | **≥4** | 滑窗平均暂存达到4算"有卡点" | `validator.js` → `computeDifficultyScore` |
| 趋势符合条件 | 后区峰值 > 前区峰值 且 前期未越位 | 无明确卡点但趋势对也算合格 | `validator.js` → `trendCompliant` |
| 难度值公式 | 0.6×玩家 + 0.4×全知 | 融合权重 | `validator.js` → `W_OMNI=0.4, W_PLAYER=0.6` |

## 五、循环控制参数

**代码位置**：`run.js` 顶部常量区

| 参数 | 当前值 | 含义 |
|---|---|---|
| MAX_ROUNDS | **10** | 最大循环轮次 |
| CANDIDATES_PER_ROUND | **5** | 每轮每关生成候选数 |
| 总尝试上限 | 10×5 = **50次/关** | 超过标记"需美术返图" |

## 六、命名规则

| 项目 | 规则 |
|---|---|
| 输出文件名 | `MMM_NNN.json` |
| MMM | 批次序号，按txt排序从001升序 |
| NNN | txt文件原名（去掉.txt后缀） |
| 每批重新编号 | 每次放入新一批txt从001重新开始 |
