# 关卡分组排序说明

> 自 2026 版起：排序**已嵌入生产流程**，关卡生产 + 审核合格后会自动排序输出，
> 无需手动操作。也可单独运行 `node sort_levels.js` 重新排序。
> 起点为**第1关**，全部合格关卡都纳入自动排序（不再手动保留第1-5关）。

## 一、排序目标

把生产出来的合格关卡按难度分组排序，形成从易到难的平滑曲线，适合玩家递进体验。

## 二、基本规则

| 项目 | 规则 |
|---|---|
| 关卡范围 | **从第1关起，全部合格关卡纳入自动排序** |
| 分组 | 每5关一组，最后一组不满5关并入前一组 |
| 组内排序 | 难度升序（组内第1关最简单，组末最难） |
| 组间趋势 | 组均值平滑递增 |
| 编号 | 关卡号从 1 连续编号，组号从 1 连续编号 |

## 三、排序算法

### 分池策略
1. 全局按难度升序排列所有关卡
2. 分为两池：
   - **普通池**（难度<55）：约90关
   - **Boss池**（难度≥55）：约17关
3. 每组分配：4关从普通池顺序取 + 1关从Boss池顺序取（作为组末boss）
4. Boss池用完后，后续组全由普通池填满

### 组内排列
- 组内按难度升序
- 最后一关（第10/15/20/...关）= 组内最高难度（boss跳升）

### 不符合预期关卡处理
- 不完全靠后
- 简单的不符合关：放前面组的1-2号位（简单位置）
- 难的前移关：放整5关位置（10/15/20等boss位）
- 实际通过全局排序+混合分配自然分布

## 四、输出格式

### 输出位置
排序结果输出到 **`output_sorted/`** 目录：
- `第N关_MMM_NNN.json` —— 排序并重命名后的关卡
- `排序清单.csv` —— 排序明细

### 文件命名
```
第N关_MMM_NNN.json
```
- N = 关卡序号（从 1 起连续编号）
- MMM_NNN = 原始关卡文件名

### 排序清单CSV
输出到 `output_sorted/排序清单.csv`，包含字段：

| 字段 | 说明 |
|---|---|
| 关卡号 | 从第1关起连续编号 |
| 文件名 | 重命名后的文件名（第N关_原名.json） |
| 原名 | 原始关卡名（批次序号_txt名） |
| 难度 | 难度强度值（0-100） |
| 难度档 | 简单(0-25) / 普通(25-50) / 困难(50-70) / 极难(70-100) |
| 曲线质量 | 符合预期 / 趋势符合 / 正常简单关 等 |
| 所属组 | 组1、组2…… |
| 目标区均暂存/均滞留 | 50-90%高压窗口平均值 |
| 前期均暂存/均滞留 | 0-50%窗口平均值 |
| 卡点区间 | 如80-90%（有明确卡点时显示） |
| 颜色种类 | 目标区使用的颜色数量 |
| 棋盘尺寸 | 如9x10 |
| 目标区均暂存 | 50-90%高压窗口平均暂存 |
| 目标区均滞留 | 50-90%高压窗口平均滞留 |
| 前期均暂存 | 0-50%高压窗口平均暂存 |
| 前期均滞留 | 0-50%高压窗口平均滞留 |
| 卡点区间 | 如80-90%（有明确卡点时显示） |

## 五、难度档位（最新）

| 档位 | 难度范围 | 说明 |
|---|---|---|
| 简单 | 0-25 | 适合新手 |
| 普通 | 25-50 | 入门进阶 |
| 困难 | 50-70 | 中等偏难 |
| 极难 | 70-100 | 高难度挑战 |

## 六、预期效果

### 前80关（第6-85关）重点区域
- 每组都有一个≥55的boss关在末尾
- 组基础从难度35渐增到55
- boss难度从55渐增到83
- 每组内部从简单开始逐步爬升到boss

### 后27关（第86-112关）
- 稳定标准难度（50-55区间）
- 作为资深玩家的持续挑战
