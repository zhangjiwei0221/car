# 闭环关卡生产流程

## 一、流程总览

```
美术提供TXT像素图 → 放入input_txt → 启动node server.js → 自动循环生产 → 合格JSON输出 + 自动分组排序 + 批量分析CSV
```

## 二、详细步骤

### 第1步：输入
- 把 `.txt` 像素图纸放入 `input_txt/` 目录
- 要求：11-12种颜色的大像素图（64×64~90×90）
- 8-9种颜色的图不建议使用（数据验证：93%出简单关）

### 第2步：启动
```bash
node server.js
```
- 浏览器自动打开 http://localhost:3000
- 网页上可调参数、导入文件、查看进度

### 第3步：自动循环生产
对每一张 txt 图：

```
┌─────────────────────────────────────────────┐
│  生成5个候选棋盘（调用关卡生成器）           │
│       ↓                                     │
│  对每个候选逐一求解分析：                    │
│    · 全知版求解（确认可通关）                │
│    · 高手档求解（3遍取均值）                 │
│    · 计算难度值 + 曲线判定                   │
│       ↓                                     │
│  判定是否合格：                              │
│    ✓ 难度落在区间 [min,max]（默认30-100，含端点）
│    ✓ 曲线符合预期 或 趋势符合               │
│    ✓ 全知版通关                             │
│    ✓ 高手档通关                             │
│    ✓ 卡死检验通过                           │
│       ↓                                     │
│  合格 → 保存JSON + 保存分析数据 → 退出循环   │
│  不合格 → 进入下一轮（渐进加压策略）         │
└─────────────────────────────────────────────┘
```

### 第4步：渐进加压策略
当前一轮不合格时，下一轮自动调整障碍物布局：

| 轮次 | 策略 | 目的 |
|---|---|---|
| 第1轮 | 全随机（默认参数） | 碰运气 |
| 第2轮 | 冰块50%偏向后区（row≥40%） | 把压力往后移 |
| 第3轮 | 冰块偏后 + 锁链上覆盖冰块 | 制造高压区块 |
| 第4-10轮 | 在第3轮基础上 +10%冰块 +1对锁链 | 加量加压 |

### 第5步：输出
- **合格JSON**：`output_json/MMM_NNN.json`
- **批量分析结果.csv**：所有合格关卡的难度排序（数据来自合格那一刻的分析，不再二次重跑）
- **生产汇总报告.csv**：每关状态（合格/不合格/需美术返图）

### 第5.5步：自动分组排序（从第1关开始）
- 全部关卡审核完后，自动按难度分组排序
- 输出到 `output_sorted/`：`第N关_MMM_NNN.json` + `排序清单.csv`
- 排序规则见《关卡分组排序说明.md》；也可单独运行 `node sort_levels.js` 重排

### 第6步：不合格关卡处理
- 10轮×5候选=50次尝试后仍不合格 → 标记"需美术返图重修"
- 同时输出该关"**最接近合格**"的候选到 `不合格关卡/`（通过闸门最多者，平手取难度更接近区间者），并在 `生产汇总报告.csv` 的「不合格原因」列写明卡在哪几条标准
- 原因通常是：目标图本身压力天花板太低，换棋盘救不了

## 三、合格标准详解

### 难度值落在区间 [min, max]（默认 30-100，含端点）
- 计算方式：0.6×高手强度 + 0.4×全知强度
- 四因子：线轴数(0.05) + 暂存占比(0.4) + 滞留步数(0.2) + 高压步数(0.35)
- 窄区间可精准命中某难度段；环境变量 `DIFFICULTY_MIN/DIFFICULTY_MAX`，网页有「难度区间」输入框

### 曲线符合（二选一即合格）

**符合预期**：50-90%进度区间的10%滑窗平均暂存≥4，且前期(0-50%)没有越位

**趋势符合**：50-90%的峰值窗口暂存 > 0-50%的峰值窗口暂存（虽没到4但趋势对），且前期未越位

### 通关检验
- 全知版：3步前瞻+全局规划，必须通关
- 高手档：信息受限+3步前瞻+误触0.025，3遍取均值，必须通关

### 卡死检验
- 使用 LevelActivityValidator 检查结构性死锁
- 放在最后对合格JSON统一核验

## 四、关键设计决策

1. **只跑高手档**：不跑菜鸟/中级，高手是基准线（速度快2-3倍）
2. **合格时即保存数据**：不二次重跑分析，避免seed随机性导致不一致
3. **渐进策略**：不一上来就加压，先碰运气再逐步加码
4. **命名规则**：MMM_NNN.json（批次序号_原名），每批从001升序
5. **不符合预期的关 ≠ 废弃**：只要趋势对+难度够也算合格

## 五、命名规则

```
输入：22_11种.txt
输出：029_22_11种.json（029=该txt在这批中的排序序号）
```

## 六、工具依赖

| 模块 | 位置 | 功能 |
|---|---|---|
| 关卡生成器 | `关卡生产工具大像素版48像素无黑块/` | 吃txt产JSON棋盘 |

| 卡死检验 | `关卡验证工具（是否卡死）/` | 结构性死锁检查 |
| 网页前端 | `web/index.html` | 操作面板 |
| 服务器 | `server.js` | 后端核心逻辑 |
