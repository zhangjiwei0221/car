# 三档玩家求解逻辑说明

本文档整理当前求解器内部的三档玩家模拟逻辑，来源于 `js/validator.js` 中的玩家求解模块。该逻辑的目标不是只求一个理论最优解，而是把不同水平玩家在信息受限、暂存压力、误触和重开尝试下的表现模拟出来，用于观察关卡对不同玩家层的真实压力。

## 1. 整体定位

当前求解体系里有两类求解视角：

| 视角 | 用途 | 特征 |
| --- | --- | --- |
| 全知/高手基准求解 | 关卡生成、审核、难度曲线基准 | 更接近高手路线，用稳定策略衡量关卡结构压力 |
| 三档玩家模拟 | 网页端观察玩家分层表现 | 菜鸟、中级、高手分别模拟，观察技能差异、死亡风险和路线差异 |

需要注意：生产审核接口目前保留为 `StrongOnly`，只跑高手档作为稳定基准；网页端展示接口使用 `PlayerTiersUI`，会恢复菜鸟、中级、高手三档路线，便于看玩家分层。

## 2. 三档玩家配置

三档玩家都处在“信息受限”模式下：

- 问号球只有激活后才知道颜色。
- 管道只看到出口球，不能提前知道整条管道的完整序列。
- 暂存区上限为 7，玩家档中结算后达到或超过 7 会判定死亡。
- 暂存压力变大时会提升推理深度，模拟玩家在危险时会更谨慎。

| 档位 | 权重 | 最大尝试次数 | 常态前瞻 | 高压前瞻 | 是否均匀取管道 | 误触率 | 玩家画像 |
| --- | ---: | ---: | ---: | ---: | --- | ---: | --- |
| 菜鸟 | 30% | 12 | 1 步 | 2 步 | 否 | 8% | 基本按眼前收益点，压力来了才稍微多想，失误和重开最多 |
| 中级 | 40% | 8 | 2 步 | 3 步 | 否 | 5% | 能做短线规划，高压时接近高手推理，但管道管理仍不稳定 |
| 高手 | 30% | 4 | 3 步 | 3 步 | 是 | 2.5% | 稳定三步前瞻，会主动均衡管道消耗，失误和重开最少 |

这三个档位不是简单改一个分数，而是同时改变了“看几步、会不会均管道、会不会误触、能失败重开几次”四个维度，因此更接近真实玩家层级差异。

## 3. 单档玩家求解流程

单档求解由 `runPlayerTier(...)` 控制，核心流程如下：

1. 读取当前档位参数，包括前瞻深度、误触率、是否均匀取管道、最大尝试次数等。
2. 从第 1 次尝试开始运行玩家版求解器 `runSolver3Step(...)`。
3. 如果本次求解通关，记录 `attempts` 并返回。
4. 如果失败，增加随机扰动 `noise`，换一个随机种子重新尝试。
5. 达到最大尝试次数仍未通关，则返回进度最好的那次结果，并标记 `attemptsCapped = true`。

这相当于模拟玩家“失败后重开”的行为。菜鸟允许更多次重开，高手允许更少次重开，因为高手路线本身更稳定。

## 4. 多次重复取均值

单档玩家不是只跑一次，而是由 `runPlayerTierAvg(...)` 重复运行 3 遍后取均值，减少随机误触和随机扰动造成的偶然波动。

当前会聚合这些指标：

| 指标 | 含义 |
| --- | --- |
| `completed` | 3 次中至少一半通关则视为该档可通关 |
| `passRate` | 该档 3 次重复中的通关率 |
| `totalSteps` | 平均步数 |
| `progress` | 平均消除进度 |
| `maxBuffer` | 平均最大暂存占用 |
| `avgBuffer` | 平均暂存占用 |
| `avgBufferRatio` | 平均暂存占用比例 |
| `attempts` | 平均重开尝试次数 |
| `misclicks` | 平均误触次数 |
| `avgResidence` | 平均滞留时间 |
| `maxResidence` | 最大滞留时间 |
| `residenceByBand` | 按 10% 进度分段统计滞留 |
| `peakResidenceBand` | 滞留压力最高的进度段 |

展示用路线 `pickOrder` 和曲线历史会取最后一次运行作为展示主体，数值指标则使用 3 次均值。

> 审核接入补充（与生产审核对齐）：`runPlayerTierAvg` 现额外产出 **`ballCurveAvg`/`ballResAvg`**（3 遍"按球暂存曲线"的逐球平均），用于**稳定的合格判定**（`computeDifficultyScore(..., {curveMode:'avg'})`）；并保留 3 遍原始解供 `analyzePlayerSolution` 用 `_selectBestRun` 挑出**"最好的一遍"**（通关+个体符合+前期最低）作为**导出/展示**解法（写入 `审核求解数据.json`，网页直接复用、不再临时求解）。即"判合格看 3 遍平均、展示与导出看最好那遍"。详见 `关卡审核体系.md` §1/§8。

## 5. 玩家版决策逻辑

玩家版求解器每一步都会先找出当前可取球，然后在“不会立即爆暂存”的候选中做决策。

### 5.1 安全候选过滤

每一步会先模拟候选球拿走后的暂存变化：

- 如果结算后暂存数量达到或超过 7，该步不可选。
- 如果所有候选都会爆暂存，则本次尝试死亡。
- 玩家模式只防即时溢出，不使用未来全知信息做安全检查。

这能模拟普通玩家只基于当前可见信息判断，而不是提前知道所有隐藏内容。

### 5.2 前瞻深度

玩家的正常决策深度由档位决定：

- 菜鸟：常态 1 步，只看当前收益。
- 中级：常态 2 步，会看一步后续。
- 高手：常态 3 步，能稳定做短期规划。

当暂存区压力达到 `BUFFER_LIMIT - 3`，也就是暂存数量大于等于 4 时，会切换到高压前瞻：

- 菜鸟从 1 步提升到 2 步。
- 中级从 2 步提升到 3 步。
- 高手保持 3 步。

这个设计对应真实玩家行为：压力低时操作更随意，压力高时会停下来仔细看。

### 5.3 单步评分

候选球的基础评分主要围绕“拿这一步后暂存是否变轻”：

| 暂存变化 | 倾向 |
| --- | --- |
| 暂存减少 2 个以上 | 强烈加分 |
| 暂存减少 1 个 | 高加分 |
| 暂存不变 | 中等加分 |
| 暂存增加 1 个 | 根据当前压力轻微到重度扣分 |
| 暂存增加 2 个以上 | 明显扣分 |

除此之外，还会考虑：

- 目标订单推进量，能推进订单会加分。
- 距离惩罚，离当前可操作区域越远略微扣分。
- 同色已在暂存但当前不能消，会扣分，避免堆重复压力。
- 冰块解冻保护，场上有已激活但未解冻冰块时，取球推进解冻会加分。
- 随机噪声，用于重开尝试时跳出固定死路。

### 5.4 多步前瞻

如果前瞻深度大于 1，求解器会做短层级搜索：

1. 当前第一步会枚举所有安全候选。
2. 后续递归只保留评分最高的前 3 个候选。
3. 累加未来若干步的评分，选择总分最高的第一步。

这不是全量穷举，而是“有限候选宽度 + 有限深度”的近似策略，效率更稳定，也更像玩家只看几个明显选择。

### 5.5 误触模拟

玩家档会加入误触，误触不是随机拿最差球，而是从“看起来还不错但不是最优”的候选里随机选一个。

误触触发条件：

- 当前暂存数量不高，暂存小于等于 3 时才可能发生。
- 候选安全步至少有 2 个。
- 随机数命中当前档位误触概率。

误触概率会随进度变化：

- 0-50%：误触率乘 0.6，前期相对专注。
- 50-70%：使用正常误触率。
- 70-100%：误触率乘 1.1，后期颜色和局面更复杂。

这个设计让玩家不是“蠢选”，而是更真实地模拟快速点击、近色看错、局面复杂导致的次优操作。

## 6. 高手档的额外管道策略

高手档开启 `evenPipe`，会主动均匀消耗管道。

策略逻辑：

- 优先取释放进度落后的管道，避免某条管道深层关键球长期埋住。
- 抑制继续取已经领先太多的管道。
- 当不同管道释放差距过大时，进一步惩罚继续刷最深的管道。

菜鸟和中级不启用这个能力，意味着他们更容易在管道类关卡里产生后期卡色、关键色埋深、暂存压力后移等问题。

## 7. 三档综合结果

网页展示用的 `analyzePlayerSolutionAllTiers(...)` 会分别跑三档，再按权重汇总：

| 档位 | 权重 |
| --- | ---: |
| 菜鸟 | 30% |
| 中级 | 40% |
| 高手 | 30% |

综合结果会输出平均步数、平均进度、平均暂存、平均通关率、平均重开次数等。默认展示路线以中级结果为主，因为中级更接近普通玩家的主体表现；但网页按钮可以切换到菜鸟、中级、高手各自路线。

## 8. 与生产审核接口的边界

当前代码保留了两个入口：

| 函数 | 返回版本 | 用途 |
| --- | --- | --- |
| `analyzePlayerSolution(...)` | `StrongOnly` | 生产审核、关卡生成联动，只跑高手档 |
| `analyzePlayerSolutionAllTiers(...)` | `PlayerTiersUI` | 网页端三档展示、路线对比、模拟观察 |

保留 `StrongOnly` 的原因：

- 关卡生成审核需要稳定、快速、可复现的基准线。
- 高手档更适合作为结构性难度曲线的基准。
- 菜鸟和中级更适合做玩家分层观察，而不适合直接干扰生产审核的核心判断。

因此当前体系是：生产审核看高手基准，网页分析看三档玩家分布。

## 9. 这套三档逻辑的设计价值

这套设计的核心价值在于，它把“求解器”从单纯找通关路线，升级成了玩家行为模拟层。

它能回答的问题包括：

- 这关高手是否能稳定解？
- 普通玩家是否会在某个进度段开始明显加压？
- 菜鸟是否会因为早期小压力波动提前死亡？
- 同一关是否存在明显技能门槛？
- 管道、冰块、隐藏色是否会放大低水平玩家和高手之间的差距？
- 暂存区曲线是否能解释玩家实际死亡进度？

尤其对于休闲游戏关卡审核，这种分档求解比单一最优解更有价值。最优解只能说明“能不能过”，三档玩家模拟可以进一步说明“谁能过、怎么死、死在哪、为什么死”。

## 10. 后续可扩展方向

后续如果继续增强，可以从以下方向扩展：

1. 增加更细的人群档位，例如新手保护档、普通主力档、付费高熟练档。
2. 把误触率和前瞻深度改成可配置参数，用于拟合真实线上数据。
3. 引入玩家死亡进度数据，反向校准三档权重和误触参数。
4. 对不同障碍类型建立单独的“理解成本”，例如冰块、管道、问号、锁链分别影响不同玩家层。
5. 把暂存曲线、滞留曲线、死亡进度曲线做相关性拟合，形成更完整的难度审核闭环。

当前版本已经具备一个比较清晰的闭环：高手基准负责生成审核，三档玩家负责解释表现差异，暂存区曲线负责连接求解器表现和真实玩家死亡进度。
