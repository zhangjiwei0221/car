## ★★ 难度评分体系（当前最新状态）★★
**入口**：`YarnLevel.Validator.computeDifficultyScore(playerResult, { omniResult })`

### 两个完全独立的输出（核心理念，不互相影响）
1. **难度值 0-100** = 多难（简单0-25/普通25-50/困难50-70/极难70-100）
2. **是否符合预期曲线** = 节奏对不对（符合预期/不符合预期/正常简单关/异常过于简单）

### 输出1·难度值 = 四因子加权×100（玩家加权0.6 + 全知0.4 融合）
| 因子 | 权重 | 来源 | 分母 |
|---|---|---|---|
| f1 线轴数 | **0.05** | totalTargetSpools | /180 |
| f2 平均暂存占比% | **0.4** | avgBufferRatio | /50 |
| f3 平均滞留步数(原始) | 0.2 | avgRawResidence | /4.5 |
| f4 高压步数加权占比 | **0.35** | 每步分级权重均值 | /1.0 |

- 难度值 = `0.6×玩家加权版强度 + 0.4×全知版强度`（两版各算一次四因子再融合）
- 高压分级权重 `_hpWeight`：暂存≤3→0、4→1、5→2、6→3、7→4
- 常量：`_SPOOL_CAP=180 _RATIO_CAP=50 _RES_CAP=4.5 _HP_CAP=1.0`
- f1从0.1→0.15→0.2逐步上调（148关分析证实线轴数与难度正相关，主要放大失误：误触r=0.38）

### 输出2·卡点/曲线判定（基准=高手档单档曲线！）
**关键决策**：卡点判定**只用高手档(strong)的按球曲线**，不用融合、不用全知。
- 理由：高手=信息受限真人最佳表现(误触0.025/3步前瞻)，最能体现"这关被好好玩时"的压力结构；
  不被菜鸟误触污染，也不被全知版"为拓展棋盘主动堆存"扭曲。卡点是关卡设计属性。
- 用户原话："高手表现是最好的，难关简单关都能精准表现"
- 代码：`var strongRes = result.tiers.strong; var sc = _ballCurveOf(strongRes);`

**判定逻辑（最新，已重写）**：
- 进度轴 = 已结算订单球数（不是步数；锁链一步放2球）。按球插值出 curve0[球]=暂存、res0[球]=滞留
- 在 50-90% 和 0-50% 各用 **10%球数宽滑窗找"平均暂存最高"的窗口**（不再是高压占比！）
- 该窗口平均暂存 ≥4 → 算"高压区"
- 每个高压区取两个量：**平均暂存(基础强度) + 平均滞留(持续情况)**
- **有效卡点** = 目标区(50-90)存在高压窗口(平均暂存≥4)
- **异常(卡点前移)** = 前期也有高压窗口时，比较：①平均暂存 ②平均滞留，
  **任一项前期>目标区 → 判前移**；两项都 目标区≥前期 → 正常；前期无高压窗口→正常
- 收尾段90-100%不参与比较
- 全局滞留阀门已废弃（改成滑窗找最高暂存窗口后不需要）

**无卡点关的细分**（用户要求降标）：
- 难度档高却无卡点 → "无难度卡点"
- 简单/普通/困难无卡点：菜鸟/中级/高手任一档出现过暂存≥4 → "正常简单关"；三档全程<4 → "异常(过于简单)"

## 误触机制（最新）
基础概率（仅暂存≤3时可能触发）：**菜鸟0.08 / 中级0.05 / 高手0.025**
- 按进度分段调整：前期(0-50%)×0.6、中期(50-70%)×1.0、后期(70-100%)×1.1
- 是确定性伪随机(seed固定则结果固定)
- 用户降过两次：因为误触过高会让菜鸟前期堆假高压、拉偏融合曲线判前移

## 死亡规则（最新，全档通用）
- `executePickOnState` 兜底：`buffer.length >= 7` → `_died=true`，**全档生效(含全知版)**
- 求解器安全检查全部收紧为"结算后 <7 才安全"(原来是≤7)
- 死亡→该次completed=false→runPlayerTier/analyzeOptimalSolution换种子回溯
- 全知版也不会再出现"暂存=7还往后推"
