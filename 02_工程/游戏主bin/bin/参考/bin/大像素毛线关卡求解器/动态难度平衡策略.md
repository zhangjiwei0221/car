# 动态难度平衡策略（生成侧）

> 原名"渐进策略"，现升级为按审核反馈自适应的闭环。
> 相关代码：`bin/run.js`（编排/状态机）、`关卡生产工具大像素版48像素无黑块/tool/scripts/run_batch_txt_node.js`（生成引擎）。
> 审核口径见同目录 `关卡审核体系.md` / `难度评分体系.md`。
> 注：失败原因 `issueType` 取自**3 遍按球平均曲线**的合格判定（见 `关卡审核体系.md` §1/§8），故减压/加压的触发基于稳定的平均口径，而非单遍随机。

## 1. 总体思路

`run.js` 每关按「轮(1-10)×候选(5)」生成并送审。原来只按轮次盲目升压；现在**每关根据上一轮的主要失败原因（审核 `issueType`）自适应切换下一轮的生成模式**，形成闭环：

```
生成候选 → 求解+审核 → 看本轮主要失败原因 → 决定下一轮生成模式 → 再生成…
```

模式存在 `task._mode`，四种：

| 模式 | 触发（上一轮主要失败原因） | 生成动作 |
|---|---|---|
| `normal` 常规 | 其它 / 首轮 | 按轮次升压（原加压阶梯 diffLevel 1→4） |
| `pressurize` 加压 | 过于简单（含难度低于下限） | 直接第 4 档加压（后区加冰/加链），并绕过区域预设 |
| `relief1` 减压① | 前期峰值前移 | **后移冰块/锁链**（把障碍推到后区） |
| `relief2` 减压② | 减压①后仍前期峰值前移 | 后移基础上**再减少冰/链障碍比例（×0.75）** |

> 减压只针对"前期压力跳升"。判定来自审核：前期最高 5% 窗口平均暂存超过该档上限（菜鸟≥3.5 / 高手·中级>4.2）→ `issueType=前期峰值前移`。

## 2. 加压策略（保留 + 一处新增）

- **保留**：原 `diffLevel` 阶梯不变 —— lvl1 全随机；lvl≥2 冰块偏后区；lvl≥3 锁链覆冰；lvl≥4 冰块+10%、锁链+1。`normal` 模式下 `diffLevel` 仍随轮次 1→4 升。
- **新增**：某关候选被判**过于简单 / 异常(过于简单) / 难度低于下限** → 直接进入 `pressurize`（`diffLevel=4` 立即在后区加障碍），不必等到第 4 轮。目的：把过于简单的关卡压力曲线抬到符合预期/趋势符合。

## 3. 减压策略（新增，仅针对前期跳升）

- **阶段①后移**（`relief1`）：当某关一整轮 5 个候选的主要失败仍是"前期峰值前移" → 下一轮把**冰块全后移**（后移比例 1.0、后区起点 row≥rows×0.5）、**锁链也后移**（新增后区优先放置）。
- **阶段②减障碍**（`relief2`）：若阶段①后下一轮仍"前期峰值前移" → 在后移基础上把**冰块、锁链数量 ×0.75**（问号不动——问号是隐藏色，不直接堆暂存）。

### 3.1 减压兜底：跑满轮次仍压不住前期

有些关前期高压来自**目标图本身的颜色分布**（前期就要缓存多色），后移/减障碍救不回来。对这种关：

- 跑满 `MAX_ROUNDS` 后，看保留的最佳候选 `_bestFail`。**仅当它"唯一卡在前期峰值前移"**（难度在区间、全知通关、该档通关、不卡死都满足，只有 `issueType=前期峰值前移`）时：
  - **选这个最接近候选**直接并入 **合格关卡 + 排序（上线）**，不当作"需美术返图"；
  - 关卡 JSON 内嵌标注：`_analysis.earlyOverLimit = true`、`_analysis.note = "前期偏高·多轮未能压低，已选最接近候选"`；
  - 生产汇总报告状态记为 **`合格·前期偏高(已标注)`**，便于事后筛/交美术微调。
- 其余失败类型（全知/该档无法通关、卡死、难度超区间、非前期的不符合）→ 仍按"不合格/需美术返图"。

## 4. 生成引擎新增环境变量（默认关闭 = 现状不变）

`run.js` 按模式设置，传给 `run_batch_txt_node.js`：

| 环境变量 | 含义 | 默认 | 减压时取值 |
|---|---|---|---|
| `RELIEF_STAGE` | 0=无 / 1=后移冰块锁链 / 2=后移+减障碍 | 0 | 1 或 2 |
| `STRATEGY_OVERRIDE_PRESET` | =1 时绕过区域预设（加压/减压触发后） | 0 | 1 |
| `RELIEF_OBSTACLE_RATIO` | 阶段②冰/链数量缩减系数 | 0.75 | 0.75 |
| `ICE_BACK_FRACTION` | 冰块后移比例（`_placeIceBiased`） | 0.5 | 1.0 |
| `BACK_ROW` | 后区起始行比例（row≥rows×该值） | 0.4 | 0.5 |
| `DIFFICULTY_LEVEL` | 加压阶梯档（1-4） | 由轮次 | 加压=4 / 减压=1 |

新增放置函数：`_placeChainsBiased(em, count, rows, threshold)`——候选链对中两端都在后区(row≥rows×threshold)的优先放置，不足再全棋盘补；`_placeIceBiased` 增加 `backFraction` 参数。

## 5. 与区域预设的关系

`障碍区域预设.json` 仍**优先**走候选生成（模糊手调区）。只有当某关候选连续失败、进入 `pressurize/relief` 后，`STRATEGY_OVERRIDE_PRESET=1` 才会绕过预设执行加压/减压。预设只是模糊提示，被覆盖可接受。

## 6. 不变项

- `PLAYER_TIERS` 求解参数、`BUFFER_LIMIT=7`、全知线、卡死检验、难度档边界均不变。
- 默认（不设新 env）= 原"渐进策略"行为，向后兼容。

## 7. 验证（已通过）

- 审核：前期 5% 窗口绝对上限，菜鸟≥3.5 越位、高手>4.2 越位（4.2 含界放行）；2 球短峰能被 5% 窗口抓出。
- 生成（input_txt/1.txt，各 5 次均值）：`relief1` 冰块 100% 后区、锁链 95% 后区；`relief2` 冰/链数量 ×0.75 且 100% 后区；`pressurize`(diff4) 障碍数量上升。
