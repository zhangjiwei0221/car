# 难度评分体系（与代码一致版）

> 入口：`YarnLevel.Validator.computeDifficultyScore(playerResult, { omniResult, auditTier })`
> 代码：`大像素毛线关卡求解器/js/validator.js` → `_strengthOf` / `_ballCurveOf` / `computeDifficultyScore`
> 单关"🙋 模拟玩家"和批量导出（横向对比表、难度排序）均已接入。
> 本文档已与代码对齐：三因子(f2/f3/f4)加权、**0.8 基准档 + 0.2 全知** 融合、难度四档、按球曲线"窗口平均暂存"判定、含"趋势符合"、审核基准档可切（strong/novice/mid）。

## 核心理念：两个完全独立的输出

评分回答两件互不干扰的事，**不会"轴一/轴二矛盾"**：

1. **难度值（0-100）**：这一关有多难？→ 简单 / 普通 / 困难 / 极难。纯量级，不管节奏。
2. **是否符合预期压力曲线**：这一关节奏对不对？→ 符合预期 / 趋势符合 / 不符合预期 + 诊断。

一关可以"很难但不符合预期曲线"（很难但高压全堆在前期），两个结论同时成立、不打架。

## 输出1 · 难度值（0-100）

三因子加权 × 100，并按 **0.8 基准档 + 0.2 全知档** 融合（缺全知则只用基准档）：

| 因子 | 权重 | 来源 | 归一化分母 |
|---|---|---|---|
| f2 平均暂存占比% | 0.45 | avgBufferRatio | /50 |
| f3 平均滞留步数(原始) | 0.2 | avgRawResidence | /4.5 |
| f4 高压步数加权占比 | 0.35 | 每步分级权重均值 | /1.0 |

> 注：原 f1 线轴数因子（权重 0.05）已移除，权重并入 f2。线轴容量对难度的影响已隐含在暂存/滞留压力里。

- 高压分级权重 `_hpWeight`：暂存≤3→0、4→1、5→2、6→3、≥7→4
- 单档强度：`strength = (0.45·f2 + 0.2·f3 + 0.35·f4) × 100`
- 融合：`strength = 0.8×基准档strength + 0.2×全知strength`（f2–f4 同样按 0.8/0.2 融合）
- **基准档由 `auditTier` 决定**：默认 `strong`(高手)，可切 `novice`(菜鸟)/`mid`(中级)。换档后难度因子用该档曲线计算，菜鸟普遍更高 → 同一关难度分自动抬高。
- 常量：`_RATIO_CAP=50 _RES_CAP=4.5 _HP_CAP=1.0`（按 64-90 难批·**高手档**实测分布校准，使最难关接近满分1.0；`_SPOOL_CAP` 随 f1 弃用）。换菜鸟基准后因子更易触顶，难度分会整体偏高（已知取舍，可后续按需单独标定）。

难度档（**四档**）：
- 简单 0–25
- 普通 25–50
- 困难 50–70
- 极难 70–100

> 难度值只反映"客观压力量级"，与节奏无关。强度高 = 压力总量大 = 很难；好不好玩由输出2判定。

## 输出2 · 是否符合预期压力曲线

### 基准 = 审核基准档(auditTier)「按球暂存曲线」
卡点用**审核基准档**的按球曲线判定（默认高手）。卡点是关卡的设计属性 → 用单档曲线；难度值用基准档+全知融合，两者分离。
- `strong`(高手，默认)：信息受限、误触极低、3 步前瞻，体现"被好好玩时"的压力结构。
- `novice`(菜鸟)：拟合真实低水平玩家，并叠加更严格的前期约束（见下）。
- 由环境变量 `AUDIT_TIER` 切换（互斥），如 `AUDIT_TIER=novice node run.js`。

### 压力分级（暂存区结算后数量）
| 暂存 | 状态 |
|---|---|
| ≤3 | 无压力 / 小压力 |
| 4 | 中压力（开始推演） |
| 5 | 压力升高 |
| 6 | 高压 |
| 7 | 极限施压（临时，结算后必须降，否则死） |

### 进度轴 = 已结算订单球数（不是步数）
- 进度 = 已完成订单的累计球数（0 → 总球数 N）。步数 ≠ 球数（锁链一步可放入 2 球）。
- **按球插值**：每步记"结算后累计完成球数 E"与"结算后暂存 B"，已放入球数 = E+B。
  实现：`curve0[球i] = (E+B) − i`，得到「进度(1..N球) → 暂存」曲线；`res0[i]` = 该点暂存球平均滞留。

### 双窗口（取"平均暂存最高的球数窗口"）
- **目标区窗口（卡点）**：`50%–90%` 进度，窗口宽 `W = max(1, round(N × 10%))`（**所有档一致，不变**）→ `zoneAvgBuf`、`zoneAvgRes`
- **前期窗口**：`0%–50%` 进度，**所有档统一收窄到 `W_early = max(1, round(N × 5%))`** → `earlyAvgBuf`、`earlyAvgRes`
  - 窗口越窄，对短促的前期峰值越敏感，近似"前期峰值不跳升"的硬约束。
- **收尾段 90-100%**：高压属后期难度，可接受，**不参与卡点比较**。

### 判定规则
- **有效卡点 `capPointValid`** = `zoneAvgBuf ≥ 4`（所有档一致）
- **卡点前移 `earlyViolation`**（前期 5% 窗口绝对上限，分档阈值）：
  - **菜鸟 novice**：`earlyAvgBuf ≥ 3.5` 即越位（严格 `<3.5`，前期必须明显低难度）。
  - **高手 strong / 中级 mid**：`earlyAvgBuf > 4.2` 才越位（`≤4.2`，略宽）。
  - 旧的"前期反超目标区"相对规则已废弃；改为绝对上限，确保全部关卡生产时前期压力不跳升。
    依据：真实数据显示低水平玩家前期暂存到 3–4 就大量失败。
- **符合预期 `compliant`** = `capPointValid 且 !earlyViolation`
- **趋势符合**（兜底，仍记为合格）= `!capPointValid 且 !earlyViolation 且 zoneAvgBuf > earlyAvgBuf`
  —— 无硬卡点(均<4)，但后段峰值高于前期、前期未越位，方向往后爬。

### 预期曲线形状（设计目标，定性）
- `0-30%`：可有小幅高压、随后快速回落
- `30-50%`：压力逐渐增大
- `50-90%`：持续增大 / 持续高压 / 跳低后迅速拉高 —— 任一即可
- `90-100%`：维持高位 或 快速下滑收尾 —— 皆可

### 结论与问题分类
| curveQuality | issueType | 触发条件 |
|---|---|---|
| 符合预期 | （空） | 卡点(zoneAvgBuf≥4)在50-90，前期未前移 |
| 趋势符合 | 趋势符合无卡点简单关 | 无硬卡点，但后段峰值>前期且前期未越位 |
| 不符合预期 | 前期峰值前移 | earlyViolation（前期最高5%窗口平均暂存超过该档上限：菜鸟≥3.5 / 高手·中级>4.2） |
| 不符合预期 | 无难度卡点 | 极难档(≥70)却无卡点且趋势也不对 |
| 正常简单关 | 正常简单关 | 简单/普通/困难无卡点、趋势不对，但审核基准档出现过暂存≥4 |
| 异常(过于简单) | 过于简单 | 审核基准档全程暂存<4，几乎无压力 |

## 关键返回字段

```
difficultyStrength   难度值 0-100（0.8基准档+0.2全知融合）
difficultyTier       简单(0-25) / 普通(25-50) / 困难(50-70) / 极难(70-100)
auditTier            审核基准档：strong(高手,默认) / novice(菜鸟) / mid(中级)
factors              {f2_bufRatio, f3_residence, f4_highPressure}（f1线轴数已移除）
totalSpools          线轴总数
compositeCurve       10段平均暂存曲线（展示用，按球数分段）
ballCurve / ballRes  审核基准档按球暂存曲线 / 对应按球滞留曲线
peakBand             目标卡点窗口（按球数换算回进度%，如 "69-79%"）；无卡点为 "-"
peakValue/zoneAvgBuf 目标区窗口平均暂存
zoneAvgRes           目标区窗口平均滞留
earlyAvgBuf/earlyAvgRes 前期(0-50%)窗口平均暂存 / 平均滞留
capWinStart/capWinLen 卡点窗口起始球索引 / 窗口宽度(球数)
peakInZone/zoneValid  = 有效卡点是否成立（= capPointValid）
earlyViolation       前期是否越位（卡点前移）
compliant            是否符合（含"趋势符合"也为 true）
curveQuality         符合预期 / 趋势符合 / 不符合预期 / 正常简单关 / 异常(过于简单)
issueType            问题类型（符合预期则空）
artNote              美术调整建议（针对目标图怎么改）
tierPass/tierClearNote/skillGapBig  各档(菜鸟/中级/高手)通关情况
note                 综合备注：难度档 / 是否符合 / 问题类型 ｜ 调整建议
diagnosis            诊断文字
```

> note 例：`极难 / 不符合预期 / 前期峰值前移（全局难度高且前期偏难）｜调整建议：高压重心落在前期，建议把目标图的复杂/密集区往 50-90% 进度方向后移`

## 在生产线中的合格门槛
> 本评分体系只产出 `difficultyStrength` 与 `compliant`。是否"合格"由生产线套用（见《闭环关卡生产流程》）：
> **难度∈[MIN,MAX] 且 compliant 且 全知版通关 且 审核基准档(AUDIT_TIER)通关 且 不卡死**，全过才合格。
> 默认 `AUDIT_TIER=strong`、难度下限 30；菜鸟用 `AUDIT_TIER=novice`、难度下限默认 20（可用 `DIFFICULTY_MIN/MAX` 覆盖）。

## 全知最优版·全局规划增强（保证通关）

全知最优版（expand=true, evenPipe=true）在 3 步前瞻+暂存保护基础上，新增全局规划：
1. **管道口优先**：当前能消的目标色若棋盘上也有同色普通球，优先取管道口的同色球，
   让管道均匀消耗，避免关键色被埋在管道深处导致中后期卡死。
2. **拓展棋盘**：取球能激活的新邻居（解锁新可用球）越多越好（每个 +2.5 分）。
3. **前期换拓展**：暂存压力小(≤2)时，即使该步增暂存，只要能解锁新球/丰富颜色，
   降低增存惩罚，优先把棋盘可用区域和颜色铺开。

效果：64-90 全 62 关 + 旧 107 关全知版均 100% 通关、0 暂存溢出。
