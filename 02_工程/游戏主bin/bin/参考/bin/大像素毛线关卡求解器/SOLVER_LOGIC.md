# 大像素毛线关卡求解器 - 算法逻辑说明

## 关卡数据模型（新大像素版）

- **blocks（目标图）**：纯数字二维数组，每个数字是颜色 id（30×30 ~ 70×70）
- **spools（棋盘）**：每格 `{id, type, param, count}`
  - `count` = 该线轴的订单量（需消除的目标像素数，48 上下浮动 44~48）
  - `type` 可为数组（如 `[4,6]` = 冰块+问号叠加）
  - 管道格 `param` = `[{id, count}, ...]`（管道内排队球的颜色+订单量序列）
- **无黑块**（id=-1 已移除）
- 暂存区上限 **7**

## 消除规则

- 每个线轴需消除自身 `count` 个同色目标像素才完成（不再是固定3）
- 目标区每列是栈，只能从栈顶（底行）往下消，被其它色埋住的同色暂时拿不到
- 从左到右扫描各列栈顶，每列每轮最多消1个，多轮循环直到满订单或消不动
- 暂存满7且无法再消 = 失败

### 锁链同色抢色规则

- 锁链两球同时进场，按"进暂存顺序"一前一后、各自独立完整扫描
- 球1 先完整扫（从左到右多轮，直到满或场上没它的色），球2 再在球1抢完后变化的棋盘上完整扫
- 两球都扫完后才统一 autoRelease
- 现象：同色两球抢色时，因埋色限制，可能出现"场上够1个订单但两球都暂时无法完成"

## 算法逻辑（多种，可横向对比）—— 路线图

> 设计目标：同一关卡用不同"信息模型/策略"的算法分别求解，UI 横向并排对比结果
> （步数、最大暂存、平均暂存、通关率等），用于评估关卡真实难度与可玩性。

### 1. 全知最优求解器（已实现，基准线）✅

- 函数：`runSolver3Step`（validator.js），入口 `analyzeOptimalSolution`
- **信息模型：全知** —— 直接读取 JSON 中问号球的真实颜色、管道内全部排队球的颜色
- 策略：3步树形前瞻 + 暂存保护
  - 对每个可取球展开3步搜索树，算3步总分，选总分最高路径的第1步
  - 单步评分表（沿用原版，去掉通道/窄路维度）：
    - bufferDelta ≤ -2 → +30；= -1 → +25；= 0 → +20
    - = +1 按暂存压力 -3/-8/-20；≥ +2 按 -5/-15
    - 旧暂存推进 +0.3/个；同色积压 -8/个；距离微惩罚 -0.1×dist
    - 冰块解冻保护：场上有"已激活未解冻"冰块时取球加分（避免困死冰块）
  - 暂存安全检查（否决权）：模拟后 simBuffer ≥7 淘汰；≥6 需有确定降暂存的后续
  - 暂存压力大（≥5）时切换精确降压模式
- 回溯兜底：第1轮无噪声；未通关则带随机噪声多轮重试（最多8轮）
- 性能：107关 100% 通关，平均 ~560ms，最慢 ~2s
- **用途**：判断关卡是否有解、理论最优步数上限。不代表玩家真实体验难度。

### 2. 玩家真实视角算法（待实现）⏳

- **信息模型：信息受限**（与玩家对称）
  - 问号球（type 6）：点开前看不到颜色，按"未知色"处理
  - 管道球：只有被释放到出口、玩家可见时才知道颜色，未释放的不可见
- 策略：在信息不全的情况下做决策（可能需要赌/概率估计），更贴近真人
- 预期：通关率可能低于全知版，步数/暂存压力更高 —— 这才是真实难度信号

### 3. （可能的更多变体）⏳

- 不同前瞻深度（1步贪心 / 2步 / 3步）
- 不同风险偏好（保守暂存 / 激进消除）
- 玩家"学习"模型（管道顺序可预判 vs 完全随机）
