# 色库（v154）：官方 22 色 + 本工程 34 色，以及两套的互转

> 这个目录是**两套色库的权威数据**。求解器界面里的「读图色库」下拉和「🎨 色库转换」面板，
> 用的色值与映射关系都出自这里；`bin/js/color-libs.js` 里内置的那份必须与这里逐项一致
> （`node bin/js/_colorlibs_test.js` 会逐项校验，不一致就报错）。

## 一、里面有什么

```
色库/
├── official_json_original_color_matrices/    官方 JSON 原始颜色编号矩阵
│   ├── README.txt                            原始说明（提取口径）
│   ├── original_color_library.txt            官方 22 色定义（编号 0-21）

    ├── original_color_library.txt            官方 22 色（副本，方便单独取用）
    ├── 标准色库毛线真实.txt                   本工程 34 色（1-34）
    └── 靠色色库.md                           靠色对与色号↔色名对照（回溯文档）
```

## 二、两套色库的区别（这是全部麻烦的来源）

| | 老色库（本工程一直在用） | 官方色库（那 300 关） |
| --- | --- | --- |
| 色数 | **34** | **22** |
| 颜色编号 | **1-34** | **0-21** |
| 空位标记 | **`0`** | **`-1`** |
| `0` 号是什么 | 空位 | **黄色 `#FFEB33`** |
| 定义文件 | `标准色库/标准色库毛线真实.txt` | `标准色库/标准色库_colors_0-21.txt` |
| 同一份还在哪 | `bin/js/utils.js` 的 `AntSolver.COLORS`；`bin/参考/ 毛线色库/` | — |

**两套色库没有一个同 Hex 的色**（已逐一比对）。编号空间又冲突：老的 `0` 是空位、新的 `0` 是黄色。
所以**按哪套读会实打实改变颜色** —— 这也是为什么界面上的「读图色库」必须显式可选，
而不是"自动猜一个"。

## 三、300 关的实际情况（实测，用于设计识别判据）

| 情况 | 关数 | 能否自动判定 |
| --- | --- | --- |
| 带 `-1` 空位 | **185** | ✅ 铁证是官方色库 |
| 实心图形，无 `-1` 也无 `0` | **63** | ❌ 两套色库都能解释 → 需人工确认 |
| 实心图形，无 `-1` 但有 `0` | **52** | ✅ 看 `0` 的占比（低=黄色底） |
| 合计 | 300 | |

另外：**180 关**存在"某一行以 `-1` 开头"。求解器原来的 TXT 解析器（`/^\d/` 判起始行）
会把这种行**整行丢掉**、导致矩阵缺行错位 —— v154 已修成 `/^-?\d/`。

## 四、两套色库怎么互转（v154 的口径）

**官方 → 老色库（新→老）**：用**最小代价单射分配**。22 个官方色落到 22 个**互不相同**的老色号上，
总色差最小（指派问题）。为什么不用"各自取最近色"：纯最近色会让 4 组官方色抢同一个老色号 ——
官方3/4→老6、官方6/7→老24、官方14/19→老26、官方17/21→老32，而 300 关里有 **141 关**
同时用到这些撞色的两个色，撞色等于把两种像素合成一种。单射的代价只比纯最近色高 **7.4%**
（1334.3 vs 1242.7）。

**老色库 → 官方（老→新）**：用上面那张表的**逆**，另外 12 个老色号取最近色。
因此这 22 个老色号都能原样变回自己的官方号，**「新→老→新」逐像素无损（300/300 关校验通过）**。
反过来「老→新→老」**必然有损**（34 色压到 22 色），这是色域差异、不是 bug。

**实际色差**（RGB 欧氏距离，0-441）：

| 方向 | 最远 | 说明 |
| --- | --- | --- |
| 官方→老 | 129.4 | 官方14 深棕 `#793A1D` → 老12 紫红 `#C60174` |
| 老→官方 | 129.4 | 老12 倒回去 |
| 官方→老 最近 | 13.5 | 官方20 玫红 `#DE1B5F` → 老4 暗粉 `#DF2455` |

完整对照表在界面「🎨 色库转换」面板里能直接看（还会标出**当前这张图真正用到的色**）。

## 五、怎么用

1. **生产时用官方关**：顶栏「读图色库」保持**自动识别**（推荐），或手动指定；再「导入TXT图」
   选 `official_json_original_color_matrices/level_*.txt`（可多选）。导入时会自动转成老色库编号，
   左栏与「导入目标图」下方会写明转换张数与色数。
2. **核对转换**：点顶栏「🎨 色库转换」→ 看色值对照表 + 本图用量高亮。
3. **整批转／落盘**：面板里「范围」选「转本批全部并下载 TXT」→ 得到带 `_官方色库0-21` /
   `_老色库34色` 后缀的 TXT，放进 `输出文件/` 或直接再导入。
4. **改判定后重判**：改了「读图色库」下拉会**重判本批全部图**（用的是存下来的原始编号，
   不会"转了又转"叠加误差），并清空棋盘缓存 —— 需要重新点「生成」。

## 六、改色值怎么办（维护须知）

色值有三处，**必须同步**：

| 位置 | 作用 |
| --- | --- |
| 本目录的两份色库定义 | 权威数据（人读） |
| `bin/js/color-libs.js` 里的 `CL.OLDER` / `CL.OFFICIAL` | 求解器运行时用的内置副本 |
| `bin/js/utils.js` 的 `AntSolver.COLORS` | 求解器渲染/命名用的老色库（必须与 `CL.OLDER` 一致） |

改完跑一遍：`node bin/js/_colorlibs_test.js`（会校验三处逐项一致 + 300 关往返无损）。
