# 正常关卡试跑：抽 TXT + v3 生成（2026-11-10）

> 输入：桌面 `正常关卡/` 下 212 个现成关卡 JSON（不是 TXT）。
> 处理：`LevelsToTxt_v1` 把每个 JSON 的 `blocks` 还原成目标图 TXT，再用 `JointSearch_v799`（v3 产线标准参数）生成。
> 目的：验证“四象限图是不是卡住生成”的假设，不是分析别人的关卡。

## 1. 抽取

- TXT：`实验关/产线v3/正常关卡_txt_20261110/`（212 个）
- 清单：`正常关卡_txt_20261110/manifest.json`
- 尺寸：30×30 ～ 45×45；颜色 9–23
- 材料（`ImageDebtScan_v1`，`正常关卡_材料_20261110.json`）：
  - **rich 22 / ok 73 / flat 117**
  - debtShare ≥0.8：14 张；≥0.7：30 张

## 2. 试跑目标与结果

```bash
node 03_工具/正式版/JointSearch_v799.js --target <txt> --outdir <dir> \

  --with-topo --topo-seeds 1 --rx-seeds 3,4
```

## 3. 结论

1. **正常关卡图可以用**：212 张里有 22 rich、73 ok；G8_43/G8_57 都能生成 can✓ 的关。
2. **四象限不是唯一瓶颈**：换成正常关卡后，v1 生成器仍会出“选择空间低、C0=1、mid 太平、can✗、容量不守恒”等问题。
3. **最可用的两张**：
   - **G8_57**：mid45、open6、M5.64、H1.07，最平衡；但 C0=1，单旋钮修不掉。
   - **G8_43**：mid79、peak4、C0=0，但 M3.81/H0.96、主体并行88%，偏“指标关”。
4. **G8_40 太平（D0.4）**，G8_23 mid7/C0=4，G8_155 can✗，G8_132/G8_159 构建无效。
5. 所以下一步不是“换图就能批量”，而是：
   - 用 **G8_57** 做结构修复（C0/开局）；
   - 用 **G8_43** 做选择空间/主体并行修复；
   - 再从 rich 里多试 5–10 张，找比这两张更干净的基底；
   - 仍按同一套硬门验收，不按 D 总分。
