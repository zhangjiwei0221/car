# M2 报告：VisibleReach 策略——纯「只看画面」是下界，不是真人

> 日期：2026-11-08
> 策略：`useVisibleReach`（默认关）。把 `optimisticConsumable` 从「真实可达 ≥ 容量」换成「**看得见的剩余像素 × 系数 ≥ 容量**」。
> 结论：纯 visible 玩家在 v1 110 张上 **0 复活 0/110、2 复活 55/110**；全知玩家 16/103。真人在两者之间；F2 的 color30 开局陷阱是纯 visible 的死因，但你试玩没踩——说明你的信息模型比「全部可见像素都可达」更准。

---

## 1. 策略定义

| 模型 | 判断「能不能吃满」的依据 | 性质 |
|---|---|---|
| `oracle`（默认 PlayerSim） | `trueReach >= count`（flood-fill 可达） | 全知上界 |
| `visible-all`（本次） | `visibleRemain * factor >= count`（该色剩余像素，不判断连通） | 盲目下界 |
| 真人（你的试玩） | 看画面 + 对阻挡/区域的直觉 | 在两者之间 |

`visibleRemain` = 目标图上该色还没被消掉的像素总数；`factor` 试了 1.0 / 0.8 / 0.6，结果相同（可见量太大，陷阱主导）。

## 3.1 补充：visible-edge / visible-component（2026-11-08）

| 模型 | 0 复活 | 2 复活 | G2 0/2 | 说明 |
|---|---:|---:|---|---|
| oracle（全知） | **16/110** | **103/110** | 3/9 | 真实可达 |
| visible-all（瞎看） | 0/110 | 55/110 | 0/4 | 所有可见像素都当可达 |
| **visible-edge（谨慎）** | **5/110** | **92/110** | 0/9 | 只算暴露的该色像素 |
| visible-component（样本 30 张） | 0/30 | 16/30 | 0/4 | 只算最大同色连通块 |

单关 F2：

| 模型 | 结果 |
|---|---|
| oracle | 47 步 100% |
| visible-all | 第 11 步 23% 死 |
| **visible-edge** | **第 28 步 61% 死** |
| visible-component | 第 24 步 54% 死 |

- **edge 最接近「谨慎玩家」**：2 复活 92/110（oracle 103），但 0 复活只有 5/110。
- **component 是中间下界**：样本 30 张 2 复活 16/30，低于 edge。
- **真人在 edge 与 oracle 之间**：你试玩 F2 觉得没问题，比 edge（28 步死）更接近 oracle（47 步通关）。
- 结论：v1 的 0 复活依赖**真实可达直觉**（看出哪些像素被埋/被挡）；谨慎玩家需要复活才能过。

## 4. 结论

1. **信息层是真实且巨大的**：如果玩家把「看得见的像素」都当成可达，v1 的关几乎不可玩（0/110）。
2. **但纯 visible 不是真人**：你试玩 F2 觉得没问题，说明你没有把顶行 30 车当成免费车；真人的估计在 oracle 和 visible-all 之间。
3. **F2 的 color30 是「可见陷阱」**：visible 229 / true 0。全知玩家避开，盲目玩家踩；真人是否踩，取决于他是否看得出 30 被埋住。
4. **M2 下一步不是继续用 visible-all 判死**，而是建**校准的信息模型**：
   - `visible-edge`：只算贴着边缘/已消区域的颜色像素；
   - `visible-component`：只算与边缘连通的最大同色块；
   - `visible-factor`：按试玩校准系数；
   - 用你的实际选车（或试玩录屏/口述）对账。
