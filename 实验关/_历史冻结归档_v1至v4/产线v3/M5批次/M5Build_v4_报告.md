# M5Build_v4 报告（路线条件化 reach，2026-11-09）

## 1. 做法

`03_工具/正式版/M5Build_v4.js`：

1. BuildFromRecipe 生成关卡；
2. `ReachabilityCurve_v1` 跑 6 条真实路线，取每辆车 `env.med` reach；
3. 每色选 `maxDebt` 最大的一辆车做债车，容量 = `med + margin`；
4. 其余同色车按剩余总量重分（守恒）；
5. 重建 + ArlCheck/PlayerEngine/LayoutScore/AnimClickSettle；循环 3 次（路线随容量变化重算）。

## 2. 结果

| 基底 | 结果 |
|---|---|
| v27（00005） | base pass（峰值4/中段47/容错15）；v4 不改坏，best 仍 pass |
| 00045 s10，margin10 | best 峰值**3**、中段35%、容错20；无 pass |
| 00045 s10，margin5/15 | best 峰值2、中段33%、容错17；无 pass |

## 3. 为什么还不够

- `ReachabilityCurve_v1` 的路线里 `replayWon=false` 居多：它的 reach 来自求解器路线，但回放到真实模拟器并不都能走通；用这些窗口定容量，窗口本身不可靠。
- 只改“每色一辆债车”的容量，没有同时改链位/冰；峰值需要多辆车同时欠，单点不够。
- 容量一改，路线就变；迭代 3 次仍可能收敛到“峰值3/中段35”这个局部。

## 4. 结论

- v4 是合格的“路线条件化容量工具”，能保住 v27，但还不能把 00045 拉过线。
- M5 仍 🟡。下一步 v5 需要：
  1. 用 **能走通** 的 click-settle/玩家路线做窗口（不用 replayWon=false 的 solve 路线）；
  2. 同时搜索“链组 + 两辆债车”的容量组合，而不是单车；
  3. 先接受单关 20–30 分钟，用 v4 做局部，不要指望一次生成。
