# M5Build_v2 报告（2026-11-09）

## 1. 做了什么

`03_工具/正式版/M5Build_v2.js`：在合法候选上做局部搜索：

- 随机改一个冰的 param（4–18）；
- 或把一组 2 连链换到另一对相邻内部格；
- 或同色两辆车之间挪容量（守恒，8–90）；
- 每次重建并跑 ArlCheck / PlayerEngine / LayoutScore / AnimClickSettle（8s 超时，防止束搜索卡死）；
- 只保留“全过”或分数更高的候选。

## 2. v27 验证

- base v27 直接 pass（峰值4、中段47、容错15、开局5、0复活、排版0）。
- 搜索生成变体：冰 `r1c1` 从 6→4，仍 pass；输出 `tune_v27/PASS.recipe.json`。
- 结论：搜索器本身能跑、能保留合格变体。

## 3. 00045 搜索

- s5（峰值4/中段40/容错1）30 iter：点击结算多次需要束搜索，加 8s 超时；未找到 pass。
- s10（峰值2/中段33/容错17）20 iter：best 峰值2/中段38/容错17；未找到 pass。
- s10 + 容量挪动 20 iter：best 峰值2/中段38/容错17；仍无 pass。
- 说明：只靠随机冰/链/容量微调，00045 仍跨不过“峰值4 + 中段45–80 + 容错55–75”的联合门槛。

## 4. 结论

- M5Build_v2 是合格的**局部调参器**，不是合格的**从图生成器**；v27 能产出多张 pass 变体，但新图仍需要“可达窗口 → 债车 → 冰/链”的结构性搜索，而不是随机微调。
- 时间：v27 从 v16 到定稿跨约 15 小时（含隔夜），有效迭代约 3–4 小时；M5Build_v2 单次迭代约 20 秒，20 轮约 7 分钟。若单关 20–30 分钟能过指标，这个成本可接受；问题是当前搜索空间没有对准窗口。
