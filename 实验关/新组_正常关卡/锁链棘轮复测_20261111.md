# 锁链棘轮复测（2026-11-11）

> **工具**：`03_工具/正式版/ChainRatchetCheck_v1.js`
> **起因**：`ZC_181` 过了低流失硬门（policy0/OpeningCheck），但真人路径在第 36 步把 buffer 推到 3 后，三锁链永远进不去，最后死锁。
> **结论**：7 个复测候选里只有 **3 个**通过；电池的硬门对「路线死锁」是乐观的。

## 1. 检查器口径

沿路线逐状态检查三类问题：

| 类型 | 定义 |
|---|---|
| `progressDead` | buffer≥3 时，5 步 / 800 节点内找不到任何走法能让**已在暂存里的车**进度增加或完成（新增债车不算进度） |
| `allMovesDead` | 所有合法走法模拟后都满足「buffer 满且本步无完成 / overflow / 无合法走法」 |
| `trap` | 某状态有可进入的链组（组大小 ≤ 空位），但走任一非链车后该链被锁，且新局面 `progressDead` |

路线：solver / free-first / max-eat / small-debt 四条策略路线；`--path` 可额外检查真人路径。

## 4. 解释

1. **电池与棘轮检查测的不是一件事**：`policy0` 证明「存在一条路线能赢」，棘轮检查证明「这些合理路线不会走进不可逆的死局」。`ZC_181` 就是前者过、后者不过。
2. **三锁链在 buffer≥3 时是死资源**：组大小 3、暂存上限 5，buffer 一旦到 3，链组就进不去；如果它锁着债车要的颜色，局面不可逆。
3. **失败集中在多链 + 多债的开局**：`ZC_24/32/44` 都是自由路线在第 5–12 步把 buffer 填到 4，同时有三条 3 链锁死。这不是「难」，是「一步走错就没有第二选择」。
4. **通过率下降是好事**：8 个「硬门候选」里只有 3 个路线稳健；如果没有这项检查，试玩会浪费在 `ZC_181` 这类关上。
