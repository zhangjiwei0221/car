## 2. 两个必须先知道的事实

### 2.1 色号：212/212 张都含 >21 的老色号（最大 34）

- 这批 TXT 的色号来自关卡 JSON 的老 34 色库（`LevelsToTxt_v1` 原样搬运），**每一张都有 5–10 个颜色 >21**。
- 官方色库是 0–21。**编辑器按官方 0–21 渲染时，>21 的格子会显示黑块**——这正是分组4 试玩失败的原因之一（见 `实验关/产线v4/失败报告_20261111.md`）。
- 但分组2 线上关卡本身就是 34 色库、游戏端可用，所以这不是「关卡错了」，而是**编辑器/验收端的色库口径问题**。
- **B2 开工前必须二选一定案**：
  1. 编辑器增加 34 色库渲染（与分组2 线上一致，不改变目标图）；
  2. 目标图做 34→22 映射（会改画面，且老库深灰/中灰在官方库里没有对应色）。
  > 推荐 1：不动图，只补渲染口径。分组4 已经证明「在错误的棋盘/色库上验证」会白跑。

### 2.2 主体检测：官方关与拼图库模板不同

- `SubjectDetect_v800` 用 `蚂蚁图库/拼接图/主体图纸库_*` 的 18×18 模板滑窗匹配；部分官方关能识别出 1–4 个主体，部分为 0。
- 主体数为 0 时，19 项里的「主体并行度 / 未动主体」会跳过——**目标感不能用这两项判**，只能用排版与试玩。

## 3. 筛选口径（按官方关分布重标定）

> 拼图库的旧目标值（16–18 色、块 3–4px）不适用于官方关：这批 212 张的中位块大小本身就是 2px（p50），色数 p50=14。

| 条件 | 取值 | 理由 |
|---|---|---|
| 候选池 | `rich`，或 `ok` 且 debtShare ≥ 0.75 | 保证有债可做 |
| 主体数 | ≥ 1 | 目标感至少有一样可查 |
| 色数（不含 0） | 11–17 | 太少压不出债，太多碎 |
| 中位块大小 | ≥ 2px | 1px 噪点做不出可辨认的车 |
| 最大色占比 | ≤ 35% | 避免一张图被单一背景色吃掉 |
| 边框占比 | 6–12%（borderPx / totalPx） | 开局免费步够用，又不至于全是免费车 |
| **空位（0）** | **0 个**（首选）；有空的先排除 | 0=空位，空位要变黑块或补色，会改变建造口径；B2 不用有空位的图 |

结果：12 张（rich 8 + ok 2 + 结构对照 2）。其中 `126`/`159` 含空位，只作备选。

**判据（事先写死）**：
