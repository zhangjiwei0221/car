## 1. 结论速览

1. **4 关里 2 关 `allPass=true`**：`v7-L6`（`.392 / .583`）与 `v6-L8`（`.533 / .520`）同时进入
   C+ 带 `.38–.54 / .28–.60`，这是 #001（0/8）之后的实质突破。
2. 另 2 关未过：`v7-L2` `.667 / .683`（双超上限）、`v6-L4` `.640 / .453`（真人已进带，原随意超上限）。
3. **结构验收 4/4 全过**：逐色容量守恒、4–5 组阶梯链、每关 7 冰、row 4..6 各 3 块 `p∈[18..31]`、
   `(5,2)/(5,4)` 与 `(6,2)/(6,4)` 上下异色且 **2×2 机关在爬山中完整保留**（总工修掉二次换位后已复验）。
4. **后段波形与 C+ 难度呈反向 trade-off**：两关通关的 `bufWave[2]` 只有 `1.73 / 1.40`，
   低于 #001 的 `2.13 / 2.92`；另两关（未通关）反而 `2.20 / 2.00`。
5. **v6-L4 的 style 3 存在管道列冲突**：5 链 style 3 的 `(4,1)` 正好是 v6 单管列 `(4,1)`，
   管道被 `chainUsed` 跳过 → 0 管 / 9 冰；最终建造器改选 style 0（1 管 / 7 冰），交工件结构合规。
6. **v6 两关各有 1 块冰落在落盘后只剩 2 辆的色上**（L4 `(5,3)` 色 14、L8 `(6,5)` 色 33）：
   建造器 `iceOk` 用的是管道/黑块之前的 `colorCars`，落盘后并车降为 2；棘轮仍 PASS、可解，
   但这是下一版应改成「按落盘后车辆数判定」的口径问题。

## 5. 发现与遗留

1. **总工修的「爬山后二次换位」确实是 #001 rand 上抬的根因之一**：本次删掉二次调用、在
   `climbFourSide` / `SwapClimb_v7` 内部保护 4 定点后，2×2 机关全程未被洗走，v7-L6 直接 allPass。
2. **靶向冰在 v7-L6 / v6-L8 命中 C+**，但在 v7-L2 / v6-L4 不够：前者 `.667/.683` 双超，
   后者真人 `.453` 已进带、原随意 `.640` 超上限。说明「冻救援车」的方向有效，但仍需按关卡图/风格选择是否加码。
3. **C+ 与 bufWave[2] 反向**：两关 allPass 的 `w2` 只有 `1.73 / 1.40`；未通关两关反而 `2.20 / 2.00`。
   若硬标准同时要求 `w2` 高压，这两关需要通过「保留更多中段暂存压力」的单独机制解决，不能只靠加难。
4. **v6-L4 style 3 管道列冲突（0 管 / 9 冰）**：5 链 style 3 的 `(4,1)` 与单管列 `(4,1)` 重合，
   管道被静默跳过；建造器最终改选 style 0（1 管 / 7 冰）。建议下一版把「管道列撞链自动顺延」真正实现。
5. **落盘后紧缺色冰**：v6-L4 `(5,3)` 色 14、v6-L8 `(6,5)` 色 33 落盘后只剩 2 辆；
   `iceOk` 的 `colorCars` 是管道/黑块之前的计数，口径需后移。
6. **未覆盖客户端 `bin/`**；改动前原件在 `_pre_change_backup/`。
   改后 md5：v6 `7410f33e`、v7 `fb07bbbc`。
