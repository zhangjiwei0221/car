## 1. 改动 ①：`--tier A|B|C` 档位预设 + CLI 锁定（第 50–76 行）

**改前**：`RAND_LO/RAND_HI/HUM_*/FAIR_MIN` 全部写死默认值（`.55/.68/.32/1.0/0/1/.90`）。

**改后**：
```js
const TIER = String(arg('--tier', 'auto') || 'auto').toUpperCase();
const TIER_PRESETS = {
  A: { randLo: 0.65, randHi: 0.85, humMin: 0.58, humMax: 0.88, humMidMin: 0.72, humMidMax: 0.95, fairMin: 0.92 },

const TP = TIER_PRESETS[TIER] || null;
const RAND_LO = has('--rand-lo') ? Number(arg('--rand-lo')) : (TP ? TP.randLo : 0.55);
... // 其余 6 个门槛同理
```

## 3. 改动 ③：解耦 N 管削冰 + 图层深度靶向冰（第 496–545 行）

**改前**：`3 管 → 0 冰`、`2 管 → 只留 2 颗`、单管 → 7 颗。

**改后**：
```js
const iceScale = gearOpts.iceScale || 1.0;
const scaleIce = (p) => Math.max(6, Math.min(33, Math.round(p * iceScale)));
const fullLadder = ... 0管9颗 / 1管7颗 / 2管6颗 / 3管4颗 ...;
const rowNeeds = fullLadder.map(([r, n, p]) => [r, n, scaleIce(p)]);
```
选冰权重从单一 `easyShare` 拆成：
- `earlyBottomShare`（底边前 30%）：`r=2,3` 浅冰按它排序；
- `midWaistShare`（图中腰 30~70%）：`r=4,5,6` 深冰按 `midWaistShare*1.2 + earlyBottomShare*0.5` 排序。

## 6. 施工发现

1. **AutoGear 对 B 档偏松图极其有效**：`comp_02` 从 `.758/.742/.850` 一路 +2 挡到 `.492/.533/.650`，**首次拿到 allPass**；且 `gearHistory` 完整记录了三轮配方。
2. **C 档两张图的“偏松”不是同一回事**：
   - `comp_04` 的问题在 `humMid .825`，+1 挡后 `humMid` 降到 `.70`（命中带内），但 **randCasual 反被推高到 .75**（+1 挡的 dumbbell/q3/black2 对随机档反而更“好点”）；
   - `comp_05` +1 挡后 rand `.475`（进带）但棘轮 false，终版只能回退 gear0 `.592`。
   → **升挡对 rand 与 humMid 的作用方向不稳定**，C 档需要“分指标微调”（例如仅加 sink/q、不加 black）而不是整包 +1。
3. **+2 挡会明显过冲**（comp_05 gearP2 `0/0/0`、comp_04 gearP2 style2 rand `.9`）：三黑+4沉底+4问号+三连链的整包对 35×35 图太重。建议下一版把 +2 拆成“只加 iceScale / 只加 sink”的细粒度。
4. **AutoBand 条件已按实测修正**（见 §2），11.txt 能触发，`#008` 六张图全部不触发（`autoBand=false`，`imageDiag` 可查）。
5. **`--tier` 一键档位可用**：`--tier B/C` 自动带入 7 个门槛，`--tries/--iters` 仍可叠加；未传时旧 CLI 行为不变。
