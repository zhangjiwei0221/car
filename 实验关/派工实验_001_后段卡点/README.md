## 6. 发现与遗留

1. **C+ 不是迭代次数问题**：对 v7-L2 / v7-L6 做 `--iters 60 --tries 1` 诊断，结果与 25 iters **md5 完全相同**
   （v7-L6：`1e471bf6`），说明 SwapClimb 早已收敛到局部最优，加迭代不改变档位。
2. **7 块深冰没有把难度压下来**：`randCasual` 4/4 上抬，`humCasual` 2/4 上抬、2/4 下压。
   冰点 `p=18/23/27`（v7 为 `20/25/30`）在 row 4..6 冻住 18–30 步，随机/短视玩家可点的分支变少，
   更不容易踩进溢出死局；这与派工单“深冰会压难度”的预期相反，需要用真人实机试玩判断体感。
3. **v6 `best` 选择仍按 0.62 兜底**（`BuildV6Stagger_v1.js` 第 780 行写死 `Math.abs(ver.randCasual - 0.62)`），
   C+ 中点应是 `.45`；这会让 v6 在多 style 都失败时选到 rand 偏高的候选。本次未改（超出派工单步骤），建议总工定夺。
4. **`p≤22` 铁律冲突**：`新会话启动.md` 的设计铁律要求行 2–6 冰 `p≤22`（防盲盒敲冰），
   本单明确要求 row 4..6 恢复到 `p=23/27/28`（v7 到 `30`）。本单按派工要求执行，但验收前需总工确认是否改写铁律。
5. **v6-L8 主跑 0 管**：同一命令 seed 4242 能落 1 管，证明是管道落位随机失败（已知问题），
   不是冰/机关改动导致；主表保留原始 seed 977 结果，重跑结果单列。
6. 两个建造器改动前的原件在 `_pre_change_backup/`；改后 md5：
   v6 `8e58b34be25a25163b7e65a0bf241c80`，v7 `b2f4ad45b890e18e91f320d21bcaa971`。
