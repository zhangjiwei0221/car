# G3 第 2 关「二锁链误判」预热关卡说明

目标：导入关卡后，先点若干格把暂存区填到 3，再点二锁链 `(4,6)`（32/22），
客户端会立刻弹「失败，存储区域已满」，但像素继续消除、实际没输。

## 导入方法

1. 备份客户端里的关卡文件（以下以第 2 关为例）：
   ```bash
   cp "/Users/red/Desktop/ParkPassenger.app/Contents/Resources/bin/G3_bq_level_2.json" \
      "/Users/red/Desktop/ParkPassenger.app/Contents/Resources/bin/G3_bq_level_2.json.bak"
   ```
2. 把本目录的 `BUG_<n>_G3-2.json` 内容覆盖进去（保留文件名 `G3_bq_level_2.json`）：
   ```bash
   cp "实验关/Bug_锁链误判/预热关卡/BUG_1_G3-2.json" \
      "/Users/red/Desktop/ParkPassenger.app/Contents/Resources/bin/G3_bq_level_2.json"
   ```
3. 重开客户端 → 分组 3 第 2 关 → 按每张的「预热点击」顺序点，再点 `(4,6)`。
4. 测完用 `.bak` 还原。

> 坐标口径与 `序列清单.md` 一致（行 r、列 c 均从 0 开始；`(4,6)` 即二锁链的触发格）。
> 每张都附色号/容量，若行列方向在客户端里相反，按色号/容量找同样的格子即可。

## 说明

- 关卡格式不能预置暂存区，所以每张都要先点「预热点击」把暂存填到 3。
- 精确法：把暂存车已吃掉的像素退回目标图、车辆按完整容量放回原格，预热后棋盘/暂存/数字冰与复现序列的点击前状态完全一致。
- 任务书法：`count` 用 `remaining`，已吃像素在 `blocks` 里保持 0；预热后棋盘/数字冰一致、暂存颜色一致，`need/progress` 按 `remaining` 重建。
- 数字冰统一写 `remaining + 预热点击数`：预热点击会让所有数字冰倒计时，这样点完预热后正好回到源状态的剩余值。
- 所有关卡都经过模拟器验证：`bufEnter==5`、`bufAfter<=4`、未溢出/未判死；逐色 `sum(count)`（含管道队列）等于 `blocks` 剩余像素。
