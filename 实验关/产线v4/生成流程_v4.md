# 产线 v4 生成流程（分组4：仅底边出口）

> 目标：在同一套指标下，生成“玩家从底部开始解”的关卡。
> 生成器：`03_工具/产线v4/V4Build_v1.js`；检查：`03_工具/正式版/* --bottom-only`。
> 指标定义不复制，见 `实验关/产线v3/指标口径_v1.md`。

## 0. 不变的东西（红线）

1. **容量是用户输入**：每色 `sum(count) == 目标像素数`；不许缩放、对半拆、按车数拆。
2. **棋盘取盒逻辑不变**：仍按顶部暴露/暂存 5；底边机制只改**目标图像像素的可达入口**。
3. **检查口径不变**：ArlCheck 19 项、点击结算 forced/policy、free-first OpeningCheck、ChoiceSpace、PlayerSim、Layout 仍各算各的，不能混。
4. **一次只改一个生成变量**：先改顺序，再改容量/链/冰；每次记录改前/改后。

## 1. 输入

- 一张正常关卡 JSON（优先桌面 `正常关卡/G8_bq_level_*.json`）——用它的 `blocks` 当目标图；
- 或一张目标图 TXT（需要先转成 `blocks` 格式）；
- 棋盘 `--rows/--cols`、车容量范围 `--box-min/--box-max`。

## 2. 生成步骤

### 2.1 底边消除顺序

```js
const eo = A.eliminationOrder(blocks, R, C, true);
```

- `eo.roundColors` 是“每一轮从底边可达区剥离的颜色段”；
- 轮次早 = 底边先露出，应该优先给玩家；
- 若 `covered < 总像素`，说明图有永久不可达像素，先换图或改图，不要硬生成。

### 2.2 切车

- 默认：每个轮次段按 `--box-max` 切；
- `--lump`：按颜色合并总像素再切，制造跨窗口的大债（v4 第一关用这个）；
- `--split-colors 19 --split-max 80`：把指定颜色拆成更多车，用来补中段/成链；
- 每辆车 `count` 必须 >0；避免 ≤5px 碎车（排版 L1 会否决）。

### 2.3 摆盘

- 棋盘 `row0` 是顶部暴露位；**轮次早的车放顶行**，轮次晚的车放深行；
- 同色车连续摆放，便于 `--auto-chain` 成链；
- 空格用 `{id:-1,type:0,param:0,count:0}`，不要用 `null`。

### 2.4 造债（按需）

- `--auto-chain N`：相邻同色两两成链，制造整组债；
- 第一关 v1 经验：`--box-max 120 --lump --split-colors 19 --split-max 80 --auto-chain 8` 得到 peak4/mid40/tol11/open7；再拆 27/20 成两辆后段车得到 v2：mid64、at3 0→1、at4 3→4。
- 更大车（140/160）会掉 peak 或不通；更小车（60/80）会 mid0/tol0。**参数不是单调的，必须逐组测。**

### 2.5 检查

```bash
node 03_工具/正式版/RecoveryVariantCheck_v1.js <目录> --bottom-only --out <checks.json>
node 03_工具/正式版/PlayerEngineCheck_v1.js <关卡.json> --bottom-only --family
```

主看：

- 硬门：can✓、容量守恒、无空格、排版 hard0；
- 低流失：peak4、mid45–80（试行下限40）、tol11–15、open≥5、C0=0、F0≤2、点击 policy0/ff、PlayerSim policy0/2；
- 目标感：象限/主体/未动主体；
- 不通过时先看是哪一项极端，不要用一个总分判断。

## 3. 第一关的复现

先用 `V4Build_v1` 生成 v1 骨架：

```bash
node 03_工具/产线v4/V4Build_v1.js /Users/red/Desktop/正常关卡/G8_bq_level_12.json \
  --out 实验关/产线v4/分组4/第一关/G4_第一关_底边重排.json \
  --rows 7 --cols 7 --box-min 20 --box-max 120 --lump \
  --split-colors 19 --split-max 80 --auto-chain 8
```

再做 v2 两处后段拆车（当前候选）：

- `27:r1c0 92 → 46 @r1c0 + 46 @r3c0`
- `20:r2c1 38 → 19 @r2c1 + 19 @r3c1`

v2 结果：peak4 / mid64 / tol11 / open7 / C0=F0=0 / 点击 policy0=Y / ff=Y / 排版 hard0；19 项仍不过 5 项（后20% at3=1、at4=4、象限3.88、主体82%、未动主体0），PlayerSim `forced=N/policy0=N/policy2=Y`。

> 后段加重（把 20 放更深行）能到 at3=2，但全部 `can✗/tol0`；v2 是当前不破坏可通关的上限。

## 4. 失败模式（已踩）

| 做法 | 结果 |
|---|---|
| 正常关直搬 | 7/8 可通关但 0/8 过 19；车盘顺序与底边像素顺序不匹配 |
| 每轮段单独切车 | peak0、mid0、tol20；车一拿就满，没有债 |
| 加冰压 tol | 行0加冰 4/6/8 仍 tol19/20；冰不是中段债的替代品 |
| 车太小（boxMax 60/80） | mid0/tol0 或不通 |
| 车太大（140/160） | peak3 或不通（180 直接死） |
| 只信点击结算 | L121/第一关点击 policy0=Y，但 PlayerSim policy0=N |
