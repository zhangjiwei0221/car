# 墙机制 / 仅底边出口：需求与实现对齐（v1，2026-11-11）

> 来源：用户需求文档“新增规则：墙”。
> 适用：产线 v4 / 分组4。

## 1. 需求原文要点

**机制**：目标区原本四周都是出口，边缘像素可以直接选取；现在把上、左、右三面改成墙，只有底边仍然是出口。

**墙的范围**：目标区的上边、左边、右边（三面）。

**墙的效果**：

1. 贴墙的像素不能从墙这一侧离开，这一侧不再算通路；
2. 贴墙的像素能不能拿，取决于它其他非墙的方向是否被阻挡；
3. **内层像素不受影响，原有消除逻辑不变。**

## 2. 实现映射

| 需求 | 实现 |
|---|---|
| 上/左/右为墙、底边唯一出口 | `outsideReachSeed(blocks,rows,cols,true)`：只从 `r===rows-1` 播种已消空格 |
| 贴墙像素不能从墙侧离开 | `floodFillEliminate` 的 `reachable()`：`bottomOnly` 时 `r===rows-1` 才直接可达；越界只在底边方向允许；其余靠“邻接已消格” |
| 其他方向被阻挡 | 同 `reachable()` 的 4 邻接已消格判定；没有通路就不算可达 |
| 内层/原消除逻辑不变 | **像素选取顺序仍是左下角(corner)**；`bottomOnly` 只改可达入口，不改 `PICK_REF` 的 corner 口径 |
| 棋盘取盒 | 不变（仍顶部暴露/暂存 5），底边机制只作用在目标图像像素 |

## 3. 检查口径

v4 检查工具统一 `--bottom-only`，且加载器用 `loadSolver('corner')`：

- `ArlCheck` / 点击结算 / OpeningCheck / ChoiceSpace / PlayerSim 全部是 **底边可达 + corner 顺序**；
- 这与需求“内层像素不受影响、原消除逻辑不变”一致。

## 4. 编辑器对齐（v638）

- 编辑器 `#sim-elim-mode` 的 **“仅底部入口”**：`pickRefOfMode('bottomOnly')` 从旧的 `ring` 改为 **`corner`**；
- 标签改为“仅底部入口（左下角，分组4）”；
- “⏩ 底部版”演示在求解/回放前显式 `setPickRef('corner')`，保证与手点同口径；
- 四边入口/底边/瞬时连锁等其他模式不变；
- 版本号：`APP_BUILD`、`<title>`、脚本 query 统一升到 **v638**。

## 5. 与旧实现的差异（重要）

旧编辑器“仅底部入口”= 底边可达 + **ring（圈序）**，和需求文档不一致；旧数据/旧截图里的“仅底部入口”结果不能直接当分组4 口径。分组4 以本文件第 2/3 节的 **bottomOnly + corner** 为准。
