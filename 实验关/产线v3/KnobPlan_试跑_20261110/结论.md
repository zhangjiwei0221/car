## 2. 分关说明

### L2：mid 能抬，tol 越界

- 基线 D14.4、peak4、mid21、tol9、open6、C0/F0=0/0、clickForced/policy0=Y/Y。
- `iceadd_r0c1_6`（给 r0c1 的 70px 车加冰 6）：D8.9、mid21→38、tol9→16、open6→5、C0/F0=0/0。
- `cap_13_small2big`：D10.1、mid34、tol16。
- 两条都把 mid 抬起来，但 tol 从 9 跳到 16，越过 low-churn 的 11–15。不是“失败”，是“方向对、单旋钮过头”；下一步应做“加冰 + 恢复/容量”两旋钮，或把 tol16 当软项单独试。
- PlayerSim：基线 `policy0=N / policy2=Y`；`iceadd_r0c1_6` 仍是 `policy0=N / policy2=Y`。真实 0 复活没有改善，但也没更差。

### L5：开局只能到 4

- 基线 D7.0、peak3、mid47、tol19、open3、C0/F0=0/0。
- `relief_transfer_r0c5/r0c6` 只能把 open 提到 4；`relief_transfer_r0c5` 还把 mid 压到 0；`swap_r0c1/r1c1` 把 C0/F0 拉到 2/5。
- 和方向1 旧结论一致：L5 不是单旋钮能修的，需要结构重做（开局/棋盘/链），不是继续调冰。

### L7：有温和候选，但真实 0 复活仍 N

- 基线 D22.1、peak4、mid84、tol20、open6、C0/F0=0/0、clickForced/policy0=Y/Y。
- `ice75_r4c4`：D21.2、mid81、tol20、open6；点击结算 profile 过，只有 `tolLoose` 提示。**这是最保守的可用候选。**
- `cap_14_big2small`：D6.5、mid77；`ice75_r0c1`：D4.9、mid74。两条都触发 `Ddrop>15`、`tolLoose`、`midCross80(D惩罚)`——D 大降主要来自“mid 从 ≥80 掉到 <80”的公式惩罚，不等于真的变成无脑。
- PlayerSim：基线 `policy0=N / policy2=Y`；三条候选全部 `policy0=N / policy2=Y`。候选没有改善真实 0 复活，只是点击结算口径过。

### L10：open4 与 profile 冲突

- 基线 D23.4、peak4、mid63、tol20、open4、C0/F0=0/2。
- `relief_split_r0c5` 能把 open 提到 5，但 mid 13、tol0；`swap` 候选都保 mid63，但 open 仍 4。

### L12：mid 只能到 23

- 基线 D24.3、peak4、mid17、tol13、open6、C0/F0=0/2。
- `cap_14_small2big`：mid23、tol20；`cap_13_small2big`：mid17、tol15；`iceadd` 反而把 mid 压到 13–17。
- mid 17 是平的，单旋钮只能抬到 23 左右，且 tol 变松；需要结构重做（链/管道/晚段债）。

## 3. 结论

1. **单旋钮工具在“基线硬门基本 OK、只差一项”的关上有效**：L7 能找到 `ice75_r4c4` 这种温和候选。
2. **L2 是“方向对但单旋钮过头”**：加冰抬 mid 的同时 tol 越过 15；下一步做两旋钮，不是继续加冰。
3. **L5/L10/L12 是结构瓶颈**：开局/棋盘/链的容量-可达问题，单旋钮只能改善一个指标、另一个塌；继续拧参数是打地鼠。
4. **L7 的 D 4.9/6.5 不能当“无脑”证据**：mid 仍有 74–77，D 大降来自 `mid≥80` 惩罚；必须同时看 mid/entropy/tol。
5. **点击结算 policy0=Y ≠ PlayerSim policy0=Y**：L2/L7 基线都是反例；真实 0 复活要单独跑 `--player`。

## 4. 下一步

1. **L7**：拿 `ice75_r4c4` 做小批试玩/线上 A/B；它是最保守的“降难度但不压平”候选。
2. **L2**：做两旋钮组合（`iceadd_r0c1_6` + 恢复车/容量重分配），目标 mid≥40、tol≤15、PlayerSim policy0 至少不降。
3. **L5/L10/L12**：停止单旋钮调参，进入结构重做（开局/链/管道/晚段债）。
4. **L3/L11**：当前 can✗，单旋钮救不了；先修容量-可达，再谈难度。
