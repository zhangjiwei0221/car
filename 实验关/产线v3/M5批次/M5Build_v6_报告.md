## 1. v6 要解决什么

v5 的 00045 候选已经做到峰值4/中段67/容错13/开局5/0复活5seeds，但：

- opening 5 全是顶行大车：`30:86 / 30:67 / 30:67 / 13:86 / 13:73`；
- 点击结算第 **5** 步 buffer3、第 **8** 步 buffer4；
- `forced=N`（第34步死）。

v6 的目标不是“把峰值做上去”，而是：

1. opening 变成 **2 辆大债车 + 3 辆中等/缓解车**；
2. 把 buffer3 推到 **10–15 步**、buffer4 推到 **13–18 步**；
3. 保持峰值4/中段45–80/容错11–15/开局5/0复活；
4. 争取 `forced=Y`。

## 2. 做法

在 v5 配方上做“opening 角色 + 小容量”搜索，不改图、不加新障碍：

1. **换位**：`0,4`（13:73）↔ `1,2`（3:19），把一辆大 13 从开局移到第 6 步后；
2. **30 容量**：`0,0/0,1/0,2` = `86/54/80`；
3. **13 容量**：`0,3`=73、`1,2`=86；
4. **3 容量**：`0,4`=60、`2,4`=49；
5. **23/22/2 微调**：23:12@`2,2` + 28@`2,0`；22:70/52；2:80/56；
6. 用点击结算看 buffer3/4 首次步，用 `ArlCheck` 看峰值/中段/容错，用 `PlayerEngineCheck` 看 forced/0复活，用 5 seeds 复核。

搜索里有一个明确的取舍：

- 把 buffer3 推到第 12–13 步、buffer4 到第 16 步的版本，0 复活只剩 t=0.4 能过；
- 保留 t=0.6/0.8 都能过 0 复活的版本，buffer3 只能到第 11 步、buffer4 第 13 步。
- 选后者：**先保证 0 复活策略族稳定，再尽量后移压力**。

## 5. 结论与下一步

- **M5 不是“峰值做不上去”**：v5/v6 都已经是峰值4；真正难的是 opening 压力形状、forced、0复活策略族和目标感同时成立。
- v6 解决了 v5 的两个主要问题：**opening 全大车** + **forced=N**；代价是 19 项目标感仍有 4–5 项不过。
- **但用户路径证明 opening 仍然“堵”**：`~/Downloads/点击路径_2026-11-09T10-32-50.json` 第1步 5 个选项只有 2 个免费；先拿 `30:86` 后第4步 `F=0`、第6步 `C=0`（两个候选都 0 消除、都加债）。贪心路线先拿 13:73 再拿 30:86，30:86 才会免费；拿反了就堵死。详见 `00045_v6/用户路径_2026-11-09T10-32-50_分析.md`。
- 所以 v6 不能按“前期压力已解决”收；它只解决了贪心平均，没有解决任意合理顺序的恢复窗口。
- 下一步优先级：
  1. 确认“顺序鲁棒性”是否作为 opening 硬门：`buffer≥1 时 F≥1`、连续 `F=0≤1`、`buffer<5` 不允许 `C=0`；
  2. v7 先修 `3:60 @0,4` 或 `30:86`，让“先拿大债”的顺序也不至于第4步 F=0；
  3. 把“2 大 + 3 中”改成“2 大 + 3 免费/恢复”，并在用户路径/多顺序上验收，不只跑贪心；
  4. 目标感 4 项（象限/主体/未动主体/低压）是否升硬门，决定 v7 要不要同时修；
  5. **opening 角色搜索尚未工具化**：批量前应把“2 大 + 3 免费/恢复”的换位/容量分配写成 `M5Build_v6.js`，否则每张图都要手工试。
- **现在不建议批量。**
