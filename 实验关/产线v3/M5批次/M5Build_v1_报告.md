# M5Build_v1 报告（2026-11-09）

> 目标：按角色（opening / gate / debt / chain / pipe）从一张 `关卡/` 图生成 7×7 候选，再跑 v3 门。
> 状态：工具已落地，**还没有候选同时过 ArlCheck 峰值/中段/容错**；M5 仍在试点。

## 1. 工具做了什么

`03_工具/正式版/M5Build_v1.js`：

- 输入 `关卡/*.txt`，统计颜色总量与边框色；
- 边框色按 ~70px/车拆，至少一辆 >76px 的“看得见但吃不满”债车；
- 内部色按 `--inner-target` 拆（默认45），凑到 48 spool + 3 管道队列；
- 顶行 5 辆 opening，其余边框车挂冰；中心放管道；
- 中段/后排各找一组相邻内部车做 2 连链；
- 输出配方，`BuildFromRecipe_v1` 重建，再跑 PlayerEngine/ArlCheck/AnimClickSettle/LayoutScore。

复现：

```bash
node 03_工具/正式版/M5Build_v1.js 关卡/关卡00045_原图050-043-036-035_分图4色_40x40.txt \
  --out 实验关/产线v3/M5批次/00045_build/s1.recipe.json --seed 1 --inner-target 45
```

## 3. 失败原因

1. 随机落点/链组没有“路线窗口”意识：链组放中段还是后排、冰值 6/8/10，都会把峰值/容错差拉得很大；
2. 边框债车（>76px）能制造峰值，但也让容错变低；内部车大多数容量 ≤ 当时可达，补不上中段；
3. 生成器只保证守恒/可通/部分压力，没有对 `峰值/中段/容错/选择空间` 做局部搜索。

## 4. 下一步

`M5Build_v2` 不在全空间搜，而是对每个种子做三件事：

1. 用 `ReachabilityCurve`/点击结算找“债车窗口”，把大车放到该窗口；
2. 对冰值/链组位置/链成员容量做小网格搜索（每组 3–5 个候选）；
3. 以 `峰值4 + 中段45–80 + 容错55–75 + 0复活 + 选择空间 buffer≥3 时 F≥1` 打分，只留全过。

当前 00045 的 s5/s17/s21 可作为“峰值4但太紧”的起点；s10 作为“太松”的起点，用来调中间档。
