# 语法库 v1（M4，2026-11-08）

> **一句话**：把 M3 验证过的障碍契约，写成「可复用、可验收、可组合」的关卡语法。
> **证据**：`M3_障碍契约_消融.md`、`M3_管道契约_问号信息.md`、v3-19～v3-22。
> **范例关**：F2（`00154中段/F2_68_36_30_25_19_25_21_42.json`）。
> **配方**：`F2_配方_v1.json` → `BuildFromRecipe_v1.js` 复现（深比较相等）。

---

## 0. 怎么用

1. 选图 → 用 `ImageDebtScan` / `LayoutScore` 判材料（碎车、同色整行、主体）；
2. 按 §2 选 motif，写在配方 `notes.grammar` 里；
3. 用 `BuildFromRecipe` 重建 → 跑 `ArlCheck_v793` + `PlayerEngineCheck --family --prefer-small-debt`；
4. 对每个 motif 做**消融**，填它的契约（Δ win/peak/mid/tolerance/opening）；
5. 契约成立才进语法；Δ=0 的标「装饰」，不许当卖点。

**记法**（每个 motif 五段）：

```
motif:     名字
slot:      放在哪（行/窗口/格位）
param:     参数范围与取值依据
contract:  它改变什么（win / peak / mid / tolerance / opening / order）
measure:   消融怎么测、Δ 多少算成立
reject:    什么情况下不算这个 motif
```

## 2. 逐个契约

### 2.1 冰·win gate

- **slot**：顶行、容量 ≥60 的大车；放在玩家开局就会看见的位置。
- **param**：F2 = 17（3:84 @ r0c0）、42（2:43 @ r1c1）。数值按「目标色窗口步」推，不搬图。
- **contract**：没有它，0 复活路线在中后段死亡。
- **measure**：去掉冰 → 0 复活从 47 步通关变为第 34 / 24 步死；2 复活仍可过（说明是 0 复活门，不是绝对门）。
- **reject**：冰值过小（≤2）或车太小（<20px）时，Δ 可能为 0；必须实测。

### 2.2 冰·peak gate

- **slot**：顶行、峰值路径上的第三辆大车（F2：3:48 @ r1c4）。
- **param**：F2 = 16；比 win gate 略小，只压峰值不压通关。
- **contract**：把峰值锁在 4。
- **measure**：去掉 → 仍通关，峰值 4→5。
- **reject**：与其他冰同时去掉时可能被链组掩盖（交互），必须成组消融。

### 2.3 冰·rhythm

- **slot**：顶行主色车（F2：3:63 @ r0c2）。
- **param**：F2 = 6；小值，只把车推后 1–2 个窗口。
- **contract**：中段压力与容错；也决定颜色 3 的第一个可拿窗口。
- **measure**：去掉 → 中段 44→33、容错 14→10；通关不变。
- **reject**：冰 ≥10 会把车推过头，开局/中段反而垮（v3-15：冰 10+ 第 8 步死）。

### 2.4 链·mid pressure

- **slot**：中下段、正交相邻的 3 车组；两组用不同 `param`。
- **param**：F2 组 1 = `r3c0 30:22 / r4c0 30:39 / r5c0 19:21`；组 2 = `r3c5 14:33 / r4c5 33:30 / r5c5 28:27`。
- **contract**：制造中期整组债与释放节奏；不负责通关门。
- **measure**：去掉两组 → 仍通关，中段 44→0、容错 14→9（「能通但没拉扯」）。
- **reject**：链组不在正交相邻位置 → 排版判据 L4 直接否决；组内车太大且暴露步不可达 → 会变成死锁（v3-06）。

### 2.5 管道·supply / order

- **slot**：内格（F2：`r2c2`）；内格放车会堵求解器，放管道正好占位。
- **param**：队列 `23:23 / 23:31 / 4:37`（3 辆）；管道格 `id=0, type=11–14, param=队列`。
- **contract**：晚段供给两辆 23、一辆 4；队列顺序是设计杠杆。
- **measure**：去管道（容量并入普通车）→ 峰值 4→3、中段 44→29；`31 先` → 默认 oracle 路线第 29 步死；`4 先` → 中段 41。
- **reject**：管道格不能算黑格；容量守恒必须把队列车算进去（`BuildFromRecipe_v1` 已支持）。

### 2.6 容量拆分·never

- **slot**：深格/边缘，避开内格（内格放车会堵）。
- **param**：F2：31 → 18+18（`r2c4`、`r4c3`）；20 → 17+18（`r3c3`、`r2c6`）。
- **contract**：把「整辆都拿不到」的 never 色变成可分次拿。
- **measure**：拆分前 0 复活 0/多次失败；拆分后首次 47 步 100% 通关。
- **reject**：拆太小（3–5px）→ 排版 L1 硬否决；拆目标色的大车可能伤峰值/容错（33 拆分实测伤）。

### 2.7 容量拆分·mid

- **slot**：多车色的容量组合。
- **param**：F2：13 → 68/36/30/25；19 → 25/21/42。
- **contract**：中段 44%、容错 14/20。
- **measure**：v3-22 对照：13 拆分把中段 38→45；19 拆分把容错 17→14–15。
- **reject**：拆分不是越多越好；先看该色在路线上的窗口，再定「大+小」比例。

### 2.8 开局换位

- **slot**：顶行目标色车 ↔ 第二行非目标色车。
- **param**：F2：`r0c6 3:48+冰16` ↔ `r1c4 22:22`。
- **contract**：开局可点 4→5，同时保住峰值 4 与 0 复活。
- **measure**：S3 换位后开局 5；S1 峰值 2；S2/S4/S5 破坏可玩。
- **reject**：用「清目标色冰」补开局会破坏可玩；必须换位。

### 2.9 问号·info（未成立）

- **slot**：玩家实际会选的车位。
- **contract**：F2 的 `r6c2 30:17` 对 oracle / visible 都无 Δ → **装饰**。
- **measure**：隐藏 vs 揭示同结果；Q3/Q4 把顶行会被选的 `2:59` 变问号，仍无差（策略没选它）。
- **reject**：当前位置不在决策上时，不许写「信息障碍」；要成立需 Q-aware 策略或真人试玩。

## 3. 组合规则

1. **先门后节奏**：先放 win gate / peak gate，再放 rhythm；顺序反了会拿节奏冰当门用。
2. **冰参数逐图重推**：同图派生可以，搬图 = 容错 0/20。
3. **链组必须正交**，且组内车在暴露步可达；否则是死锁，不是压力。
4. **管道放内格**，队列顺序最后调；先定供给颜色，再定顺序。
5. **拆分先 never 后 mid**：never 决定能不能通，mid 决定好不好玩。
6. **开局最后补**：用换位，不用清冰。
7. **一次只动一个 motif**，消融 Δ 记录在证书里。

## 4. 失败语法（负结果，别再试）

| 做法 | 结果 |
|---|---|
| 搬冰参数到新图 | 容错 0/20 |
| 同色整行/整列 | 排版 L2 硬否决（半成品关） |
| 3–5px 碎车 | 排版 L1 硬否决 |
| 链组不在正交位 | 排版 L4 否决 |
| 内格放普通车 | 求解器堵死（v3-19） |
| 问号随便放 | 无决策，Δ=0 |
| 用清冰补开局 | 破坏可玩（v3-21） |
| 局部加冰打地鼠 | 第二瓶颈顶上来（v3-16） |

## 5. 配方与复现

配方字段（`BuildFromRecipe_v1.js`）：

```json
{
  "name": "...",
  "toprow": 40, "maprow": 7, "mapcol": 7,
  "blocks": [[...]],
  "cars":   [{"r":0,"c":0,"id":3,"count":84}],
  "black":  [],
  "obstacles": [{"r":0,"c":0,"type":7,"param":17},
                {"r":6,"c":2,"type":[0,6],"param":0,"q":true}],
  "pipes":  [{"r":2,"c":2,"type":11,
              "param":[{"id":23,"count":23},{"id":23,"count":31},{"id":4,"count":37}]}],
  "notes": {"grammar": ["ice:win-gate ..."]}
}
```

复现：

```bash
node 03_工具/正式版/BuildFromRecipe_v1.js 实验关/产线v3/F2_配方_v1.json --out 实验关/产线v3/F2_重建_v1.json
```

验收：解析后与 F2 **深比较相等**（`JSON.stringify` 一致）。文件 sha 不同仅因原文件带空格格式。
