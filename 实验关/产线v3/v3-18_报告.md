# v3-18 报告：WindowPlan_v2——early / never 分开了；第二瓶颈是 never

> 日期：2026-11-07
> 工具：`03_工具/正式版/WindowPlan_v2.js`
> 输入：00154 原关 + `00154_r0c2_冰6.json`
> 目的：用更长的玩家路线（p2）算窗口，区分 `early`（能等）和 `never`（等不到）。

---

## 1. 方法

1. 跑 `PlayerSim` 0 复活（p0）和 2 复活（p2），都开 `trackReach`；
2. 取「拿车更多/走得更远」的那条当参考（00154 冰6：p2 45 步通关，p0 26 步）；
3. 每辆车：`windowStep` = 参考路线里该色第一次 `reach >= count` 的步；
4. 分类：
   - `ok`：玩家拿时 reach ≥ count；
   - `early`：玩家拿时不够，参考路线后面能追上 → 建议冰；
   - `never`：参考路线直到结束都没追上 → 加冰救不了；
   - `unpicked`：玩家路线没拿；
   - `chain`：锁链车。

---

## 2. 结果

### 00154 原关

```
p0 picks=7 won=false; p2 picks=28 won=false; ref=p2
status: { early:3, unpicked:34, ok:3, chain:6 }
```

early：
- `r0c1` 30:70 → window 26，early 24 步/24 球（冰 20）
- `r0c4` 30:52 → window 26，early 23 步/23 球（冰 20）
- `r0c2` 3:63 → window 17，early 12 步/12 球（冰 12）

### 00154 冰6

```
p0 picks=26 won=false; p2 picks=45 won=true; ref=p2
status: { early:4, unpicked:17, ok:17, never:2, chain:6 }
```

- early：`r1c0` 3:15 → window 23，early 4 步/4 球（冰 4）
- **never：`r2c4` 31:36（玩家第 15 步 reach 31）、`r3c3` 20:35（玩家第 16 步 reach 9）**
- 这两个正是第二瓶颈的 `31:4 / 20:26`。

### 应用 early 冰

- `--apply-top 2` 给 early 车加冰：p0 仍 0/1，p2 1/1；
- **early 冰救不了 never 的 31/20。**

---

## 3. 结论

1. `WindowPlan_v2` 成功把「能等」和「等不到」分开：early 可以加冰/延后；never 不行。
2. **00154 第二瓶颈 31/20 是 never**：在 p2 通关路线里都没有 reach 窗口（p2 是靠复活移走它们赢的）。加冰只会把债换给 24，不会通关。
3. 这和 v3-16 完全一致：第二瓶颈是结构性的，需要改容量/棋盘/图，不是加冰。
4. `never` 的处理方向：
   - 单色单车：把容量拆成两辆（如 31:36 → 18+18），让它们在不同窗口分别填；
   - 或把车移到更晚/更早的位置，让窗口出现；
   - 或换图/改目标图，让该色更早暴露。

---

## 4. 对编译器的三分类

| 状态 | 处理 |
|---|---|
| `early` | 按窗口加冰/延后（WindowPlan 可自动出冰量） |
| `never` | 不加冰；拆容量 / 改位置 / 换图 |
| `chain / pipe` | 特殊排程，单独规则 |
