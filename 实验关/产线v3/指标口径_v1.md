# 指标口径 v1（2026-11-09）

> **用途**：一张表说清“每个指标算什么、用什么模型、能不能当硬门”。
> **原则**：同名不同模型的，必须标模型；不要把求解器、噪声求解器、PlayerSim、点击结算混着比。
> **状态**：口径记录，不是新需求；冲突时以代码 + 本文件为准，历史报告只作证据。

## 0. 六个模型（先看这个）

| 层 | 工具/代码 | 路线/引擎 | 回答什么 |
|---|---|---|---|
| 结构求解 | `ArlCheck_v793` 的 `runMinBuffer` | 求解器**最小暂存路线**（一次取车=完整结算） | 最优路线能不能通、峰值/at4/免费连续 |
| 噪声求解器族 | `ArlCheck_v793` 的 20 局 | 20 局带噪声求解器（不是 PlayerSim） | 中段/后20/玩家峰值/容错 |
| 玩家引擎 | `PlayerEngineCheck_v1` / `playersim.js` | `PlayerSim` 逐 tick 并发结算 | forced、0/2复活、真 stuck |
| 点击结算 | `AnimClickSettle_v1` | 点一次车 → 当前可达像素一次吃满 | 点击后的最终暂存、免费步、raw 债 |
| 选择空间 | 工作日志 §1021–§1022 原型 | 每步枚举合法车并 `applyPick` 试算 | M/C/F/D、压力步安全选项 |
| 排版 | `LayoutScore_v1` | 静态布局 | 碎车/同色行/链正交/可辨性 |
| 信息层（诊断） | `VisibleReach` / M2 报告 | PlayerSim + 可见 reach | 看得到 vs 真可达 |

**关键**：ArlCheck 里的“玩家中段/玩家峰值/容错”不是 PlayerSim，是 20 局噪声求解器。真正的玩家引擎结论在 `PlayerEngineCheck`。

## 1. ArlCheck 19 项（完整硬门）

> 代码：`03_工具/正式版/ArlCheck_v793.js` 第 251–300 行。  
> 注意：19 项内部也不是一条路线：峰值/at4/免费连续用最小路线；中段/后20/容错用 20 局噪声求解器；象限/主体用普通求解器取车序；开局/没得选用 Simulator 回放求解器取车序。

### 1.1 通关/守恒（3）

| 指标 | 定义 | 目标 |
|---|---|---|
| 可通关（最小路线） | `Solver.runMinBuffer(depth3, instantChain=false)` 是否走完 | 必须 ✓ |
| 无空格 | 车盘没有空槽（管道格算合法） | 必须 0 |
| 容量守恒 | 所有车容量（含管道队列）== 目标像素数 | 必须相等 |

### 1.2 压力形状（5）

| 指标 | 定义 | 目标 |
|---|---|---|
| 峰值=4 | 最小暂存路线上 `buffer` 最大值 | 必须 =4 |
| 前10% at4≤1 | 最小路线前 10% 中 `buffer≥4` 的步数 | ≤1 |
| 玩家中段 45–80% | 20 局噪声求解器，每局中段（10–80%）at3 占比，取中位数 | 45–80% |
| 中段最长低压≤5 | 最小路线中段连续 `buffer≤1` 的最长步数 | ≤5 |
| 玩家峰值≤5 | 20 局噪声求解器峰值中位数 | ≤5（最优路线仍须4） |

### 1.3 选择/被迫（4）

| 指标 | 定义 | 目标 |
|---|---|---|
| 开局可点≥5 | 开局 `Simulator.listMoves` 的合法车数 | ≥5 |
| 没得选≤一半 | 按求解器取车序回放：合法车≤1，或没有一辆能**吃满**的步数 | ≤总步数一半 |
| 最长连续没得选≤2 | 上面这种步的连续长度 | ≤2 |
| at4≥5 | 最小路线上 `buffer≥4` 的步数 | ≥5 |

### 1.4 节奏/后段/容错（4）

| 指标 | 定义 | 目标 |
|---|---|---|
| 最长连续免费≤5 | 最小路线连续 `buffer=0` 的最长步数 | ≤5 |
| 玩家后20% at3≥2 | 20 局噪声求解器后 20% 的 at3 中位数 | ≥2 |
| 玩家后20% 连续≥2 | 后 20% 连续 at3 的中位数 | ≥2 |
| 容错 55–75% | 20 局噪声求解器里赢了几局 | 11–15/20 |

> **容错不是玩家容错**：它是“噪声求解器胜率”。20/20=太松，<11/20=太脆；第2关 tol19/20 但线上流失45.8% 就是反例。

### 1.5 目标感（3）

| 指标 | 定义 | 目标 |
|---|---|---|
| 象限并行度≤3.6 | 按求解器取车序，平均有几个象限处于 2–98% 进度 | ≤3.6 |
| 主体并行度≤65% | `SubjectDetect_v800` 识别的主体里，平均多少在动 | ≤65% |
| 全程最少未动主体≥1 | 任何一步至少还有 1 个主体没被碰 | ≥1 |

> 主体检测不出时这两项跳过；它们主要服务图库拼图。

### 1.6 软项/参考项（不参与通过）

- 前10% 免费步（只提示）
- 象限内部碎度（参考）
- 参考“最小暂存路线 通/完成”
- 参考“求解器路线中段”
- 参考“全知 at4”
- 参考“决策度”
- 原始“没得选”计数
- 参考“贪心路线可通关”
- `容错` 加 `--soft-tolerance` 可降软

## 2. PlayerEngineCheck（真正玩家引擎）

代码：`03_工具/正式版/PlayerEngineCheck_v1.js`。

| 输出 | 定义 | 怎么读 |
|---|---|---|
| `solver=Y/N(steps)` | 最小暂存路线能否通 | 和 ArlCheck“可通关”同口径 |
| `forced=Y/N(picks,dDeath,mmMismatch)` | 把求解器最小路线**强制**喂给 PlayerSim | `forced=N`=最优路线玩家引擎走不通；`d`死亡步，`mm`没照走的步数 |
| `policy0=Y/N` | 策略族里 0 复活至少一条能通 | “0复活能不能过” |
| `policy2=Y/N` | 策略族里最多 2 次复活至少一条能通 | “2复活能不能过” |
| `GAP` | solver=Y 但 policy0=N | 求解器能过、玩家不能过 |
| `revive` | 死亡时自动复活，最多 `reviveCap` 次 | 0/2 是上限，不是“允许错2次” |

**策略族口径**：

- `pickThreshold`：不加 `--family` 只跑 0.6；加了跑 0.4/0.6/0.8。
- `lookahead2`：`--lookahead` 才开。
- `preferSmallDebt`：`--prefer-small-debt` 才同时跑 false/true；不加只跑 false。
- A 关“0复活 5seeds”必须写清阈值和 psd，否则不可比。
- 00045 v5 只有 `0.8 + psd=false` 5/5；`psd=true` 0复活会死。v6 在 `0.6/0.8 + psd=false` 5/5，`0.4 + psd=true` 也能过。

**真 stuck**（`playersim.js:447-467`）：

- `stuckCars` = 未完成 + 该色当前**没有任何可达像素**的车。
- `stuckPx` = 这些车还差多少像素。
- raw buffer 里的“正在吃/免费”车不算真 stuck。

## 3. AnimClickSettle（点击结算）

代码：`03_工具/正式版/AnimClickSettle_v1.js`。

### 3.1 路线

默认 `click-settle-greedy (free-first)`：

1. 枚举合法车，逐只 `applyPick` 试算；
2. 先选 `bufferAfter=0` 的；
3. 再比吃得多；
4. 再比 buffer 少、stuckPx 少；
5. 贪心死局时可用 `--beam` 回退。

`--from-player` 是旧口径，仅对照。

### 3.2 输出

| 字段 | 代码里的意思 | 备注 |
|---|---|---|
| `freeSteps` | 点击后 `bufferAfter=0` 的点击数 | 不是“免费车数量” |
| `freeRun` | 连续 `bufferAfter=0` 的最长步数 | 诊断 |
| `maxBuffer` | 点击后暂存成员数最大值 | 含已吃满但被链组占槽的成员 |
| `stuckPeak` | **代码里等于 `maxBuffer`** | **不是真 stuck** |
| `stuckSteps` | `bufferAfter≥1` 的步数 | 也是 raw buffer |
| `stuckCars` / `stuckPx`（每步） | 暂存成员数 / 这些成员还差多少像素 | raw 债，不是“无路可吃”真债 |

`debtOf(s)=s.buffer`：暂存里所有成员都算债，包括链组里已吃满但仍占槽的成员。

**命名坑**：点击结算的 `stuck*` 是 raw buffer；真 stuck 只在 PlayerSim tick 里。历史报告里“真债峰值4”多数其实是 raw buffer 4，不是 true stuck 4。

### 3.3 `debtCars(>10px)`

- 用户路径分析里的临时口径：buffer 中剩余 >10px 的车。
- 不是 v3 原有指标，也不是 true stuck；只用于解释“raw buffer 高但都是快吃完的车”。

## 4. 选择空间 M/C/F/D（未固化）

来源：工作日志 §1021–§1022。  
原型：每步枚举候选并 `applyPick` 试算。

| 符号 | 定义 |
|---|---|
| `M` | 合法可选车（过容量门，`listMoves` 非 blocked） |
| `C` | 本步至少消 1px 的车 |
| `F` | 免费选项：本步**不新增未完成车** |
| `D` | 债选项：本步新增未完成车 |

注意：

- `C` 是“至少吃 1px”；ArlCheck 的“没得选”用“能不能**吃满**”，两者不同。
- `F` 是**每步安全选项数**，不是路线上的 `freeSteps`。路线免费步少≠没有恢复窗口；路线免费步多≠安全。
- 链组要按整组进场算：一组人进场可能新增多个未完成车，不能只按被点的那辆算。

**提案门槛（未工具化）**：

1. `buffer≥3` 的债务峰值步，`F≥1`；
2. 连续 `F=0` 不超过 1–2 步；
3. 压力段 `F/M` 约 20–50%；
4. 拿错后，在 `buffer≥3` 时仍有 `F≥1`，否则加恢复车，不要用冰把债推没。

v27 实测：全程 `F=0` 仅 1 步（buffer=0）；`buffer≥3` 的 17 步里 `F` 最少 3、`F/M` 最低 0.50。

**状态**：提案，未做成正式工具；不能当硬门，但可以作为体验诊断。

## 5. LayoutScore（排版）

代码：`03_工具/正式版/LayoutScore_v1.js`。

**硬否决**：

- L1 碎车：任一辆 ≤5px；或 ≥3 辆 <8px 且该色总像素 ≥100。
- L2 半成品：≥2 行/列整行同色；或同色连 ≥6。
- L4 锁链不正交：链组成员不是正交相邻。
- L5 目标图不可辨：大色（≥100px）超 50% 碎成 ≤2px，且最大连通块 <10。

**软警告**：

- L2 同色连 5
- L3 黑墙/黑块比例（真正单选题需 Decision/ArlCheck 复核）
- L6 单格迷宫
- 车尺寸分布、同色连、同色连通块、障碍数量、问号在链组伙伴上

## 6. 信息层（M2，诊断）

- `visibleRemain`：玩家当前“看得见”的该色剩余像素。
- `trueReach`：实际可达像素。
- 差大 = “看起来能拿、实际拿不到”的信息陷阱。
- 模型结果：oracle 0复活 16/103；visible-edge 5/92；visible-all 0/55；visible-component 0/16。真人在 edge 与 oracle 之间。
- F2 的 color30 是 visible 陷阱（229/0）；第2关的“差1px”车也是同一类。
- 状态：诊断，不是硬门；Q 问号在 F2 无决策，待 Q-aware/真人。

`ReachabilityCurve` / `TargetReachCurve` / `WindowPlan` 是容量-可达时序诊断，用于规划/解释，不是验收硬门。

## 7. 当前 M5 用的“关键门” vs 19 项

`M5Build_v5.js` 的 `pass` 只检查：

```text
peak=4 && mid 45–80 && tol 11–15 && open≥5 && policy0 && layout hard=0
```

**它不是 19 项全过**。所以会出现：

- v6 关键门全过，但 ArlCheck 仍 `→ 不通过`；
- 未过项：中段低压 8、象限 3.69、主体 76%、未动主体 0、at4=2。

以后写“v6 指标全过”必须说“M5 关键门全过”，不能说“19项全过”。

## 8. 已降级 / 不要混

1. **免费步长短**：不再是目标。只保留 `最长连续免费≤5` 作为“别长时间空转”的护栏；`freeSteps/freeRun` 是诊断。M4.5 v27 free3/47、M5 v5 free7/48、v6 free8/48 都接受。
2. **`tol`**：不是玩家容错，是 20 局噪声求解器胜率。第2关 tol19/20 但线上流失45.8%。
3. **点击结算 `stuck`**：是 raw buffer，不是真债；真 stuck 只在 PlayerSim tick。
4. **`at4` 三个口径**：最小路线 at4（19项硬门）、原始玩家 at4（含免费/在吃车）、真债 at4（stuck）。体验不要拿最小路线 at4 当玩家压力。
5. **`M/C/F/D`**：未固化；`F` 是每步安全选项，不是路线免费步。
6. **`forced`**：有工具，但还没进 M5 硬门；v5 forced=N，v6 forced=Y。
7. **“0复活”**：依赖策略族；必须写阈值、psd、seed。
8. **`峰值`**：最小路线峰值；不是每个玩家都会走到的峰值。`玩家峰值` 是 20 局噪声求解器中位数，也不是 PlayerSim。
9. **`中段`**：20 局噪声求解器中位数，不是 PlayerSim 逐 tick 曲线；真正玩家中段还没有常规输出。
10. **“没得选”**：以“能不能吃满”判，不是“能不能吃 1px”；`C` 和它不是一个东西。
