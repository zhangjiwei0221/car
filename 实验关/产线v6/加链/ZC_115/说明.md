# ZC_115 加链 A/B（2026-11-13）

> 目的：在原“加压版”成品上只加 **1 条两连锁**，看锁链改变了什么。
> 口径：`--mode a --ref corner`；`useSlotStart:true`、`instantChain:false`。
> 结论：**加链有增量**——随机通关 0.827 → 0.657（−17.0pp，附加 3 种子同样 −16.7pp），会玩路线仍全通（freeP3 0.458、熵 1.532、fill 0–1）。

## 1. 输入与改动

- A：`实验关/产线v6/加压版/ZC_115/关卡_ZC_115_p47_win85.json`（freeP3 0.469，随机 0.827）
- B：`B/关卡_ZC_115_p47_win85_chain1.json`
- 改动：仅 `(1,4)` 与 `(1,5)` 两格设同一锁链组 `type:5, param:1`
  - `(1,4)` 颜色 7 / 容量 30；`(1,5)` 颜色 30 / 容量 34；正交相邻
  - 容量、颜色、目标图、其他障碍全部不动（建 B 脚本逐格 diff 自检：只有这两格变）
- 未加冰、未加管道、未改切车与容量。

### 1.1 选链过程（与规则的一处偏差，必须记）

规则要求“首次**可点**进度在 0.20–0.60”。实跑 20 局随机 + 1 条 free-first：本关第 0–1 行**没有任何车**的首次可点进度超过 0.076（第 0 行按规则从 0 就可点；第 1 行在第 0 行车被拿后立即打开），严格口径下**无解**（明细见 `A/扫描.json`）。

因此改用同一模拟的**首次被拿进度**作为选车尺，并加上“颜色中段需求 + 棘轮 PASS”两条硬约束。逐对实测：

> `midShare` = free-first 路线中该颜色像素在进度 0.20–0.60 内被吃掉的比例；`firstEat/lastEat` 为该颜色第一次/最后一次被吃的进度。

|---|---|---|---:|---|---|
| (1,0)+(1,1) | 14 + 31 | 0.313 / 0.149 | 14 中段 | **FAIL**（progressDead + allMovesDead） | 换 |

## 3. 三个问题的回答（本关）

1. **A→B 变化**：随机通关 **−17.0pp**（标准 3 种子）/ **−16.7pp**（附加 3 种子），6 种子合并 −16.8pp；freeP3 −1.1pp；熵 +0.009。这是明显且可复现的难度上升。
2. **必经还是可绕开**：结构上**必经**——每辆车都要消完，链组两辆车迟早都要拿；solver / free-first / max-eat / small-debt 四条会玩路线全部拿链。可绕开的是**时机**：0.19–0.32 都有人拿，fill 0–1。随机路线 fill 中位 0、均值 2.4–3.3。
3. **是否出现“随机更容易死、会玩还能过”**：**出现了结果，但机制不是链的滞留代价**。
   - 随机 0.827 → 0.657，会玩 free-first 仍通（freeP3 0.458、H 1.532、fill=1）。
   - 但 80% 以上的死亡发生在**拿链之前**（进度约 0.23）：链把 `(1,4)+(1,5)` 两辆车绑成一组，改变了前中段的合法选项与开图顺序，随机玩家的路线被推早死；不是“拿了链、填不满、被 2 格拖死”。
   - 因此这张图可以算“加链有增量”，但增量来自**开图/选项集改变**，不是 v5 想要的“耦合债务”。若下一步要验证“耦合代价”，需要选一张随机玩家**先拿链**比例更高的图，或用更强的钩子（例如把链放在随机路线必经的拿链时点）。
