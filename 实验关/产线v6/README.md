## 1. 流程（6 步）

### 步 0 · 选图

```bash
node 03_工具/正式版/ImageTensionScan_v1.js /Users/red/Desktop/正常关卡 --top 30 --out 选图.json
```

判据（2026-11-12 用户补充的"总量 × 连通性"）：

| 项 | 门槛 | 为什么 |
|---|---|---|
| 色数 | 11–17 | 太少了没调度，太多了看不清 |
| 最大同色块占彩色像素 | **<25–30%** | "大且联"的顺手色会让关卡变平（23 = 32% → 完全没压力） |
| 中间色数 | ≥3 | 中间色 = `总量≥60px 且 40≤最大块≤120px`，只有这种颜色才需要"先开一片、再拿一辆" |
| 已用图 | 排除 | 每关必须有不同目标图 |
| 最小颜色 | **没有任何颜色 ≤5px**（总量） | 5px/1px 的小色必须切成 ≤5px 的车，LayoutScore 直接硬否决，且不切车就破坏守恒（141 的 5px、157 的 1px） |
| 空像素（0）占比 | **≤5%** | 空像素多时 ArlCheck 的守恒分母会把空位算进去（显示 1397/1600），交付也要特判；61 图有 13% 空位，虽逐色守恒正确但被工具误报 |

**关于“碎色”（2026-11-12 实测更正）**：`LayoutScore` 的 L5（≥100px 的颜色 >50% 碎在 ≤2px、最大块 <10）**降为警告，不否决**。实测 154 原图版：色 7 = 138px / 74 块 / 最大 3px，切成 4 辆 34–35 的车，实战中位 3–6.5 步吃完、最长 18 步，**赢局 100% 离场**——碎色可以慢慢吃，不是死债。之前的“碎色必须合并/切小”是错的。

红色预警：
- 任何颜色 `总量≥80px 且最大块<40px` = 死债色（永远吃不满）；
- **两个以上颜色占比 ≥15% 且块都很大** = 顺手色太多，关卡会平（77 图：28 占 19.3%、30 占 19.2%，freeP3 上限只有 0.082）。

**底座探测（步 1 之后、步 2 之前）**：在底座上跑一次 `PressureBuild_v5 --eval-only`，若 `freeP3 < 0.10` 且换位后仍上不去，说明这张图 + 这套切法**做不出压力**，直接换图，不要浪费 3 轮修复。

## 3. 已知边界（来自 v5 §6.5 / §23，不要再试）

- 门（链/管/冰）不能当难度工具：gate1/2/3 全部失败；中段链全部免费。
- 切法（容量分布）不能造难度：5 组切法 CV 0.17–0.78，随机通关全 1.00。
- 中段代价车无效：0–5 辆全 1.00（剂量不足 + 代价属性消失）。
- 调开局宽度（4/5/6）+ 代价车 0–2 无效：9 组全 1.00。
- 唯一能把通关率压进 0.85–0.92 的是 C3 的 8–10 辆零收益后期色车铺满开局，**死亡 100% 在进度 <20%**——是开局陷阱，不是我们要的难度。
- 三面墙：只当可选关型（4 张里 1 张从 1.00 掉到 0.29），不是规则前提。
- 模拟不能定点：随机/贪心/插值/全知都试过；最优 p=0.1 与纯随机只差 0.66pp。

## 3.5 管道试点（2026-11-13，单关）

在 33/34 同批的 115 加压版上放 1 条管道（2 辆最早色车进队列）：
- 出口在第 1 行（朝下）：开管在 15.6% 进度、随机中位 37.6%，**21% 的随机局到死都没开**；随机通关 0.833 ≈ 原 0.827、熵 1.52 不变，但 **freeP3 0.469 → 0.102**；
- 出口在第 0 行（朝上）：第 1 步就开，几乎无感。
**结论**：管道是“延迟供给”，会把会玩的人的压力**打没**，不是难度工具；内容不可见还带来“不知道缺在哪”的风险。只作试玩纹理候选。

## 3.6 锁链位置对照（2026-11-13，单关四组）

同一张 115 加压版，同样两辆车（7/30、30/34）四种摆法，各 6 种子 × 100 局：

| 组 | 位置 | 链 | 随机通关 |
|---|---|---|---:|
| A | 第 1 行 | 无 | 0.832 |
| B | 第 1 行 | **有** | **0.625** |
| C | 第 5 行 | 无 | 0.777 |
| D | 第 5 行 | 有 | 0.807 |

**结论：链的威力全在“位置”，不在“绑定”。**
- 第 1 行加链：−20.7pp；第 5 行加链：+3.0pp（噪声内）。
- 机制是**早期选项减少**：链的两个成员只要有一个没激活，两个都不能点——在开局这种选项本来就少的地方，等于抽掉 1–2 个选择。深位加链时它早已激活，等于没加。
- 深层无链（C）比 A 低 5.5pp，说明“把这两辆车挪深”本身也有影响，但不是链造成的。

**用法（修正）**：这一次对照说明“位置”是主因，但**不能外推成“链只能放开局”**——分组2 的链普遍在 3–6 行，而且多是**同一列的纵向三连**（L2：(3,0)(4,0)(5,0)；L10 有五组三连横跨 2–4 行），它们门住的是整段供给，不是两个随机格子。待验证：把“纵向三连”放中段，是否和开局两连一样有效。

## 3.7 三连锁形状与位置（2026-11-13，单关六组）

底座 115 加压版（随机 0.832、freeP3 0.469）。每张只加一组三连，全部过棘轮后才计入：

| 变体 | 格子（色/容量） | 随机通关 | vs 底座 | freeP3 | 被拿率 | fill(随机中位) |

**结论**：
1. **没有稳定的形状效应**；位置效应随形状反转（−5.9pp 到 +7.3pp）。
2. **一半三连让关卡更容易**（+3 到 +7pp）——开局可点但能等的链，被会玩的人当“延迟提款机”。
3. 唯一降容错的（H_开局）**把 freeP3 打到 0**：是“烦”，不是“压”。
4. 三连很脆：14 组候选只有 6 组过 Solvable+棘轮（57% 失败），其中一组连可通关都不过。
5. 对比：**两连锁（第 1 行）是 −17pp**，三连最好只有 −5.9pp。

**用法**：要难度用两连锁；三连只当纹理（V_开局/L_开局 略升容错），不当难度工具。

## 3.95 策略族平均通关率（2026-11-17，用户提出，已验证稳定）

**定义**：对同一关，跑 p=0,0.1,…,1.0 共 11 档“贪心概率”玩家（每档 100 局），取通关率的**平均**。它对应“玩家策略各异”，不再依赖“挑一个最优 p”。

验证（分组2 第 2–13 关，线上失败率取自 `关卡数据-20261113` ② 列）：

| 种子 | 与失败率的秩相关 | 与 97.7% 图相关 |
|---|---:|---:|
| 977 | −0.74 | — |
| **4242** | **−0.80** | — |
| **两种子之间** | — | **ρ=0.99，r=1.00** |

结论：
1. **排序在种子间几乎完全一致**（ρ=0.99），说明这个定义稳定、可复现；
2. 与线上失败率 ρ=−0.74~−0.80，**不差于** p=0.1（−0.74），而且**不需要解释“为什么是 0.1”**；
3. 仍只能排序、不能定点（12 个点，ρ<0.9）。

**用法**：作为 v6 的难度主指标，替代“单一 p 的随机通关率”；加入新策略（链可行性、看目标图、估算噪声）时，直接并入这个族一起平均。

## 3.9 链避开陷阱（2026-11-13，负结果）

假设：链"有时不增加难度"是因为它锁住了陷阱格。实测（115 底座，7,197 次选项评估）：
- **没有达到 30% 致命比例的格子**；修正 2s 超时（122 个抽样用 12s 重搜，全部有解）后，全盘致命比例 11.7%，最高 (2,4)/(3,3) 28.3%，第 0–1 行最高只有 22.5%；
- A 组（现有 3 链）6 个链格**没有一个是陷阱格**（12–18%）；
- B 组（避开 A 与前 4 名致命格）随机通关 **0.848**，比 A 的 0.453 **高 39.5pp**——方向与假设相反。

**真正的差别在“绑什么颜色”**：A 绑的是中段需求色（7/30/31，midShare 0.38–0.62），持续欠债；B 的 g1/g3 绑开局色 19/26，g2 是开通很晚的 (1,0)+(2,0)，三条链都不形成持续债务。

**结论**：链的难度不来自“锁住陷阱”，来自**绑中段需求色 + 首次被拿 10–35%**。另：2s 束搜索判“无解”不可靠（48% 超时），致命选项检测要给足预算。

## 3.96 三段口径与链数扫描（2026-11-17，现役难度口径）

**为什么改**（用户 2026-11-17）：“现在我还不太相信真实玩家有多认真，感觉他们都傻傻的”；“0–0.1 为随意、0.8–1.0 为认真，那中间的呢”。
§3.95 的策略族平均把 11 个 p 一视同仁，掩盖了两件不同的事：**能不能过**（公平）和**认不认真有没有用**（回报）。

**定义**（同一关，11 档 p-greedy 玩家，每档 100 局，种子 977）：

| 段 | 由哪几档组成 | 解释 |
|---|---|---|
| 随意档 | p 0 / 0.1 / 0.2 的均值 | 真人最接近这档（分组2 失败率 64%，p=0.3 的模拟已能到 0.9+） |
| 中间档 | p 0.3–0.7 的均值 | **只看形状**：单调上升 = 回报连续；夹反常 = 设计对“想了一点”的玩家不友好 |
| 认真档 | p 0.8 / 0.9 / 1.0 的均值 | 公平性底线：有路可走 |

**判据（候选，尚无线上校准）**：随意 0.50–0.70、认真 ≥0.85、认真−随意 ≥0.15、曲线倒序 ≤2 处。
三段都只有 100 局/档：随意档（300 局）95%CI 约 ±0.06，所以 0.47–0.53 和 0.67–0.73 都算压线。

### 3.96.3 规则修正：接受早期链（用户 2026-11-17「先按你说的来」）

`首次被拿`（firstPick）= 底座上 20 局随机路线里，该车第一次被点的进度中位；它在**绑链之前**量，告诉你这条链会在哪一段拆掉玩家的计划。
链的机制是“组内全部成员激活才可点、点一端两端一起进暂存（占 2 格）”，所以 firstPick 越低，拆掉的越是开局本来就少的选项。

- 原规则：firstPick **0.10–0.35**（六个变体试出来的窗口）。
- 下限 0.10 原本是防“开局陷阱”（112 C4：两格第 0 行、7 步吃完、随机 0.076），是**间接护栏**。
- 新证据：194 C2-早链（.038/.043）、205 C1（.088）证明 2–10% 可以做出“难而公平”的关；而直接护栏（三段口径）会把陷阱识别为随意档 ≈0.08，必被拦。
- **新规则：firstPick 2–35%**，同时保留：绑中段需求色、棘轮 PASS、可通关、三段口径。
- **未决**：上限 0.35 是否也放宽——18 C2 的第二条链 .421 高于上限，但它的作用是把中高 p“拉回公平”，不是造难度；上限原本只是描述性的（太晚=无效），不是安全护栏。等试玩后定。
- **候选补充（2026-11-17，解剖 194/205 后）**：链车**不能是它的颜色的唯一/主要载体**——独占比例（该车 count / 该色总像素）>50% 视为危险。依据：205 的链车色 18 独占 100%、可吃窗口只有 43–53%，真人死 3 次；194 的四辆链车独占 12–22%、颜色供给贯穿全程，一次通关。见 `难度带/卡关解剖_194_vs_205_20261117.md`。
  **验证（2026-11-17，四张新图 19/183/188/103，高独占 vs 低独占同图对照）= 部分成立**：at4 4/4 更差（+2.25～+4.78 步，均值 +3.27）；随意档胜率 **0/4** 更差（三个底座随意档都是 1.000，饱和；103 的低独占链反而 0.977、13 局开局锁死）。→ **独占比例只作“过程压力”的诊断/选链偏好，不进硬门**；205 的体验更像“窄窗时序 + 底座结构”共同作用。记录 `难度带/独占色验证/说明.md`、日志 §1103。
- **103 那 13 局死亡的真正原因（2026-11-17 追查）：链吞掉了开局的“逃生阀”**。复现 13/13、逐局回放：死亡恒在第 5–6 步、暂存 4、里面 3–4 辆 0 进度车；**链组一次都没进过暂存**。低独占链把 `(0,5) 色1/35`（开局外框背景色，单格一次吃满、是唯一能腾位的一辆）绑到未激活的 `(1,5)` 上：`(1,5)` 激活前它被链锁得点不了；激活后整组要 2 空位、4+2>5 被拦。独立复核：同样 6 步后点 `(0,5)`，无链版 4 格存活，有链版 buffer 6 死亡。对照组（V_无链 0 死、V_早独占 0 死、V_共享晚 0 死）证明与“独占/早/共享”都无关。
  → **候选规则：链不要绑“开局能一次吃满”的车（逃生阀）**——判别：该车 count ≤ 开局可吃的同色像素数（corner 下常见于外框/背景色的车）。这类车是满格时的唯一出路，绑上链等于抽掉安全绳。见 `难度带/独占色验证/103_机制/说明.md`、日志 §1104。
  **已做成工具 `03_工具/正式版/EscapeValveCheck_v1.js`**（2026-11-17）：`--pair r1,c1 r2,c2` 建链前检查，可批量查目录，退出码 1 = 绑了逃生阀；G3 35–42 与带内四张已全部 PASS（日志 §1105）。

## 3.96.6 压力指标 at4（2026-11-17，用户口径 + 真人路径）

**用户原话（2026-11-17）**：“暂存区压力最高就是 4，如果到 5 就输了……暂存为 4 的时候只有一次机会了，下一来那个钥匙再选错背债了就输了”；“这个新指标好像就是 v1 产线的 at4”。

- **定义**：`ArlCheck_v793` 第 57–58 行，at4 = 路线上 `暂存 ≥ 4` 的步数；v1 标准：峰值 **必须 = 4**（5 = 死，3 = 没逼到天花板）、**at4 ≥ 5**、前 10% at4 ≤ 1。
- **歧义在路线**：ArlCheck 数的是 `runMinBuffer` 的**最小暂存路线**；同一张 194，最小路线峰值 3 / at4 = 0（判 ❌），而真人路径峰值 4 / **at4 = 12（连续最长 6 步）**。→ 报告 at4 必须注明路线：
  - **at4_min**：最优路线被逼到 4 的步数（结构硬度）；
  - **at4_casual**：p 0.1–0.3 随意玩家的步数（实际体验压力）。
- **四张的 at4_casual**（`at4_扫描_v1.js`，seed 977，100 局；步数为全部对局均值，含死亡局）：

| 关 | at4 p0.1 / p0.2 | 峰值 | 触 4 的对局 | 通关 p0.1 / p0.2 |
|---|---:|---:|---:|---:|
| 194 C2-早链 | 9.6 / 9.3 | 4.00 | 100% | .50 / .57 |
| 211 C4 | 12.6 / 13.0 | 4.00 | 100% | .58 / .64 |
| 205 C1 | **21.3 / 18.8** | 4.00 | 100% | .58 / .65 |
| 18 C2 | 11.8 / 12.3 | 4.00 | 100% | .60 / .70 |
| 194 **真人**（47 步通关） | **12**（25.5%） | 4 | — | 通关 |

**读法**：
1. 随意档模拟的 at4（9–21 步）和真人（12 步）在同一量级——**at4_casual 是能接上真人体验的指标**，而 at4_min=0 会得出“这关没有压力”的错误结论；
2. 四张关的随意玩家**每一局都摸到 4**（100/100）——峰值 4 是常态，不是例外；
3. **at4 和通关率是两个轴**：205 的 at4 最高（19–21 步在 4 上）但 p0.2 通关仍 .65；194 的 at4 最低但通关也最低（.57）。"紧张"与"容错"可以分开调，这一对数就是“难度与容错平衡”的坐标；
4. 真人样本只有 194 一条，且它是编辑器判“极难”的那张——**真人是靠换走法赢下来的，不是靠不背债**（自由路线 freeP3 仅 .085，真人 p3 61.7%）。

**四张真人试玩（2026-11-17，8 条路径；用户自述“看到啥点啥”，属随意档样本）**：205 死 3 次（40%/63%/77%）、18 死 1 次（开局）、211/194 一次通关；四条死亡都是“在 4 的下一步选了凑不满的新颜色车”。真人 at4（通关局）：194 12、205 8、18 3、211 2——205 与模拟一致（最紧），211/18 真人远低于模拟。**按随意玩法，205 的“压线 .523”更像过难：三次死亡都在中后段，是流失形态而非学习形态。** 明细：`待试玩_20261117/试玩记录_20261117.md`。

## 4. 还没解决

1. **锁链与管道的内核**：链是"耦合"（两辆车同进同出），管道是"隐藏队列"。数据上它们在中性剂量（1–3 组链、1–3 格管道）与线上表现无关；真正的问题是怎么让"耦合"产生代价。计划：在成批关里挑 3 张，各加 1–2 组链做 A/B（棘轮 + 随机通关 + 熵）。
2. **绝对难度标定**：只能靠试玩与上线数据。
3. **难度曲线/关卡位置**：暂不考虑。
