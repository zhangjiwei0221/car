## 1. 它做什么 / 不做什么

- **做**：把 A1 v2 的“某色在某进度形成需求峰”翻译成给人修改的**卡点卡片草案**：
  门色、进度窗口、门类型、钥匙车、代价车、门外计划、替代路线、一句话理由。
- **不做**：不造关、不切车、不摆位、不加锁链/冰/管道；不读关卡 JSON。
  卡片里的容量只是草案占位值，不是 S2 的最终切车结论。

## 3. 取法（暂定规则，B 阶段用数据校准）

1. 候选只来自 A1 的 `gateCandidates`（需求峰 + 开局不可达 + 该色总量 ≥60px）。
   峰的窗口必须**完整**落在 `--min-window .. --max-window`（默认 0.20–0.85）。
2. 同一颜色的相邻 5% 窗口（`windowIndex` 相差 ≤1）合并成一条**需求带**；
   每条带取“峰占该窗口比例 × 该色总量”最高的窗口作为候选（任务书口径）。
3. 按得分降序选门；一关最多 `--max-gates`（默认 2）；两个门不能在同一 5% 窗口。
4. `gateType`（按优先级）：
   - 该窗口该色需求 >120px → `chain3`
   - 窗口起点 ≥0.75 → `chain2`（后段优先两连）
   - 窗口起点 <0.60 且需求 40–80px → `chain2`
   - 该色有 ≥2 段分开的峰 → `pipe`（供给闸门）
   - 其余 → `ice`
5. `priceCar.color`：该窗口之后 10% 内（两个 5% 窗口）需求最大的**另一色**；
   没有别的色则用门色自身，`why` 写“代价即本色的后半段”。
6. 容量占位：钥匙车 40（峰需求必 ≥40px）；代价车 ≤30，取该色后续 10% 需求的
   5 的倍数（最低 5）。这是草案值，S2 还要按逐色守恒重切。

### 3.1 与任务书“同一个颜色只放一个门”的差异（必须知道）

任务书同时要求“同一个颜色只放一个门”和“91 应产出 ≥2 个门”，但 A1 v2 的 91
**只有色27 一个门候补色**（4 个峰：20–25/25–30/75–80/80–85%）。两者不能同时满足。

本工具默认按**需求带**放宽：同一颜色的、分开 ≥2 个窗口的两段峰各算一个门；
同一条带内仍只出一个门。理由：

- 91 的 20–30% 与 75–85% 在空间上是分开的（质心分别在左下、右上，见 §6），
  A1 说明 §7.5 也写了“是否算两个门要 S1 卡片人工判断”；
- 验收 1 明确要求 91 ≥2 个门。

第二张卡片的 `rationale` 会写明“该色共有 N 段分开的需求带，本卡片只是其中一段，
需人工确认是否算独立门”。想严格按字面规则时加 `--strict-one-per-color`，
此时 91 只出 1 个门（已实测）。

## 4. 卡片字段

| 字段 | 含义 |
|---|---|
| `gateId` | 本图内的门序号（按候选得分降序） |
| `progressWindow` | 门的进度窗口 `[from, to]`，0–1，来自 A1 的 5% 窗口 |
| `gateColor` | 门卡住的颜色（A1 门候补色） |
| `demandPxInWindow` | 该色在该窗口被吃的像素数（= A1 峰的 `pxInWindow`） |
| `windowPx` | 该窗口被吃的总像素数（A1 `demandCurve[i].total`） |
| `gateType` | `chain2` / `chain3` / `pipe` / `ice`，见 §3 |
| `keyCar` | 钥匙车草案：`{color, capacity, why}`；why 带窗口内可达像素数 |
| `priceCar` | 代价车草案：`{color, capacity, why}`；color 为后续 10% 需求最大的另一色 |
| `outsidePlan` | 门外计划：门外该色容量合计 ≤ 窗口需求 × 0.4 |
| `alternativeRoute` | 第二种过法草案：`{type:"ice", color, iceSteps:"比门晚 6–10 辆"}` |
| `rationale` | 一句话理由（占比、px、该色总量；同色多带时附人工确认提示） |
| `draft` | 恒为 `true`：这是草案，不是定稿 |

文件顶层另有 `imageVerdict`、`gateCandidates`、`candidatesRanked`、
`noGateReason`、`notes`，方便人核对“为什么选/没选它”。

## 6. 草案能不能直接给人改

**可以拿去做 S1 的起点，但不能当定稿。** 主要待人工判断的点：

1. **91 的两个门是同一色的两段带**：A1 说明也把它标为“要人判断”。草案已提示。
2. **132 的第二个门是 `pipe`**：因为色19 有 3 段分开的峰，按规则在 70–75%
   （需求 45px、窗口起点 <0.75）落到 `pipe`。这是规则推导，不代表图上一定有
   适合做管道队列的形状；要人看 TXT 确认。
3. **容量是占位值**：钥匙 40 / 代价 ≤30，未做逐色守恒，也没考虑车盘格子数。
4. **价色只按“后续 10% 需求最大”选**，没有检查该色是否已在别的门里当钥匙/代价。
5. **只用了 A1 的 canonical 消融顺序**：真人会换颜色，需求峰可能被绕开；
   A1 说明 §7.1 已声明。
6. **规则阈值（20–85%、60px、40–80px、120px、0.75、0.60）都是暂定值**，
   等 B1/B3 有结果后用数据校准。

结论：草案适合作为“人改卡片的初稿”——字段完整、每个选择都能追溯到 A1 的峰；
但每个门仍需人做三件事：确认该色在该进度的空间位置合理、确认门类型、
按图重定容量与门外比例。
