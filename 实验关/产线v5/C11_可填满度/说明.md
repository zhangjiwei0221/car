## 0. 问题原话

> 「19 没任何压力，**纯色联通太大了**。」（用户 2026-11-12）

假设：车能不能吃满，取决于该颜色**连通块有多大**，而不只是颜色总像素。

## 1. 指标定义（与任务一致）

对每个颜色 c，4 连通求连通块：

- `bigPx(c)` = 落在 **≥40px** 连通块里的像素数（40 = 一辆车典型容量）
- `fillable(c)` = `bigPx(c) / totalPx(c)`（0–1；=0 表示该色没有任何块大到能装满一辆车）

关卡级：

- `fillableWeighted` = Σ bigPx / Σ totalPx（像素加权）
- `fillableMean` = fillable(c) 的简单平均
- `bigBlobShare` = 最大同色连通块像素 / 全图像素（H×W）

## 4. 与已知量的 Spearman（n=12；双尾 p<0.05 需 |ρ|≳0.587）

| 指标 | vs 随机通关率 | vs 线上失败率② |
|---|---:|---:|
| fillableWeighted | **−0.168** | **+0.232** |
| fillableMean | −0.049 | −0.028 |
| bigBlobShare | +0.359 | −0.231 |

**假设的方向是**：fillable 越高 → 越容易（随机通关率↑、失败率↓）。

## 6. 判断：值不值得进选图流程

**不建议作为选图流程的难度分数/门槛；建议保留为“逐色可填满度体检表”。**

理由（均有数字）：

1. **线性方向不成立**：12 关实测 `fillableWeighted` 与随机通关率 ρ=−0.168、与失败率 ρ=+0.232，方向与假设相反且不显著；“越填满越简单”没有数据支持。
2. **阈值不稳定**：40px 换成 80/100px，相关翻成 +0.296 / +0.184；阈值敏感说明它是描述量而非因果量。
3. **指标把两端都算作“坏”，但两端难度相反**：fillable=0（91 色 24，327px 全碎）会让车永远装不满（压力/挫败来源），fillable≈1 且最大块 252px（106 色 14）则让车瞬间吃满（无压力）。单一单调分数必然互相抵消——这解释了为什么相关接近 0。
4. **106 vs 91 的图像级对比确实支持用户感受**，说明机制存在，但它是**局部/逐色**的，不是关卡级标量。

可落地用法（若要用）：

- 在选图/验收时输出逐色表，标红两类极端：`最大块 ≥ 120px`（≈3 辆车，无压力风险）与 `totalPx ≥ 80 且 fillable = 0`（永远装不满风险）。
- 若要做关卡级分数，应改成**分方向的两项**（如 `bigBlobShare` 与 `unfillablePxShare`）而不是一个 fillableWeighted；本次数据里 `bigBlobShare` 是唯一方向符合假设的（ρ=+0.359 通关率 / −0.231 失败率），但仍不显著，只能当提示，不能当判据。
- 另外注意：G2 的随机通关率还受车辆容量/分配影响（本次只用了 blocks），负结果不足以完全否定机制，但足以说明**不要把它放进选图门槛**。
