# C1 建造：ZC_23 v2 “有代价的门”说明

> 2026-11-12。工具：`03_工具/正式版/GateApply_v2.js`（新增，v1 保留未改）。
> 底座：`实验关/新组_正常关卡/ZC_23/安全版/关卡_ZC_23_safe.json`（未改动）。
> 产物：`关卡_ZC_23_gate2.json`、`GateApply_v2.json`、本文件。
> 规则：不预设钥匙/代价色；遍历所有正交相邻车格对（至少一个成员是门色 31）；
> 先筛 win≥0.9、entropy≥1.45、守恒、可通关；再优先 `chainFillSteps≥2`。

## 0. 结论

**找得到有代价的门：`6,2(4/31) + 6,3(31/31)`，会玩 chainFillSteps=6，win=100%，entropy=1.57。**
但它在 **74.5%** 才开门，不在卡片的 50–55%；而且随机玩家的 fill 中位只有 0.5/0/0——
**代价主要由 free-first（会玩）路线承担，随机玩家常常更早拿门、当步吃满**。
卡点窗口 45–60% 内的 9 个相邻对**全部 fill=0**：
这张 7×7 安全版能做出“尾部、对会玩路线有代价的门”，做不出“50–55%、对两种路线都有代价的门”。

> 如果“chainFillSteps≥2”按**随机中位**判，唯一在中间进度满足的是
> `2,1(30/32)+2,2(31/32)`：随机 fill 中位 2、随机开门 58.5%、win 100%、熵 1.56，
> 但会玩 fill=0（会玩路线当步吃满）。所以无论按哪条路线，都没有“两边都 ≥2”的候选。

## 2. 选中方案：`6,2(4/31) + 6,3(31/31)`

- 两个格子：`(6,2)` 颜色 4 / 31px；`(6,3)` 颜色 31 / 31px。正交相邻。
- 上链：两格 `type:5, param:1`（盘上原无锁链）。没有改 count / id / 其他障碍。
- 代价来自哪：开门（74.5%）时，颜色 4 在目标图上可达 31px（=它的 31 容量），
  但颜色 31 只剩 **3px 可达**（容量 31）。链组进场后，31 那一半吃不饱，
  要等 6 个后续 pick 才离场——这就是“占着暂存 2 格好几步”。
- 随机玩家常常在更早（72.6–73.7%）拿门，此时 31 供给还够，fill 中位降到 0.5/0/0；
  代价主要由 free-first（会玩）路线承担。

## 4. 为什么 50–55% 的窗口里做不出代价

46 个相邻对里，处于 45–60% 开门的只有 9 对，**9 对全部 fill=0**。例：

| 相邻对 | 开门 | fill | 开门时可达 px / 容量 |
|---|---:|---:|---|
| 4,1(28/32)+4,2(31/32) | 52.5% | 0 | 28: 220/32；31: 8/32 |
| 4,2(31/32)+4,3(28/32) | 50.5% | 0 | 28: 252/32；31: 2/32 |
| 5,1(31/32)+5,2(28/32) | 54.5% | 0 | 28: 188/32；31: 11/32 |
| 3,2(31/32)+4,2(31/32) | 50.5% | 0 | 31: 40/64 |

- 这些位置的颜色供给太足：28 色一次可达 188–252px（容量只有 32），31 虽然只剩几个可达，
  但链组里先吃的 28 会把相邻的 31 像素打开，所以 31 也能在同一步吃完 → fill=0。
- 反过来，只有“一边快耗尽”的地方才有代价：
  - 0% 的 `(0,1)6 + (0,2)31`：两边可达都是 0，fill=35；但熵 1.34，不达标。
  - 74.5% 的 `(6,2)4 + (6,3)31`：31 可达 3 / 容量 31，fill=6；熵 1.57，达标。
  - 6.1% 的 `(1,4)18 + (1,5)31`：18 可达 0 / 容量 36，fill=2；熵 1.42，不达标。
- 所以：**这张盘不是“根本做不出有代价的门”，而是“做不出卡在 50–55% 且两种路线都收费的门”**。
  代价门只出现在开头（0–6%）或尾巴（74.5%）；中间进度的代价只对随机玩家成立（见下）。

### 4.1 如果按“随机中位”判：`2,1(30/32)+2,2(31/32)`

| 指标 | 数值 |
|---|---:|
| 会玩 fill | 0 |
| 随机 fill 中位 | **2** |
| 会玩开门 | 44.5% |
| 随机开门中位 | 58.5% |

- 这对比选中方案更接近卡片窗口（随机 58.5%，会玩 44.5%），且随机玩家真的占 2 步；
- 但会玩（free-first）路线在 44.5% 拿门时两种颜色的可达像素都够，fill=0——
  **代价只对随机玩家成立**。
- 因此它不是“两边都收费”的解；如果规则要求“会玩 fill≥2”，它不合格。

## 6. 局限

1. `chainFillSteps` 是模拟估的：定义是“拿到链组后，链组仍占着暂存的后续 pick 数”；
   会玩路线是 free-first，随机玩家是“洗牌→当步不死”，都不是真人。
2. 代价主要在会玩路线（fill=6）；随机玩家常常更早拿门（72.6–73.7%），fill 中位 0.5/0/0。
   所以它不是一个“对所有人都收费”的门。
3. 门在 74.5% 才开，不在卡片 50–55%；如果要的是 50–55% 的卡点，这个方案不算达标。
4. 随机通关率仍 100%，freeP3 只从 0.000 升到 0.063；门增加了 6 步暂存压力，
   但没有把任何随机玩家挡死。
5. ArlCheck 15 项硬门仍不全过（中段 at3、后 20% at3、at4≥5 等压力项）；
   底座本来也不过。本任务只把“可通关 / 守恒 / 无空格 / 开局≥5”当合法门。
6. 只改了 `(6,2)` 与 `(6,3)` 两个 type/param；逐色守恒、总 1600→1600、blocks 不变。
