# 产线 v5-0：致命选项 × 分组2 线上失败率（2026-11-11）

> 产线 v5 = 用户 2026-11-11 同意的新产线编号；v5-0 是“先验证尺子”。日志 §1094。

## 问题

压力与容错打架，是因为“容错 = 有免费退路”，而有免费退路玩家就不欠债。
假设：把容错改成“**没有致命选项**”（尤其是“当步没死、其实已无解”的延迟致死），能否对上线上失败率？

## 方法

- 工具：`03_工具/正式版/FatalOptionCheck_v0.js`（corner 规则，Simulator 同 ArlCheck_v793）。
- 路线：每步在**非致命**选项里挑“最诱人”（本步吃得最多，平手暂存少）的那个。
- 每步枚举所有可点车：free / cost / fatal-immediate / fatal-hidden；`bait` = 最诱人的选项是致命的。
- 可通关判定：束搜索 W1=8，失败再 W2=32 复核（找不到≠严格无解，fatal 略高估）。
- 数据：`测试版本/2026_10_05/分组2/G2_bq_level_{2..13}.json`（与线上一致，已核对）；线上 `分组2-20261110-新指标.csv` 的 ② 列。
- 命令：`node 03_工具/正式版/FatalOptionCheck_v0.js <关卡> --out L{n}_w8.json`；相关性 `python3 corr.py [最少进入人数]`。

## 结论

1. **v5-0 未通过**（事先定的门：ρ≥0.6 且优于现有指标）。新指标方向对（失败率 ≤28% 的 L8/L9/L13 致命占比 ≤3%；L2/L5/L7 有 6–8 步诱饵陷阱），但**没有比 ChoiceSpace 选择熵更好**。
2. **解释不了的**：L3（失败 64%、致命 4.6%）与 L10（失败 48%、致命 0）。这条路线上没有陷阱，但玩家照样失败 → 要么陷阱在别的路线上（单路线覆盖不够），要么失败来自别的原因（选项后果趋同 / 长磨，见 `ChoiceSpace_20261110.md`）。
3. **最强的单信号仍是“选择”**：9 张可靠关上选择熵 ρ=−0.83。和用户的直觉（“每一步都有选择”）一致。
4. 可用的设计规则（方向性，非硬门）：**最诱人的选项不能是延迟致死**；选择熵要高。
