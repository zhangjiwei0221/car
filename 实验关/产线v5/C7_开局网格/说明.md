## 0. 结论（三选一）

**只能造开局陷阱。**

- 规定的 9 组（A4/5/6 × B0/1/2）**全部 1.000（300/300 通关，0 死亡）**；A7 三个对照也全部 1.000。**没有任何一组落进 0.85–0.92，也没有 20–50% 进度的死亡**。
- 也就是说：**本网格规定的剂量（冰 n=1–3、代价车 0–2 辆）没有触达能标定的区间**——A 只让开局前 1–3 步少几个选项，B 只加 0–2 辆 C5 代价车。
- 把同底座已有证据一起看，结论才是“只能造开局陷阱”：
  - **C3**：唯一能进 0.85–0.92 的开局改法是 9–10 辆 C3 的 32/43 代价车（0.913 / 0.893），而它们的死亡 **100% 在 <20% 进度**，20–50% 进度死亡为 0；
  - **C5**：C5 那批代价车（22/14、23/29、1/34、5/24、5/43）**5 辆全放开局也仍 1.000、0 死亡**（M5_open）；
  - **C7（本实验）**：冰 + 0–2 辆 C5 车仍是 1.000、0 死亡。
  - 合并：这个底座上的开局旋钮，要么**无效**（低剂量 / C5 车），要么**只能造开局陷阱**（C3 高剂量）。**没有“适中且不死在开局”的证据。**
- 严格说，这 9 组本身是“未触达”，不是“造出了开局陷阱”；“只能造开局陷阱”是对“开局旋钮家族”的合并判断（C3 高剂量是唯一进带证据），不是这 9 组的直接观测。这一点在局限里再写一次。

## 4. 逐问回答

### 问 1：9 组表
见 §3。通关率全部 1.000，熵 1.248–1.439，死亡全部 0，开局可点 4/5/6，救援车 1/2/3（随 A 变，不随 B 变）。

### 问 2：有没有落在 0.85–0.92、且死亡在 20–50% 进度的组合？
**没有。** 9 组全部 1.000、0 死亡；0.85–0.92 区间和 20–50% 进度死亡在本网格里都没有出现。

### 问 3：冰造成的熵损失有多大？
**冰没有降熵，反而略微升熵**（ChoiceSpaceCheck_v1 的 avgEntropy，A7 为对照）：

| B | A7 | A6（Δ） | A5（Δ） | A4（Δ） |
|---|---:|---:|---:|---:|
| 0 | 1.2458 | 1.2476（**+0.0018**） | 1.2512（**+0.0054**） | 1.2622（**+0.0163**） |
| 1 | 1.4225 | 1.4243（+0.0018） | 1.4279（+0.0054） | 1.4389（+0.0165） |
| 2 | 1.3779 | 1.3791（+0.0011） | 1.3810（+0.0031） | 1.3891（+0.0111） |

- A 从 7 降到 4，熵最多 **+0.0163**（B0），不是损失；三档 B 方向一致。
- **最高熵 1.4389（A4_B1），没有破 1.45**，不需要单独标注退回。
- 解释：冰拿走的是“最好的救援选项”，剩下选项的后果差异反而更大（avgM 只从 8.08 降到 7.96），所以熵略升。

### 问 4：结论三选一
**只能造开局陷阱**（合并 C3/C5 证据；本 9 组本身未触达，见 §0 与 §6）。

所有命令在 `实验关/产线v5/C7_开局网格/` 下执行（工具都是现役正式版，未改动）：

```bash
BASE=../C1_建造/106_base/关卡_ZC_106_v1.json
DIR=$PWD
TOOLS=../../../03_工具/正式版

# 1) 构建 12 个变体（A=7 三个是对照；逐色守恒/总量/车数/空格）
node build_grid.js "$BASE" --out "$DIR"

# 2) 开局可点 / 救援车 / 逐车首点 ratio
for f in A7_B0 A7_B1 A7_B2 A6_B0 A6_B1 A6_B2 A5_B0 A5_B1 A5_B2 A4_B0 A4_B1 A4_B2; do
  node opening_stats.js "$f.json" --out "open_$f.json" > "open_$f.log" 2>&1
done

# 3) 合法性：Solvable width8 + LayoutScore
for f in A7_B0 A7_B1 A7_B2 A6_B0 A6_B1 A6_B2 A5_B0 A5_B1 A5_B2 A4_B0 A4_B1 A4_B2; do
  node "$TOOLS/Solvable_v1.js" "$f.json" --width 8 --out "solvable_$f.json" > "solvable_$f.log" 2>&1
  node "$TOOLS/LayoutScore_v1.js" "$f.json" --out "layout_$f.json" > "layout_$f.log" 2>&1
done

# 4) 随机玩家 100 局 × 3 种子（--no-mcfd）
for f in A7_B0 A7_B1 A7_B2 A6_B0 A6_B1 A6_B2 A5_B0 A5_B1 A5_B2 A4_B0 A4_B1 A4_B2; do
  node "$TOOLS/PopulationSim_v1.js" "$f.json" --random 100 --seeds 977,4242,31337 --no-mcfd --out "pop_$f" > "pop_$f.log" 2>&1
done

# 5) 选择熵
for f in A7_B0 A7_B1 A7_B2 A6_B0 A6_B1 A6_B2 A5_B0 A5_B1 A5_B2 A4_B0 A4_B1 A4_B2; do
  node "$TOOLS/ChoiceSpaceCheck_v1.js" "$f.json" --out "cs_$f.json" > "cs_$f.log" 2>&1

# 6) 汇总（通关率 / 熵 / 死亡分档 / 开局可点 / 救援车）
node analyze_grid.js --dir "$DIR" --out "$DIR/grid_summary.json"
```

实际执行时 12 个变体的 3)–5) 用 `xargs -P 6/8` 并行；每个变体的输出写进自己的 `pop_<变体>/`、`cs_<变体>.json`、`*_<变体>.log`，互不覆盖。

## 6. 局限

1. **B 的“第 0–1 行”实际只能是第 0 行**：本底座是“顶部暴露”棋盘（`isExposedAt`：r=0 恒暴露；其余行要正交邻格是外部连通空格）。开局（step 0）7 个合法可点全在第 0 行，第 1 行一辆也不可点（`opening_stats` 的 `openingRow0Moves == openingLegalMoves`）。所以“开局就能点到的第 0–1 行位置”= 第 0 行。第 1 行要等第 0 行清出空格后才暴露，不属于“开局可点”。
2. **冰是临时的**：n=1–3 只锁最初 1–3 个球；A4 的开局 4 个选项在 3 步内就恢复成 7 个。这决定了 A 的天花板很低——它只改“开局前几步的选择数”，不改中段。
3. **C5 代价车本身剂量弱**：22/14、23/29、1/34 的容量小（14/29/34），且颜色在中段会变可达；C5 已实测“5 辆全放开局也 1.000”（M5_open）。本实验 B 只放 0–2 辆，更不可能移动通关率。
4. **换位有后期副作用**：22/14、23/29 换到第 0 行后，11/58、24/54 被回填到第 6 行。它们在中后段才可点，可能轻微改变后期节奏；本实验 300 局全胜，无法从通关率上分离这个副作用。
5. **本网格 9 组未触达目标带**：全部 1.000、0 死亡，严格说这 9 组没有“造出开局陷阱”，只是“剂量不足”。结论“只能造开局陷阱”依赖 C3 高剂量（9–10 辆 32/43，0.913/0.893，死亡全部 <20% 进度）与 C5（5 辆 C5 车放开局 1.000）的合并证据，不是 C7 单独证明的。
6. **只有随机玩家模型**：未跑会玩路线（free-first）、未做真人 `OpeningCheck --path`。随机玩家 1.000 不等于真人体验；本实验只回答“随机通关率能不能被开局旋钮标定”。
7. **死亡分档为空**：因为 0 死亡，20–50% 进度死亡为 0 是“没死”，不是“death 位置被测量为 0”。若要验证“能否死在 20–50%”，需要先有能进 0.85–0.92 的剂量（C3 的 9–10 辆），而那批是 <20% 早死。
8. **未改目标图/容量/颜色/锁链/管道/黑块**：只整辆车互换 + 给第 0 行 3 辆车加数字冰；逐色守恒已由 `build_grid.js` 校验。本底座本身无锁链/管道/黑块。
